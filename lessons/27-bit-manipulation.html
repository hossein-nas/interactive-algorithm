Bit manipulation

A number is a row of switches; flip them in bulk.

Book link: Grokking Algorithms does not teach bit tricks, but its binary search chapter and the "log₂" discussion in chapter 1 rest on binary numbers, and the bitmask idea is the compact way to represent the sets that chapters 10 and 11 enumerate (set covering, knapsack, traveling salesperson). This file covers v2 question #6 (Counting Bits, LeetCode 338) and adds the XOR tricks, bitmasks, and a bit trie.

Reach for it when

"O(1) extra space" with pairs, sets of up to ~20 items, powers of two, or the problem talks about bits.

The key tricks

x & (x − 1) clears the lowest 1; x & −x keeps it; x ^ x = 0; bit i of a mask = item i is in.

Language traps

JavaScript bit operators are 32-bit signed; >>> is the unsigned shift. Go's unary ^ is NOT; parenthesize every bit test.

1. The idea in plain English

Inside the computer every integer is a row of bits (0 or 1). Bit manipulation means working on those bits directly. It is useful for three things:

  1. Speed and memory: a set of up to 64 items fits in one integer (bit i = "item i is in the set"). This is a bitmask.
  2. Clever tricks: XOR cancels equal numbers, so "find the number that appears once" becomes a one-line loop.
  3. Problems that ask about binary directly: counting 1 bits, powers of two, parity, adding without +.

Reading a binary number

Each position is worth a power of two, from the right: 1, 2, 4, 8, 16, …

  decimal 13  =  8 + 4 + 0 + 1   =   1 1 0 1   (binary)
  positions:                        8 4 2 1

XOR is the star: three facts

So XOR-ing a whole list makes every number that appears twice vanish, leaving the one that appears once.

Two's complement and negative numbers

Computers store a negative number so that adding it to the positive version gives 0. The recipe is "flip all bits, add 1": −x = ~x + 1. For 8 bits, 5 = 00000101, so −5 = 11111011. The leftmost bit is the sign bit. The consequences you will use:

  • x & -x isolates the lowest set bit (see below).
  • ~x = -x - 1.
  • A right shift of a negative number keeps the sign (an arithmetic shift), in both TypeScript (>>) and Go.

Why x & (x − 1) clears the lowest 1 (the most important trick)

Subtracting 1 from a binary number flips the lowest 1 to 0 and every 0 below it to 1. ANDing with the original cancels exactly those positions:

  x       = 1 0 1 1 0 0      (44)
  x - 1   = 1 0 1 0 1 1      (43)
  x & x-1 = 1 0 1 0 0 0      (40)   <- the lowest 1 is gone

Repeating x &= x - 1 until x is 0 counts the 1 bits, one per loop (Brian Kernighan's algorithm).

4. How to recognize it

  • "Single number", "appears twice except one" → XOR.
  • "Count the number of 1 bits", "Hamming distance", "power of two/four".
  • Constraints like n ≤ 20 with "all subsets" / "visit all nodes" → bitmask over a set.
  • "Without using +, -", "O(1) space" tricks.
  • "Maximum XOR", "XOR queries" → a binary trie.
  • "Compress a boolean array into an integer" (state for DP or BFS).

Problem 1 · Number of 1 Bits (LeetCode 191) and Power of Two (LeetCode 231), Easy

Task. (a) Count the 1 bits in an unsigned 32-bit integer (the Hamming weight). 11 (1011) → 3. (b) Is n a power of two?

Two ways to count:

  • Check every bit: loop 32 times, count += (n >> i) & 1: always 32 steps.
  • Kernighan: n &= n − 1 removes one 1 per loop, so it takes exactly as many steps as there are 1s: faster for sparse numbers.

Trace of Kernighan on 11 = 1011:

stepn (binary)after n &= n−1count
1101110101
2101010002
3100000003

Power of two: exactly one 1 bit means n & (n − 1) == 0, and n must be positive (zero would also satisfy the AND).

function hammingWeight(n: number): number {
  let count = 0;
  while (n !== 0) {
    n &= n - 1; // clears the lowest 1 bit
    count++;
  }
  return count;
}

function isPowerOfTwo(n: number): boolean {
  return n > 0 && (n & (n - 1)) === 0; // exactly one bit set
}

console.log(hammingWeight(11)); // 3
console.log(hammingWeight(128)); // 1
console.log(hammingWeight(4294967293)); // 31   (all 32 bits except bit 1)
console.log(isPowerOfTwo(16), isPowerOfTwo(18), isPowerOfTwo(1), isPowerOfTwo(0)); // true false true false
func hammingWeight(n uint32) int {
	count := 0
	for n != 0 {
		n &= n - 1 // clears the lowest 1 bit
		count++
	}
	return count
}

func isPowerOfTwo(n int) bool {
	return n > 0 && n&(n-1) == 0 // exactly one bit set
}

func exampleBitCounting() {
	fmt.Println(hammingWeight(11))                                                  // 3
	fmt.Println(hammingWeight(128))                                                 // 1
	fmt.Println(hammingWeight(4294967293))                                          // 31
	fmt.Println(bits.OnesCount32(4294967293))                                       // 31   (the standard library does the same)
	fmt.Println(isPowerOfTwo(16), isPowerOfTwo(18), isPowerOfTwo(1), isPowerOfTwo(0)) // true false true false
}

Complexity. O(number of 1 bits) time (at most 32), O(1) space.

Problem 2 · Counting Bits (LeetCode 338, Easy; v2 list)

Task. For every number i from 0 to n, return the number of 1 bits in i, as an array. n = 5 → [0, 1, 1, 2, 1, 2].

Brute force. Count bits of each number: O(n log n).

The DP insight (a bridge to file 25). The bit count of i is related to a smaller number's count:

bits[i] = bits[i >> 1] + (i & 1)

Shifting right drops the last bit; the rest was already counted at i >> 1; add 1 if the dropped bit was a 1. Another version: bits[i] = bits[i & (i − 1)] + 1.

Trace:

ibinaryi >> 1bits[i >> 1]last bitbits[i]
00000
10010011
20101101
30111112
41002101
51012112
function countBits(n: number): number[] {
  const bits = new Array<number>(n + 1).fill(0); // bits[0] = 0
  for (let i = 1; i <= n; i++) bits[i] = bits[i >> 1] + (i & 1); // reuse the answer for i / 2
  return bits;
}
console.log(countBits(5)); // [ 0, 1, 1, 2, 1, 2 ]
console.log(countBits(2)); // [ 0, 1, 1 ]
console.log(countBits(0)); // [ 0 ]
func countBits(n int) []int {
	bitCount := make([]int, n+1) // bitCount[0] = 0
	for i := 1; i <= n; i++ {
		bitCount[i] = bitCount[i>>1] + (i & 1) // reuse the answer for i / 2
	}
	return bitCount
}

func exampleCountBits() {
	fmt.Println(countBits(5)) // [0 1 1 2 1 2]
	fmt.Println(countBits(2)) // [0 1 1]
	fmt.Println(countBits(0)) // [0]
}

Complexity. Time O(n), space O(n) (the output).

Problem 3 · Single Number (LeetCode 136), Missing Number (268), Single Number III (260)

Single Number. Every number appears twice except one, which appears once. Find it in O(n) time and O(1) space. [4,1,2,1,2] → 4.

Idea. XOR everything. Pairs cancel (a ^ a = 0), and 0 ^ x = x. A hash set would be O(n) space; XOR needs none.

Missing Number. An array has n distinct numbers from 0..n (one is missing). Find it. [3,0,1] → 2.

Idea. XOR all the indexes 0..n with all the values. Every number present appears twice (once as an index, once as a value) and cancels; the missing number appears only as an index, so it survives. (The sum formula n(n+1)/2 − sum also works.)

Single Number III. Exactly two numbers appear once; all others appear twice. Find both. [1,2,1,3,2,5] → [3, 5].

Idea (two steps).

  1. XOR everything: the pairs cancel, leaving x = a ^ b (the two unique numbers XOR-ed). Since a ≠ b, x is not zero, so at least one bit differs between a and b.
  2. Take the lowest set bit of x (low = x & −x): a bit where a and b differ. Split all numbers into two groups by whether that bit is set. a and b land in different groups, and each pair of duplicates lands together in the same group. XOR each group separately: each yields one of the unique numbers.

Trace ([1,2,1,3,2,5]): total XOR = 3 ^ 5 = 6 (110); lowest set bit = 2 (010). Numbers with bit 1 set: 2, 3, 2 → XOR = 3. Numbers with it clear: 1, 1, 5 → XOR = 5.

function singleNumber(nums: number[]): number {
  let result = 0;
  for (const x of nums) result ^= x; // pairs cancel, leaving the single number
  return result;
}

function missingNumber(nums: number[]): number {
  let result = nums.length; // include the index n, which has no matching slot
  for (let i = 0; i < nums.length; i++) result ^= i ^ nums[i]; // every present number cancels with its index
  return result;
}

function singleNumberIII(nums: number[]): number[] {
  let xor = 0;
  for (const x of nums) xor ^= x; // = a ^ b
  const low = xor & -xor; // a bit where a and b differ
  let a = 0, b = 0;
  for (const x of nums) {
    if (x & low) a ^= x; // group with the bit set
    else b ^= x; // group with the bit clear
  }
  return [a, b].sort((p, q) => p - q);
}

console.log(singleNumber([2, 2, 1]), singleNumber([4, 1, 2, 1, 2])); // 1 4
console.log(missingNumber([3, 0, 1]), missingNumber([9, 6, 4, 2, 3, 5, 7, 0, 1])); // 2 8
console.log(singleNumberIII([1, 2, 1, 3, 2, 5])); // [ 3, 5 ]
console.log(singleNumberIII([-1, 0])); // [ -1, 0 ]
func singleNumber(nums []int) int {
	result := 0
	for _, x := range nums {
		result ^= x // pairs cancel, leaving the single number
	}
	return result
}

func missingNumber(nums []int) int {
	result := len(nums) // include the index n, which has no matching slot
	for i, x := range nums {
		result ^= i ^ x // every present number cancels with its index
	}
	return result
}

func singleNumberIII(nums []int) []int {
	xor := 0
	for _, x := range nums {
		xor ^= x // = a ^ b
	}
	low := xor & -xor // a bit where a and b differ
	a, b := 0, 0
	for _, x := range nums {
		if x&low != 0 {
			a ^= x // group with the bit set
		} else {
			b ^= x // group with the bit clear
		}
	}
	if a > b {
		a, b = b, a
	}
	return []int{a, b}
}

func exampleXorTricks() {
	fmt.Println(singleNumber([]int{2, 2, 1}), singleNumber([]int{4, 1, 2, 1, 2}))                       // 1 4
	fmt.Println(missingNumber([]int{3, 0, 1}), missingNumber([]int{9, 6, 4, 2, 3, 5, 7, 0, 1}))       // 2 8
	fmt.Println(singleNumberIII([]int{1, 2, 1, 3, 2, 5}))                                             // [3 5]
	fmt.Println(singleNumberIII([]int{-1, 0}))                                                        // [-1 0]
}

Complexity. All three: time O(n), space O(1).

Related: Single Number II (every number appears three times except one): count each bit position modulo 3, or use two accumulators ones and twos.

Problem 4 · Sum of Two Integers: add without + (LeetCode 371, Medium)

Task. Compute a + b without using + or −. 1 + 2 → 3.

Idea. Addition in binary has two parts, and each is a bit operation:

  • XOR gives the sum of each bit without carries: 1 ^ 1 = 0 (and a carry), 1 ^ 0 = 1.
  • AND, shifted left by 1 gives the carries: (a & b) << 1.

Then add the carries to the partial sum, which is the same problem again: repeat until there are no carries.

Trace for 3 + 5 (011 + 101):

roundaba ^ b(a & b) << 1
1011101110010
2110010100100
31001000001000
4000100010000000 → done: 1000 = 8

Negative numbers work automatically in 32-bit two's complement. In JavaScript the bit operators are already 32-bit; in Go we use int32 to get the same wrap-around behavior (otherwise the loop still ends, but at 64-bit width).

function getSum(a: number, b: number): number {
  while (b !== 0) {
    const carry = (a & b) << 1; // positions where both bits are 1 produce a carry to the left
    a = a ^ b; // add without the carries
    b = carry; // now add the carries
  }
  return a;
}
console.log(getSum(1, 2)); // 3
console.log(getSum(2, 3)); // 5
console.log(getSum(-2, 3)); // 1
console.log(getSum(-1, 1)); // 0
console.log(getSum(20, -30)); // -10
func getSum(a, b int) int {
	x, y := int32(a), int32(b) // 32-bit two's complement, like the problem expects
	for y != 0 {
		carry := (x & y) << 1 // positions where both bits are 1 produce a carry to the left
		x ^= y                // add without the carries
		y = carry             // now add the carries
	}
	return int(x)
}

func exampleGetSum() {
	fmt.Println(getSum(1, 2))    // 3
	fmt.Println(getSum(2, 3))    // 5
	fmt.Println(getSum(-2, 3))   // 1
	fmt.Println(getSum(-1, 1))   // 0
	fmt.Println(getSum(20, -30)) // -10
}

Complexity. Time O(1) (at most 32 rounds), space O(1).

Problem 5 · Bitmask subsets (LeetCode 78 revisited) and submask enumeration

Task. Generate all subsets of [1, 2, 3]. File 11 used backtracking; the bit version is shorter.

Idea. There are 2ⁿ subsets, and each one is described by an n-bit number: bit i set means "include nums[i]". Counting mask from 0 to 2ⁿ − 1 visits every subset exactly once.

maskbinarysubset of [1,2,3]
0000[]
1001[1]
2010[2]
3011[1, 2]
4100[3]
5101[1, 3]
6110[2, 3]
7111[1, 2, 3]

A classic idiom: enumerate all submasks of a mask (all subsets of a subset):

for (sub = mask; sub > 0; sub = (sub - 1) & mask) { ... }  // then handle sub = 0 separately

(sub − 1) & mask jumps to the next smaller submask. For mask = 101: 101 → 100 → 001 → 000. This appears in subset-sum-style DP over bitmasks and in the "Shortest Path Visiting All Nodes" problem of file 22.

Where bitmask state is used: traveling salesperson DP (dp[mask][last]), assigning tasks to workers (dp[mask]), "visited nodes" in BFS, and board games with small boards. The constraint n ≤ 20 is the usual hint.

function subsetsByMask(nums: number[]): number[][] {
  const n = nums.length;
  const result: number[][] = [];
  for (let mask = 0; mask < 1 << n; mask++) {
    const subset: number[] = [];
    for (let i = 0; i < n; i++) if (mask & (1 << i)) subset.push(nums[i]); // bit i = "take nums[i]"
    result.push(subset);
  }
  return result;
}

// All non-empty submasks of `mask`, from largest to smallest.
function submasksOf(mask: number): number[] {
  const subs: number[] = [];
  for (let sub = mask; sub > 0; sub = (sub - 1) & mask) subs.push(sub);
  return subs;
}

console.log(subsetsByMask([1, 2, 3]));
// [ [], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3] ]
console.log(submasksOf(0b101).map((m) => m.toString(2))); // [ '101', '100', '1' ]
console.log(submasksOf(0b111).length); // 7   (all non-empty subsets of 3 bits)
func subsetsByMask(nums []int) [][]int {
	n := len(nums)
	result := make([][]int, 0, 1<<n)
	for mask := 0; mask < 1<<n; mask++ {
		subset := []int{}
		for i := 0; i < n; i++ {
			if mask&(1<<i) != 0 {
				subset = append(subset, nums[i]) // bit i = "take nums[i]"
			}
		}
		result = append(result, subset)
	}
	return result
}

// All non-empty submasks of mask, from largest to smallest.
func submasksOf(mask int) []int {
	subs := []int{}
	for sub := mask; sub > 0; sub = (sub - 1) & mask {
		subs = append(subs, sub)
	}
	return subs
}

func exampleBitmaskSubsets() {
	fmt.Println(subsetsByMask([]int{1, 2, 3})) // [[] [1] [2] [1 2] [3] [1 3] [2 3] [1 2 3]]
	for _, m := range submasksOf(0b101) {
		fmt.Printf("%b ", m)
	}
	fmt.Println()                        // 101 100 1
	fmt.Println(len(submasksOf(0b111))) // 7
}

Complexity. subsetsByMask: time O(n · 2ⁿ), space O(n · 2ⁿ) for the output. Submask enumeration of all masks of n bits totals O(3ⁿ).

Problem 6 · Maximum XOR of Two Numbers in an Array (LeetCode 421, Medium/Hard)

Task. Find the maximum value of nums[i] ^ nums[j] over all pairs. [3,10,5,25,2,8] → 28 (5 ^ 25).

Brute force. All pairs: O(n²).

The greedy-on-bits idea. To make an XOR as big as possible, we want a 1 in the highest bit position, then in the next, and so on. For a given number x, its best partner y has, at each bit from the top, the opposite bit of x whenever possible (because 1 ^ 0 = 1).

A binary trie (file 18) makes this fast. Insert every number as a path of 31 bits (from the highest bit to the lowest). For each x, walk the trie from the top: at each bit, prefer the child with the opposite bit (it gives a 1 in the XOR); if that child does not exist, take the same-bit child (a 0 in the XOR). The walk spells out the best partner, and the XOR accumulates the answer.

Trace idea with 5-bit numbers: x = 5 = 00101. The trie holds 3 = 00011, 10 = 01010, 25 = 11001, ... Starting at the top bit, x has 0, so we prefer a child with 1: 25 (11001) goes that way. Continuing down, we keep choosing opposite bits when available: the path spells 11001 = 25, and 5 ^ 25 = 28.

function findMaximumXOR(nums: number[]): number {
  // The trie: each node is [child for bit 0, child for bit 1]; -1 means "no such child".
  const trie: [number, number][] = [[-1, -1]];
  const BITS = 30; // values are below 2^31, so bits 30..0 are enough

  for (const num of nums) {
    let node = 0;
    for (let bit = BITS; bit >= 0; bit--) {
      const b = (num >> bit) & 1;
      if (trie[node][b] === -1) {
        trie.push([-1, -1]);
        trie[node][b] = trie.length - 1;
      }
      node = trie[node][b];
    }
  }

  let best = 0;
  for (const num of nums) {
    let node = 0, xor = 0;
    for (let bit = BITS; bit >= 0; bit--) {
      const b = (num >> bit) & 1;
      const want = 1 - b; // the opposite bit makes this position a 1 in the XOR
      if (trie[node][want] !== -1) {
        xor |= 1 << bit;
        node = trie[node][want];
      } else {
        node = trie[node][b]; // forced to take the same bit: a 0 here
      }
    }
    best = Math.max(best, xor);
  }
  return best;
}
console.log(findMaximumXOR([3, 10, 5, 25, 2, 8])); // 28
console.log(findMaximumXOR([14, 70, 53, 83, 49, 91, 36, 80, 92, 51, 66, 70])); // 127
console.log(findMaximumXOR([0])); // 0
console.log(findMaximumXOR([2, 4])); // 6
func findMaximumXOR(nums []int) int {
	// The trie: each node is [child for bit 0, child for bit 1]; -1 means "no such child".
	trie := [][2]int{{-1, -1}}
	const bitsCount = 30 // values are below 2^31, so bits 30..0 are enough

	for _, num := range nums {
		node := 0
		for bit := bitsCount; bit >= 0; bit-- {
			b := (num >> bit) & 1
			if trie[node][b] == -1 {
				trie = append(trie, [2]int{-1, -1})
				trie[node][b] = len(trie) - 1
			}
			node = trie[node][b]
		}
	}

	best := 0
	for _, num := range nums {
		node, xor := 0, 0
		for bit := bitsCount; bit >= 0; bit-- {
			b := (num >> bit) & 1
			want := 1 - b // the opposite bit makes this position a 1 in the XOR
			if trie[node][want] != -1 {
				xor |= 1 << bit
				node = trie[node][want]
			} else {
				node = trie[node][b] // forced to take the same bit: a 0 here
			}
		}
		best = max(best, xor)
	}
	return best
}

func exampleFindMaximumXOR() {
	fmt.Println(findMaximumXOR([]int{3, 10, 5, 25, 2, 8}))                                     // 28
	fmt.Println(findMaximumXOR([]int{14, 70, 53, 83, 49, 91, 36, 80, 92, 51, 66, 70}))         // 127
	fmt.Println(findMaximumXOR([]int{0}))                                                      // 0
	fmt.Println(findMaximumXOR([]int{2, 4}))                                                   // 6
}

Complexity. Time O(n · B) where B = 31 (a constant), space O(n · B) for the trie.

Alternative without a trie (good to mention): build the answer bit by bit from the top. For each bit, keep the set of all numbers' prefixes so far, and test whether some pair of prefixes XORs to the candidate answer (candidate = answer | (1 << bit), then check with a set: for each prefix p, is candidate ^ p in the set?). Also O(n · B), using hashing instead of a trie.

Common mistakes

  • Operator precedence: in many languages == binds tighter than &. Write (x & 1) === 0, not x & 1 === 0. (TypeScript and Go: always parenthesize.)
  • JavaScript's 32-bit trap: 1 << 31 is negative; 1 << 32 is 1; bit operations on numbers above 2³² silently discard the high bits. Use BigInt when needed.
  • Using >> on a negative number when you wanted an unsigned shift (>>> in JavaScript).
  • Go's ^: it is both XOR (binary) and NOT (unary); there is no ~.
  • Using a signed type for masks and shifting into the sign bit.
  • Off-by-one in the loop bound (mask < 1 << n, not <=).
  • Forgetting n > 0 in the power-of-two test (0 & −1 = 0).
  • Reaching for bit tricks first when a plain approach is clear: readability counts in an interview unless the problem demands O(1) space or bit-level behavior.

1 · By hand

Compute by hand: 13 & 7, 13 | 7, 13 ^ 7, 13 >> 2, 13 << 1. Check each with the binary form 1101.

Answer

13 = 1101, 7 = 0111. 13 & 7 = 0101 = 5; 13 | 7 = 1111 = 15; 13 ^ 7 = 1010 = 10; 13 >> 2 = 11 = 3; 13 << 1 = 11010 = 26.

2 · 44 and 43

Explain, using the binary of 44 and 43, why x & (x − 1) clears the lowest set bit.

Answer

44 = 101100, 43 = 101011. Subtracting 1 turns the lowest 1 (bit 2) into 0 and the zeros below it into 1s; everything above is unchanged. ANDing keeps the unchanged upper bits and wipes the rest: 101000 = 40. Run 44 in the first animation.

3 · Reverse Bits

Reverse Bits (LeetCode 190): peel the lowest bit off n and push it onto the result, 32 times. Which two operations does each round need?

Answer

Each of the 32 rounds needs a shift-and-OR into the result and a shift of n: result = (result << 1) | (n & 1); n >>>= 1;. In JavaScript finish with result >>> 0 to read it as unsigned.

4 · Hamming Distance

Hamming Distance (LeetCode 461): which two operations from this file combine to count the differing bits of two numbers?

Answer

XOR marks the positions where the two numbers differ, then count the 1 bits with n &= n − 1: hammingWeight(x ^ y).

5 · Gray Code for n = 3

Gray Code (LeetCode 89): the i-th Gray code is i ^ (i >> 1). Check it for n = 3.

Answer

i = 0..7 gives 000, 001, 011, 010, 110, 111, 101, 100. Each neighbor differs in exactly one bit (including 100 back to 000).

6 · A set in one integer

A set of up to 20 elements stored as one integer: write the expressions to add element k, remove it, test membership, and count members.

Answer

Add: s |= 1 << k. Remove: s &= ~(1 << k) (Go: s &^= 1 << k). Test: (s >> k) & 1 (or (s & (1 << k)) !== 0). Count: the popcount, hammingWeight(s) (Go: bits.OnesCount(uint(s))).
