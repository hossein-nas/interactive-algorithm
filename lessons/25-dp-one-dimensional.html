Dynamic programming, part 1: one dimension

Solve each smaller question once, write it down, and build up.

1. The idea in plain English

Suppose you must compute something big, and you notice that to compute it you keep needing the same smaller answers again and again. Instead of recomputing them each time, compute each small answer once, write it down, and look it up later. That is dynamic programming (DP).

An everyday comparison. You are climbing a staircase and want to know how many different ways there are to reach step 10, if you can climb 1 or 2 steps at a time. To arrive at step 10 you must have come from step 9 or step 8. So:

ways(10) = ways(9) + ways(8)

and the same logic applies to ways(9) and ways(8). If you compute naively, you recompute ways(8) many times. If you write each answer down the first time, every answer is computed once.

The repeated nodes are overlapping subproblems. DP removes the repetition.

Two properties a problem needs

PropertyMeaning
Overlapping subproblemsThe same smaller question is asked many times. (If every subproblem were different, there is nothing to remember; that is divide and conquer, file 09.)
Optimal substructureThe best answer for the big problem can be built from the best answers of smaller problems.

How DP differs from greedy and from plain recursion

  • Greedy (file 23) commits to one choice and never looks back. DP tries all choices (efficiently, by reusing answers) and picks the best.
  • Plain recursion may recompute the same answer exponentially many times. DP computes each distinct answer once: exponential becomes polynomial.

2. The five-step recipe (memorize this)

Step 1 is the hard one. Write the sentence: "dp[i] = the fewest coins needed to make amount i". If you cannot say it clearly, the rest will be wrong.

For step 2, ask the "last move" question: "What was the last decision that led to this state?" Each possible last decision gives one term; take the best (min, max, or sum).

Interview advice: write the recurrence in words, then write the top-down version (it is close to the math), then convert to bottom-up and shrink the memory if the interviewer asks.

How to recognize a DP problem

  • Asks for the minimum / maximum / count of ways / is it possible, over choices.
  • Brute force is a recursion that tries every option and the options repeat the same sub-situation.
  • The input is small enough for O(n²) or O(n · k) (typically n ≤ 5000 or a target up to 10⁴ or 10⁵).
  • "Longest/shortest subsequence", "minimum cost to reach", "number of ways to", "can you partition…".

Three flavors you will meet

Yes / no (feasible?)or (is any last choice good?)word break, subset sum

Problem 1 · Climbing Stairs: the DP warm-up (LeetCode 70, Easy)

Task. You can climb 1 or 2 steps. How many distinct ways to reach step n? n = 3 → 3 (1+1+1, 1+2, 2+1). n = 5 → 8.

  1. State: ways[i] = the number of ways to stand on step i.
  2. Recurrence: the last move was a 1-step (from i − 1) or a 2-step (from i − 2): ways[i] = ways[i−1] + ways[i−2].
  3. Base: ways[1] = 1, ways[2] = 2 (or ways[0] = 1).
  4. Order: left to right.
  5. Answer: ways[n].

Three versions: slow recursion, memoized recursion, and constant-space loop. The code shows all three so you can see the evolution.

// 1) Naive recursion: O(2^n), recomputes the same answers.
function climbNaive(n: number): number {
  if (n <= 2) return n;
  return climbNaive(n - 1) + climbNaive(n - 2);
}

// 2) Top-down with a memo: O(n) time and space.
function climbMemo(n: number, memo = new Map<number, number>()): number {
  if (n <= 2) return n;
  const saved = memo.get(n);
  if (saved !== undefined) return saved;
  const result = climbMemo(n - 1, memo) + climbMemo(n - 2, memo);
  memo.set(n, result);
  return result;
}

// 3) Bottom-up table: O(n) time and space.
function climbTable(n: number): number {
  if (n <= 2) return n;
  const ways = new Array<number>(n + 1).fill(0);
  ways[1] = 1;
  ways[2] = 2;
  for (let i = 3; i <= n; i++) ways[i] = ways[i - 1] + ways[i - 2];
  return ways[n];
}

// 4) Keep only the last two values: O(n) time, O(1) space.
function climbStairs(n: number): number {
  if (n <= 2) return n;
  let prev2 = 1, prev1 = 2;
  for (let i = 3; i <= n; i++) [prev2, prev1] = [prev1, prev1 + prev2];
  return prev1;
}

console.log(climbStairs(3), climbStairs(5), climbStairs(45)); // 3 8 1836311903

func climbTable(n int) int {
	if n <= 2 {
		return n
	}
	ways := make([]int, n+1)
	ways[1], ways[2] = 1, 2
	for i := 3; i <= n; i++ {
		ways[i] = ways[i-1] + ways[i-2]
	}
	return ways[n]
}

		return n

		prev2, prev1 = prev1, prev1+prev2
	}

func exampleClimbStairs() {
	fmt.Println(climbNaive(10), climbMemo(10, map[int]int{}), climbTable(10), climbStairs(10)) // 89 89 89 89
	fmt.Println(climbStairs(3), climbStairs(5), climbStairs(45))                               // 3 8 1836311903
}

Complexity. Naive O(2ⁿ); memo/table O(n); rolling variables O(n) time and O(1) space.

The "rolling variables" idea. Since ways[i] depends only on the previous two, keep just those two. Whenever dp[i] depends on a fixed number of recent cells, you can shrink memory to that many variables.

Problem 2 · House Robber (LeetCode 198, Medium; v2 Q8)

Task. Houses in a row contain money nums[i]. You cannot rob two adjacent houses (alarm). Maximize the money. [1,2,3,1] → 4 (houses 1 and 3). [2,7,9,3,1] → 12 (2 + 9 + 1).

  1. State: best[i] = the maximum money from the first i houses (considering houses 0..i−1).
  2. Recurrence (the last-move question: rob house i − 1 or not?):
    • Skip house i−1: best[i−1].
    • Rob house i−1: you could not have robbed i−2, so best[i−2] + nums[i−1].
    • best[i] = max(best[i−1], best[i−2] + nums[i−1]).
  3. Base: best[0] = 0 (no houses), best[1] = nums[0].
  4. Answer: best[n].

function rob(nums: number[]): number {
  let skip = 0; // best[i-2]: best when we have NOT used the previous house
  let take = 0; // best[i-1]: best over the houses so far
  for (const money of nums) {
    const newBest = Math.max(take, skip + money); // skip this house, or rob it on top of best[i-2]
    skip = take;
    take = newBest;
  }
  return take;
}
console.log(rob([1, 2, 3, 1])); // 4
console.log(rob([2, 7, 9, 3, 1])); // 12
console.log(rob([5])); // 5
console.log(rob([])); // 0
console.log(rob([2, 1, 1, 2])); // 4
func rob(nums []int) int {
	skip, take := 0, 0 // best[i-2] and best[i-1]
	for _, money := range nums {
		newBest := max(take, skip+money) // skip this house, or rob it on top of best[i-2]
		skip, take = take, newBest
	}
	return take
}

func exampleRob() {
	fmt.Println(rob([]int{1, 2, 3, 1}))    // 4
	fmt.Println(rob([]int{2, 7, 9, 3, 1})) // 12
	fmt.Println(rob([]int{5}))             // 5
	fmt.Println(rob(nil))                  // 0
	fmt.Println(rob([]int{2, 1, 1, 2}))    // 4
}

Complexity. Time O(n), space O(1).

Why not greedy? [2, 1, 1, 2]: greedy "take the biggest available" grabs a 2, then a 1, getting 3; the best is 2 + 2 = 4. DP considers both options at every house.

Follow-ups. House Robber II (LeetCode 213), houses in a circle: the first and last are adjacent, so run the linear version twice (without the first house, without the last house) and take the max. House Robber III (LeetCode 337), houses in a tree: tree DP returning a pair (rob this node, skip this node).

Problem 3 · Coin Change (LeetCode 322, Medium; v2 Q7), and Coin Change II (LeetCode 518)

Task (322). Given coin values and a target amount, find the fewest coins that sum to it, or −1. Coins [1,2,5], amount = 11 → 3 (5 + 5 + 1). Coins [2], amount = 3 → −1. (Each coin type may be used any number of times.)

Why greedy fails. Coins [1, 3, 4], amount 6: greedy gives 4 + 1 + 1 (3 coins); best is 3 + 3 (2 coins).

  1. State: fewest[a] = the fewest coins to make amount a.
  2. Recurrence (the last coin): if the last coin used is c, the rest is fewest[a − c], plus one coin: fewest[a] = 1 + min over coins c ≤ a of fewest[a − c].
  3. Base: fewest[0] = 0. All others start at "infinity" (impossible).
  4. Order: a from 1 up to amount.
  5. Answer: fewest[amount] (or −1 if still infinity).

function coinChange(coins: number[], amount: number): number {
  const fewest = new Array<number>(amount + 1).fill(Infinity); // Infinity = not reachable
  fewest[0] = 0; // zero coins make amount 0
  for (let a = 1; a <= amount; a++) {
    for (const coin of coins) {
      if (coin <= a && fewest[a - coin] + 1 < fewest[a]) fewest[a] = fewest[a - coin] + 1;
    }
  }
  return fewest[amount] === Infinity ? -1 : fewest[amount];
}

// Coin Change II: the NUMBER OF COMBINATIONS (order does not matter) that make the amount.
function change(amount: number, coins: number[]): number {
  const ways = new Array<number>(amount + 1).fill(0);
  ways[0] = 1; // one way to make 0: use no coins
  for (const coin of coins) { // coins in the OUTER loop: each combination is counted once
    for (let a = coin; a <= amount; a++) ways[a] += ways[a - coin];
  }
  return ways[amount];
}

func coinChange(coins []int, amount int) int {
	unreachable := amount + 1 // bigger than any real answer, safe to add 1 to
	fewest := make([]int, amount+1)
	for a := 1; a <= amount; a++ {
		fewest[a] = unreachable
		for _, coin := range coins {
			if coin <= a && fewest[a-coin]+1 < fewest[a] {
				fewest[a] = fewest[a-coin] + 1
			}
		}
	}
	if fewest[amount] >= unreachable {
		return -1
	}
	return fewest[amount]
}

// Coin Change II: the NUMBER OF COMBINATIONS (order does not matter) that make the amount.
func change(amount int, coins []int) int {
	ways := make([]int, amount+1)
	ways[0] = 1 // one way to make 0: use no coins
	for _, coin := range coins { // coins in the OUTER loop: each combination is counted once
		for a := coin; a <= amount; a++ {
			ways[a] += ways[a-coin]
		}
	}
	return ways[amount]
}

func exampleCoinChange() {
	fmt.Println(coinChange([]int{1, 2, 5}, 11))              // 3
	fmt.Println(coinChange([]int{2}, 3))                     // -1
	fmt.Println(coinChange([]int{1}, 0))                     // 0
	fmt.Println(coinChange([]int{1, 3, 4}, 6))               // 2
	fmt.Println(coinChange([]int{186, 419, 83, 408}, 6249)) // 20
	fmt.Println(change(5, []int{1, 2, 5}))                   // 4
	fmt.Println(change(3, []int{2}))                         // 0
	fmt.Println(change(10, []int{10}))                       // 1
}

Complexity. Time O(amount × number of coins), space O(amount).

Why the loop order matters in Coin Change II. With coins outside and amounts inside, each combination is built in one fixed coin order, so {1, 2} is counted once. If you swap the loops (amounts outside), 1+2 and 2+1 are counted separately: that counts permutations, which is a different problem (LeetCode 377, Combination Sum IV).

Problem 4 · Longest Increasing Subsequence (LeetCode 300, Medium; v2 Q9)

Task. Find the length of the longest strictly increasing subsequence (items need not be adjacent, but must keep their order). [10,9,2,5,3,7,101,18] → 4 (2,3,7,101).

Solution A: O(n²) DP.

  1. State: len[i] = the length of the longest increasing subsequence ending exactly at index i (that last item must be nums[i]).
  2. Recurrence: look at every earlier j < i with nums[j] < nums[i]; extend the best of them: len[i] = 1 + max(len[j]), or just 1 if none.
  3. Base: every len[i] starts at 1 (the item alone).
  4. Answer: the maximum over all len[i] (the best subsequence can end anywhere).

Maximum = 4.

Solution B: O(n log n), the "tails" trick (patience sorting). Keep an array tails where tails[k] = the smallest possible last value of an increasing subsequence of length k + 1. This array is always sorted. For each number x:

  • Find the first position in tails whose value is ≥ x (binary search: the lower bound from file 08).
  • If found, replace it with x (we found a smaller ending for that length, which can only help future extensions).
  • If not found (x is bigger than everything), append x (a longer subsequence now exists).

The length of tails at the end is the answer. (The array itself is not necessarily a valid subsequence; only its length is meaningful.)

function lengthOfLISQuadratic(nums: number[]): number {
  const len = new Array<number>(nums.length).fill(1); // each item alone is a subsequence of length 1
  let best = 0;
  for (let i = 0; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) len[i] = Math.max(len[i], len[j] + 1);
    }
    best = Math.max(best, len[i]);
  }
  return best;
}

function lengthOfLIS(nums: number[]): number {
  const tails: number[] = []; // tails[k] = smallest last value of any increasing subsequence of length k+1
  for (const x of nums) {
    let lo = 0, hi = tails.length; // lower bound: first index with tails[index] >= x
    while (lo < hi) {
      const mid = lo + ((hi - lo) >> 1);
      if (tails[mid] >= x) hi = mid;
      else lo = mid + 1;
    }
    tails[lo] = x; // replaces a larger tail, or appends when lo === tails.length
  }
  return tails.length;
}

console.log(lengthOfLISQuadratic([7, 7, 7, 7]), lengthOfLIS([7, 7, 7, 7])); // 1 1

func lengthOfLISQuadratic(nums []int) int {
	length := make([]int, len(nums))
	best := 0
	for i := range nums {
		length[i] = 1 // each item alone is a subsequence of length 1
		for j := 0; j < i; j++ {
			if nums[j] < nums[i] {
				length[i] = max(length[i], length[j]+1)
			}
		}
		best = max(best, length[i])
	}
	return best
}

func lengthOfLIS(nums []int) int {
	tails := []int{} // tails[k] = smallest last value of any increasing subsequence of length k+1
	for _, x := range nums {
		pos := sort.SearchInts(tails, x) // lower bound: first index with tails[index] >= x
		if pos == len(tails) {
			tails = append(tails, x) // a longer subsequence now exists
		} else {
			tails[pos] = x // a smaller end for an existing length
		}
	}
	return len(tails)
}

func exampleLIS() {
	fmt.Println(lengthOfLISQuadratic([]int{10, 9, 2, 5, 3, 7, 101, 18}), lengthOfLIS([]int{10, 9, 2, 5, 3, 7, 101, 18})) // 4 4
	fmt.Println(lengthOfLISQuadratic([]int{0, 1, 0, 3, 2, 3}), lengthOfLIS([]int{0, 1, 0, 3, 2, 3}))                     // 4 4
	fmt.Println(lengthOfLISQuadratic([]int{7, 7, 7, 7}), lengthOfLIS([]int{7, 7, 7, 7}))                                 // 1 1
	fmt.Println(lengthOfLIS(nil))                                                                                        // 0
}

Complexity. O(n²) time and O(n) space; or O(n log n) time and O(n) space.

Follow-ups. Print the actual subsequence: store a prev[i] pointer in the O(n²) version and walk back from the best end. Non-decreasing instead of strictly increasing: use an upper bound (first index with tails[k] > x). Russian Doll Envelopes (LeetCode 354): sort by width ascending and height descending for ties, then LIS on heights.

Problem 5 · Word Break (LeetCode 139, Medium)

Task. Can the string s be split into a sequence of words from a dictionary? (Words may be reused.) s = "leetcode", dict ["leet","code"] → true. s = "catsandog", dict ["cats","dog","sand","and","cat"] → false.

This is a "yes/no" DP.

  1. State: can[i] = true if the first i characters of s (the prefix s[0..i)) can be split into dictionary words.
  2. Recurrence (the last word): the prefix of length i can be built if there is a split point j < i such that the prefix of length j is splittable and the piece s[j..i) is a dictionary word: can[i] = OR over j of (can[j] AND s[j..i) is a word).
  3. Base: can[0] = true (the empty prefix).
  4. Answer: can[n].

function wordBreak(s: string, wordDict: string[]): boolean {
  const words = new Set(wordDict);
  const maxLen = Math.max(0, ...wordDict.map((w) => w.length)); // longer pieces cannot match
  const can = new Array<boolean>(s.length + 1).fill(false);
  can[0] = true; // the empty prefix is splittable
  for (let i = 1; i <= s.length; i++) {
    for (let j = Math.max(0, i - maxLen); j < i; j++) {
      if (can[j] && words.has(s.slice(j, i))) {
        can[i] = true; // found one valid last word
        break;
      }
    }
  }
  return can[s.length];
}
console.log(wordBreak("leetcode", ["leet", "code"])); // true
console.log(wordBreak("applepenapple", ["apple", "pen"])); // true
console.log(wordBreak("catsandog", ["cats", "dog", "sand", "and", "cat"])); // false
console.log(wordBreak("", ["a"])); // true
func wordBreak(s string, wordDict []string) bool {
	words := make(map[string]bool, len(wordDict))
	maxLen := 0 // longer pieces cannot match
	for _, w := range wordDict {
		words[w] = true
		maxLen = max(maxLen, len(w))
	}
	can := make([]bool, len(s)+1)
	can[0] = true // the empty prefix is splittable
	for i := 1; i <= len(s); i++ {
		for j := max(0, i-maxLen); j < i; j++ {
			if can[j] && words[s[j:i]] {
				can[i] = true // found one valid last word
				break
			}
		}
	}
	return can[len(s)]
}

func exampleWordBreak() {
	fmt.Println(wordBreak("leetcode", []string{"leet", "code"}))                             // true
	fmt.Println(wordBreak("applepenapple", []string{"apple", "pen"}))                       // true
	fmt.Println(wordBreak("catsandog", []string{"cats", "dog", "sand", "and", "cat"}))      // false
	fmt.Println(wordBreak("", []string{"a"}))                                               // true
}

Complexity. Time O(n · L) substring checks where L = maxLen (each check costs up to O(L) for the slice and hash), space O(n).

Follow-up. Word Break II (LeetCode 140): return all sentences. Add backtracking guided by the can table (or memoized recursion returning lists). Warn that the output can be exponential.

Problem 6 · Maximum Subarray (LeetCode 53) and Maximum Product Subarray (LeetCode 152)

These two show a DP whose state tracks more than one number.

Maximum Subarray (Kadane's algorithm). Find the contiguous subarray with the largest sum. [-2,1,-3,4,-1,2,1,-5,4] → 6 (4, -1, 2, 1).

  1. State: endingHere = the best sum of a subarray that ends at the current index.
  2. Recurrence: either extend the previous best (endingHere + x) or start fresh at x: endingHere = max(x, endingHere + x). (Start fresh when the running total has turned negative: it can only hurt.)
  3. Answer: the maximum endingHere seen anywhere.

Maximum Product Subarray. Same task with products. [2,3,-2,4] → 6; [-2,3,-4] → 24.

The twist. A negative number can turn the smallest product into the largest. So track both the maximum and the minimum product of a subarray ending at the current index. When x is negative, swap them first (the biggest becomes the smallest and vice versa).

function maxSubArray(nums: number[]): number {
  let endingHere = nums[0];
  let best = nums[0];
  for (let i = 1; i < nums.length; i++) {
    endingHere = Math.max(nums[i], endingHere + nums[i]); // extend, or start fresh
    best = Math.max(best, endingHere);
  }
  return best;
}

function maxProduct(nums: number[]): number {
  let curMax = nums[0], curMin = nums[0], best = nums[0];
  for (let i = 1; i < nums.length; i++) {
    const x = nums[i];
    if (x < 0) [curMax, curMin] = [curMin, curMax]; // a negative flips big and small
    curMax = Math.max(x, curMax * x);
    curMin = Math.min(x, curMin * x);
    best = Math.max(best, curMax);
  }
  return best;
}

console.log(maxSubArray([-2, 1, -3, 4, -1, 2, 1, -5, 4])); // 6
console.log(maxSubArray([1]), maxSubArray([5, 4, -1, 7, 8]), maxSubArray([-1, -2])); // 1 23 -1
console.log(maxProduct([2, 3, -2, 4])); // 6
console.log(maxProduct([-2, 0, -1])); // 0
console.log(maxProduct([-2, 3, -4])); // 24
func maxSubArray(nums []int) int {
	endingHere, best := nums[0], nums[0]
	for _, x := range nums[1:] {
		endingHere = max(x, endingHere+x) // extend, or start fresh
		best = max(best, endingHere)
	}
	return best
}

func maxProduct(nums []int) int {
	curMax, curMin, best := nums[0], nums[0], nums[0]
	for _, x := range nums[1:] {
		if x < 0 {
			curMax, curMin = curMin, curMax // a negative flips big and small
		}
		curMax = max(x, curMax*x)
		curMin = min(x, curMin*x)
		best = max(best, curMax)
	}
	return best
}

func exampleMaxSubarray() {
	fmt.Println(maxSubArray([]int{-2, 1, -3, 4, -1, 2, 1, -5, 4}))                                // 6
	fmt.Println(maxSubArray([]int{1}), maxSubArray([]int{5, 4, -1, 7, 8}), maxSubArray([]int{-1, -2})) // 1 23 -1
	fmt.Println(maxProduct([]int{2, 3, -2, 4}))                                                   // 6
	fmt.Println(maxProduct([]int{-2, 0, -1}))                                                     // 0
	fmt.Println(maxProduct([]int{-2, 3, -4}))                                                     // 24
}

Complexity. Both O(n) time, O(1) space.

Why start from nums[0] rather than 0? If all numbers are negative ([-1, -2]), the best subarray has a negative sum: a start of 0 would wrongly report 0.

The zero case in products. A zero resets both curMax and curMin to x (that is, 0) through max(x, curMax*x), which acts as "start fresh" after the zero.

4. Common mistakes

  • Not writing down what dp[i] means (the single biggest cause of bugs).
  • Wrong base case (dp[0] = 0 for minimum, 1 for counting ways, true for feasibility).
  • Using Infinity + 1 in Go-like integer worlds (use a sentinel like amount + 1, or check before adding).
  • Wrong loop order (the coin-change combinations vs. permutations; filling a cell before its dependencies).
  • Taking dp[n] as the answer when the best can end anywhere (LIS, max subarray): take the max over all.
  • Greedy shortcuts (taking the biggest coin, robbing the biggest house).
  • Forgetting the empty case (amount = 0, nums = [], s = "").
  • Recursion depth in memoized versions (JavaScript stack overflow on n = 100000): convert to a loop.

1 · Six problems in one breath

For each of the six problems, say the state sentence, the recurrence, and the base case in one breath.

Answer
  • Stairs: ways[i] = ways to reach step i; ways[i−1] + ways[i−2]; ways[1] = 1, ways[2] = 2.
  • Robber: best[i] = most money from the first i houses; max(best[i−1], best[i−2] + nums[i−1]); best[0] = 0.
  • Coin change: fewest[a] = fewest coins for amount a; min over coins of fewest[a − c] + 1; fewest[0] = 0, the rest ∞.
  • LIS: len[i] = longest increasing subsequence ending at i; 1 + max len[j] over j < i with nums[j] < nums[i]; each len starts at 1; answer max len.
  • Word break: can[i] = the first i letters split; true if some j has can[j] and s[j..i) a word; can[0] = true.
  • Max subarray: end[i] = best sum ending at i; max(nums[i], end[i−1] + nums[i]); end[0] = nums[0]; answer max end.

2 · Decode Ways

Decode Ways (LeetCode 91): "226" can be decoded as BZ, VF, or BBF → 3. What is dp[i], and when can you take two digits?

Answer

dp[i] = the number of ways to decode the first i digits; dp[0] = 1. Take one digit if it is 1–9: add dp[i−1]. Take two digits if they form 10–26 (so the first is not 0): add dp[i−2]. For "226": dp = 1, 1, 2, 3.

3 · Min Cost Climbing Stairs

Min Cost Climbing Stairs (LeetCode 746): which of today's recurrences is it a disguise of?

Answer

It is Climbing Stairs with a cost (and House Robber's "from one or two back" shape): cost to reach i = cost[i] + min(reach[i−1], reach[i−2]), answer min(reach[n−1], reach[n−2]). Two rolling variables suffice.

4 · Extra state beside len[i]

Longest Arithmetic Subsequence and Number of Longest Increasing Subsequences (LeetCode 673): what extra state do you track beside len[i]?

Answer

Number of LIS (673): also keep count[i], how many subsequences of length len[i] end at i. When len[j] + 1 beats len[i], copy count[j]; when it ties, add count[j]. Longest arithmetic subsequence: the state needs the difference: dp[i][d] = length of the longest arithmetic subsequence ending at i with step d (a map per index).

5 · 1, 2 or 3 steps

Turn climbMemo into a version for 1, 2, or 3 steps. What changes in the recurrence and the rolling variables?

Answer

The recurrence gains a term: ways[i] = ways[i−1] + ways[i−2] + ways[i−3], with bases ways[0] = 1, ways[1] = 1, ways[2] = 2 (or start at 0 with ways[0] = 1 and treat negative indices as 0). The rolling version keeps three variables and slides them each step.

6 · Counts and loop order

Why is dp for "number of ways to make change" called a count, and why does the loop order decide whether you count combinations or permutations?

Answer

It is a count because the recurrence adds the counts of sub-answers instead of taking a min or max. Coins in the outer loop build every combination in one fixed coin order, so {1, 2} is counted once. Amounts in the outer loop let any coin be last at every amount, so 1+2 and 2+1 are counted separately: that is permutations (Combination Sum IV, LeetCode 377).
