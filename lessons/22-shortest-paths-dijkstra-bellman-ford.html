Shortest paths: Dijkstra and Bellman-Ford

Settle the closest node first, unless weights can be negative.

Book link: Grokking Algorithms, chapter 9 (working with Dijkstra's algorithm, terminology, "trading for a piano", negative-weight edges, implementation). The book shows Dijkstra with a hash table of costs, a hash table of parents, and a list of processed nodes. This file explains the same algorithm in my own words, replaces the "find the cheapest unprocessed node by scanning" step with a heap (the interview-standard version), and adds Bellman-Ford for negative weights, which the book mentions as the thing Dijkstra cannot handle.

Pick the tool

Equal weights: BFS. Non-negative weights: Dijkstra. Negative weights or "at most k edges": Bellman-Ford.

Dijkstra's idea

Pop the node with the smallest known distance; with weights ≥ 0 nothing later can beat it. Relax its edges.

What it costs

Dijkstra O((V + E) log V); Bellman-Ford O(V · E).

1. The idea in plain English

In file 19, BFS found the path with the fewest edges. But real roads have different lengths, flights different prices, trades different costs. We now want the path with the smallest total weight, which might use more edges.

  • Fewest edges: Start → A → Finish (2 edges) costs 6 + 1 = 7.
  • Cheapest: Start → B → A → Finish (3 edges) costs 2 + 3 + 1 = 6.

BFS would pick the 2-edge path. We need a method that cares about weights.

The book's "trading for a piano" story

You want a piano. You offer your sheet music, and someone trades it for a poster, and the poster for a guitar, and so on, each trade having a cost. The cheapest chain of trades from "sheet music" to "piano" is a shortest-path problem on a weighted graph where nodes are items and edge weights are the extra money you must pay.

2. Dijkstra's algorithm

The one idea

Always finalize the unfinished node that is currently closest to the start.

Why that is safe (if no edge weight is negative): suppose node X is the closest not-yet-finalized node, at distance d. Any other route to X would have to go through some other unfinalized node first, and that node is already at distance ≥ d; adding a non-negative edge only makes it longer. So d is the true shortest distance to X. We can lock it in forever.

The recipe

  1. Keep dist[v]: the best known distance from the start to v. Start with dist[start] = 0 and every other ∞.
  2. Keep a min-heap of (distance, node) pairs, starting with (0, start).
  3. Pop the pair with the smallest distance. If it is stale (a better distance was already found), skip it.
  4. Relax each outgoing edge u → v with weight w: if dist[u] + w < dist[v], update dist[v] and push (dist[v], v).
  5. When the heap is empty, dist holds the shortest distance to every reachable node.

"Relaxing" just means "check whether going through u gives a shorter way to v, and if so, take it".

Costs

With a binary heap and adjacency lists: O((V + E) log V) time (usually written O(E log V)), O(V + E) space. The book's version (scan all nodes to find the cheapest) is O(V²), which is fine for small dense graphs.

The restriction: no negative weights

With a negative edge, "locking in" a node is no longer safe: a later, longer route could become cheaper by crossing a negative edge.

Dijkstra locks A at distance 1 first. But S → B → A costs 5 − 10 = −5, which is better. Dijkstra misses it. Use Bellman-Ford (below).

Path reconstruction

Keep parent[v] = u whenever you improve dist[v] through u. At the end, walk from the target back to the start along parent, then reverse (same as BFS in file 19).

Negative cycle: a cycle whose edge weights sum to a negative number. Going around it forever makes the distance −∞, so "shortest path" is undefined. Bellman-Ford can tell you one exists.

4. Reusable heap (used by the Dijkstra problems)

Both languages need a priority queue (file 17). Here is the compact version used below.

class Heap<T> {
  private data: T[] = [];
  constructor(private less: (a: T, b: T) => boolean) {}
  get size(): number {
    return this.data.length;
  }
  push(item: T): void {
    this.data.push(item);
    let i = this.data.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (!this.less(this.data[i], this.data[parent])) break;
      [this.data[i], this.data[parent]] = [this.data[parent], this.data[i]];
      i = parent;
    }
  }
  pop(): T | undefined {
    if (this.data.length === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop()!;
    if (this.data.length > 0) {
      this.data[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let best = i;
        if (l < this.data.length && this.less(this.data[l], this.data[best])) best = l;
        if (r < this.data.length && this.less(this.data[r], this.data[best])) best = r;
        if (best === i) break;
        [this.data[i], this.data[best]] = [this.data[best], this.data[i]];
        i = best;
      }
    }
    return top;
  }
}

// A generic Dijkstra on an adjacency list of [neighbor, weight] pairs.
function dijkstra(adj: [number, number][][], start: number): number[] {
  const dist = new Array<number>(adj.length).fill(Infinity);
  dist[start] = 0;
  const heap = new Heap<[number, number]>((a, b) => a[0] < b[0]); // [distance, node]
  heap.push([0, start]);
  while (heap.size > 0) {
    const [d, u] = heap.pop()!;
    if (d > dist[u]) continue; // stale entry: a shorter route was found after this was pushed
    for (const [v, w] of adj[u]) {
      if (d + w < dist[v]) {
        dist[v] = d + w; // relax the edge
        heap.push([dist[v], v]);
      }
    }
  }
  return dist;
}

type Heap[T any] struct {
	data []T
	less func(a, b T) bool
}

func NewHeap[T any](less func(a, b T) bool) *Heap[T] { return &Heap[T]{less: less} }
func (h *Heap[T]) Len() int                          { return len(h.data) }

func (h *Heap[T]) Push(item T) {
	h.data = append(h.data, item)
	i := len(h.data) - 1
	for i > 0 {
		parent := (i - 1) / 2
		if !h.less(h.data[i], h.data[parent]) {
			break
		}
		h.data[i], h.data[parent] = h.data[parent], h.data[i]
		i = parent
	}
}

func (h *Heap[T]) Pop() T {
	top := h.data[0]
	last := len(h.data) - 1
	h.data[0] = h.data[last]
	h.data = h.data[:last]
	i := 0
	for {
		l, r := 2*i+1, 2*i+2
		best := i
		if l < len(h.data) && h.less(h.data[l], h.data[best]) {
			best = l
		}
		if r < len(h.data) && h.less(h.data[r], h.data[best]) {
			best = r
		}
		if best == i {
			break
		}
		h.data[i], h.data[best] = h.data[best], h.data[i]
		i = best
	}
	return top
}

type Edge struct{ to, weight int }

// A generic Dijkstra on an adjacency list. Unreachable nodes stay at math.MaxInt.
func dijkstra(adj [][]Edge, start int) []int {
	dist := make([]int, len(adj))
	for i := range dist {
		dist[i] = math.MaxInt
	}
	dist[start] = 0
	type item struct{ d, node int }
	pq := NewHeap(func(a, b item) bool { return a.d < b.d })
	pq.Push(item{0, start})
	for pq.Len() > 0 {
		cur := pq.Pop()
		if cur.d > dist[cur.node] {
			continue // stale entry: a shorter route was found after this was pushed
		}
		for _, e := range adj[cur.node] {
			if cur.d+e.weight < dist[e.to] {
				dist[e.to] = cur.d + e.weight // relax the edge
				pq.Push(item{dist[e.to], e.to})
			}
		}
	}
	return dist
}

Problem 1 · Network Delay Time (LeetCode 743, Medium)

Task. A network has n nodes (1 to n) and directed, weighted edges times[i] = [u, v, w]: a signal from u to v takes w time. A signal is sent from node k. How long until all nodes have received it? Return −1 if some node never does. times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2 → 2.

Idea. The time for the signal to reach a node is its shortest distance from k. The signal has reached everyone when the farthest node is reached, so the answer is the maximum of all shortest distances (or −1 if any is infinite).

Distances from 2: node 1 → 1, node 3 → 1, node 4 → 2. Max = 2.

function networkDelayTime(times: number[][], n: number, k: number): number {
  const adj: [number, number][][] = Array.from({ length: n + 1 }, () => []); // nodes are 1..n
  for (const [u, v, w] of times) adj[u].push([v, w]);
  const dist = dijkstra(adj, k);
  let worst = 0;
  for (let node = 1; node <= n; node++) {
    if (dist[node] === Infinity) return -1; // someone never gets the signal
    worst = Math.max(worst, dist[node]);
  }
  return worst;
}
console.log(networkDelayTime([[2, 1, 1], [2, 3, 1], [3, 4, 1]], 4, 2)); // 2
console.log(networkDelayTime([[1, 2, 1]], 2, 1)); // 1
console.log(networkDelayTime([[1, 2, 1]], 2, 2)); // -1
func networkDelayTime(times [][]int, n, k int) int {
	adj := make([][]Edge, n+1) // nodes are 1..n
	for _, t := range times {
		adj[t[0]] = append(adj[t[0]], Edge{t[1], t[2]})
	}
	dist := dijkstra(adj, k)
	worst := 0
	for node := 1; node <= n; node++ {
		if dist[node] == math.MaxInt {
			return -1 // someone never gets the signal
		}
		worst = max(worst, dist[node])
	}
	return worst
}

func exampleNetworkDelayTime() {
	fmt.Println(networkDelayTime([][]int{{2, 1, 1}, {2, 3, 1}, {3, 4, 1}}, 4, 2)) // 2
	fmt.Println(networkDelayTime([][]int{{1, 2, 1}}, 2, 1))                       // 1
	fmt.Println(networkDelayTime([][]int{{1, 2, 1}}, 2, 2))                       // -1
}

Complexity. Time O((V + E) log V), space O(V + E).

Problem 2 · Path With Minimum Effort: Dijkstra with a different "cost" (LeetCode 1631, Medium)

Task. A grid of heights. You walk from the top-left to the bottom-right moving up/down/left/right. The effort of a route is the largest height difference between two consecutive cells on it. Find the route with the minimum effort. [[1,2,2],[3,8,2],[5,3,5]] → 2.

Why Dijkstra still works. The cost of a path is not the sum of edges; it is the maximum edge on it. Dijkstra only needs the cost to be monotone: extending a path can never make it cheaper. A max has that property. So the same algorithm applies with two small changes:

  • Edge between neighboring cells = |height difference|.
  • Combine along a path with max(currentEffort, edge) instead of currentEffort + edge.

Two candidate routes on [[1,2,2],[3,8,2],[5,3,5]]:

RouteSteps between cellsEffort (the largest step)
right, right, down, down: 1 → 2 → 2 → 2 → 51, 0, 0, 33
down, down, right, right: 1 → 3 → 5 → 3 → 52, 2, 2, 22

Dijkstra explores cells in order of the effort needed to reach them, so it settles on the second route and returns 2.

function minimumEffortPath(heights: number[][]): number {
  const rows = heights.length, cols = heights[0].length;
  const effort = Array.from({ length: rows }, () => new Array<number>(cols).fill(Infinity));
  effort[0][0] = 0;
  const heap = new Heap<[number, number, number]>((a, b) => a[0] < b[0]); // [effort, row, col]
  heap.push([0, 0, 0]);
  const dirs = [[1, 0], [-1, 0], [0, 1], [0, -1]];
  while (heap.size > 0) {
    const [e, r, c] = heap.pop()!;
    if (r === rows - 1 && c === cols - 1) return e; // the first time we pop the target, e is optimal
    if (e > effort[r][c]) continue; // stale
    for (const [dr, dc] of dirs) {
      const nr = r + dr, nc = c + dc;
      if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
      const next = Math.max(e, Math.abs(heights[nr][nc] - heights[r][c])); // the path's cost is its largest step
      if (next < effort[nr][nc]) {
        effort[nr][nc] = next;
        heap.push([next, nr, nc]);
      }
    }
  }
  return 0;
}

console.log(minimumEffortPath([[1, 2, 3], [3, 8, 4], [5, 3, 5]])); // 1
console.log(minimumEffortPath([[1]])); // 0
func minimumEffortPath(heights [][]int) int {
	rows, cols := len(heights), len(heights[0])
	effort := make([][]int, rows)
	for i := range effort {
		effort[i] = make([]int, cols)
		for j := range effort[i] {
			effort[i][j] = math.MaxInt
		}
	}
	effort[0][0] = 0
	type state struct{ e, r, c int }
	pq := NewHeap(func(a, b state) bool { return a.e < b.e })
	pq.Push(state{0, 0, 0})
	dirs := [][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}
	for pq.Len() > 0 {
		cur := pq.Pop()
		if cur.r == rows-1 && cur.c == cols-1 {
			return cur.e // the first time we pop the target, e is optimal
		}
		if cur.e > effort[cur.r][cur.c] {
			continue // stale
		}
		for _, d := range dirs {
			nr, nc := cur.r+d[0], cur.c+d[1]
			if nr < 0 || nr >= rows || nc < 0 || nc >= cols {
				continue
			}
			diff := heights[nr][nc] - heights[cur.r][cur.c]
			if diff < 0 {
				diff = -diff
			}
			next := max(cur.e, diff) // the path's cost is its largest step
			if next < effort[nr][nc] {
				effort[nr][nc] = next
				pq.Push(state{next, nr, nc})
			}
		}
	}
	return 0
}

func exampleMinimumEffortPath() {
	fmt.Println(minimumEffortPath([][]int{{1, 2, 2}, {3, 8, 2}, {5, 3, 5}})) // 2
	fmt.Println(minimumEffortPath([][]int{{1, 2, 3}, {3, 8, 4}, {5, 3, 5}})) // 1
	fmt.Println(minimumEffortPath([][]int{{1}}))                              // 0
}

Complexity. Time O(rows·cols · log(rows·cols)), space O(rows·cols).

Alternatives. Binary search on the answer (file 08) plus BFS: "can we cross using steps ≤ x?" is monotone. Union-find over edges sorted by weight (Kruskal-style) also works. Mentioning two alternatives shows range.

Problem 3 · Cheapest Flights Within K Stops (LeetCode 787, Medium)

Task. flights[i] = [from, to, price]. Find the cheapest price from src to dst using at most k stops (k + 1 flights). Return −1 if impossible. With the sample flights 0→1 (100), 1→2 (100), 2→0 (100), 1→3 (600), 2→3 (200): from 0 to 3, k = 1 → 700; k = 2 → 400.

Why plain Dijkstra fails. The cheapest route might use too many stops; a slightly pricier route with fewer stops may be the only legal one. Dijkstra's "lock in the cheapest" ignores the stop budget.

Bellman-Ford with a round limit. Bellman-Ford relaxes every edge in rounds. After round i, dist[v] is the cheapest price using at most i flights. So run exactly k + 1 rounds. One subtle point: in each round, relax using a copy of the previous round's distances, so a single round cannot chain several flights.

Trace (src = 0, dst = 3, k = 1 → 2 rounds)

Rounddist after (nodes 0,1,2,3)Meaning
start[0, ∞, ∞, ∞]
1[0, 100, ∞, ∞]one flight: only 0→1 is possible
2[0, 100, 200, 700]two flights: 1→2 (200), 1→3 (700)

Answer 700 (the route 0 → 2 → 3 needs three flights, which is too many).

function findCheapestPrice(n: number, flights: number[][], src: number, dst: number, k: number): number {
  let dist = new Array<number>(n).fill(Infinity);
  dist[src] = 0;
  for (let round = 0; round <= k; round++) { // k stops = k + 1 flights = k + 1 rounds
    const next = [...dist]; // read from `dist`, write to `next`: one flight per round
    for (const [from, to, price] of flights) {
      if (dist[from] !== Infinity && dist[from] + price < next[to]) next[to] = dist[from] + price;
    }
    dist = next;
  }
  return dist[dst] === Infinity ? -1 : dist[dst];
}

func findCheapestPrice(n int, flights [][]int, src, dst, k int) int {
	dist := make([]int, n)
	for i := range dist {
		dist[i] = math.MaxInt
	}
	dist[src] = 0
	for round := 0; round <= k; round++ { // k stops = k + 1 flights = k + 1 rounds
		next := append([]int(nil), dist...) // read from dist, write to next: one flight per round
		for _, f := range flights {
			from, to, price := f[0], f[1], f[2]
			if dist[from] != math.MaxInt && dist[from]+price < next[to] {
				next[to] = dist[from] + price
			}
		}
		dist = next
	}
	if dist[dst] == math.MaxInt {
		return -1
	}
	return dist[dst]
}

func exampleFindCheapestPrice() {
	flights := [][]int{{0, 1, 100}, {1, 2, 100}, {2, 0, 100}, {1, 3, 600}, {2, 3, 200}}
	fmt.Println(findCheapestPrice(4, flights, 0, 3, 1))                                                   // 700
	fmt.Println(findCheapestPrice(4, flights, 0, 3, 2))                                                   // 400
	fmt.Println(findCheapestPrice(3, [][]int{{0, 1, 100}, {1, 2, 100}, {0, 2, 500}}, 0, 2, 0))          // 500
	fmt.Println(findCheapestPrice(3, [][]int{{0, 1, 100}, {1, 2, 100}, {0, 2, 500}}, 0, 2, 1))          // 200
	fmt.Println(findCheapestPrice(3, [][]int{{0, 1, 100}}, 0, 2, 5))                                     // -1
}

Complexity. Time O(k · E), space O(V).

Why the copy matters. Without next, relaxing 0→1 and then 1→2 in the same round would let two flights happen in one "round", breaking the stop limit. The copy enforces "one more flight per round".

Problem 4 · Bellman-Ford with negative edges and negative-cycle detection

(The book's "negative-weight edges" section: Dijkstra cannot cope; Bellman-Ford can.)

Task. Given a directed graph with possibly negative weights, return the shortest distance from a start to every node, or report that a negative cycle is reachable.

Idea. A shortest path never needs more than V − 1 edges (it would otherwise repeat a node, and with no negative cycle, repeating a node never helps). So:

  1. Start with dist[start] = 0, others ∞.
  2. Repeat V − 1 times: relax every edge.
  3. Do one more pass. If any edge can still be relaxed, a negative cycle is reachable (a cycle that keeps making distances smaller forever).

Early exit: if a whole pass makes no change, you can stop early.

Trace on the cycle 0 → 1 (1), 1 → 2 (−1), 2 → 0 (−1) (total weight 1 − 1 − 1 = −1, negative)

PassChanges
after passes 1 to 2 (V − 1)distances keep dropping each lap around the cycle
extra passan edge still improves → negative cycle
// Returns the distances, or null if a negative cycle is reachable from the start.
function bellmanFord(n: number, edges: number[][], start: number): number[] | null {
  const dist = new Array<number>(n).fill(Infinity);
  dist[start] = 0;
  for (let pass = 0; pass < n - 1; pass++) {
    let changed = false;
    for (const [u, v, w] of edges) {
      if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        changed = true;
      }
    }
    if (!changed) break; // already stable: stop early
  }
  for (const [u, v, w] of edges) {
    if (dist[u] !== Infinity && dist[u] + w < dist[v]) return null; // still improving: negative cycle
  }
  return dist;
}
const negEdges = [[0, 1, 6], [0, 2, 7], [1, 2, 8], [1, 3, 5], [1, 4, -4], [2, 3, -3], [2, 4, 9], [3, 1, -2], [4, 0, 2], [4, 3, 7]];

// Returns the distances and ok=true, or ok=false if a negative cycle is reachable from the start.
func bellmanFord(n int, edges [][]int, start int) ([]int, bool) {
	dist := make([]int, n)
	for i := range dist {
		dist[i] = math.MaxInt
	}
	dist[start] = 0
	for pass := 0; pass < n-1; pass++ {
		changed := false
		for _, e := range edges {
			u, v, w := e[0], e[1], e[2]
			if dist[u] != math.MaxInt && dist[u]+w < dist[v] {
				dist[v] = dist[u] + w
				changed = true
			}
		}
		if !changed {
			break // already stable: stop early
		}
	}
	for _, e := range edges {
		u, v, w := e[0], e[1], e[2]
		if dist[u] != math.MaxInt && dist[u]+w < dist[v] {
			return nil, false // still improving: negative cycle
		}
	}
	return dist, true
}

	negEdges := [][]int{{0, 1, 6}, {0, 2, 7}, {1, 2, 8}, {1, 3, 5}, {1, 4, -4}, {2, 3, -3}, {2, 4, 9}, {3, 1, -2}, {4, 0, 2}, {4, 3, 7}}
	fmt.Println(bellmanFord(5, negEdges, 0))                                       // [0 2 7 4 -2] true
	fmt.Println(bellmanFord(3, [][]int{{0, 1, 1}, {1, 2, -1}, {2, 0, -1}}, 0))     // [] false
	fmt.Println(bellmanFord(3, [][]int{{0, 1, 4}, {1, 2, -2}}, 0))                 // [0 4 2] true
}

Complexity. Time O(V · E), space O(V).

Why V − 1 passes? After pass i, every shortest path using at most i edges is correct. A simple shortest path has at most V − 1 edges. (This is also the proof for Problem 3.)

Link to arbitrage. If edge weights are −log(exchange rate), a negative cycle means a currency-trading loop that makes free money. A classic "applications" answer.

Problem 5 · Shortest Path Visiting All Nodes (LeetCode 847, Hard)

Task. An undirected, connected graph of n ≤ 12 nodes. Find the length of the shortest walk that visits every node at least once. You may start and end anywhere and revisit nodes and edges. graph = [[1,2,3],[0],[0],[0]] (a star with center 0) → 4.

Why this is not a simple shortest path. "Visited all nodes" is not about where you are; you must also remember what you have already visited. So the BFS must run over states (current node, set of visited nodes). This is a state-space BFS: the real graph's nodes are not enough.

Bitmask for the visited set. With n ≤ 12 nodes, the visited set fits in a number of n bits: bit i is 1 if node i was visited. Visiting node v sets its bit: mask | (1 << v). The goal is mask == (1 << n) − 1 (all bits set). (File 27 explains bit tricks.)

Plan.

  • Start from every node at once (multi-source BFS from file 19): state (i, 1 << i) at distance 0.
  • BFS step: from (node, mask), move to each neighbor v: new state (v, mask | (1 << v)) at distance +1.
  • The first time we reach a state whose mask is full, its distance is the answer. Use a visited[node][mask] table so each state is processed once.

Trace for the star 0 — {1, 2, 3}: best walk 1 → 0 → 2 → 0 → 3 has 4 edges.

StepState (node, visited set)Distance
start at 1(1, {1})0
1 → 0(0, {0,1})1
0 → 2(2, {0,1,2})2
2 → 0(0, {0,1,2})3
0 → 3(3, {0,1,2,3}) all visited4
function shortestPathLength(graph: number[][]): number {
  const n = graph.length;
  if (n === 1) return 0;
  const full = (1 << n) - 1; // all n bits set
  const seen = Array.from({ length: n }, () => new Array<boolean>(1 << n).fill(false));
  let queue: [number, number][] = []; // [node, mask]
  for (let i = 0; i < n; i++) {
    queue.push([i, 1 << i]); // start anywhere, having visited only the start
    seen[i][1 << i] = true;
  }
  let steps = 0;
  while (queue.length > 0) {
    steps++;
    const next: [number, number][] = [];
    for (const [node, mask] of queue) {
      for (const neighbor of graph[node]) {
        const newMask = mask | (1 << neighbor);
        if (newMask === full) return steps; // everything visited after this move
        if (!seen[neighbor][newMask]) {
          seen[neighbor][newMask] = true;
          next.push([neighbor, newMask]);
        }
      }
    }
    queue = next;
  }
  return -1; // not reachable for a connected graph
}
console.log(shortestPathLength([[1, 2, 3], [0], [0], [0]])); // 4
console.log(shortestPathLength([[1], [0, 2, 4], [1, 3, 4], [2], [1, 2]])); // 4
console.log(shortestPathLength([[]])); // 0
func shortestPathLength(graph [][]int) int {
	n := len(graph)
	if n == 1 {
		return 0
	}
	full := (1 << n) - 1 // all n bits set
	seen := make([][]bool, n)
	for i := range seen {
		seen[i] = make([]bool, 1<<n)
	}
	type state struct{ node, mask int }
	queue := []state{}
	for i := 0; i < n; i++ {
		queue = append(queue, state{i, 1 << i}) // start anywhere, having visited only the start
		seen[i][1<<i] = true
	}
	steps := 0
	for len(queue) > 0 {
		steps++
		next := []state{}
		for _, cur := range queue {
			for _, neighbor := range graph[cur.node] {
				newMask := cur.mask | (1 << neighbor)
				if newMask == full {
					return steps // everything visited after this move
				}
				if !seen[neighbor][newMask] {
					seen[neighbor][newMask] = true
					next = append(next, state{neighbor, newMask})
				}
			}
		}
		queue = next
	}
	return -1 // not reachable for a connected graph
}

func exampleShortestPathLength() {
	fmt.Println(shortestPathLength([][]int{{1, 2, 3}, {0}, {0}, {0}}))        // 4
	fmt.Println(shortestPathLength([][]int{{1}, {0, 2, 4}, {1, 3, 4}, {2}, {1, 2}})) // 4
	fmt.Println(shortestPathLength([][]int{{}}))                               // 0
}

Complexity. There are n · 2ⁿ states and each looks at up to n neighbors: time O(n² · 2ⁿ), space O(n · 2ⁿ). That is why n ≤ 12: a hint in the constraints that bitmask state is intended.

The general lesson: when "being at a node" is not enough information to continue, enlarge the state (add what you have collected, the remaining fuel, the number of keys held, …) and run BFS or Dijkstra over states.

Common mistakes

  • Using Dijkstra with negative edges.
  • Forgetting the stale-entry check (if d > dist[u] continue) → still correct but much slower, or wrong in variants.
  • Marking nodes "visited" when first pushed (like BFS) instead of when popped with their final distance: Dijkstra must be allowed to improve a distance while a node is still in the heap.
  • Using Infinity + weight (fine in JavaScript, but math.MaxInt + w overflows in Go). Check for the sentinel before adding.
  • Using BFS for weighted graphs, or Dijkstra when all weights are equal (BFS is simpler and faster).
  • Bellman-Ford without the copy in "at most k edges" problems.
  • Not handling unreachable nodes (return −1, not Infinity).
  • Wrong graph direction (directed vs undirected); an undirected edge needs entries both ways.
  • Using a plain array as the priority queue (re-sorting every time is O(V² log V)).

1 · Why Dijkstra is correct, and where it breaks

Explain in three sentences why Dijkstra is correct with non-negative weights, and draw a 3-node graph with a negative edge where it fails.

Answer

When Dijkstra pops u with distance d, every other route to u must leave the settled set through some node whose distance is already ≥ d. With non-negative weights, the rest of such a route can only add, so it costs ≥ d. That makes d final. A negative edge breaks the "can only add" step. Example: 0 → 1 (weight 2), 0 → 2 (weight 3), 2 → 1 (weight −2). Dijkstra pops 1 at distance 2 and calls it final, but 0 → 2 → 1 costs 1.

2 · Relaxation and the stale check

From memory, write the relaxation step and the stale check.

Answer

const [d, u] = heap.pop(); if (d > dist[u]) continue; then for each edge (v, w): if (d + w < dist[v]) { dist[v] = d + w; heap.push([dist[v], v]); }. Watch both in the first animation; its bug replay shows what goes wrong if you lock a node when it is first pushed.

3 · Path With Maximum Probability

Path With Maximum Probability (LeetCode 1514): edge weights are probabilities in [0, 1] and you want the largest product. What changes: max-heap, × instead of +?

Answer

Same Dijkstra skeleton, three changes: a max-heap on probability, start at probability 1, and combine with × instead of +. It still works because multiplying by a number in [0, 1] can never increase the value, the same way adding a non-negative weight can never decrease a distance.

4 · Swim in Rising Water

Swim in Rising Water (LeetCode 778): which of the two ideas from Problem 2 do you reuse?

Answer

Reuse Problem 2's idea that a path's cost is its maximum, not its sum: Dijkstra with next = max(cost, grid[nr][nc]), return when the bottom-right is popped. (Binary search on the time plus a BFS also works.)

5 · Spanning tree versus shortest paths

Minimum Cost to Connect All Points (LeetCode 1584): this is a minimum spanning tree (Prim or Kruskal), not shortest paths. What is the difference between the two problems?

Answer

A minimum spanning tree picks edges with the smallest total weight that connect every node; there is no source. Shortest paths minimize the route from one source to each node. The trees differ: in a triangle with weights 1, 1, 1.5, the MST uses the two 1s, while the shortest path between the ends of the 1.5 edge is that edge. Use Prim (a heap of edge weights) or Kruskal (sort + union-find) for 1584.

6 · Return −1, not infinity

Network Delay with k = 1 and one unreachable node returns −1. Why would returning Infinity/MaxInt be a bug?

Answer

The problem defines −1 as "not every node gets the signal". Returning Infinity breaks the contract, and in Go math.MaxInt looks like a real (huge) answer; worse, adding a weight to it overflows into a negative number. Check for the sentinel before using it.
