Tries

Words that share a beginning share a path.

Book link: Grokking Algorithms does not teach tries, but chapter 5 (hash tables) and chapter 7 (trees) are the two ideas this structure combines. The book's Huffman tree and "inverted index" ideas (chapter 13) are close relatives. This file covers v2 question #19 (Implement Trie) and four more.

Reach for it when

Many words and prefix questions: autocomplete, "starts with", a dictionary searched on a board.

How it works

Each node is one letter; a path from the root spells a prefix; a flag marks where a word ends.

What it costs

O(L) per insert or lookup for a word of length L, whatever the number of words.

1. The idea in plain English

When you type ca into a search box and it suggests cat, car, and card, something is finding "all words that start with ca" very quickly. A hash map is bad at this: it can answer "is cat a word?" but cannot answer "which words start with ca?" without scanning everything.

A trie (pronounced "try", from re*trie*val) is a tree where each step down is one letter. Words that share a beginning share a path. Walking letter by letter from the root spells out a word.

This trie stores the words to, tea, ten, in, and inn. A star * marks a node where a word ends. That mark matters: in is a word, and so is inn, but te is only a prefix, not a word.

What a node holds

  • a way to find the child for each letter (a map or an array of 26 slots),
  • a flag "a word ends here" (or the word itself).

The cost

For a word of length L:

OperationTimeNote
InsertO(L)independent of how many words are stored
Search a whole wordO(L)
Check a prefix (startsWith)O(L)the headline feature
Spaceup to O(total letters)shared prefixes save space; but each node has overhead

A hash set also does word lookup in O(L) (you must hash the whole word), but it can not answer prefix questions, and it can not list all words with a given prefix.

2. How to recognize it

  • "Does any word start with this prefix?", "autocomplete", "type-ahead", "search suggestions".
  • "Longest common prefix of many strings."
  • "Dictionary of words and you must check many strings or a grid against it" (Word Search II).
  • "Wildcard matching with ." over a fixed dictionary.
  • "XOR maximum of two numbers": a trie over bits (the same idea with a 2-way branch).
  • You would otherwise compare each query against every word.

3. The basic trie

class TrieNode {
  children = new Map<string, TrieNode>();
  isWord = false; // a word ends at this node
}

class Trie {
  private root = new TrieNode();

  insert(word: string): void {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch)!; // step down one letter
    }
    node.isWord = true;
  }

  // Walk the letters of `text`; returns the node reached, or null if the path breaks.
  private walk(text: string): TrieNode | null {
    let node = this.root;
    for (const ch of text) {
      const next = node.children.get(ch);
      if (next === undefined) return null;
      node = next;
    }
    return node;
  }

  search(word: string): boolean {
    return this.walk(word)?.isWord === true;
  }

  startsWith(prefix: string): boolean {
    return this.walk(prefix) !== null;
  }
}

for (const w of ["to", "tea", "ten", "in", "inn"]) basicTrie.insert(w);

console.log(basicTrie.startsWith("te"), basicTrie.startsWith("x")); // true false
console.log(basicTrie.search("inn"), basicTrie.search("innn")); // true false
type TrieNode struct {
	children [26]*TrieNode // one slot per letter a..z
	isWord   bool          // a word ends at this node
}

type Trie struct{ root *TrieNode }

func NewTrie() *Trie { return &Trie{root: &TrieNode{}} }

func (t *Trie) Insert(word string) {
	node := t.root
	for i := 0; i < len(word); i++ {
		idx := word[i] - 'a'
		if node.children[idx] == nil {
			node.children[idx] = &TrieNode{}
		}
		node = node.children[idx] // step down one letter
	}
	node.isWord = true
}

// walk follows the letters of text; it returns nil if the path breaks.
func (t *Trie) walk(text string) *TrieNode {
	node := t.root
	for i := 0; i < len(text); i++ {
		node = node.children[text[i]-'a']
		if node == nil {
			return nil
		}
	}
	return node
}

func (t *Trie) Search(word string) bool {
	node := t.walk(word)
	return node != nil && node.isWord
}

func (t *Trie) StartsWith(prefix string) bool { return t.walk(prefix) != nil }

func exampleBasicTrie() {
	trie := NewTrie()
	for _, w := range []string{"to", "tea", "ten", "in", "inn"} {
		trie.Insert(w)
	}
	fmt.Println(trie.Search("tea"), trie.Search("te"))     // true false
	fmt.Println(trie.StartsWith("te"), trie.StartsWith("x")) // true false
	fmt.Println(trie.Search("inn"), trie.Search("innn"))   // true false
}

Map vs. array of 26. An array gives the fastest step (a direct index) but wastes memory when nodes have few children, and only works for a known alphabet. A map (or map[rune]*Node in Go) handles any characters and uses memory proportional to the children present. Ask which letters are allowed.

Problem 2 · Longest Common Prefix (LeetCode 14, Easy)

Task. Find the longest string that is a prefix of all strings. ["flower", "flow", "flight"] → "fl".

Simple solutions first (say them): compare column by column (O(total characters), no trie needed), or sort and compare only the first and last. A trie is the "design" answer when the same set is queried repeatedly.

Trie idea. Insert all words. Then walk down from the root while the current node has exactly one child and is not the end of a word. The letters walked are the common prefix. A node with two or more children means the words diverge there; a word end means one word is a prefix of the others.

The walk goes f (one child) → l (two children: o and i) → stop. The common prefix is fl.

function longestCommonPrefixTrie(words: string[]): string {
  if (words.length === 0) return "";
  const root = new TrieNode();
  for (const w of words) {
    if (w === "") return "";
    let node = root;
    for (const ch of w) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch)!;
    }
    node.isWord = true;
  }
  // Walk down while there is exactly one way forward and no word ends here.
  let node = root;
  let prefix = "";
  while (node.children.size === 1 && !node.isWord) {
    const [letter, next] = [...node.children][0];
    prefix += letter;
    node = next;
  }
  return prefix;
}
console.log(longestCommonPrefixTrie(["flower", "flow", "flight"])); // fl
console.log(JSON.stringify(longestCommonPrefixTrie(["dog", "racecar", "car"]))); // ""
console.log(longestCommonPrefixTrie(["same", "same"])); // same
console.log(longestCommonPrefixTrie(["ab", "abc"])); // ab
func longestCommonPrefixTrie(words []string) string {
	if len(words) == 0 {
		return ""
	}
	root := &TrieNode{}
	for _, w := range words {
		if w == "" {
			return ""
		}
		node := root
		for i := 0; i < len(w); i++ {
			idx := w[i] - 'a'
			if node.children[idx] == nil {
				node.children[idx] = &TrieNode{}
			}
			node = node.children[idx]
		}
		node.isWord = true
	}
	// Walk down while there is exactly one way forward and no word ends here.
	var sb strings.Builder
	node := root
	for !node.isWord {
		count, only := 0, -1
		for i, child := range node.children {
			if child != nil {
				count++
				only = i
			}
		}
		if count != 1 {
			break
		}
		sb.WriteByte(byte('a' + only))
		node = node.children[only]
	}
	return sb.String()
}

func exampleLongestCommonPrefixTrie() {
	fmt.Println(longestCommonPrefixTrie([]string{"flower", "flow", "flight"})) // fl
	fmt.Printf("%q\n", longestCommonPrefixTrie([]string{"dog", "racecar", "car"})) // ""
	fmt.Println(longestCommonPrefixTrie([]string{"same", "same"}))             // same
	fmt.Println(longestCommonPrefixTrie([]string{"ab", "abc"}))                // ab
}

Complexity. Time O(total characters), space O(total characters).

Problem 3 · Replace Words (LeetCode 648, Medium)

Task. A dictionary has roots (like cat, bat, rat). Replace every word in a sentence with the shortest root that is its prefix (keep the word if no root matches). "the cattle was rattled by the battery" → "the cat was rat by the bat".

Idea. Put the roots into a trie. For each word, walk it through the trie; the first time you reach a node marked as a word end, stop: that is the shortest root. If the path breaks first, keep the whole word.

Trace for cattle with roots cat, bat, rat:

LetterNode reachedWord end?
ccno
acano
tcatyes: replace cattle with cat
function replaceWords(roots: string[], sentence: string): string {
  const root = new TrieNode();
  for (const r of roots) {
    let node = root;
    for (const ch of r) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch)!;
    }
    node.isWord = true;
  }
  const shortestRoot = (word: string): string => {
    let node = root;
    for (let i = 0; i < word.length; i++) {
      const next = node.children.get(word[i]);
      if (next === undefined) return word; // no root matches: keep the word
      node = next;
      if (node.isWord) return word.slice(0, i + 1); // the first word end is the shortest root
    }
    return word;
  };
  return sentence.split(" ").map(shortestRoot).join(" ");
}
console.log(replaceWords(["cat", "bat", "rat"], "the cattle was rattled by the battery")); // the cat was rat by the bat
console.log(replaceWords(["a", "b", "c"], "aadsfasf absbs bbab cadsfafs")); // a a b c
func replaceWords(roots []string, sentence string) string {
	root := &TrieNode{}
	for _, r := range roots {
		node := root
		for i := 0; i < len(r); i++ {
			idx := r[i] - 'a'
			if node.children[idx] == nil {
				node.children[idx] = &TrieNode{}
			}
			node = node.children[idx]
		}
		node.isWord = true
	}
	shortestRoot := func(word string) string {
		node := root
		for i := 0; i < len(word); i++ {
			node = node.children[word[i]-'a']
			if node == nil {
				return word // no root matches: keep the word
			}
			if node.isWord {
				return word[:i+1] // the first word end is the shortest root
			}
		}
		return word
	}
	words := strings.Fields(sentence)
	for i, w := range words {
		words[i] = shortestRoot(w)
	}
	return strings.Join(words, " ")
}

func exampleReplaceWords() {
	fmt.Println(replaceWords([]string{"cat", "bat", "rat"}, "the cattle was rattled by the battery")) // the cat was rat by the bat
	fmt.Println(replaceWords([]string{"a", "b", "c"}, "aadsfasf absbs bbab cadsfafs"))              // a a b c
}

Complexity. Time O(total characters of roots + sentence), space O(total characters of roots).

Problem 4 · Design Add and Search Words with Wildcards (LeetCode 211, Medium)

Task. addWord(word) stores a word; search(pattern) returns whether any stored word matches the pattern, where . matches any one letter. After adding bad, dad, mad: search("pad") false, search("bad") true, search(".ad") true, search("b..") true.

Idea. A normal letter follows the one matching child. A . could be any child, so we must try all of them: that is a small DFS (backtracking) over the trie.

class WordDictionary {
  private root = new TrieNode();

  addWord(word: string): void {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch)!;
    }
    node.isWord = true;
  }

  search(pattern: string): boolean {
    const dfs = (node: TrieNode, i: number): boolean => {
      if (i === pattern.length) return node.isWord;
      const ch = pattern[i];
      if (ch === ".") {
        for (const child of node.children.values()) if (dfs(child, i + 1)) return true; // try every letter
        return false;
      }
      const next = node.children.get(ch);
      return next !== undefined && dfs(next, i + 1);
    };
    return dfs(this.root, 0);
  }
}

console.log(dict.search("b."), dict.search("...")); // false true
type WordDictionary struct{ root *TrieNode }

func NewWordDictionary() *WordDictionary { return &WordDictionary{root: &TrieNode{}} }

func (d *WordDictionary) AddWord(word string) {
	node := d.root
	for i := 0; i < len(word); i++ {
		idx := word[i] - 'a'
		if node.children[idx] == nil {
			node.children[idx] = &TrieNode{}
		}
		node = node.children[idx]
	}
	node.isWord = true
}

func (d *WordDictionary) Search(pattern string) bool {
	var dfs func(node *TrieNode, i int) bool
	dfs = func(node *TrieNode, i int) bool {
		if i == len(pattern) {
			return node.isWord
		}
		if pattern[i] == '.' {
			for _, child := range node.children {
				if child != nil && dfs(child, i+1) {
					return true // try every letter
				}
			}
			return false
		}
		next := node.children[pattern[i]-'a']
		return next != nil && dfs(next, i+1)
	}
	return dfs(d.root, 0)
}

func exampleWordDictionary() {
	dict := NewWordDictionary()
	for _, w := range []string{"bad", "dad", "mad"} {
		dict.AddWord(w)
	}
	fmt.Println(dict.Search("pad"), dict.Search("bad"), dict.Search(".ad"), dict.Search("b..")) // false true true true
	fmt.Println(dict.Search("b."), dict.Search("..."))                                       // false true
}

Complexity. addWord O(L). search is O(L) without dots; in the worst case with many dots it can touch O(26^dots · L) nodes, though it is limited by the trie size.

Problem 5 · Word Search II (LeetCode 212, Hard)

Task. Given a grid of letters and a list of words, return all words that can be formed by walking through adjacent cells (up/down/left/right), using each cell at most once per word. Example board:

o a a n
e t a e
i h k r
i f l v

words ["oath", "pea", "eat", "rain"] → ["eat", "oath"].

Why it is hard. The simple approach is: for every word run the "Word Search I" DFS from every cell. With many words that is words × cells × 4^L, far too slow.

The trie insight. Search for all words at once. Put every word in a trie. Then run one DFS from each cell, walking the grid and the trie together:

  • Move to a neighbor cell only if the trie has a child for that cell's letter. If not, prune the whole branch immediately.
  • When the trie node you reach marks a word, you found it.

Two optimizations that matter:

  1. Store the whole word at the end node (instead of a boolean), so you can record it without rebuilding it from the path.
  2. Clear the word once found (so duplicates are not returned), and optionally delete trie branches that no longer lead to any word so later searches skip them.
class WordNode {
  children = new Map<string, WordNode>();
  word: string | null = null; // the full word, if one ends here
}

function findWords(board: string[][], words: string[]): string[] {
  const root = new WordNode();
  for (const w of words) {
    let node = root;
    for (const ch of w) {
      if (!node.children.has(ch)) node.children.set(ch, new WordNode());
      node = node.children.get(ch)!;
    }
    node.word = w;
  }
  const found: string[] = [];
  const rows = board.length, cols = board[0].length;

  function dfs(r: number, c: number, parent: WordNode): void {
    const ch = board[r][c];
    const node = parent.children.get(ch);
    if (node === undefined) return; // no word continues with this letter: prune
    if (node.word !== null) {
      found.push(node.word);
      node.word = null; // do not report the same word twice
    }
    board[r][c] = "#"; // mark visited
    for (const [dr, dc] of [[1, 0], [-1, 0], [0, 1], [0, -1]]) {
      const nr = r + dr, nc = c + dc;
      if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && board[nr][nc] !== "#") dfs(nr, nc, node);
    }
    board[r][c] = ch; // un-mark (backtrack)
    if (node.children.size === 0 && node.word === null) parent.children.delete(ch); // prune dead branch
  }

  for (let r = 0; r < rows; r++) for (let c = 0; c < cols; c++) dfs(r, c, root);
  return found.sort();
}

type wordNode struct {
	children [26]*wordNode
	word     string // the full word, if one ends here ("" means none)
	kids     int    // how many children exist (for pruning)
}

func findWords(board [][]byte, words []string) []string {
	root := &wordNode{}
	for _, w := range words {
		node := root
		for i := 0; i < len(w); i++ {
			idx := w[i] - 'a'
			if node.children[idx] == nil {
				node.children[idx] = &wordNode{}
				node.kids++
			}
			node = node.children[idx]
		}
		node.word = w
	}
	found := []string{}
	rows, cols := len(board), len(board[0])
	dirs := [][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}

	var dfs func(r, c int, parent *wordNode)
	dfs = func(r, c int, parent *wordNode) {
		ch := board[r][c]
		node := parent.children[ch-'a']
		if node == nil {
			return // no word continues with this letter: prune
		}
		if node.word != "" {
			found = append(found, node.word)
			node.word = "" // do not report the same word twice
		}
		board[r][c] = '#' // mark visited
		for _, d := range dirs {
			nr, nc := r+d[0], c+d[1]
			if nr >= 0 && nr < rows && nc >= 0 && nc < cols && board[nr][nc] != '#' {
				dfs(nr, nc, node)
			}
		}
		board[r][c] = ch // un-mark (backtrack)
		if node.kids == 0 && node.word == "" {
			parent.children[ch-'a'] = nil // prune dead branch
			parent.kids--
		}
	}

	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			dfs(r, c, root)
		}
	}
	sort.Strings(found)
	return found
}

Complexity. Time roughly O(cells × 4 · 3^(L−1)) in the worst case (L = longest word), but the trie prunes most of it. Space O(total characters in words).

Walk-through of why pruning is so powerful. Starting at cell o: the trie has root children o, p, e, r, so o is allowed. Next the walk tries neighbors a, e, ...: only a continues the path oa..., and later t, h: spelling oath. Branches like oe... die at once because no word starts with oe.

Common mistakes

  • Forgetting the "word ends here" flag, so every prefix looks like a word (search("te") wrongly true).
  • Confusing search and startsWith.
  • Using an array of 26 when characters may be uppercase, digits, or Unicode.
  • Using a trie where a hash set would do (only exact membership).
  • In Word Search II: not marking cells visited, or forgetting to un-mark (backtrack) afterwards.
  • Returning duplicate words (clear the stored word after finding it).
  • Recursing from the whole word instead of the trie, which brings back the slow per-word search.
  • Large memory: a trie over many long random strings can take far more memory than a plain list. Mention compressed tries (radix trees) if asked.

1 · Draw a small trie

Draw the trie for ["car", "card", "care", "cat"]. Mark word ends. How many nodes (excluding the root)?

Answer

c → a, then a has children r and t; r has children d and e. Word ends: r (car), d (card), e (care), t (cat). 6 nodes besides the root, against 14 letters in the four words. Run the second preset of the first animation.

2 · Prefix queries

Why does a trie answer "all words starting with ca" faster than a hash set? What does it return after walking c, a?

Answer

A hash set can only test whole words, so it must scan every word to find those starting with ca. A trie walks c, a in two steps and returns the node for that prefix; every word below it starts with ca, so a DFS from there lists them in time proportional to the output.

3 · Search Suggestions System

Search Suggestions System (LeetCode 1268): after each typed letter, return up to 3 lexicographically smallest words with that prefix. What do you store at each node, or do you sort + binary search instead?

Answer

Either store at each trie node a list of up to 3 smallest words that pass through it (insert words in sorted order and append while the list has fewer than 3), or skip the trie: sort the products, and for each typed prefix binary-search the first word ≥ prefix and take up to 3 that still start with it. Both are about O(n log n + typed · log n); the sort + binary search one is shorter to write.

4 · Maximum XOR

Maximum XOR of Two Numbers in an Array (LeetCode 421): what is the "alphabet" of this trie?

Answer

The alphabet is bits: insert every number as its 31 or 32 bits from the highest down, so each node has at most two children (0 and 1). For each number, walk the trie preferring the child with the opposite bit at each level; that greedily builds the largest XOR. O(n · 32).

5 · Set versus trie memory

Compare memory: 100,000 English words in a Set<string> vs. a trie. When does the trie win?

Answer

A set stores each word once plus hashing overhead: about the total number of letters. A trie stores one node per distinct prefix, and each node carries a map or a 26-slot array, which costs far more than a letter. The trie wins on memory only when words share long prefixes (dictionaries, URLs, IP routes); with random strings it is much bigger. It wins on speed for prefix queries either way. Compressed tries (radix trees) merge single-child chains to cut memory.
