Dynamic programming, part 2: two dimensions

When one index is not enough, fill a table cell by cell.

Book link: Grokking Algorithms, chapter 11. This is where the book's famous grid lives: the knapsack table (rows = items, columns = bag sizes) and the longest-common-substring table (rows and columns = the two words). This file works those two examples exactly, then adds the interview classics built on the same kind of table: grid paths, partition into equal subsets, longest common subsequence, edit distance, longest palindromic subsequence, and regular-expression matching.

Reach for it when

Two strings, a grid, items and a capacity, or a range i..j: the answer depends on two indexes.

The table

dp[i][j] answers the question for the first i of one thing and the first j of the other. Pad row 0 and column 0 for the empty case.

What it costs

Cells × work per cell, usually O(m × n); often one or two rolling rows of memory.

1. When one dimension is not enough

In file 25, a state was described by one number: the amount, the house index, the position in the array. Some problems need two numbers to describe a situation:

ProblemState needs…
Walk a gridthe row and the column
Knapsackwhich items have been considered, and how much room is left
Compare two stringshow much of string A and how much of string B you have used
Palindrome inside a stringleft end and right end of the part you are looking at

A state described by two numbers (i, j) lives in a table (a grid) dp[i][j]. You fill it cell by cell, and each cell is computed from cells you have already filled: its neighbors above, to the left, or diagonally up-left.

Fill order is the new thing to get right: row by row, left to right works when each cell depends only on the cell above, to the left, and the diagonal up-left.

The same five steps, with two indexes

  1. State: say in a sentence what dp[i][j] means, naming both i and j.
  2. Recurrence: how does dp[i][j] come from neighbors?
  3. Base cases: usually the first row and first column (empty prefixes).
  4. Order: an order in which neighbors are ready.
  5. Answer: a corner cell (often dp[m][n]), or the max over the table.

The padding trick

Most string tables use an extra row and column of zeros for the empty prefix: dp[0][j] means "zero characters of A against j characters of B". This avoids special cases for index −1.

Saving memory: keep only the rows you need

If dp[i][j] only needs row i − 1 and row i, store two rows (or even one, if you are careful about the update order). That turns O(m · n) space into O(n).

Reading the answer back

Sometimes you must output what the best choice was (which items, which characters), not just the number. Keep the whole table, then walk backward from the final cell, at each step asking "which neighbor did this value come from?"

2. How to recognize a 2D DP problem

  • Two sequences (strings or arrays) compared or aligned: LCS, edit distance, interleaving strings, regex/wildcard matching.
  • A grid with moves that only go right/down (paths, minimum cost, obstacles).
  • A resource and a list of items: capacity vs items (knapsack), target sum, partition.
  • Ranges: "the best for the substring from i to j" (palindromes, burst balloons, matrix chain).

Problem 1 · Unique Paths (LeetCode 62) and Minimum Path Sum (LeetCode 64), Medium

Unique Paths. A robot starts at the top-left of an m × n grid and can move only right or down. How many different paths reach the bottom-right? 3 × 7 → 28.

  1. State: paths[r][c] = number of ways to reach cell (r, c).
  2. Recurrence: you arrived from above or from the left: paths[r][c] = paths[r−1][c] + paths[r][c−1].
  3. Base: the first row and first column each have exactly 1 way.
  4. Order: row by row, left to right.
  5. Answer: paths[m−1][n−1].

Table for a 3 × 4 grid:

c=0c=1c=2c=3
r=01111
r=11234
r=213610

Space trick: each row depends only on the row above and the cell to its left, so a single row of length n suffices: update it in place (row[c] += row[c−1]; the old row[c] is "above", the new row[c−1] is "left").

Minimum Path Sum. Each cell has a cost; find the path (right/down only) with the smallest total cost. [[1,3,1],[1,5,1],[4,2,1]] → 7 (1→3→1→1→1). Same shape, but min instead of +: cost[r][c] = grid[r][c] + min(cost[r−1][c], cost[r][c−1]).

function uniquePaths(m: number, n: number): number {
  const row = new Array<number>(n).fill(1); // the first row: one way to reach each cell
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) row[c] += row[c - 1]; // above (old row[c]) + left (new row[c-1])
  }
  return row[n - 1];
}

function minPathSum(grid: number[][]): number {
  const m = grid.length, n = grid[0].length;
  const cost = new Array<number>(n).fill(Infinity); // cost[c] = best cost to reach (current row, c)
  cost[0] = 0;
  for (let r = 0; r < m; r++) {
    cost[0] += grid[r][0]; // the first column can only come from above
    for (let c = 1; c < n; c++) cost[c] = grid[r][c] + Math.min(cost[c], cost[c - 1]); // above vs left
  }
  return cost[n - 1];
}

func uniquePaths(m, n int) int {
	row := make([]int, n)
	for c := range row {
		row[c] = 1 // the first row: one way to reach each cell
	}
	for r := 1; r < m; r++ {
		for c := 1; c < n; c++ {
			row[c] += row[c-1] // above (old row[c]) + left (new row[c-1])
		}
	}
	return row[n-1]
}

func minPathSum(grid [][]int) int {
	m, n := len(grid), len(grid[0])
	cost := make([]int, n) // cost[c] = best cost to reach (current row, c)
	for c := range cost {
		cost[c] = math.MaxInt / 2 // "infinity" that is safe to add to
	}
	cost[0] = 0
	for r := 0; r < m; r++ {
		cost[0] += grid[r][0] // the first column can only come from above
		for c := 1; c < n; c++ {
			cost[c] = grid[r][c] + min(cost[c], cost[c-1]) // above vs left
		}
	}
	return cost[n-1]
}

func exampleGridPaths() {
	fmt.Println(uniquePaths(3, 7))                                        // 28
	fmt.Println(uniquePaths(3, 2))                                        // 3
	fmt.Println(uniquePaths(1, 1))                                        // 1
	fmt.Println(minPathSum([][]int{{1, 3, 1}, {1, 5, 1}, {4, 2, 1}}))     // 7
	fmt.Println(minPathSum([][]int{{1, 2, 3}, {4, 5, 6}}))                // 12
}

Complexity. Time O(m · n), space O(n).

Problem 2 · The knapsack problem (the book's grid) and Partition Equal Subset Sum (LeetCode 416)

Task (the book). A bag holds 4 lb. Items: guitar (1 lb, $1500), stereo (4 lb, $3000), laptop (3 lb, $2000). Choose items (each at most once: 0/1 knapsack) to maximize total value. Greedy (file 23) gets $3000; the true best is $3500 (guitar + laptop).

The book's grid. Rows are items considered so far, columns are bag capacity from 0 to 4. The cell best[i][w] = the best value using only the first i items with a bag of capacity w.

cap 0cap 1cap 2cap 3cap 4
no items00000
guitar (1 lb, 1500)01500150015001500
+ stereo (4 lb, 3000)01500150015003000
+ laptop (3 lb, 2000)01500150020003500

The recurrence for each cell (item i has weight wt and value val): two choices, skip or take:

best[i][w] = max( best[i−1][w], best[i−1][w − wt] + val ) (the second option only if wt ≤ w)

  • Skip item i: the best you could do without it: the cell directly above.
  • Take item i: you earn val, and the remaining room w − wt is filled with the best of the previous items.

Reading the table: the last cell (3500) is the answer. To find which items, walk backward from the bottom-right cell, comparing each cell with the one directly above it:

CellCompared with the cell aboveMeaningNext
laptop row, capacity 4: 3500stereo row, capacity 4: 3000different → the laptop was takencapacity 4 − 3 = 1, go up a row
stereo row, capacity 1: 1500guitar row, capacity 1: 1500same → the stereo was not takengo up a row, same capacity
guitar row, capacity 1: 1500no-items row, capacity 1: 0different → the guitar was takencapacity 1 − 1 = 0, done

Items: guitar + laptop.

Space optimization (the standard interview version): use one array best[w] and process capacities from high to low, so each item is used at most once (the cell you read, best[w − wt], has not been updated for this item yet).

If you looped upward instead, best[w − wt] would already include this item, and you could take the same item repeatedly: that is the unbounded knapsack (and Coin Change).

Partition Equal Subset Sum (LeetCode 416). Can the array be split into two subsets with equal sums? [1,5,11,5] → true (11 vs 1+5+5). [1,2,3,5] → false.

This is a feasibility knapsack: the "capacity" is sum / 2, the "weights" are the numbers, and the question is can some subset add up to exactly sum / 2? If the total is odd, answer false immediately.

can[s] = is a subset sum of s possible? with can[0] = true; for each number x, for s from the target down to x: can[s] = can[s] or can[s − x].

type KnapItem = { name: string; weight: number; value: number };

// The book's grid, built in full so we can read back WHICH items were chosen.
function knapsackWithItems(items: KnapItem[], capacity: number): { best: number; chosen: string[] } {
  const n = items.length;
  const best = Array.from({ length: n + 1 }, () => new Array<number>(capacity + 1).fill(0));
  for (let i = 1; i <= n; i++) {
    const { weight, value } = items[i - 1];
    for (let w = 0; w <= capacity; w++) {
      best[i][w] = best[i - 1][w]; // skip the item
      if (weight <= w) best[i][w] = Math.max(best[i][w], best[i - 1][w - weight] + value); // or take it
    }
  }
  const chosen: string[] = [];
  let w = capacity;
  for (let i = n; i >= 1; i--) {
    if (best[i][w] !== best[i - 1][w]) { // the value changed, so this item was taken
      chosen.push(items[i - 1].name);
      w -= items[i - 1].weight;
    }
  }
  return { best: best[n][capacity], chosen: chosen.reverse() };
}

// The same answer with ONE array: capacities go from high to low so each item is used once.
function knapsack1D(weights: number[], values: number[], capacity: number): number {
  const best = new Array<number>(capacity + 1).fill(0);
  for (let i = 0; i < weights.length; i++) {
    for (let w = capacity; w >= weights[i]; w--) best[w] = Math.max(best[w], best[w - weights[i]] + values[i]);
  }
  return best[capacity];
}

function canPartition(nums: number[]): boolean {
  const total = nums.reduce((a, b) => a + b, 0);
  if (total % 2 !== 0) return false; // an odd total can never split evenly
  const target = total / 2;
  const can = new Array<boolean>(target + 1).fill(false);
  can[0] = true; // the empty subset sums to 0
  for (const x of nums) {
    for (let s = target; s >= x; s--) can[s] = can[s] || can[s - x];
  }
  return can[target];
}

type KnapItem struct {
	name          string
	weight, value int
}

// The book's grid, built in full so we can read back WHICH items were chosen.
func knapsackWithItems(items []KnapItem, capacity int) (int, []string) {
	n := len(items)
	best := make([][]int, n+1)
	for i := range best {
		best[i] = make([]int, capacity+1)
	}
	for i := 1; i <= n; i++ {
		weight, value := items[i-1].weight, items[i-1].value
		for w := 0; w <= capacity; w++ {
			best[i][w] = best[i-1][w] // skip the item
			if weight <= w {
				best[i][w] = max(best[i][w], best[i-1][w-weight]+value) // or take it
			}
		}
	}
	chosen := []string{}
	w := capacity
	for i := n; i >= 1; i-- {
		if best[i][w] != best[i-1][w] { // the value changed, so this item was taken
			chosen = append(chosen, items[i-1].name)
			w -= items[i-1].weight
		}
	}
	slices.Reverse(chosen)
	return best[n][capacity], chosen
}

func canPartition(nums []int) bool {
	total := 0
	for _, x := range nums {
		total += x
	}
	if total%2 != 0 {
		return false // an odd total can never split evenly

	target := total / 2
	can := make([]bool, target+1)
	can[0] = true // the empty subset sums to 0
	for _, x := range nums {
		for s := target; s >= x; s-- {
			can[s] = can[s] || can[s-x]
		}
	}
	return can[target]
}

func exampleKnapsack() {
	book := []KnapItem{{"guitar", 1, 1500}, {"stereo", 4, 3000}, {"laptop", 3, 2000}}
	fmt.Println(knapsackWithItems(book, 4))                          // 3500 [guitar laptop]
	fmt.Println(knapsack1D([]int{1, 4, 3}, []int{1500, 3000, 2000}, 4)) // 3500
	fmt.Println(canPartition([]int{1, 5, 11, 5}))                    // true
	fmt.Println(canPartition([]int{1, 2, 3, 5}))                     // false
	fmt.Println(canPartition([]int{2, 2, 3, 5}))                     // false
}

Complexity. Knapsack: time O(items × capacity), space O(items × capacity) for the full table or O(capacity) rolling. Partition: time O(n × sum/2), space O(sum).

A subtle point worth saying aloud. The running time is O(n · W), not polynomial in the input size (because W can be exponentially large in its number of digits). This is called pseudo-polynomial time, and it is why knapsack is still NP-complete even though this DP is fast for reasonable W. (File 23.)

Related problems: Target Sum (LeetCode 494), Last Stone Weight II (LeetCode 1049), Ones and Zeroes (LeetCode 474: a knapsack with two capacities).

Problem 3 · Longest Common Subsequence (LeetCode 1143), plus the book's Longest Common Substring

Task (LCS). Find the length of the longest subsequence common to two strings (characters in the same order, not necessarily adjacent). "abcde" and "ace" → 3 ("ace"). "abc" and "def" → 0.

  1. State: lcs[i][j] = the LCS length of the first i characters of A and the first j characters of B.
  2. Recurrence (look at the last characters A[i−1] and B[j−1]):
    • They match → they extend the best common subsequence of the shorter prefixes: lcs[i][j] = lcs[i−1][j−1] + 1.
    • They differ → at least one of them is not used: lcs[i][j] = max(lcs[i−1][j], lcs[i][j−1]).
  3. Base: lcs[0][j] = lcs[i][0] = 0 (empty prefix).
  4. Answer: lcs[m][n].

The table for A = "abcde" (rows) and B = "ace" (columns):

b0111
c0122
d0122
e0123

Reading it: a matches a (diagonal 0 + 1 = 1). c matches c: diagonal lcs[2][1] = 1, plus 1 = 2. e matches e: diagonal lcs[4][2] = 2, plus 1 = 3.

Longest Common Substring (the book's version). A substring must be contiguous. The only change: when the characters differ, the answer for that cell is 0 (the run is broken), and the final answer is the maximum cell anywhere (not the last cell). When they match: dp[i][j] = dp[i−1][j−1] + 1.

The book's example: how similar are "hish" and "fish"? The longest common substring is "ish" (3). The table for "hish" (rows) vs "fish" (columns):

fish
h0001
i0100
s0020
h0003

The diagonal run 1, 2, 3 (the cells for i, s, h) is the substring "ish".

function longestCommonSubsequence(a: string, b: string): number {
  const m = a.length, n = b.length;
  const lcs = Array.from({ length: m + 1 }, () => new Array<number>(n + 1).fill(0)); // row/col 0 = empty prefix
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      lcs[i][j] = a[i - 1] === b[j - 1]
        ? lcs[i - 1][j - 1] + 1 // matching characters extend the diagonal
        : Math.max(lcs[i - 1][j], lcs[i][j - 1]); // otherwise drop one character from either string
    }
  }
  return lcs[m][n];
}

function longestCommonSubstring(a: string, b: string): number {
  const m = a.length, n = b.length;
  const run = Array.from({ length: m + 1 }, () => new Array<number>(n + 1).fill(0));
  let best = 0;
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (a[i - 1] === b[j - 1]) {
        run[i][j] = run[i - 1][j - 1] + 1; // extend the current matching run
        best = Math.max(best, run[i][j]);
      } // else the run is broken, and the cell stays 0
    }
  }
  return best;
}

func longestCommonSubsequence(a, b string) int {
	m, n := len(a), len(b)
	lcs := make([][]int, m+1) // row/col 0 = empty prefix
	for i := range lcs {
		lcs[i] = make([]int, n+1)
	}
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if a[i-1] == b[j-1] {
				lcs[i][j] = lcs[i-1][j-1] + 1 // matching characters extend the diagonal
			} else {
				lcs[i][j] = max(lcs[i-1][j], lcs[i][j-1]) // otherwise drop one character from either string
			}
		}
	}
	return lcs[m][n]
}

		run[i] = make([]int, n+1)
	}
	best := 0
	for i := 1; i <= m; i++ {

			if a[i-1] == b[j-1] {

	}

Complexity. Time O(m · n), space O(m · n) (reduce to O(min(m, n)) with two rows if only the length is needed).

Why this matters (the book's point). Edit-distance-like tables power spell checkers ("did you mean…"), diff (the lines two file versions share), DNA sequence alignment, and plagiarism detection.

Problem 4 · Edit Distance (LeetCode 72, Medium/Hard)

Task. The minimum number of operations to turn word1 into word2, where one operation is insert, delete, or replace a character. "horse" → "ros" = 3 (horse → rorse → rose → ros).

  1. State: edit[i][j] = the minimum operations to turn the first i characters of word1 into the first j characters of word2.
  2. Recurrence (look at the last characters):
    • They match → no cost: edit[i−1][j−1].
    • They differ → choose the cheapest of three operations (each costs 1):
      • replace word1[i−1] with word2[j−1]: edit[i−1][j−1] + 1
      • delete word1[i−1]: edit[i−1][j] + 1
      • insert word2[j−1] into word1: edit[i][j−1] + 1
  3. Base: edit[i][0] = i (delete all i characters), edit[0][j] = j (insert all j characters).
  4. Answer: edit[m][n].

The table for "horse" (rows) → "ros" (columns):

""ros
""0123
h1123
o2212
r3222
s4332
e5443

For example, the cell (o, o) is 1: the two os match, so it copies the diagonal cell (h, r), which is 1. The last cell (e, s): e ≠ s, so it is 1 + min(replace: 3, delete: 2, insert: 4) = 3, where those three numbers are the diagonal, the cell above, and the cell to the left.

function minDistance(word1: string, word2: string): number {
  const m = word1.length, n = word2.length;
  const edit = Array.from({ length: m + 1 }, () => new Array<number>(n + 1).fill(0));
  for (let i = 0; i <= m; i++) edit[i][0] = i; // delete everything
  for (let j = 0; j <= n; j++) edit[0][j] = j; // insert everything
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        edit[i][j] = edit[i - 1][j - 1]; // matching: no cost
      } else {
        edit[i][j] = 1 + Math.min(edit[i - 1][j - 1], edit[i - 1][j], edit[i][j - 1]); // replace, delete, insert
      }
    }
  }
  return edit[m][n];
}

console.log(minDistance("intention", "execution")); // 5
console.log(minDistance("", "a")); // 1
console.log(minDistance("abc", "abc")); // 0
console.log(minDistance("kitten", "sitting")); // 3
func minDistance(word1, word2 string) int {
	m, n := len(word1), len(word2)
	edit := make([][]int, m+1)
	for i := range edit {
		edit[i] = make([]int, n+1)
		edit[i][0] = i // delete everything
	}
	for j := 0; j <= n; j++ {
		edit[0][j] = j // insert everything
	}
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if word1[i-1] == word2[j-1] {
				edit[i][j] = edit[i-1][j-1] // matching: no cost
			} else {
				edit[i][j] = 1 + min(edit[i-1][j-1], edit[i-1][j], edit[i][j-1]) // replace, delete, insert
			}
		}
	}
	return edit[m][n]
}

func exampleMinDistance() {
	fmt.Println(minDistance("horse", "ros"))           // 3
	fmt.Println(minDistance("intention", "execution")) // 5
	fmt.Println(minDistance("", "a"))                  // 1
	fmt.Println(minDistance("abc", "abc"))             // 0
	fmt.Println(minDistance("kitten", "sitting"))      // 3
}

Complexity. Time O(m · n), space O(m · n), reducible to O(min(m, n)) with two rows.

Follow-ups. Print the edit script: walk back from edit[m][n], choosing whichever neighbor produced the value. Different operation costs: put the costs in the recurrence. One Edit Distance (LeetCode 161): an O(n) two-pointer check.

Problem 5 · Longest Palindromic Subsequence: an interval table (LeetCode 516, Medium)

Task. Find the length of the longest palindromic subsequence of s. "bbbab" → 4 ("bbbb"). "cbbd" → 2 ("bb").

A new kind of state: a range. pal[i][j] = the longest palindromic subsequence inside s[i..j] (both ends included).

Recurrence (look at the two ends):

  • s[i] == s[j] → the two ends can wrap a palindrome from the inside: pal[i][j] = pal[i+1][j−1] + 2.
  • They differ → at least one end is unused: pal[i][j] = max(pal[i+1][j], pal[i][j−1]).

Base: pal[i][i] = 1 (a single character), and an empty range counts as 0.

Order. pal[i][j] depends on cells with a larger i or a smaller j (shorter ranges), so fill i from the end of the string down to 0, and for each i, j from i + 1 up. (Equivalently: by increasing range length.)

A neat equivalence to mention: the longest palindromic subsequence of s equals the LCS of s and its reverse.

function longestPalindromeSubseq(s: string): number {
  const n = s.length;
  if (n === 0) return 0;
  const pal = Array.from({ length: n }, () => new Array<number>(n).fill(0));
  for (let i = n - 1; i >= 0; i--) {
    pal[i][i] = 1; // a single character is a palindrome of length 1
    for (let j = i + 1; j < n; j++) {
      if (s[i] === s[j]) {
        pal[i][j] = (j - 1 >= i + 1 ? pal[i + 1][j - 1] : 0) + 2; // wrap the best palindrome inside
      } else {
        pal[i][j] = Math.max(pal[i + 1][j], pal[i][j - 1]); // drop one end
      }
    }
  }
  return pal[0][n - 1];
}

func longestPalindromeSubseq(s string) int {
	n := len(s)
	if n == 0 {
		return 0
	}
	pal := make([][]int, n)
	for i := range pal {
		pal[i] = make([]int, n)
	}
	for i := n - 1; i >= 0; i-- {
		pal[i][i] = 1 // a single character is a palindrome of length 1
		for j := i + 1; j < n; j++ {
			if s[i] == s[j] {
				inside := 0
				if j-1 >= i+1 {
					inside = pal[i+1][j-1]
				}
				pal[i][j] = inside + 2 // wrap the best palindrome inside
			} else {
				pal[i][j] = max(pal[i+1][j], pal[i][j-1]) // drop one end
			}
		}
	}
	return pal[0][n-1]
}

func exampleLongestPalindromeSubseq() {
	fmt.Println(longestPalindromeSubseq("bbbab")) // 4
	fmt.Println(longestPalindromeSubseq("cbbd"))  // 2
	fmt.Println(longestPalindromeSubseq("a"))     // 1
	fmt.Println(longestPalindromeSubseq("abcde")) // 1
}

Complexity. Time O(n²), space O(n²) (can reduce to O(n) since row i only needs row i + 1).

Problem 6 · Regular Expression Matching (LeetCode 10, Hard)

Task. Implement matching for patterns with . (matches any single character) and * (matches zero or more of the preceding element). The match must cover the entire string. ("aa", "a") → false; ("aa", "a*") → true; ("ab", ".*") → true; ("aab", "c*a*b") → true; ("mississippi", "mis*is*p*.") → false.

Why DP. A * creates a choice (how many copies?), and the same sub-question ("does this part of the pattern match that part of the string?") recurs. Define the state over prefixes of both:

dp[i][j] = true if the first i characters of s match the first j characters of the pattern p.

Recurrence. Look at the last pattern character p[j−1]:

  1. It is not * (a letter or .): it must match the last string character, and the rest must match: dp[i][j] = i > 0 AND (p[j−1] == s[i−1] OR p[j−1] == '.') AND dp[i−1][j−1].
  2. It is * (it modifies the element p[j−2] before it). Two options:
    • Zero copies of p[j−2]: drop the two pattern characters p[j−2]*: dp[i][j−2].
    • One or more copies: the last string character s[i−1] must match p[j−2] (or p[j−2] is .), and then the string without that last character still matches the same pattern: dp[i−1][j]. (The star can absorb it and keep going.)
    • dp[i][j] = dp[i][j−2] OR ( i > 0 AND matches(s[i−1], p[j−2]) AND dp[i−1][j] ).

Base. dp[0][0] = true (empty matches empty). dp[0][j] (empty string vs. a pattern) is true only when the pattern can vanish: it ends in x* pairs. So for j ≥ 2 with p[j−1] == '*': dp[0][j] = dp[0][j−2].

Table for s = "aab", p = "c*a*b" (columns are pattern prefixes of length 0 to 5; T = true):

""cc*c*ac*a*c*a*b
""TFTFTF
aFFFTTF
aaFFFFTF
aabFFFFFT

Reading it: c* can vanish (zero copies of c), so the empty string matches c* and c*a*. Then a, aa are absorbed by a*, and finally b matches b.

function isMatch(s: string, p: string): boolean {
  const m = s.length, n = p.length;
  const dp = Array.from({ length: m + 1 }, () => new Array<boolean>(n + 1).fill(false));
  dp[0][0] = true; // empty matches empty
  for (let j = 2; j <= n; j++) {
    if (p[j - 1] === "*") dp[0][j] = dp[0][j - 2]; // "x*" can match nothing
  }
  const charMatches = (i: number, j: number): boolean => p[j - 1] === "." || p[j - 1] === s[i - 1]; // s[i-1] vs p[j-1]
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (p[j - 1] === "*") {
        const zeroCopies = j >= 2 && dp[i][j - 2]; // drop "x*"
        const moreCopies = j >= 2 && charMatches(i, j - 1) && dp[i - 1][j]; // let x* eat s[i-1] and keep going
        dp[i][j] = zeroCopies || moreCopies;
      } else {
        dp[i][j] = charMatches(i, j) && dp[i - 1][j - 1];
      }
    }
  }
  return dp[m][n];
}

func isMatch(s, p string) bool {
	m, n := len(s), len(p)
	dp := make([][]bool, m+1)
	for i := range dp {
		dp[i] = make([]bool, n+1)
	}
	dp[0][0] = true // empty matches empty
	for j := 2; j <= n; j++ {
		if p[j-1] == '*' {
			dp[0][j] = dp[0][j-2] // "x*" can match nothing
		}
	}
	charMatches := func(i, j int) bool { return p[j-1] == '.' || p[j-1] == s[i-1] } // s[i-1] vs p[j-1]
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if p[j-1] == '*' {
				zeroCopies := j >= 2 && dp[i][j-2]                         // drop "x*"
				moreCopies := j >= 2 && charMatches(i, j-1) && dp[i-1][j] // let x* eat s[i-1] and keep going
				dp[i][j] = zeroCopies || moreCopies
			} else {
				dp[i][j] = charMatches(i, j) && dp[i-1][j-1]
			}
		}
	}
	return dp[m][n]
}

	fmt.Println(isMatch("aa", "a"))                     // false
	fmt.Println(isMatch("aa", "a*"))                    // true
	fmt.Println(isMatch("ab", ".*"))                    // true
	fmt.Println(isMatch("aab", "c*a*b"))                // true
	fmt.Println(isMatch("mississippi", "mis*is*p*."))   // false
	fmt.Println(isMatch("", "a*b*"))                    // true
	fmt.Println(isMatch("", "."))                       // false
}

Complexity. Time O(m · n), space O(m · n).

Why dp[i−1][j] (and not dp[i−1][j−2]) for "one or more copies"? After letting the star absorb one character, we stay at the same pattern position j (the star can absorb more). That is what makes the recurrence compact.

Common mistakes

  • Not padding with the empty prefix and then fighting i − 1 = −1.
  • Mixing up i (a length) and i − 1 (an index) in s[i − 1].
  • Looping capacities upward in 0/1 knapsack (it silently becomes unbounded knapsack).
  • Wrong fill order (reading a cell before it has been computed), especially for interval DP.
  • Using the last cell as the answer when the answer is the max over the table (longest common substring).
  • Forgetting base rows/columns (edit[i][0] = i).
  • Space-optimizing too early and losing the ability to reconstruct the solution.
  • dp[0][j] for patterns with stars (regex): the empty string can match a*b*.
  • min with Infinity in Go. Use a large safe constant (MaxInt / 2).

2 · Why high to low

Why must the 0/1 knapsack's inner loop go from high capacity to low when using one array?

Answer

With one array, best[w − weight] must still hold the value without the current item. Going from high capacities to low, every cell you read is to the left of the ones written so far this pass, so it is still the previous row. Going upward, the cell you read may already include this item, so the item could be taken twice (that is the unbounded knapsack). The bug replay on Partition shows exactly that.

3 · Longest Palindromic Substring

Longest Palindromic Substring (LeetCode 5): outline the expand-around-center approach and say why it has O(1) extra space.

Answer

Expand around each center: there are 2n − 1 centers (each letter, and each gap between letters). From a center, move left and right while the two letters match; record the longest stretch. O(n²) time and only a few index variables, so O(1) extra space, while the table version needs O(n²) memory.

4 · Target Sum as subset counting

Target Sum (LeetCode 494): turn it into a subset-sum count. (If P is the sum of the + numbers and S the total, then P = (S + target) / 2.)

Answer

Split the numbers into a plus group (sum P) and a minus group (sum S − P). Then P − (S − P) = target, so P = (S + target) / 2. If that is negative or not a whole number, the answer is 0. Otherwise count subsets summing to P: ways[0] = 1, and for each number loop sums high to low with ways[s] += ways[s − x].

5 · Wildcard Matching

Wildcard Matching (LeetCode 44): which line of the regex recurrence changes when * matches any sequence by itself?

Answer

The star line changes. In wildcard matching a * stands alone and matches any sequence, so dp[i][j] = dp[i][j−1] (the star matches nothing) || dp[i−1][j] (it eats one more letter of s). There is no "previous character" to check, and row 0 is true only while the pattern is all stars.

6 · Distinct Subsequences

Distinct Subsequences (LeetCode 115): define dp[i][j] and the two transitions when the last characters match vs. not.

Answer

dp[i][j] = the number of ways the first j letters of t appear as a subsequence of the first i letters of s. Base: dp[i][0] = 1 (empty t), dp[0][j] = 0 for j > 0. If s[i−1] === t[j−1]: dp[i][j] = dp[i−1][j−1] + dp[i−1][j] (use this letter, or skip it). Otherwise dp[i][j] = dp[i−1][j] (skip it).
