Two pointers

Move a pointer only when you can prove it is safe.

Book link: two pointers is not a chapter in Grokking Algorithms, but it is the "next step" after the book's binary search (chapter 1) and selection sort (chapter 2): instead of searching blindly, you use order to throw away candidates. This file replaces v2 file 01 and adds more problems and a proof habit.

Reach for it when

The data is sorted, the work must happen in place, or the problem is symmetric, like a palindrome.

The sentence to say

"This candidate can be thrown away because…" Every move needs that reason.

What it costs

O(n) time and O(1) memory: each step moves a pointer, and no pointer ever moves back.

How to use the animations

1. The idea in plain English

A pointer here just means an index into an array (or string). "Two pointers" means you keep two indexes and move them with a rule, so that a single pass does a job that would normally need two nested loops.

An everyday comparison. You are looking for two people in a line, sorted by height, whose heights add up to exactly 10 feet. You stand at both ends of the line and look at the shortest and the tallest person together.

  • Together they are too tall (more than 10)? The tallest person is too tall for everyone, even the shortest. Send the tallest person away and look at the next tallest.
  • Together they are too short? The shortest person is too short even with the tallest partner. Send the shortest person away.

You never need to try every pair, because each look eliminates a person for good. That sentence, "this candidate can be thrown away because…", is the heart of the pattern.

Watch it happen. Each look sends one person away for good, so the line shrinks by one every step.

2. How to recognize it

You should think "two pointers" when you see:

  • "Sorted array" plus "find a pair / triplet that…".
  • "Do it in place" and "with O(1) extra memory".
  • "Is this a palindrome?" or anything symmetric.
  • "Remove/move items … keep the order of the rest."
  • A brute force with two nested loops over the same array and an order you can exploit.

If the array is not sorted and the problem asks for a pair, the usual choice is a hash map (file 04), or sort first and accept O(n log n). Be careful: sorting destroys the original indexes, so if the answer must be indexes, sort pairs of (value, originalIndex) or use the map.

3. The proof habit: "why is this move safe?"

Do not just memorize "move left if the sum is small". Be ready to say why. Here is the template for the explanation, using pair sum:

"left is at the smallest remaining value and right at the largest. Suppose nums[left] + nums[right] is less than the target. Then nums[left] could not work with any other partner either, because nums[right] is already the biggest partner available, so every other partner is ≤ it. So I can discard left forever. If the sum is greater than the target, the same argument discards right."

See the proof run

The Pair Sum animation in Problem 1 carries a copy of this map. As it runs, the branch being taken lights up, so every move comes with its reason.

// 1) Opposite ends
function oppositeEnds(a: number[]): void {
  let left = 0, right = a.length - 1;
  while (left < right) {
    // decide using a[left], a[right] -> move one pointer (or both)
    left++;
    right--;
  }
}

// 2) Same direction, read/write
function readWrite(a: number[], keep: (x: number) => boolean): number {
  let write = 0; // everything before `write` is the finished answer
  for (let read = 0; read < a.length; read++) {
    if (keep(a[read])) a[write++] = a[read];
  }
  return write; // the new length
}

// Reverse String (LeetCode 344): the simplest opposite-ends problem.
function reverseString(chars: string[]): void {
  let left = 0, right = chars.length - 1;
  while (left < right) {
    [chars[left], chars[right]] = [chars[right], chars[left]];
    left++;
    right--;
  }
}

reverseString(letters);
console.log(letters.join("")); // olleh
const evens = [1, 2, 3, 4, 5, 6];

console.log(evens.slice(0, n)); // [ 2, 4, 6 ]

// Same direction, read/write. Returns the new length.
func readWrite(a []int, keep func(int) bool) int {
	write := 0 // everything before `write` is the finished answer
	for read := 0; read < len(a); read++ {
		if keep(a[read]) {
			a[write] = a[read]
			write++
		}
	}
	return write
}

}

5. Practice problems (easy → hard)

Problem 1 · Pair Sum in a sorted array (LeetCode 167, Medium/Easy)

Task. In a sorted array, find two positions whose values add to target. Example: [2, 7, 11, 15], target 9 → [0, 1].

Brute force. Every pair: O(n²). A hash map gives O(n) time but O(n) memory. Two pointers gives O(n) time and O(1) memory because the array is sorted.

Trace. [1, 2, 4, 8], target 10

leftrightvaluessumDecision
031 + 89too small → the 1 can't reach 10 even with the largest partner, left++
132 + 810found [1, 3]
function pairSumSorted(nums: number[], target: number): [number, number] | null {
  let left = 0, right = nums.length - 1;
  while (left < right) {
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    if (sum < target) left++; // need something bigger
    else right--; // need something smaller
  }
  return null; // no pair
}
console.log(pairSumSorted([2, 7, 11, 15], 9)); // [ 0, 1 ]
console.log(pairSumSorted([1, 2, 4, 8], 10)); // [ 1, 3 ]
console.log(pairSumSorted([1, 2, 3], 100)); // null
func pairSumSorted(nums []int, target int) (int, int, bool) {
	left, right := 0, len(nums)-1
	for left < right {
		sum := nums[left] + nums[right]
		switch {
		case sum == target:
			return left, right, true
		case sum < target:
			left++ // need something bigger
		default:
			right-- // need something smaller
		}
	}
	return -1, -1, false // no pair
}

func examplePairSumSorted() {
	fmt.Println(pairSumSorted([]int{2, 7, 11, 15}, 9)) // 0 1 true
	fmt.Println(pairSumSorted([]int{1, 2, 4, 8}, 10))  // 1 3 true
	fmt.Println(pairSumSorted([]int{1, 2, 3}, 100))    // -1 -1 false
}

Complexity. Time O(n): each step moves a pointer, and pointers only move inward, so at most n steps. Space O(1).

Follow-ups. "Return all pairs / count pairs?" → when you find a match with duplicates, count both runs. "Unsorted?" → hash map (file 04) or sort first.

Problem 2 · Remove Duplicates from a Sorted Array (LeetCode 26, Easy)

Task. Modify the sorted array in place so each value appears once, and return the new length. [0, 0, 1, 1, 1, 2, 2, 3] → length 4, array starts [0, 1, 2, 3].

Idea (read/write pointers). write marks where the next new value goes. read scans forward. Because the array is sorted, a value is new exactly when it differs from the last one we wrote (nums[write - 1]).

Trace. [0, 0, 1, 1, 2]

readnums[read]last writtenActionarray (| = write boundary)
00(none, write=0)write 0 → write=10 | 0 1 1 2
100same, skip0 | 0 1 1 2
210write 1 → write=20 1 | 1 1 2
311skip0 1 | 1 1 2
421write 2 → write=30 1 2 | 1 2

Answer: length 3, first three items [0, 1, 2].

function removeDuplicates(nums: number[]): number {
  if (nums.length === 0) return 0;
  let write = 1; // nums[0] is always kept
  for (let read = 1; read < nums.length; read++) {
    if (nums[read] !== nums[write - 1]) {
      nums[write] = nums[read];
      write++;
    }
  }
  return write;
}
const dupes = [0, 0, 1, 1, 1, 2, 2, 3];
const k = removeDuplicates(dupes);
console.log(k, dupes.slice(0, k)); // 4 [ 0, 1, 2, 3 ]
console.log(removeDuplicates([])); // 0
func removeDuplicates(nums []int) int {
	if len(nums) == 0 {
		return 0
	}
	write := 1 // nums[0] is always kept
	for read := 1; read < len(nums); read++ {
		if nums[read] != nums[write-1] {
			nums[write] = nums[read]
			write++
		}
	}
	return write
}

func exampleRemoveDuplicates() {
	dupes := []int{0, 0, 1, 1, 1, 2, 2, 3}
	k := removeDuplicates(dupes)
	fmt.Println(k, dupes[:k])                // 4 [0 1 2 3]
	fmt.Println(removeDuplicates([]int{})) // 0
}

Complexity. Time O(n), space O(1).

Follow-up. "Allow each value at most twice (LeetCode 80)." Compare with nums[write - 2] instead of nums[write - 1].

Problem 3 · Sort Colors / Dutch National Flag (LeetCode 75, Medium)

Task. The array contains only 0, 1, 2 (red, white, blue). Sort it in place in one pass without using a sort function. [2, 0, 2, 1, 1, 0] → [0, 0, 1, 1, 2, 2].

Idea. Keep three zones with three pointers:

Look at nums[mid]:

  • It is 0 → swap it with nums[low] (the start of the 1-zone), then low++, mid++. The swapped-in item came from the 1-zone, so it is already known to be a 1; safe to step over.
  • It is 1 → already in the right zone; mid++.
  • It is 2 → swap with nums[high], then high--. Do not move mid: the item swapped in from the right is unknown and still must be checked.

That last point is the classic bug.

Trace. [2, 0, 1]

lowmidhighnums[mid]Actionarray
0022swap(mid, high), high--[1, 0, 2]
0011mid++[1, 0, 2]
0110swap(mid, low), low++, mid++[0, 1, 2]
121mid > high → stop[0, 1, 2]
function sortColors(nums: number[]): void {
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid <= high) {
    if (nums[mid] === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++;
      mid++;
    } else if (nums[mid] === 1) {
      mid++;
    } else {
      [nums[mid], nums[high]] = [nums[high], nums[mid]];
      high--; // do NOT move mid: the item we just received is unchecked
    }
  }
}
const colors = [2, 0, 2, 1, 1, 0];
sortColors(colors);
console.log(colors); // [ 0, 0, 1, 1, 2, 2 ]
func sortColors(nums []int) {
	low, mid, high := 0, 0, len(nums)-1
	for mid <= high {
		switch nums[mid] {
		case 0:
			nums[low], nums[mid] = nums[mid], nums[low]
			low++
			mid++
		case 1:
			mid++
		default:
			nums[mid], nums[high] = nums[high], nums[mid]
			high-- // do NOT move mid: the item we just received is unchecked
		}
	}
}

func exampleSortColors() {
	colors := []int{2, 0, 2, 1, 1, 0}
	sortColors(colors)
	fmt.Println(colors) // [0 0 1 1 2 2]
}

Complexity. Time O(n) in a single pass, space O(1). (The two-pass alternative, counting each color then rewriting, is also fine in an interview, and simpler. Mention it, then do the one-pass version if asked.)

Problem 4 · 3Sum (LeetCode 15, Medium)

Task. Return all unique triplets in the array that sum to zero. [-1, 0, 1, 2, -1, -4] → [[-1,-1,2],[-1,0,1]].

Brute force. Three nested loops: O(n³).

Idea. Fix one number, then solve pair-sum on the rest. Sort the array first. For each i, look for two numbers after i that add up to -nums[i] using left and right. That is n times an O(n) pair-sum: O(n²).

The part that trips people up: duplicates. The answer must not contain the same triplet twice.

  • Skip a value for i if it equals the previous i value (nums[i] === nums[i-1]).
  • After finding a triplet, move left forward and right backward past all equal values.

Trace. sorted [-4, -1, -1, 0, 1, 2]

ivalueleft, rightsumAction
0−41, 5−4 −1 +2 = −3<0, left++
0−42, 5−4 −1 +2 = −3<0, left++
0−43, 5−4 +0 +2 = −2<0, left++ … no triplet for −4
1−12, 5−1 −1 +2 = 0record [−1,−1,2], skip dups, left=3, right=4
1−13, 4−1 +0 +1 = 0record [−1,0,1], left=4, right=3 → end
2−1same as nums[1], skip
304, 50 +1 +2 = 3>0, right-- … nothing

Also a small optimization: once nums[i] > 0, no triplet can sum to zero (all later numbers are bigger), so stop.

function threeSum(nums: number[]): number[][] {
  const a = [...nums].sort((x, y) => x - y); // copy so the caller's array is untouched
  const result: number[][] = [];
  for (let i = 0; i < a.length - 2; i++) {
    if (a[i] > 0) break; // all remaining numbers are positive
    if (i > 0 && a[i] === a[i - 1]) continue; // skip duplicate first values
    let left = i + 1, right = a.length - 1;
    while (left < right) {
      const sum = a[i] + a[left] + a[right];
      if (sum < 0) left++;
      else if (sum > 0) right--;
      else {
        result.push([a[i], a[left], a[right]]);
        left++;
        right--;
        while (left < right && a[left] === a[left - 1]) left++; // skip duplicate seconds
        while (left < right && a[right] === a[right + 1]) right--; // skip duplicate thirds
      }
    }
  }
  return result;
}
console.log(threeSum([-1, 0, 1, 2, -1, -4])); // [ [ -1, -1, 2 ], [ -1, 0, 1 ] ]
console.log(threeSum([0, 0, 0, 0])); // [ [ 0, 0, 0 ] ]
console.log(threeSum([1, 2, 3])); // []
func threeSum(nums []int) [][]int {
	a := make([]int, len(nums))
	copy(a, nums) // copy so the caller's slice is untouched
	sort.Ints(a)
	result := [][]int{}
	for i := 0; i < len(a)-2; i++ {
		if a[i] > 0 {
			break // all remaining numbers are positive
		}
		if i > 0 && a[i] == a[i-1] {
			continue // skip duplicate first values
		}
		left, right := i+1, len(a)-1
		for left < right {
			sum := a[i] + a[left] + a[right]
			if sum < 0 {
				left++
			} else if sum > 0 {
				right--
			} else {
				result = append(result, []int{a[i], a[left], a[right]})
				left++
				right--
				for left < right && a[left] == a[left-1] {
					left++ // skip duplicate seconds
				}
				for left < right && a[right] == a[right+1] {
					right-- // skip duplicate thirds
				}
			}
		}
	}
	return result
}

func exampleThreeSum() {
	fmt.Println(threeSum([]int{-1, 0, 1, 2, -1, -4})) // [[-1 -1 2] [-1 0 1]]
	fmt.Println(threeSum([]int{0, 0, 0, 0}))          // [[0 0 0]]
	fmt.Println(threeSum([]int{1, 2, 3}))             // []
}

Complexity. Time O(n²) (sorting O(n log n) is smaller). Space O(1) extra besides the output (and the sorted copy).

Follow-ups. "4Sum?" Add another outer loop: O(n³). "3Sum closest?" Same loop; track the sum with the smallest |sum - target|. "Why not a hash set?" It works too, but handling duplicates is messier and it needs O(n) memory.

Problem 5 · Container With Most Water (LeetCode 11, Medium)

Task. height[i] are vertical lines at positions i. Choose two lines that, with the x-axis, hold the most water. Water = (right − left) × min(height[left], height[right]). Example: [1,8,6,2,5,4,8,3,7] → 49.

Idea. Start with the widest container (left = 0, right = n − 1). Now, to find something better, we must find a taller shorter-side, because moving inward always makes the width smaller.

Why the proof works. The water is limited by the shorter line. Say height[left] is the shorter one. Any container that keeps left but moves right inward has a smaller width and can't have a higher limit than height[left], so it can never beat the current one. So left is useless going forward: discard it, left++. Symmetric for the right side. (If equal, move either.)

Trace. [1, 8, 6, 2, 5, 4, 8, 3, 7]

leftrighth[l], h[r]widthareabestmove
081, 7888left (1 is shorter)
188, 774949right
178, 361849right
…… stays 49
function maxArea(height: number[]): number {
  let left = 0, right = height.length - 1, best = 0;
  while (left < right) {
    const width = right - left;
    const limit = Math.min(height[left], height[right]);
    best = Math.max(best, width * limit);
    if (height[left] < height[right]) left++; // the shorter side can't do better
    else right--;
  }
  return best;
}
console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7])); // 49
console.log(maxArea([1, 1])); // 1
func maxArea(height []int) int {
	left, right, best := 0, len(height)-1, 0
	for left < right {
		width := right - left
		limit := min(height[left], height[right])
		best = max(best, width*limit)
		if height[left] < height[right] {
			left++ // the shorter side can't do better
		} else {
			right--
		}
	}
	return best
}

func exampleMaxArea() {
	fmt.Println(maxArea([]int{1, 8, 6, 2, 5, 4, 8, 3, 7})) // 49
	fmt.Println(maxArea([]int{1, 1}))                      // 1
}

Complexity. Time O(n), space O(1).

Problem 6 · Trapping Rain Water (LeetCode 42, Hard)

Task. height[i] is the height of a bar of width 1. After rain, how much water is trapped? [0,1,0,2,1,0,1,3,2,1,2,1] → 6.

Understanding it (the hard part). Focus on one position i. Water above position i stands as high as the lower of two walls: the tallest bar somewhere to its left and the tallest bar somewhere to its right. So

water at i = min(maxLeft(i), maxRight(i)) − height[i] (never below zero).

First solution (prefix arrays, O(n) time, O(n) space). Precompute maxLeft[i] and maxRight[i] with two passes, then sum. It is easy to explain and totally acceptable in an interview.

Two-pointer solution (O(n) time, O(1) space). Keep left and right and the tallest bars seen so far from each side: leftMax, rightMax.

Why it works: look at the two current bars. Suppose height[left] < height[right]. Then the true right-side wall for left is at least height[right], which is already larger than height[left]. So the water level at left is decided by the left side alone, namely leftMax. We can compute its water without knowing the exact right maximum, and then move left. If instead height[right] <= height[left], symmetric reasoning lets us finish right using rightMax.

function trapWithArrays(height: number[]): number {
  const n = height.length;
  const maxLeft = new Array<number>(n).fill(0);
  const maxRight = new Array<number>(n).fill(0);
  for (let i = 0; i < n; i++) maxLeft[i] = Math.max(height[i], i > 0 ? maxLeft[i - 1] : 0);
  for (let i = n - 1; i >= 0; i--) maxRight[i] = Math.max(height[i], i < n - 1 ? maxRight[i + 1] : 0);
  let water = 0;
  for (let i = 0; i < n; i++) {
    water += Math.min(maxLeft[i], maxRight[i]) - height[i]; // level minus the bar itself
  }
  return water;
}
console.log(trapWithArrays([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])); // 6
console.log(trapWithArrays([4, 2, 0, 3, 2, 5])); // 9
console.log(trapWithArrays([])); // 0
func trapWithArrays(height []int) int {
	n := len(height)
	maxLeft := make([]int, n)
	maxRight := make([]int, n)
	for i := 0; i < n; i++ {
		maxLeft[i] = height[i]
		if i > 0 {
			maxLeft[i] = max(maxLeft[i], maxLeft[i-1])
		}
	}
	for i := n - 1; i >= 0; i-- {
		maxRight[i] = height[i]
		if i < n-1 {
			maxRight[i] = max(maxRight[i], maxRight[i+1])
		}
	}
	water := 0
	for i := 0; i < n; i++ {
		water += min(maxLeft[i], maxRight[i]) - height[i] // level minus the bar itself
	}
	return water
}

func exampleTrapWithArrays() {
	fmt.Println(trapWithArrays([]int{0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1})) // 6
	fmt.Println(trapWithArrays([]int{4, 2, 0, 3, 2, 5}))                    // 9
	fmt.Println(trapWithArrays(nil))                                        // 0
}
function trapRainWater(height: number[]): number {
  let left = 0, right = height.length - 1;
  let leftMax = 0, rightMax = 0, water = 0;
  while (left < right) {
    if (height[left] < height[right]) {
      // The right side has a wall at least this tall, so only the left wall matters.
      if (height[left] >= leftMax) leftMax = height[left];
      else water += leftMax - height[left];
      left++;
    } else {
      if (height[right] >= rightMax) rightMax = height[right];
      else water += rightMax - height[right];
      right--;
    }
  }
  return water;
}

console.log(trapRainWater([4, 2, 0, 3, 2, 5])); // 9
console.log(trapRainWater([2, 0, 1, 3])); // 3
console.log(trapRainWater([])); // 0
func trapRainWater(height []int) int {
	if len(height) == 0 {
		return 0
	}
	left, right := 0, len(height)-1
	leftMax, rightMax, water := 0, 0, 0
	for left < right {
		if height[left] < height[right] {
			// The right side has a wall at least this tall, so only the left wall matters.
			if height[left] >= leftMax {
				leftMax = height[left]
			} else {
				water += leftMax - height[left]
			}
			left++
		} else {
			if height[right] >= rightMax {
				rightMax = height[right]
			} else {
				water += rightMax - height[right]
			}
			right--
		}
	}
	return water
}

func exampleTrapRainWater() {
	fmt.Println(trapRainWater([]int{0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1})) // 6
	fmt.Println(trapRainWater([]int{4, 2, 0, 3, 2, 5}))                    // 9
	fmt.Println(trapRainWater([]int{2, 0, 1, 3}))                          // 3
	fmt.Println(trapRainWater(nil))                                        // 0
}

Complexity. Time O(n), space O(1).

Other solutions to mention. The prefix-array version (O(n) space) and a monotonic stack version (file 13). Naming alternatives shows range.

Common mistakes

  • Using the pattern on unsorted data where the "safe to discard" argument fails.
  • left <= right vs left < right. For pairs you need two different elements: <. For single-element checks (palindrome with an odd center) < is also fine because the middle needs no comparison.
  • Not skipping duplicates in 3Sum (duplicate triplets) or skipping them before recording (missing valid triplets such as [0,0,0]).
  • Moving mid after swapping with high in Sort Colors.
  • Forgetting to handle the empty array in read/write loops.

1 · Say why each move is safe

State out loud the "why safe" argument for pair sum, container with most water, and trapping rain water. Each one in two sentences.

Show model answers

Pair sum. When the sum is too small, nums[left] is already paired with the biggest value left and still falls short, so no partner can work for it: discard it. When the sum is too big, nums[right] overshoots even with the smallest value left, so discard it.

Container with most water. The water is limited by the shorter line, and moving inward only shrinks the width. Any container that keeps the shorter line is narrower and no taller, so it can never beat the current one: discard that line.

Trapping rain water. If h[left] < h[right], there is a wall on the right at least h[right] tall, so the water at left is decided by leftMax alone and can be settled now. The same argument, mirrored, settles right when h[right] ≤ h[left].

2 · Move Zeroes (LeetCode 283)

Move all zeros to the end, keep the order of the rest, in place. Which flavor is it?

Hint

Which part of the array is "finished" as you go? Keep one pointer at the next free slot for a non-zero.

Answer, animation and code

It is the same-direction (read/write) flavor. read visits every value; each non-zero is swapped into write. The non-zeros keep their order and the zeros drift to the back. Swapping instead of copying means no second pass to fill in zeros. O(n) time, O(1) memory.

function moveZeroes(nums: number[]): void {
  let write = 0; // everything before `write` is a non-zero, in the original order
  for (let read = 0; read < nums.length; read++) {
    if (nums[read] !== 0) {
      [nums[write], nums[read]] = [nums[read], nums[write]];
      write++;
    }
  }
}

moveZeroes(zs);
console.log(zs); // [ 1, 3, 12, 0, 0 ]
const noZeros = [1, 2];
moveZeroes(noZeros);
console.log(noZeros); // [ 1, 2 ]

3 · Valid Palindrome (LeetCode 125)

Ignore non-letters and case. Write it with opposite ends in both languages.

Hint

Before comparing, let each pointer skip past anything that is not a letter or digit.

Answer, animation and code

Opposite ends. Skip characters that are not letters or digits on either side, then compare the two characters in lower case, and return false at the first mismatch. The loop uses left < right: the middle character of an odd-length string needs no partner. O(n) time, O(1) memory.

function isAlphaNum(c: string): boolean {
  return /^[a-z0-9]$/i.test(c);
}

function isPalindrome(s: string): boolean {
  let left = 0, right = s.length - 1;
  while (left < right) {
    if (!isAlphaNum(s[left])) { left++; continue; } // skip spaces and punctuation
    if (!isAlphaNum(s[right])) { right--; continue; }
    if (s[left].toLowerCase() !== s[right].toLowerCase()) return false;
    left++;
    right--;
  }
  return true;
}
console.log(isPalindrome("A man, a plan, a canal: Panama")); // true
console.log(isPalindrome("race a car")); // false
console.log(isPalindrome(" ")); // true
func isAlphaNum(b byte) bool {
	return (b >= 'a' && b <= 'z') || (b >= 'A' && b <= 'Z') || (b >= '0' && b <= '9')
}

func toLower(b byte) byte {
	if b >= 'A' && b <= 'Z' {
		return b + ('a' - 'A')
	}
	return b
}

func isPalindrome(s string) bool {
	left, right := 0, len(s)-1
	for left < right {
		if !isAlphaNum(s[left]) {
			left++ // skip spaces and punctuation
			continue
		}
		if !isAlphaNum(s[right]) {
			right--
			continue
		}
		if toLower(s[left]) != toLower(s[right]) {
			return false
		}
		left++
		right--
	}
	return true
}

func exampleIsPalindrome() {
	fmt.Println(isPalindrome("A man, a plan, a canal: Panama")) // true
	fmt.Println(isPalindrome("race a car"))                     // false
	fmt.Println(isPalindrome(" "))                              // true
}

4 · Merge Sorted Array (LeetCode 88)

Merge two sorted arrays into one. What happens when you merge from the back into an array with spare room?

Hint

Merging from the front would overwrite values of nums1 you have not read yet. Where is the empty space?

Answer, animation and code

The spare room is at the back, so fill it from the back: compare the last real values of both arrays and put the bigger one at write. A write never lands on a value you still need. When nums2 runs out, what is left of nums1 is already in place; if nums1 runs out first, the loop keeps copying nums2. O(m + n) time, O(1) extra memory.

function mergeSorted(nums1: number[], m: number, nums2: number[], n: number): void {
  let i = m - 1, j = n - 1, write = m + n - 1; // write fills the spare room from the back
  while (j >= 0) {
    if (i >= 0 && nums1[i] > nums2[j]) {
      nums1[write] = nums1[i];
      i--;
    } else {
      nums1[write] = nums2[j];
      j--;
    }
    write--;
  }
}
const room = [1, 2, 3, 0, 0, 0];
mergeSorted(room, 3, [2, 5, 6], 3);
console.log(room); // [ 1, 2, 2, 3, 5, 6 ]
const onlySecond = [0];
mergeSorted(onlySecond, 0, [1], 1);
console.log(onlySecond); // [ 1 ]
func mergeSorted(nums1 []int, m int, nums2 []int, n int) {
	i, j, write := m-1, n-1, m+n-1 // write fills the spare room from the back
	for j >= 0 {
		if i >= 0 && nums1[i] > nums2[j] {
			nums1[write] = nums1[i]
			i--
		} else {
			nums1[write] = nums2[j]
			j--
		}
		write--
	}
}

func exampleMergeSorted() {
	room := []int{1, 2, 3, 0, 0, 0}
	mergeSorted(room, 3, []int{2, 5, 6}, 3)
	fmt.Println(room) // [1 2 2 3 5 6]
	onlySecond := []int{0}
	mergeSorted(onlySecond, 0, []int{1}, 1)
	fmt.Println(onlySecond) // [1]
}

5 · 3Sum Closest (LeetCode 16)

Modify the 3Sum loop to track the closest sum.

Hint

Same loop as 3Sum. Instead of a list of triplets, what single value do you remember?

Answer and code

Keep best, the sum closest to the target so far. For each sum, replace best when |sum − target| is smaller, return at once on an exact match, and otherwise move left or right toward the target, exactly as in 3Sum. Duplicate skipping is optional here because only a sum is returned. O(n²) time.

function threeSumClosest(nums: number[], target: number): number {
  const a = [...nums].sort((x, y) => x - y);
  let best = a[0] + a[1] + a[2];
  for (let i = 0; i < a.length - 2; i++) {
    let left = i + 1, right = a.length - 1;
    while (left < right) {
      const sum = a[i] + a[left] + a[right];
      if (Math.abs(sum - target) < Math.abs(best - target)) best = sum; // closer: remember it
      if (sum === target) return sum; // nothing is closer than exact
      if (sum < target) left++;
      else right--;
    }
  }
  return best;
}
console.log(threeSumClosest([-1, 2, 1, -4], 1)); // 2
console.log(threeSumClosest([0, 0, 0], 1)); // 0
console.log(threeSumClosest([1, 1, 1, 0], 100)); // 3
func absInt(x int) int {
	if x < 0 {
		return -x
	}
	return x
}

func threeSumClosest(nums []int, target int) int {
	a := make([]int, len(nums))
	copy(a, nums)
	sort.Ints(a)
	best := a[0] + a[1] + a[2]
	for i := 0; i < len(a)-2; i++ {
		left, right := i+1, len(a)-1
		for left < right {
			sum := a[i] + a[left] + a[right]
			if absInt(sum-target) < absInt(best-target) {
				best = sum // closer: remember it
			}
			if sum == target {
				return sum // nothing is closer than exact
			}
			if sum < target {
				left++
			} else {
				right--
			}
		}
	}
	return best
}

func exampleThreeSumClosest() {
	fmt.Println(threeSumClosest([]int{-1, 2, 1, -4}, 1)) // 2
	fmt.Println(threeSumClosest([]int{0, 0, 0}, 1))      // 0
	fmt.Println(threeSumClosest([]int{1, 1, 1, 0}, 100)) // 3
}
