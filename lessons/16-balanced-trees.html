Balanced trees

Keep the tree short, and every search stays fast.

Book link: Grokking Algorithms, chapter 8 (a balancing act, shorter trees are faster, AVL trees, splay trees, B-trees) and appendix A. This file explains the same ideas in plain English and then makes them concrete with a working AVL tree. Interviews seldom ask you to code a balanced tree from scratch, but they often ask why balancing matters, what the rotations do, and which structure a database or TreeMap uses. You need to answer those cleanly.

Why it matters

A BST costs O(height). Sorted input makes a chain (height n); balancing keeps it about log₂ n.

The repair tool

A rotation rewires three links in O(1) and keeps the BST order.

Know by name

AVL (strict), red-black (TreeMap, std::map), B-tree (databases), skip list (Redis).

1. Why balance matters

From file 15: searching a binary search tree (BST) costs O(height). Height depends on the shape:

ShapeHeight for n nodesSearch cost
Chain (worst, sorted input)nO(n), no better than a linked list
Balancedabout log₂ nO(log n)

For a million items: a chain needs up to 1,000,000 steps; a balanced tree needs about 20.

Balanced means that for every node, the heights of its left and right subtrees are similar. A self-balancing tree repairs its own shape after every insert or delete, so you get O(log n) guaranteed, even if the data arrives in sorted order.

2. The repair tool: rotations

A rotation is a small local rewiring of three nodes that makes one side shorter and the other taller while keeping the BST ordering rule intact (smaller on the left, larger on the right).

Right rotation (fixes a left-heavy shape)

Node y is too heavy on the left. Its left child x is lifted up to become the parent; y drops down to the right of x. x's old right subtree (B), whose values lie between x and y, becomes y's new left subtree.

Order check: A < x < B < y < C holds before and after. Only three pointers changed, so a rotation costs O(1).

A left rotation is the mirror image.

3. AVL trees: the strict-balance tree

An AVL tree (named after its inventors Adelson-Velsky and Landis) keeps this rule for every node:

balance factor = height(left) − height(right) ∈ {−1, 0, +1}

After each insert or delete, walk back up the path, update heights, and where a node's balance factor reaches ±2, fix it with rotations. There are four cases, named by where the extra weight sits:

The zig-zag cases need two rotations. If the extra weight is on the inner side (left-right or right-left), a single rotation would just move the problem to the other side. First turn the zig-zag into a straight line, then rotate.

A tiny walk-through: insert 1, 2, 3 into an AVL tree.

StepTreeBalance
insert 11fine
insert 21 → right 21 has balance −1: fine
insert 31 → right 2 → right 3 (a chain)1 has balance −2: RR case
rotate left at 12 with children 1 and 3balanced ✔

Guarantees. Height ≤ about 1.44 · log₂ n. Search, insert, delete: all O(log n). An insert needs at most one rebalancing step (one single or double rotation); a delete may need up to O(log n) rotations along the path.

You rarely code these. You should be able to say what they are for.

Why databases use B-trees, not binary trees

A disk read is the slow part (thousands of times slower than memory). A binary tree over a billion rows is about 30 levels deep, which means about 30 disk reads. A B-tree whose nodes each hold, say, 500 keys is only about log₅₀₀ 10⁹ ≈ 3.3 levels deep, so roughly 3 or 4 disk reads. Fewer, fatter nodes is the whole trick.

A B+ tree keeps all the actual records in the leaves, linked left to right, so a range query ("all orders from March") is one descent plus a scan along the leaf chain.

5. Where this shows up in interviews

  • "Why not just use a plain BST?" (sorted input degrades it to a chain.)
  • "What does TreeMap/std::map/an ordered map give you that a hash map does not?" (sorted iteration, range queries, floor/ceiling, all O(log n).)
  • "Design a data structure that supports insert, delete, and 'find the closest value'" (a balanced BST or sorted structure; in Go there is no built-in one, so you would use a library or explain it.)
  • "How does a database index work?" (B+ tree.)
  • Questions that give you sorted data and ask you to build a balanced BST (Problem 1 below).

Go and TypeScript have no built-in balanced tree. In an interview you describe it, use a sorted array with binary search (O(log n) search, O(n) insert), or pick the right tool (a heap, a sorted structure from a library). Be ready to say that explicitly.

Problem 1 · Convert Sorted Array to Height-Balanced BST (LeetCode 108, Easy)

Task. Turn a sorted array into a BST whose two subtrees' heights never differ by more than 1. [-10, -3, 0, 5, 9] → a tree such as [0, -10, 5, null, -3, null, 9].

Idea. The middle element is the best root: half the items are smaller (left subtree) and half are larger (right subtree). Do the same recursively on each half. Halving guarantees balance, and the sorted order guarantees the BST rule.

class TreeNode {
  constructor(
    public val: number,
    public left: TreeNode | null = null,
    public right: TreeNode | null = null,
  ) {}
}

function toLevelArray(root: TreeNode | null): (number | null)[] {
  const out: (number | null)[] = [];
  const queue: (TreeNode | null)[] = [root];
  for (let head = 0; head < queue.length; head++) {
    const node = queue[head];
    if (node === null) {
      out.push(null);
      continue;
    }
    out.push(node.val);
    queue.push(node.left, node.right);
  }
  while (out.length > 0 && out[out.length - 1] === null) out.pop();
  return out;
}

function sortedArrayToBST(nums: number[]): TreeNode | null {
  function build(lo: number, hi: number): TreeNode | null {
    if (lo > hi) return null;
    const mid = lo + Math.floor((hi - lo) / 2); // the middle becomes the root
    return new TreeNode(nums[mid], build(lo, mid - 1), build(mid + 1, hi));
  }
  return build(0, nums.length - 1);
}
console.log(toLevelArray(sortedArrayToBST([-10, -3, 0, 5, 9]))); // [ 0, -10, 5, null, -3, null, 9 ]
console.log(toLevelArray(sortedArrayToBST([1, 3]))); // [ 1, null, 3 ]
console.log(toLevelArray(sortedArrayToBST([]))); // []
type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}

func toLevelArray(root *TreeNode) []string {
	out := []string{}
	queue := []*TreeNode{root}
	for head := 0; head < len(queue); head++ {
		node := queue[head]
		if node == nil {
			out = append(out, "null")
			continue
		}
		out = append(out, strconv.Itoa(node.Val))
		queue = append(queue, node.Left, node.Right)
	}
	for len(out) > 0 && out[len(out)-1] == "null" {
		out = out[:len(out)-1]
	}
	return out
}

func sortedArrayToBST(nums []int) *TreeNode {
	var build func(lo, hi int) *TreeNode
	build = func(lo, hi int) *TreeNode {
		if lo > hi {
			return nil
		}
		mid := lo + (hi-lo)/2 // the middle becomes the root
		return &TreeNode{Val: nums[mid], Left: build(lo, mid-1), Right: build(mid+1, hi)}
	}
	return build(0, len(nums)-1)
}

func exampleSortedArrayToBST() {
	fmt.Println(toLevelArray(sortedArrayToBST([]int{-10, -3, 0, 5, 9}))) // [0 -10 5 null -3 null 9]
	fmt.Println(toLevelArray(sortedArrayToBST([]int{1, 3})))             // [1 null 3]
	fmt.Println(toLevelArray(sortedArrayToBST([]int{})))                 // []
}

Complexity. Time O(n), space O(log n) for the recursion (plus the tree). Follow-up: sorted linked list to BST (LeetCode 109): use slow/fast pointers to find the middle (file 12).

Problem 2 · Balanced Binary Tree (LeetCode 110, Easy)

Task. Is the tree height-balanced: for every node, do its left and right subtree heights differ by at most 1?

The slow way. At every node compute both heights separately: heights are recomputed again and again, O(n²) for a chain.

The one-pass way. Make height(node) return a signal: the real height, or −1 meaning "something below is already unbalanced". The moment any child returns −1, or the two heights differ by more than 1, return −1 upward.

function isBalanced(root: TreeNode | null): boolean {
  // returns the height, or -1 if some subtree below is not balanced
  function heightOrFail(node: TreeNode | null): number {
    if (node === null) return 0;
    const left = heightOrFail(node.left);
    if (left === -1) return -1; // bad news travels up
    const right = heightOrFail(node.right);
    if (right === -1) return -1;
    if (Math.abs(left - right) > 1) return -1; // this node is unbalanced
    return 1 + Math.max(left, right);
  }
  return heightOrFail(root) !== -1;
}
const balancedTree = new TreeNode(3, new TreeNode(9), new TreeNode(20, new TreeNode(15), new TreeNode(7)));
const chainTree = new TreeNode(1, new TreeNode(2, new TreeNode(3)));
console.log(isBalanced(balancedTree)); // true
console.log(isBalanced(chainTree)); // false
console.log(isBalanced(null)); // true
func isBalanced(root *TreeNode) bool {
	// returns the height, or -1 if some subtree below is not balanced
	var heightOrFail func(node *TreeNode) int
	heightOrFail = func(node *TreeNode) int {
		if node == nil {
			return 0
		}
		left := heightOrFail(node.Left)
		if left == -1 {
			return -1 // bad news travels up
		}
		right := heightOrFail(node.Right)
		if right == -1 {
			return -1
		}
		if left-right > 1 || right-left > 1 {
			return -1 // this node is unbalanced
		}
		return 1 + max(left, right)
	}
	return heightOrFail(root) != -1
}

func exampleIsBalanced() {
	balanced := &TreeNode{Val: 3, Left: &TreeNode{Val: 9}, Right: &TreeNode{Val: 20, Left: &TreeNode{Val: 15}, Right: &TreeNode{Val: 7}}}
	chain := &TreeNode{Val: 1, Left: &TreeNode{Val: 2, Left: &TreeNode{Val: 3}}}
	fmt.Println(isBalanced(balanced)) // true
	fmt.Println(isBalanced(chain))    // false
	fmt.Println(isBalanced(nil))      // true
}

Complexity. Time O(n), space O(h).

Problem 3 · Delete Node in a BST (LeetCode 450, Medium)

Searching and inserting in a BST are straightforward (go left or right by comparison). Deleting is the one operation with real cases, and it is what an AVL tree must also do before rebalancing.

Task. Delete the node with a given key and return the new root. [5, 3, 6, 2, 4, null, 7], key 3 → [5, 4, 6, 2, null, null, 7] (one valid answer).

The three cases after finding the node:

Why the inorder successor? It is the next value in sorted order. Putting it in the deleted node's place keeps everything on the left smaller and everything on the right larger. Being the smallest of the right subtree, it has no left child, so deleting it falls into the easy cases (0 or 1 child).

function insertBST(root: TreeNode | null, val: number): TreeNode {
  if (root === null) return new TreeNode(val);
  if (val < root.val) root.left = insertBST(root.left, val);
  else root.right = insertBST(root.right, val);
  return root;
}

function deleteNode(root: TreeNode | null, key: number): TreeNode | null {
  if (root === null) return null; // key not found
  if (key < root.val) root.left = deleteNode(root.left, key);
  else if (key > root.val) root.right = deleteNode(root.right, key);
  else {
    if (root.left === null) return root.right; // 0 or 1 child (right)
    if (root.right === null) return root.left; // 1 child (left)
    let successor = root.right; // 2 children: the smallest node of the right subtree
    while (successor.left !== null) successor = successor.left;
    root.val = successor.val; // copy its value up
    root.right = deleteNode(root.right, successor.val); // then remove the original
  }
  return root;
}

for (const v of [5, 3, 6, 2, 4, 7]) bst = insertBST(bst, v);
console.log(toLevelArray(bst)); // [ 5, 3, 6, 2, 4, null, 7 ]

console.log(toLevelArray(bst)); // [ 5, 4, 6, 2, null, null, 7 ]

console.log(toLevelArray(bst)); // [ 6, 4, 7, 2 ]
console.log(toLevelArray(deleteNode(bst, 99))); // [ 6, 4, 7, 2 ]  (unchanged)
func insertBST(root *TreeNode, val int) *TreeNode {
	if root == nil {
		return &TreeNode{Val: val}
	}
	if val < root.Val {
		root.Left = insertBST(root.Left, val)
	} else {
		root.Right = insertBST(root.Right, val)
	}
	return root
}

func deleteNode(root *TreeNode, key int) *TreeNode {
	if root == nil {
		return nil // key not found
	}
	if key < root.Val {
		root.Left = deleteNode(root.Left, key)
	} else if key > root.Val {
		root.Right = deleteNode(root.Right, key)
	} else {
		if root.Left == nil {
			return root.Right // 0 or 1 child (right)
		}
		if root.Right == nil {
			return root.Left // 1 child (left)
		}
		successor := root.Right // 2 children: the smallest node of the right subtree
		for successor.Left != nil {
			successor = successor.Left
		}
		root.Val = successor.Val                       // copy its value up
		root.Right = deleteNode(root.Right, successor.Val) // then remove the original
	}
	return root
}

func exampleDeleteNode() {
	var bst *TreeNode
	for _, v := range []int{5, 3, 6, 2, 4, 7} {
		bst = insertBST(bst, v)
	}
	fmt.Println(toLevelArray(bst)) // [5 3 6 2 4 null 7]
	bst = deleteNode(bst, 3)
	fmt.Println(toLevelArray(bst)) // [5 4 6 2 null null 7]
	bst = deleteNode(bst, 5) // delete the root
	fmt.Println(toLevelArray(bst)) // [6 4 7 2]
	fmt.Println(toLevelArray(deleteNode(bst, 99))) // [6 4 7 2]
}

Complexity. Time O(h), space O(h).

Problem 4 · Implement an AVL Tree (insert with rotations)

Task. Insert values into a self-balancing tree and show it stays short even for sorted input. This is the "hard" exercise for this topic. Do it once, slowly, so the rotations stop being magic.

Plan.

  1. Every node stores its height (a leaf has height 1; an empty tree has height 0).
  2. After inserting recursively, update the current node's height on the way back up.
  3. Compute the balance factor = height(left) − height(right).
  4. If it is > 1 (left-heavy): if the new value went into the left child's right side (LR case) rotate that child left first; then rotate right at the current node.
  5. If it is < −1 (right-heavy): mirror it.

insert 23 with left child 2+1 fine
insert 13 → 2 → 1 going left+2 at 3: LL case
rotate right at 32 with children 1 and 30 ✔

Walk-through: insert 3, 1, 2 (LR case: the zig-zag)

class AVLNode {
  height = 1; // a new node is a leaf
  constructor(
    public val: number,
    public left: AVLNode | null = null,
    public right: AVLNode | null = null,
  ) {}
}

const heightOf = (n: AVLNode | null): number => (n === null ? 0 : n.height);
const refreshHeight = (n: AVLNode): void => {
  n.height = 1 + Math.max(heightOf(n.left), heightOf(n.right));
};
const balanceFactor = (n: AVLNode): number => heightOf(n.left) - heightOf(n.right);

function rotateRight(y: AVLNode): AVLNode {
  const x = y.left!; // x moves up
  y.left = x.right; // x's inner subtree becomes y's left
  x.right = y; // y moves down
  refreshHeight(y); // y first: it is now lower than x
  refreshHeight(x);
  return x; // the new root of this subtree
}

function rotateLeft(x: AVLNode): AVLNode {
  const y = x.right!; // y moves up
  x.right = y.left;
  y.left = x;
  refreshHeight(x);
  refreshHeight(y);
  return y;
}

function avlInsert(node: AVLNode | null, val: number): AVLNode {
  if (node === null) return new AVLNode(val);
  if (val < node.val) node.left = avlInsert(node.left, val);
  else if (val > node.val) node.right = avlInsert(node.right, val);
  else return node; // ignore duplicates
  refreshHeight(node);
  const balance = balanceFactor(node);
  if (balance > 1) {
    if (val > node.left!.val) node.left = rotateLeft(node.left!); // LR case: straighten first
    return rotateRight(node); // LL case
  }
  if (balance < -1) {
    if (val < node.right!.val) node.right = rotateRight(node.right!); // RL case: straighten first
    return rotateLeft(node); // RR case
  }
  return node;
}

function avlInorder(node: AVLNode | null, out: number[] = []): number[] {
  if (node === null) return out;
  avlInorder(node.left, out);
  out.push(node.val);
  avlInorder(node.right, out);
  return out;
}

type AVLNode struct {
	Val         int
	Height      int
	Left, Right *AVLNode
}

func heightOf(n *AVLNode) int {
	if n == nil {
		return 0
	}
	return n.Height
}
func refreshHeight(n *AVLNode)     { n.Height = 1 + max(heightOf(n.Left), heightOf(n.Right)) }
func balanceFactor(n *AVLNode) int { return heightOf(n.Left) - heightOf(n.Right) }

func rotateRight(y *AVLNode) *AVLNode {
	x := y.Left // x moves up
	y.Left = x.Right // x's inner subtree becomes y's left
	x.Right = y      // y moves down
	refreshHeight(y) // y first: it is now lower than x
	refreshHeight(x)
	return x // the new root of this subtree
}

func rotateLeft(x *AVLNode) *AVLNode {
	y := x.Right // y moves up
	x.Right = y.Left
	y.Left = x
	refreshHeight(x)
	refreshHeight(y)
	return y
}

func avlInsert(node *AVLNode, val int) *AVLNode {
	if node == nil {
		return &AVLNode{Val: val, Height: 1} // a new node is a leaf
	}
	if val < node.Val {
		node.Left = avlInsert(node.Left, val)
	} else if val > node.Val {
		node.Right = avlInsert(node.Right, val)
	} else {
		return node // ignore duplicates
	}
	refreshHeight(node)
	balance := balanceFactor(node)
	if balance > 1 {
		if val > node.Left.Val {
			node.Left = rotateLeft(node.Left) // LR case: straighten first
		}
		return rotateRight(node) // LL case
	}
	if balance < -1 {
		if val < node.Right.Val {
			node.Right = rotateRight(node.Right) // RL case: straighten first
		}
		return rotateLeft(node) // RR case
	}
	return node
}

func avlInorder(node *AVLNode, out *[]int) {
	if node == nil {
		return
	}
	avlInorder(node.Left, out)
	*out = append(*out, node.Val)
	avlInorder(node.Right, out)
}

func plainHeight(n *TreeNode) int {
	if n == nil {
		return 0
	}
	return 1 + max(plainHeight(n.Left), plainHeight(n.Right))
}

func exampleAVL() {
	var plain *TreeNode
	var avl *AVLNode
	for v := 1; v <= 15; v++ {
		plain = insertBST(plain, v)
		avl = avlInsert(avl, v)
	}
	fmt.Println("plain BST height:", plainHeight(plain)) // 15
	fmt.Println("AVL height:", avl.Height)               // 4
	var order []int
	avlInorder(avl, &order)
	fmt.Println(order) // [1 2 3 ... 15]
	fmt.Println(avl.Val) // 8  (the root is the middle value)

	// The two single-rotation walk-throughs from the text:
	ll := avlInsert(avlInsert(avlInsert(nil, 3), 2), 1)
	lr := avlInsert(avlInsert(avlInsert(nil, 3), 1), 2)
	fmt.Println("LL case root:", ll.Val, "LR case root:", lr.Val) // 2 and 2
}

What the output shows. Inserting 1…15 in order gives a plain BST of height 15 (a chain) but an AVL tree of height 4 (a perfect tree). That is exactly the log₂ 15 ≈ 3.9 promise.

Complexity. Insert O(log n), space O(log n) recursion.

Why refreshHeight(y) before refreshHeight(x) in a rotation? After the rotation y is a child of x, so x's height depends on y's new height. Always update the lower node first.

Quick Q&A for the interview

QuestionShort answer
What is the height of a balanced BST with n nodes?Θ(log n).
AVL vs red-black?AVL is stricter (faster lookups, more rotations on update); red-black is looser (fewer rotations on update, used in library TreeMaps).
Why not balance by always rebuilding from a sorted array?Rebuilding is O(n) per update. Rotations are O(1) local fixes.

Common mistakes

  • Quoting O(log n) for a plain BST without saying "if balanced".
  • Mixing up the four rotation cases: the zig-zag (LR/RL) needs two rotations.
  • Forgetting to update heights after a rotation (and in the wrong order: child first).
  • Losing the new subtree root after a rotation (you must return it and reattach it to the parent).
  • Deleting a node with two children by simply removing it. Use the inorder successor (or predecessor).
  • Duplicates in a BST without deciding the rule (left, right, or counts).
  • Claiming TypeScript or Go has a built-in ordered tree map. Neither does.

1 · Six AVL inserts

Draw the tree after inserting 10, 20, 30, 40, 50, 25 into an AVL tree (apply the rule one insert at a time).

Hint

After 10, 20, 30 the first rotation happens. Watch for a zig-zag when 25 arrives.

Answer

10, 20, 30: RR at 10, so rotate left: 20(10, 30). 40 hangs under 30. 50 makes 30 right-heavy (RR): rotate left at 30, giving 20(10, 40(30, 50)). 25 goes 20 → 40 → 30 → left. Now 20 has balance −2 and its right child 40 has +1: the RL case. Rotate 40 right, then 20 left. Result, level order: [30, 20, 40, 10, 25, null, 50], height 3. 2 · Balance −2, right child +1

A node has balance factor −2 and its right child has balance factor +1. Which case is this, and which two rotations fix it?

Answer

The RL case: heavy on the right, with the extra weight on the inner (left) side of the right child. First rotate the right child right to straighten the zig-zag, then rotate the node left. The second preset of the “LR case” tab shows the mirror image.

3 · B-tree height

Why does a B-tree node hold many keys? Compute the height for 10⁹ keys with 500 keys per node.

Answer

A node fills one disk page, so it holds hundreds of keys and has hundreds of children: each disk read rules out far more than half. With 500 keys per node, about 501 children: height ≈ log₅₀₀(10⁹) = 9 / 2.7 ≈ 3.3, so 4 levels, and the top one or two usually sit in memory. A balanced binary tree would need about 30 levels, each one a disk read.

4 · Sorted list to BST

Convert Sorted Linked List to BST (LeetCode 109) using the slow/fast middle trick. What is its complexity?

Answer

Find the middle of the range [start, end) with slow/fast pointers, make it the root, and recurse on the two halves. Each level of recursion walks the whole list once in total, and there are log n levels: O(n log n) time, O(log n) stack. (An O(n) version builds in inorder order while walking the list once.)

class ListNode {
  constructor(public val: number, public next: ListNode | null = null) {}
}
class TreeNode {
  constructor(public val: number, public left: TreeNode | null = null, public right: TreeNode | null = null) {}
}

// Sorted List to BST: the middle node (found with slow/fast) becomes the root.
function sortedListToBST(head: ListNode | null): TreeNode | null {
  function build(start: ListNode | null, end: ListNode | null): TreeNode | null {
    if (start === end) return null; // the range [start, end) is empty
    let slow = start!, fast = start!;
    while (fast.next !== end && fast.next!.next !== end) {
      slow = slow.next!;
      fast = fast.next!.next!;
    }
    return new TreeNode(slow.val, build(start, slow), build(slow.next, end));
  }
  return build(head, null);
}

const fromArray = (a: number[]): ListNode | null => a.reduceRight<ListNode | null>((next, v) => new ListNode(v, next), null);
const preorder = (n: TreeNode | null): number[] => (n === null ? [] : [n.val, ...preorder(n.left), ...preorder(n.right)]);
console.log(preorder(sortedListToBST(fromArray([-10, -3, 0, 5, 9]))).join(",")); // 0,-10,-3,5,9
console.log(preorder(sortedListToBST(fromArray([1, 2, 3, 4]))).join(",")); // 2,1,3,4
console.log(preorder(sortedListToBST(null)).length); // 0
type ListNode struct {
	Val  int
	Next *ListNode
}
type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}

// Sorted List to BST: the middle node (found with slow/fast) becomes the root.
func sortedListToBST(head *ListNode) *TreeNode {
	var build func(start, end *ListNode) *TreeNode
	build = func(start, end *ListNode) *TreeNode {
		if start == end {
			return nil // the range [start, end) is empty
		}
		slow, fast := start, start
		for fast.Next != end && fast.Next.Next != end {
			slow = slow.Next
			fast = fast.Next.Next
		}
		return &TreeNode{Val: slow.Val, Left: build(start, slow), Right: build(slow.Next, end)}
	}
	return build(head, nil)
}

func preorder(n *TreeNode) []int {
	if n == nil {
		return []int{}
	}
	return append(append([]int{n.Val}, preorder(n.Left)...), preorder(n.Right)...)
}

func exampleSortedListToBST() {
	fromSlice := func(a []int) *ListNode {
		var head *ListNode
		for i := len(a) - 1; i >= 0; i-- {
			head = &ListNode{Val: a[i], Next: head}
		}
		return head
	}
	fmt.Println(preorder(sortedListToBST(fromSlice([]int{-10, -3, 0, 5, 9})))) // [0 -10 -3 5 9]
	fmt.Println(preorder(sortedListToBST(fromSlice([]int{1, 2, 3, 4}))))       // [2 1 3 4]
	fmt.Println(len(preorder(sortedListToBST(nil))))                            // 0
}

5 · An ordered set in Go

You need an "ordered set with floor and ceiling" in Go. What are your options? (Sorted slice + binary search, an external library, or write a tree.)

Answer

Go has no built-in ordered map. Options: (1) a sorted slice + sort.SearchInts: O(log n) floor/ceiling, O(n) insert, simplest and fine for interviews; (2) an external library (a B-tree or red-black tree package, or a skip list); (3) write your own tree (treap or AVL), which is rarely worth it in an interview. TypeScript is in the same position: no built-in TreeMap.

// An ordered set of ints on a sorted slice: Floor and Ceiling by binary search.
// Insert is O(n) because of the shift, which is fine up to roughly 10^5 items.
type OrderedSet struct{ keys []int }

func (s *OrderedSet) Insert(v int) {
	i := sort.SearchInts(s.keys, v)
	if i < len(s.keys) && s.keys[i] == v {
		return // already present
	}
	s.keys = append(s.keys, 0)
	copy(s.keys[i+1:], s.keys[i:])
	s.keys[i] = v
}

// Floor: the largest key <= v.
func (s *OrderedSet) Floor(v int) (int, bool) {
	i := sort.SearchInts(s.keys, v+1) // first key > v
	if i == 0 {
		return 0, false
	}
	return s.keys[i-1], true
}

// Ceiling: the smallest key >= v.
func (s *OrderedSet) Ceiling(v int) (int, bool) {
	i := sort.SearchInts(s.keys, v) // first key >= v
	if i == len(s.keys) {
		return 0, false
	}
	return s.keys[i], true
}

func exampleOrderedSet() {
	s := &OrderedSet{}
	for _, v := range []int{20, 5, 40, 10, 5} {
		s.Insert(v)
	}
	fmt.Println(s.keys)          // [5 10 20 40]
	fmt.Println(s.Floor(15))     // 10 true
	fmt.Println(s.Ceiling(15))   // 20 true
	fmt.Println(s.Floor(4))      // 0 false
	fmt.Println(s.Ceiling(40))   // 40 true
}
