1. The idea in plain English

An interval is a range with a start and an end: a meeting from 9:00 to 10:30, a booking from day 3 to day 7, a segment [2, 6] on a number line. Many questions ask: do these overlap? merge them? how many are active at once? what is covered?

The key trick: sort first. If you sort intervals by start time, then any interval that could overlap the current one is right next to it in the list. A messy two-dimensional picture becomes a single left-to-right scan.

The overlap test (memorize it)

Two intervals [a, b] and [c, d] overlap when each one starts before the other ends:

a ≤ d and c ≤ b

Equivalently, they do not overlap when one ends before the other starts (b < c or d < a).

Always ask the touching question. Do [1,2] and [2,3] overlap? For meetings (one ends at 2, the next starts at 2) usually no. For merging number ranges, often yes (they join into [1,3]). The problem statement decides; ask.

Intervals are inclusive or half-open

[1, 3] might include 3 (closed) or stop just before it ([1, 3), half-open). It changes ≤ versus <. Clarify once and use it consistently.

2. The three core moves

MoveWhenHow
Sort by start, merge neighborscombine overlapping rangeskeep the last merged interval; extend its end if the next starts within it
Sort by end, take greedilymaximum non-overlapping set, minimum arrowspick the interval that finishes first (file 23)
Sweep line over events"how many are active at a time?", skylineturn each interval into a start event and an end event, sort all events, scan, track a counter or a structure

The sweep line (the idea behind many hard problems)

Imagine a vertical line sweeping from left to right over the number line. Whenever it hits a start, a new interval becomes active; whenever it hits an end, one stops being active. What you need (a count, the maximum height, the earliest end) is maintained only at event points.

The maximum of the running count is "the most overlap at any moment".

3. How to recognize it

  • Input is a list of [start, end] pairs (meetings, bookings, ranges, segments, jobs).
  • "Merge", "insert", "intersection", "overlap", "conflict", "free time", "minimum rooms", "maximum at the same time".
  • Time-based schedules or calendars.
  • A 1D "coverage" question (cover a segment with the fewest ranges).

Problem 1 · Merge Intervals (LeetCode 56, Medium)

Task. Merge all overlapping intervals. [[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]].

Idea. Sort by start. Keep a result list. For each interval, compare with the last interval in the result:

  • It overlaps (current.start ≤ last.end) → extend: last.end = max(last.end, current.end). (Use max because the current one might be fully inside the last one.)
  • Otherwise → start a new merged interval.

function mergeIntervals(intervals: number[][]): number[][] {
  if (intervals.length === 0) return [];
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]); // by start
  const merged: number[][] = [[...sorted[0]]]; // copy so we do not change the input
  for (let i = 1; i < sorted.length; i++) {
    const [start, end] = sorted[i];
    const last = merged[merged.length - 1];
    if (start <= last[1]) last[1] = Math.max(last[1], end); // overlap: extend
    else merged.push([start, end]); // gap: a new group
  }
  return merged;
}

console.log(mergeIntervals([[1, 4], [4, 5]])); // [ [ 1, 5 ] ]
console.log(mergeIntervals([[1, 4], [0, 4]])); // [ [ 0, 4 ] ]
console.log(mergeIntervals([[1, 10], [2, 3], [4, 5]])); // [ [ 1, 10 ] ]
func mergeIntervals(intervals [][]int) [][]int {
	if len(intervals) == 0 {
		return [][]int{}
	}
	sorted := append([][]int(nil), intervals...)
	sort.Slice(sorted, func(i, j int) bool { return sorted[i][0] < sorted[j][0] }) // by start
	merged := [][]int{{sorted[0][0], sorted[0][1]}}                                    // copy so we do not change the input
	for _, iv := range sorted[1:] {
		last := merged[len(merged)-1]
		if iv[0] <= last[1] {
			last[1] = max(last[1], iv[1]) // overlap: extend
		} else {
			merged = append(merged, []int{iv[0], iv[1]}) // gap: a new group
		}
	}
	return merged
}

func exampleMergeIntervals() {
	fmt.Println(mergeIntervals([][]int{{1, 3}, {2, 6}, {8, 10}, {15, 18}})) // [[1 6] [8 10] [15 18]]
	fmt.Println(mergeIntervals([][]int{{1, 4}, {4, 5}}))                    // [[1 5]]
	fmt.Println(mergeIntervals([][]int{{1, 4}, {0, 4}}))                    // [[0 4]]
	fmt.Println(mergeIntervals([][]int{{1, 10}, {2, 3}, {4, 5}}))           // [[1 10]]
}

Complexity. Time O(n log n) (the sort), space O(n).

Why max? For [1,10] followed by [2,3], 2 ≤ 10 overlaps, but 3 is smaller than 10. Without max, you would shrink the merged interval to [1,3].

Problem 2 · Insert Interval (LeetCode 57, Medium)

Task. You have a list of non-overlapping intervals sorted by start, and a new interval. Insert it, merging as needed. [[1,3],[6,9]] + [2,5] → [[1,5],[6,9]].

Idea: three phases, one pass, no sort. Because the list is already sorted:

  1. Before: copy all intervals that end before the new one starts (end < new.start): they are untouched.
  2. Overlapping: while an interval starts at or before the new one's end (start ≤ new.end), absorb it: new.start = min(...), new.end = max(...). Then add the merged new interval.
  3. After: copy the rest.

Trace. [[1,2],[3,5],[6,7],[8,10],[12,16]] + [4,8]

IntervalPhaseAction
[1,2]1 (2 < 4)copy
[3,5]2 (3 ≤ 8)new → [3,8]
[6,7]2new stays [3,8]
[8,10]2 (8 ≤ 8)new → [3,10]
(add [3,10])
[12,16]3copy

Result [[1,2],[3,10],[12,16]] ✔.

function insertInterval(intervals: number[][], newInterval: number[]): number[][] {
  const result: number[][] = [];
  let i = 0;
  let [start, end] = newInterval;
  while (i < intervals.length && intervals[i][1] < start) result.push(intervals[i++]); // 1. entirely before
  while (i < intervals.length && intervals[i][0] <= end) { // 2. overlapping: absorb into the new one
    start = Math.min(start, intervals[i][0]);
    end = Math.max(end, intervals[i][1]);
    i++;
  }
  result.push([start, end]);
  while (i < intervals.length) result.push(intervals[i++]); // 3. entirely after
  return result;
}

console.log(insertInterval([[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], [4, 8])); // [ [ 1, 2 ], [ 3, 10 ], [ 12, 16 ] ]
console.log(insertInterval([], [5, 7])); // [ [ 5, 7 ] ]
console.log(insertInterval([[1, 5]], [6, 8])); // [ [ 1, 5 ], [ 6, 8 ] ]
func insertInterval(intervals [][]int, newInterval []int) [][]int {
	result := [][]int{}
	i := 0
	start, end := newInterval[0], newInterval[1]
	for i < len(intervals) && intervals[i][1] < start { // 1. entirely before
		result = append(result, intervals[i])
		i++
	}
	for i < len(intervals) && intervals[i][0] <= end { // 2. overlapping: absorb into the new one
		start = min(start, intervals[i][0])
		end = max(end, intervals[i][1])
		i++
	}
	result = append(result, []int{start, end})
	for i < len(intervals) { // 3. entirely after
		result = append(result, intervals[i])
		i++
	}
	return result
}

func exampleInsertInterval() {
	fmt.Println(insertInterval([][]int{{1, 3}, {6, 9}}, []int{2, 5}))                                    // [[1 5] [6 9]]
	fmt.Println(insertInterval([][]int{{1, 2}, {3, 5}, {6, 7}, {8, 10}, {12, 16}}, []int{4, 8}))         // [[1 2] [3 10] [12 16]]
	fmt.Println(insertInterval(nil, []int{5, 7}))                                                       // [[5 7]]
	fmt.Println(insertInterval([][]int{{1, 5}}, []int{6, 8}))                                           // [[1 5] [6 8]]
}

Complexity. Time O(n), space O(n). (A simpler alternative: append the new interval and call mergeIntervals, O(n log n). Mention it, then show the linear version.)

Problem 3 · Interval List Intersections (LeetCode 986, Medium)

Task. Two lists of closed intervals, each sorted and internally non-overlapping. Return the intersections between the two lists. A = [[0,2],[5,10],[13,23],[24,25]], B = [[1,5],[8,12],[15,24],[25,26]] → [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]].

Idea: two pointers (file 05). For the current pair A[i], B[j]:

  • Their intersection (if any) is [max(starts), min(ends)]; it is valid when max(starts) ≤ min(ends).
  • Then advance the pointer whose interval ends first: that interval cannot intersect anything further in the other list (the other list's later intervals start even later).

Trace (first steps)

A[i]B[j]lo, hiRecordAdvance
[0,2][1,5]1, 2[1,2]A (ends at 2 < 5)
[5,10][1,5]5, 5[5,5]B (5 < 10)
[5,10][8,12]8, 10[8,10]A (10 < 12)
[13,23][8,12]13, 12noneB (12 < 23)
function intervalIntersection(A: number[][], B: number[][]): number[][] {
  const result: number[][] = [];
  let i = 0, j = 0;
  while (i < A.length && j < B.length) {
    const lo = Math.max(A[i][0], B[j][0]);
    const hi = Math.min(A[i][1], B[j][1]);
    if (lo <= hi) result.push([lo, hi]); // they share the stretch [lo, hi]
    if (A[i][1] < B[j][1]) i++; // drop the one that ends first
    else j++;
  }
  return result;
}

func intervalIntersection(A, B [][]int) [][]int {
	result := [][]int{}
	i, j := 0, 0
	for i < len(A) && j < len(B) {
		lo := max(A[i][0], B[j][0])
		hi := min(A[i][1], B[j][1])
		if lo <= hi {
			result = append(result, []int{lo, hi}) // they share the stretch [lo, hi]
		}
		if A[i][1] < B[j][1] {
			i++ // drop the one that ends first
		} else {
			j++
		}
	}
	return result
}

	fmt.Println(intervalIntersection(

		[][]int{{1, 5}, {8, 12}, {15, 24}, {25, 26}},
	)) // [[1 2] [5 5] [8 10] [15 23] [24 24] [25 25]]

Problem 4 · Minimum Number of Arrows to Burst Balloons (LeetCode 452, Medium)

Task. Balloons are horizontal segments [xstart, xend]. An arrow shot vertically at x bursts every balloon with xstart ≤ x ≤ xend. Find the minimum number of arrows. [[10,16],[2,8],[1,6],[7,12]] → 2.

Idea (greedy, as in file 23). Sort by end. Shoot the first arrow at the end of the first balloon (this bursts as many as possible that overlap it). Any later balloon whose start is ≤ arrow position is already burst. When a balloon starts after the arrow position, you need a new arrow at its end.

Trace. sorted by end: [1,6], [2,8], [7,12], [10,16]

Balloonstart > arrowAt?arrowsarrowAt
[1,6](first)16
[2,8]2 > 6? no: burst16
[7,12]7 > 6 yes: new arrow212
[10,16]10 > 12? no: burst212
function findMinArrowShots(points: number[][]): number {
  if (points.length === 0) return 0;
  const sorted = [...points].sort((a, b) => a[1] - b[1]); // by END
  let arrows = 1;
  let arrowAt = sorted[0][1];
  for (const [start, end] of sorted) {
    if (start > arrowAt) { // this balloon is out of reach of the current arrow
      arrows++;
      arrowAt = end;
    }
  }
  return arrows;
}

console.log(findMinArrowShots([[1, 2], [3, 4], [5, 6], [7, 8]])); // 4
console.log(findMinArrowShots([[1, 2], [2, 3], [3, 4], [4, 5]])); // 2
console.log(findMinArrowShots([])); // 0
func findMinArrowShots(points [][]int) int {
	if len(points) == 0 {
		return 0
	}
	sorted := append([][]int(nil), points...)
	sort.Slice(sorted, func(i, j int) bool { return sorted[i][1] < sorted[j][1] }) // by END
	arrows := 1
	arrowAt := sorted[0][1]
	for _, p := range sorted {
		if p[0] > arrowAt { // this balloon is out of reach of the current arrow
			arrows++
			arrowAt = p[1]
		}
	}
	return arrows
}

func exampleFindMinArrowShots() {
	fmt.Println(findMinArrowShots([][]int{{10, 16}, {2, 8}, {1, 6}, {7, 12}})) // 2
	fmt.Println(findMinArrowShots([][]int{{1, 2}, {3, 4}, {5, 6}, {7, 8}}))    // 4
	fmt.Println(findMinArrowShots([][]int{{1, 2}, {2, 3}, {3, 4}, {4, 5}}))    // 2
	fmt.Println(findMinArrowShots(nil))                                        // 0
}

Complexity. Time O(n log n), space O(1) extra (or O(n) for the sorted copy).

Careful with integer overflow in comparators. A sort comparator (a, b) => a[1] - b[1] can overflow with huge values (in languages with fixed-width ints); with JavaScript numbers it is safe within 2⁵³, and Go's sort.Slice uses <, which is always safe.

Problem 5 · Meeting Rooms I and II with the sweep line (LeetCode 252 and 253)

Meeting Rooms I. Can one person attend all meetings? (No two overlap.) Sort by start; if any meeting starts before the previous one ends, the answer is false.

Meeting Rooms II. The minimum number of rooms (the maximum number of simultaneous meetings). File 17 used a heap. Here is the sweep line version, which only needs sorting:

  1. Put all start times in one sorted list and all end times in another sorted list.
  2. Walk through the starts with a pointer e into the ends. For each start s:
    • If the earliest unmatched end is ≤ s, that meeting is over: the room is reused (e++).
    • Otherwise a new room is needed.
  3. The number of rooms used at the end is the answer.

(Equivalent view: +1 at each start, −1 at each end; the maximum running sum is the answer.)

function canAttendMeetings(intervals: number[][]): boolean {
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]);
  for (let i = 1; i < sorted.length; i++) {
    if (sorted[i][0] < sorted[i - 1][1]) return false; // starts before the previous one ends
  }
  return true;
}

function minMeetingRoomsSweep(intervals: number[][]): number {
  const starts = intervals.map((iv) => iv[0]).sort((a, b) => a - b);
  const ends = intervals.map((iv) => iv[1]).sort((a, b) => a - b);
  let rooms = 0, e = 0;
  for (const s of starts) {
    if (ends[e] <= s) e++; // a meeting has finished: reuse its room
    else rooms++; // everyone is still busy: open a new room
  }
  return rooms;
}

console.log(canAttendMeetings([[7, 10], [2, 4]])); // true
console.log(minMeetingRoomsSweep([[0, 30], [5, 10], [15, 20]])); // 2
console.log(minMeetingRoomsSweep([[7, 10], [2, 4]])); // 1
console.log(minMeetingRoomsSweep([[1, 5], [2, 6], [3, 7]])); // 3
func canAttendMeetings(intervals [][]int) bool {
	sorted := append([][]int(nil), intervals...)
	sort.Slice(sorted, func(i, j int) bool { return sorted[i][0] < sorted[j][0] })
	for i := 1; i < len(sorted); i++ {
		if sorted[i][0] < sorted[i-1][1] {
			return false // starts before the previous one ends
		}
	}
	return true
}

func minMeetingRoomsSweep(intervals [][]int) int {
	starts := make([]int, len(intervals))
	ends := make([]int, len(intervals))
	for i, iv := range intervals {
		starts[i], ends[i] = iv[0], iv[1]
	}
	sort.Ints(starts)
	sort.Ints(ends)
	rooms, e := 0, 0
	for _, s := range starts {
		if ends[e] <= s {
			e++ // a meeting has finished: reuse its room
		} else {
			rooms++ // everyone is still busy: open a new room
		}
	}
	return rooms
}

func exampleMeetingRooms() {
	fmt.Println(canAttendMeetings([][]int{{0, 30}, {5, 10}, {15, 20}}))      // false
	fmt.Println(canAttendMeetings([][]int{{7, 10}, {2, 4}}))                 // true
	fmt.Println(minMeetingRoomsSweep([][]int{{0, 30}, {5, 10}, {15, 20}}))   // 2
	fmt.Println(minMeetingRoomsSweep([][]int{{7, 10}, {2, 4}}))              // 1
	fmt.Println(minMeetingRoomsSweep([][]int{{1, 5}, {2, 6}, {3, 7}}))       // 3
}

Complexity. Time O(n log n), space O(n).

Why it is correct. At any moment, the number of busy rooms equals (starts so far) − (ends so far). The sweep tracks exactly that by consuming one end for each reuse. (We never need to know which meeting ended, only that one did.)

Problem 6 · The Skyline Problem (LeetCode 218, Hard)

Task. Given buildings [left, right, height], return the skyline: the list of key points [x, height] where the outline's height changes, listed left to right, ending with a point of height 0. For [[2,9,10],[3,7,15],[5,12,12],[15,20,10],[19,24,8]] → [[2,10],[3,15],[7,12],[12,0],[15,10],[20,8],[24,0]].

Why it is hard. At each x, the skyline's height is the maximum height among buildings currently covering x. As x sweeps, buildings enter and leave, and you must always know the current maximum while supporting deletion.

Sweep-line plan.

  1. Turn each building into two events: a start at left and an end at right, each carrying the height.
  2. Sort events by x. For ties at the same x, the order matters:
    • Starts before ends (so a building that begins exactly where another ends doesn't create a fake dip to 0).
    • Among starts: taller first. Among ends: shorter first.
    • Trick: encode a start as (x, −height) and an end as (x, +height) and sort by (x, second) ascending: starts have negative values (and taller = more negative = first); ends are positive (shorter first). This one sort gives exactly the rule above.
  3. Keep a max-heap of active heights (start with a ground height 0).
  4. After processing all events at the same x (or equivalently after each event, comparing against the previous top), if the current maximum differs from the previous maximum, output [x, newMax].

Removing a height from a heap is awkward (heaps only remove the top). Use lazy deletion: when a building ends, record toRemove[height]++. Whenever the top of the heap has a pending removal, pop it and decrement the counter. Only the top needs to be correct.

class MaxHeap {
  private data: number[] = [];
  get size(): number {
    return this.data.length;
  }
  peek(): number {
    return this.data[0];
  }
  push(x: number): void {
    this.data.push(x);
    let i = this.data.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.data[p] >= this.data[i]) break;
      [this.data[p], this.data[i]] = [this.data[i], this.data[p]];
      i = p;
    }
  }
  pop(): number {
    const top = this.data[0];
    const last = this.data.pop()!;
    if (this.data.length > 0) {
      this.data[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let big = i;
        if (l < this.data.length && this.data[l] > this.data[big]) big = l;
        if (r < this.data.length && this.data[r] > this.data[big]) big = r;
        if (big === i) break;
        [this.data[big], this.data[i]] = [this.data[i], this.data[big]];
        i = big;
      }
    }
    return top;
  }
}

function getSkyline(buildings: number[][]): number[][] {
  const events: [number, number][] = []; // [x, signed height]: start = -h, end = +h
  for (const [left, right, height] of buildings) {
    events.push([left, -height]);
    events.push([right, height]);
  }
  events.sort((a, b) => a[0] - b[0] || a[1] - b[1]); // by x; then starts (tall first) before ends (short first)

  const heights = new MaxHeap();
  heights.push(0); // the ground
  const pendingRemoval = new Map<number, number>(); // height -> how many to drop lazily
  const skyline: number[][] = [];
  let previous = 0;
  for (const [x, signedHeight] of events) {
    if (signedHeight < 0) heights.push(-signedHeight); // a building starts
    else pendingRemoval.set(signedHeight, (pendingRemoval.get(signedHeight) ?? 0) + 1); // a building ends
    while (heights.size > 0 && (pendingRemoval.get(heights.peek()) ?? 0) > 0) {
      const top = heights.pop(); // the top height belongs to a building that already ended
      pendingRemoval.set(top, pendingRemoval.get(top)! - 1);
    }
    const current = heights.peek();
    if (current !== previous) {
      skyline.push([x, current]); // the outline changes height here
      previous = current;
    }
  }
  return skyline;
}

// A tiny max-heap of ints, written out by hand.
type MaxHeap struct{ data []int }

func (h *MaxHeap) Len() int  { return len(h.data) }
func (h *MaxHeap) Peek() int { return h.data[0] }

func (h *MaxHeap) Push(x int) {
	h.data = append(h.data, x)
	i := len(h.data) - 1
	for i > 0 {
		p := (i - 1) / 2
		if h.data[p] >= h.data[i] {
			break
		}
		h.data[p], h.data[i] = h.data[i], h.data[p]
		i = p
	}
}

func (h *MaxHeap) Pop() int {
	top := h.data[0]
	last := len(h.data) - 1
	h.data[0] = h.data[last]
	h.data = h.data[:last]
	i := 0
	for {
		l, r := 2*i+1, 2*i+2
		big := i
		if l < len(h.data) && h.data[l] > h.data[big] {
			big = l
		}
		if r < len(h.data) && h.data[r] > h.data[big] {
			big = r
		}
		if big == i {
			break
		}
		h.data[big], h.data[i] = h.data[i], h.data[big]
		i = big
	}
	return top
}

func getSkyline(buildings [][]int) [][]int {
	events := make([][2]int, 0, 2*len(buildings)) // [x, signed height]: start = -h, end = +h
	for _, b := range buildings {
		events = append(events, [2]int{b[0], -b[2]}, [2]int{b[1], b[2]})
	}
	sort.Slice(events, func(i, j int) bool { // by x; then starts (tall first) before ends (short first)
		if events[i][0] != events[j][0] {
			return events[i][0] < events[j][0]
		}
		return events[i][1] < events[j][1]
	})

	heights := &MaxHeap{}
	heights.Push(0) // the ground
	pendingRemoval := make(map[int]int) // height -> how many to drop lazily
	skyline := [][]int{}
	previous := 0
	for _, ev := range events {
		x, signed := ev[0], ev[1]
		if signed < 0 {
			heights.Push(-signed) // a building starts
		} else {
			pendingRemoval[signed]++ // a building ends
		}
		for heights.Len() > 0 && pendingRemoval[heights.Peek()] > 0 {
			top := heights.Pop() // the top height belongs to a building that already ended
			pendingRemoval[top]--
		}
		current := heights.Peek()
		if current != previous {
			skyline = append(skyline, []int{x, current}) // the outline changes height here
			previous = current
		}
	}
	return skyline
}

func exampleGetSkyline() {
	fmt.Println(getSkyline([][]int{{2, 9, 10}, {3, 7, 15}, {5, 12, 12}, {15, 20, 10}, {19, 24, 8}}))
	// [[2 10] [3 15] [7 12] [12 0] [15 10] [20 8] [24 0]]
	fmt.Println(getSkyline([][]int{{0, 2, 3}, {2, 5, 3}}))               // [[0 3] [5 0]]
	fmt.Println(getSkyline([][]int{{1, 2, 1}, {1, 2, 2}, {1, 2, 3}}))    // [[1 3] [2 0]]
}

Complexity. Time O(n log n) (sorting events plus heap operations; each height is pushed once and popped once), space O(n).

Why the tie-breaking rule matters (two examples).

  • [[0,2,3],[2,5,3]]: one building ends at x = 2 and another of the same height starts at x = 2. If the end were processed first, the height would briefly drop to 0 and create a fake key point [2, 0], then [2, 3]. Processing the start first keeps the maximum at 3, so no point is emitted: the skyline is just [[0,3],[5,0]].
  • [[1,2,1],[1,2,2],[1,2,3]]: three buildings start at the same x. If they were processed shortest-first, you would emit [1,1], [1,2], [1,3]: three points at the same x. Processing tallest first emits only [1,3].

The alternative approach to mention: divide and conquer (merge the skylines of the two halves, like merge sort), O(n log n) as well.

Common mistakes

  • Not sorting first (or sorting by the wrong field).
  • Forgetting max when extending an interval that fully contains the next.
  • Wrong overlap test (< vs. ≤ for touching intervals): read the statement, and ask.
  • Mutating the input intervals (copy before extending last[1]).
  • Greedy by start instead of by end in the "maximum non-overlapping" and "arrows" problems.
  • In sweep lines, the order of simultaneous events (starts vs. ends at the same coordinate).
  • Assuming intervals are given sorted when they are not (merge intervals) or assuming they are not sorted when they are (insert interval, intersections: use the linear solution).
  • Overflow in subtraction comparators for very large coordinates.

1 · The overlap test

Write the overlap test and say which of [1,5]/[5,8] and [1,5]/[6,8] overlap if touching counts and if it does not.

Answer

Touching counts: a1 ≤ b2 && a2 ≤ b1. Touching does not count: a1 < b2 && a2 < b1. [1,5] and [5,8] overlap only if touching counts. [1,5] and [6,8] never overlap.

2 · Employee Free Time

Employee Free Time (LeetCode 759): schedules of several employees. Which two tools combine? (Merge all intervals into one sorted list; the gaps between merged intervals are the free time.)

Answer

Two tools: merge K sorted lists (a heap, lesson 17, or just flatten and sort) and merge intervals. After merging all busy time into one sorted list, every gap between consecutive merged intervals is free time for everyone.

3 · Car Pooling

Car Pooling (LeetCode 1094): which of the ideas in file 07 (difference array) or this file (sweep line) does it use? (Both are the same idea.)

Answer

Both views are the same idea. Add +passengers at each pickup and −passengers at each drop-off (a difference array over positions, lesson 07, or sorted events, this lesson), then take a running sum. If it ever exceeds the capacity, return false. Process drop-offs before pickups at the same position.

4 · My Calendar I

My Calendar I (LeetCode 729): a new booking arrives online; reject it if it overlaps. What data structure gives O(log n) per booking? (A sorted structure / balanced BST: file 16.)

Answer

Keep bookings in a sorted structure keyed by start: a balanced BST or ordered map (lesson 16). For a new booking [s, e), look at the booking just before s (floor) and just after (ceiling); reject if either overlaps. O(log n) per booking. In TypeScript or Go, a sorted array with binary search gives O(log n) lookups but O(n) inserts.

5 · Remove Covered Intervals

Remove Covered Intervals (LeetCode 1288): sort by start ascending and end descending. Why descending end for ties?

Answer

Sort by start ascending, and for equal starts by end descending, so the longest of a tie comes first and the shorter ones after it are recognized as covered. Then walk once, tracking the largest end so far: an interval whose end ≤ that maximum is covered. Ascending ends would let [1,2] come before [1,4] and miss that it is covered.

6 · Counting overlaps with events

Count the maximum number of overlapping intervals with +1 at starts and −1 at ends. Write the event list for [[1,4],[2,5],[7,9]].

Answer

Events for [[1,4],[2,5],[7,9]]: (1,+1) (2,+1) (4,−1) (5,−1) (7,+1) (9,−1). Running sum: 1, 2, 1, 0, 1, 0. The maximum, 2, is the most intervals overlapping at once. At equal coordinates, put −1 before +1 if intervals are half-open (touching does not overlap).
