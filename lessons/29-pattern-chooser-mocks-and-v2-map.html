1.3 The master decision flow

1.4 Twelve "confusable pairs" and how to decide

PairDecision rule
Two pointers vs. hash mapSorted (or sortable without needing indexes) → two pointers (O(1) space). Unsorted, need indexes → hash map.
Sliding window vs. prefix sumsPositives and a monotone rule → window. Negatives, or "sum equals K" → prefix sums + map.
BFS vs. DFSFewest steps / layers → BFS. Reachability, components, backtracking, deep exploration → DFS.
BFS vs. DijkstraEqual edge costs → BFS. Different costs → Dijkstra.
Dijkstra vs. Bellman-FordNon-negative → Dijkstra. Negative weights, or "at most K edges" → Bellman-Ford.
Recursion vs. DPSame sub-call repeated with the same arguments → add a cache (DP).
Greedy vs. DPCan you prove the local choice safe (exchange argument)? Yes → greedy. If a tiny counterexample exists → DP.
Backtracking vs. DPMust list every answer → backtracking. Only a count / best / yes-no → DP.
Heap vs. sortingNeed only the top K, or items keep arriving → heap. Need the full order once → sort.
Heap vs. quickselectStreaming or small K → heap. One-shot, single k-th value → quickselect O(n).
Stack vs. queueNewest first (nesting, undo, next greater) → stack. Oldest first (levels, fairness) → queue.
Union-find vs. DFSEdges arrive over time, or "does this edge close a cycle" (undirected) → union-find. Fixed graph, one question → DFS/BFS.

Mock 1 · Find All Anagrams in a String (LeetCode 438, Medium) · target 25 minutes

Interviewer says: "Given two strings s and p, return the starting indexes of all substrings of s that are anagrams of p. For s = "cbaebabacd", p = "abc", return [0, 6]."

Candidate's thinking, step by step

0:01Clarify"Are the strings lowercase letters only? Can p be longer than s? (then the answer is empty.) Do overlapping matches count, such as in abab with ab? I'll assume yes."
0:03Example"For cbaebabacd and abc: the window cba at 0 works; bac at 6 works. Answer [0, 6]."

0:10Design"I keep need[26] = how many of each letter p still requires and missing = how many required letters are still absent from the window. function findAnagrams(s: string, p: string): number[] {
  const m = p.length;
  const result: number[] = [];
  if (m > s.length) return result;
  const need = new Array<number>(26).fill(0);
  for (let i = 0; i < m; i++) need[p.charCodeAt(i) - 97]++;
  let missing = m; // how many required letters are still absent from the window
  for (let r = 0; r < s.length; r++) {
    const add = s.charCodeAt(r) - 97;
    if (need[add] > 0) missing--; // this letter fills a real gap
    need[add]--; // may go negative: a surplus
    if (r >= m) { // the window is now m + 1 long: drop the oldest letter
      const drop = s.charCodeAt(r - m) - 97;
      need[drop]++;
      if (need[drop] > 0) missing++; // we just lost a needed letter
    }
    if (r >= m - 1 && missing === 0) result.push(r - m + 1); // a full window with nothing missing
  }
  return result;
}

console.log(findAnagrams("a", "ab")); // []
console.log(findAnagrams("aaaaa", "aa")); // [ 0, 1, 2, 3 ]
func findAnagrams(s, p string) []int {
	m := len(p)
	result := []int{}
	if m > len(s) {
		return result
	}
	var need [26]int
	for i := 0; i < m; i++ {
		need[p[i]-'a']++
	}
	missing := m // how many required letters are still absent from the window
	for r := 0; r < len(s); r++ {
		add := s[r] - 'a'
		if need[add] > 0 {
			missing-- // this letter fills a real gap
		}
		need[add]-- // may go negative: a surplus
		if r >= m { // the window is now m + 1 long: drop the oldest letter
			drop := s[r-m] - 'a'
			need[drop]++
			if need[drop] > 0 {
				missing++ // we just lost a needed letter
			}
		}
		if r >= m-1 && missing == 0 {
			result = append(result, r-m+1) // a full window with nothing missing
		}
	}
	return result
}

func exampleFindAnagrams() {
	fmt.Println(findAnagrams("cbaebabacd", "abc")) // [0 6]
	fmt.Println(findAnagrams("abab", "ab"))        // [0 1 2]
	fmt.Println(findAnagrams("a", "ab"))           // []
	fmt.Println(findAnagrams("aaaaa", "aa"))       // [0 1 2 3]
}

Complexity. Time O(n + m), space O(1) (26 counters).

Follow-ups the interviewer may ask, with strong answers.

  • "What if the alphabet is Unicode?" Replace the 26-array with a hash map and delete keys at zero (file 06); the logic is identical.
  • "What if s is a stream?" The window state is just counts, so it works online.
  • "Why not compare the two count arrays each step?" That is O(26) per step: still linear, but the missing counter makes each step truly O(1).
  • "How is this different from Minimum Window Substring?" That window has a variable length (shrink while valid); this one is fixed at m.

Mock 2 · Evaluate Division (LeetCode 399, Medium) · target 35 minutes

Interviewer says: "You are given equations like a / b = 2.0 and b / c = 3.0, and queries like a / c = ?. Return the answers, or -1.0 when an answer cannot be determined. Equations: [[a,b],[b,c]], values [2.0, 3.0], queries [[a,c],[b,a],[a,e],[a,a],[x,x]] → [6.0, 0.5, -1.0, 1.0, -1.0]."

Candidate's thinking

Run this mock against the clock. Read the problem above, press Start, and talk out loud through each phase.

TimeStepWhat the candidate says
0:00Restate"Each equation relates two variables by a ratio. A query asks for a ratio that may follow by chaining equations, like a/c = (a/b)·(b/c)."
0:03Clarify"What if a variable never appears in any equation? Return -1. What about a / a? If a appears, it is 1; if it never appeared, -1 (that's why x/x is -1). Is division by zero possible? I'll assume values are positive."
0:06See the graph"Variables are nodes. An equation a / b = 2 is an edge a → b with weight 2, and also an edge b → a with weight 1/2. Then a / c is the product of the weights along any path from a to c."
0:09Choose"I need to know whether a path exists and its product: a graph search from the numerator to the denominator, multiplying as I go. DFS or BFS both work. Or union-find with weights, which is faster for many queries but fiddlier. I'll do DFS first."
0:12Edge cases"If either variable is unknown: -1. If numerator equals denominator and known: 1. Use a visited set so cycles do not loop forever."

Walk through [a, c]: from a, edge to b (×2), from b edge to c (×3): product 6. For [b, a]: edge b → a with weight 0.5. For [a, e]: e is not in the graph, so -1.

function calcEquation(equations: string[][], values: number[], queries: string[][]): number[] {
  // adjacency: variable -> (neighbor -> ratio  variable / neighbor)
  const graph = new Map<string, Map<string, number>>();
  const link = (a: string, b: string, ratio: number): void => {
    if (!graph.has(a)) graph.set(a, new Map());
    graph.get(a)!.set(b, ratio);
  };
  equations.forEach(([a, b], i) => {
    link(a, b, values[i]); // a / b = value
    link(b, a, 1 / values[i]); // b / a = 1 / value
  });

  function evaluate(src: string, dst: string): number {
    if (!graph.has(src) || !graph.has(dst)) return -1; // an unknown variable
    if (src === dst) return 1;
    const visited = new Set<string>([src]);
    const stack: [string, number][] = [[src, 1]]; // [node, product of ratios from src to node]
    while (stack.length > 0) {
      const [node, product] = stack.pop()!;
      for (const [next, ratio] of graph.get(node)!) {
        if (next === dst) return product * ratio; // found a path: multiply the last step
        if (!visited.has(next)) {
          visited.add(next);
          stack.push([next, product * ratio]);
        }
      }
    }
    return -1; // no path: not determinable
  }
  return queries.map(([a, b]) => evaluate(a, b));
}

func calcEquation(equations [][]string, values []float64, queries [][]string) []float64 {
	// adjacency: variable -> (neighbor -> ratio  variable / neighbor)
	graph := make(map[string]map[string]float64)
	link := func(a, b string, ratio float64) {
		if graph[a] == nil {
			graph[a] = make(map[string]float64)
		}
		graph[a][b] = ratio
	}
	for i, eq := range equations {
		link(eq[0], eq[1], values[i])   // a / b = value
		link(eq[1], eq[0], 1/values[i]) // b / a = 1 / value
	}

	evaluate := func(src, dst string) float64 {
		if graph[src] == nil || graph[dst] == nil {
			return -1 // an unknown variable
		}
		if src == dst {
			return 1
		}
		type entry struct {
			node    string
			product float64 // product of ratios from src to node
		}
		visited := map[string]bool{src: true}
		stack := []entry{{src, 1}}
		for len(stack) > 0 {
			cur := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			for next, ratio := range graph[cur.node] {
				if next == dst {
					return cur.product * ratio // found a path: multiply the last step
				}
				if !visited[next] {
					visited[next] = true
					stack = append(stack, entry{next, cur.product * ratio})
				}
			}
		}
		return -1 // no path: not determinable
	}

	answers := make([]float64, len(queries))
	for i, q := range queries {
		answers[i] = evaluate(q[0], q[1])
	}
	return answers
}

func exampleCalcEquation() {
	eq := [][]string{{"a", "b"}, {"b", "c"}}
	vals := []float64{2.0, 3.0}
	fmt.Println(calcEquation(eq, vals, [][]string{{"a", "c"}, {"b", "a"}, {"a", "e"}, {"a", "a"}, {"x", "x"}})) // [6 0.5 -1 1 -1]
	fmt.Println(calcEquation([][]string{{"a", "b"}, {"c", "d"}}, []float64{1.5, 2.5}, [][]string{{"a", "c"}, {"c", "d"}})) // [-1 2.5]
}

Complexity. Building: O(E). Each query: O(V + E) in the worst case. Total O(E + Q · (V + E)).

Follow-ups, with strong answers.

  • "Many queries?" Use weighted union-find: each node stores weightToParent (its ratio to its root). find with path compression multiplies the ratios along the way. Queries become O(α(n)) after one O(E α) build. Or run Floyd-Warshall over the variables if there are few of them (O(V³)).
  • "What if there are contradictory equations?" The problem guarantees none; otherwise you could detect a cycle whose product is not 1.
  • "Floating-point error?" Multiplication chains accumulate rounding error; mention it, and note that LeetCode accepts a small tolerance.

Mock 3 · Longest Valid Parentheses (LeetCode 32, Hard) · target 40 minutes

Interviewer says: "Given a string of only ( and ), return the length of the longest valid (well-formed) parentheses substring. "(()" → 2. ")()())" → 4. "" → 0."

Candidate's thinking

TimeStepWhat the candidate says
0:00Restate"Find the longest contiguous stretch where every ( is matched by a later ) in proper nesting."
0:03Brute force"Check every substring with the counter-based validity test: O(n²) (or O(n³) if I rescan)."
0:07Pattern hints"Matching brackets point to a stack (file 13). The question is what to push so I can measure lengths."
0:10Key idea"Push indexes, not characters. Keep at the bottom the index of the last position that could not be matched (start with -1). For (, push its index. The follow-up: O(1) space. Scan twice with two counters.

  • Left to right: count open and close. When they are equal, the substring is valid: best = max(best, 2 · close). If close > open, reset both to 0 (too many closers can never be repaired by what follows).
  • Right to left: do the mirror image (reset when open > close). The second pass catches cases like "(()" where there are surplus openers on the left.
function longestValidParentheses(s: string): number {
  const stack: number[] = [-1]; // the index just before the current valid stretch
  let best = 0;
  for (let i = 0; i < s.length; i++) {
    if (s[i] === "(") {
      stack.push(i);
    } else {
      stack.pop();
      if (stack.length === 0) stack.push(i); // an unmatched ')' becomes the new base
      else best = Math.max(best, i - stack[stack.length - 1]); // length of the valid stretch ending here
    }
  }
  return best;
}

function longestValidParenthesesTwoPass(s: string): number {
  let best = 0;
  let open = 0, close = 0;
  for (let i = 0; i < s.length; i++) { // left to right
    if (s[i] === "(") open++;
    else close++;
    if (open === close) best = Math.max(best, 2 * close);
    else if (close > open) open = close = 0; // too many ')': start over
  }
  open = close = 0;
  for (let i = s.length - 1; i >= 0; i--) { // right to left
    if (s[i] === "(") open++;
    else close++;
    if (open === close) best = Math.max(best, 2 * open);
    else if (open > close) open = close = 0; // too many '(': start over
  }
  return best;
}

func longestValidParentheses(s string) int {
	stack := []int{-1} // the index just before the current valid stretch
	best := 0
	for i := 0; i < len(s); i++ {
		if s[i] == '(' {
			stack = append(stack, i)
		} else {
			stack = stack[:len(stack)-1]
			if len(stack) == 0 {
				stack = append(stack, i) // an unmatched ')' becomes the new base
			} else {
				best = max(best, i-stack[len(stack)-1]) // length of the valid stretch ending here
			}
		}
	}
	return best
}

func longestValidParenthesesTwoPass(s string) int {
	best := 0
	open, close := 0, 0
	for i := 0; i < len(s); i++ { // left to right
		if s[i] == '(' {
			open++
		} else {
			close++
		}
		if open == close {
			best = max(best, 2*close)
		} else if close > open {
			open, close = 0, 0 // too many ')': start over
		}
	}
	open, close = 0, 0
	for i := len(s) - 1; i >= 0; i-- { // right to left
		if s[i] == '(' {
			open++
		} else {
			close++
		}
		if open == close {
			best = max(best, 2*open)
		} else if open > close {
			open, close = 0, 0 // too many '(': start over
		}
	}
	return best
}

func exampleLongestValidParentheses() {
	for _, input := range []string{"(()", ")()())", "", "()(())", "()(()"} {
		fmt.Printf("%q %d %d\n", input, longestValidParentheses(input), longestValidParenthesesTwoPass(input))
	}
	// "(()" 2 2 | ")()())" 4 4 | "" 0 0 | "()(())" 6 6 | "()(()" 2 2
}

Complexity. Stack version: time O(n), space O(n). Two-pass version: time O(n), space O(1).

Follow-ups, with strong answers.

  • "Can you do it with DP?" Yes: dp[i] = length of the longest valid substring ending at i. If s[i] == ')' and s[i−1] == '(', dp[i] = dp[i−2] + 2; if s[i−1] == ')' and the character before the block that ends at i−1 is (, then dp[i] = dp[i−1] + 2 + dp[i − dp[i−1] − 2]. O(n) time and space.
  • "Why does the two-pass version need the reverse pass?" For "(()" the left-to-right scan ends with open = 2, close = 1 and never sees them equal. The right-to-left pass finds close = 1, open = 1 at the right place and reports 2.
  • "What if other bracket types appear?" The counters no longer work; use the stack with indexes (and a type check on pop).
