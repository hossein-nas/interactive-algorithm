1. The idea in plain English

An emergency room does not treat patients in the order they arrive. It always treats the most urgent one next. A priority queue is that waiting room: you can add anyone at any time, and you can always take the most urgent person quickly.

A heap is the standard way to build a priority queue. It does not keep everything sorted (that would be wasteful). It keeps just enough order that the smallest (min-heap) or largest (max-heap) item is always on top.

OperationCost
Look at the top (peek)O(1)
Add an item (push)O(log n)
Remove the top (pop)O(log n)
Build a heap from n itemsO(n)
Search for an arbitrary itemO(n) (heaps are bad at this)

Compare with sorting. Sorting everything costs O(n log n) and gives you all the order. A heap costs O(log n) per item and gives you only the next one. If you only need the top few, or items keep arriving, a heap is far cheaper.

2. How a heap works inside

A tree stored in an array

A heap is a complete binary tree (every level full except possibly the last, which fills from the left). Because of that shape, it needs no pointers: store it in an array and compute parent/child positions with arithmetic.

The array is [1, 3, 2, 7, 4, 9]. For the item at index i:

  • parent = (i − 1) / 2 (integer division)
  • left child = 2i + 1
  • right child = 2i + 2

The heap rule (min-heap): every parent is ≤ both its children. That is all. Notice that siblings (3 and 2) are in no particular order. Only the parent-versus-child relationship matters, which is why a heap is cheaper to maintain than a fully sorted structure.

Push: add at the end, then "sift up"

Put the new item in the first free slot (the end of the array). It might be smaller than its parent, which breaks the rule, so swap it upward until it is no longer smaller than its parent. The path from the bottom to the top has at most log n steps.

Pop: take the root, move the last item up, then "sift down"

The top is the answer. To fill the hole, take the last item of the array and put it at the root (so the shape stays complete). It is probably too big, so swap it downward with its smaller child until both children are bigger. Again at most log n steps.

Building a heap in O(n) (a favorite trick question)

Pushing n items one by one costs O(n log n). But if you already have all the items in an array, you can heapify in O(n): start from the last parent and sift down each node, going backward to the root.

Why only O(n)? Most nodes are near the bottom, where sifting down is cheap. About half the nodes are leaves (0 steps), a quarter can move 1 level, an eighth can move 2 levels, and so on. The total work is

n/4·1 + n/8·2 + n/16·3 + … ≤ n.

That is the "halving with work" pattern from file 02: the sum converges to a constant times n.

Heap sort

Heapify, then pop the top n times: O(n log n), in place, not stable.

3. Implementation you can type in an interview

Neither language has a ready-to-use heap in the form you want (TypeScript has none; Go has container/heap, which needs five boilerplate methods). Below is a small generic heap with a less function in each language. Every problem on this page uses it.

To get a max-heap: flip the comparison (a > b). To heap pairs or objects: compare the field you care about.

class Heap<T> {
  private data: T[] = [];
  constructor(private less: (a: T, b: T) => boolean) {}

  get size(): number {
    return this.data.length;
  }
  peek(): T | undefined {
    return this.data[0];
  }

  push(item: T): void {
    this.data.push(item);
    let i = this.data.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (!this.less(this.data[i], this.data[parent])) break;
      [this.data[i], this.data[parent]] = [this.data[parent], this.data[i]];
      i = parent;
    }
  }

  pop(): T | undefined {
    if (this.data.length === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop()!;
    if (this.data.length > 0) {
      this.data[0] = last;
      this.siftDown(0);
    }
    return top;
  }

  private siftDown(i: number): void {
    const n = this.data.length;
    for (;;) {
      const l = 2 * i + 1, r = 2 * i + 2;
      let best = i;
      if (l < n && this.less(this.data[l], this.data[best])) best = l;
      if (r < n && this.less(this.data[r], this.data[best])) best = r;
      if (best === i) return;
      [this.data[i], this.data[best]] = [this.data[best], this.data[i]];
      i = best;
    }
  }

  // Build in O(n): sift down every parent, from the last one back to the root.
  static from<T>(items: T[], less: (a: T, b: T) => boolean): Heap<T> {
    const heap = new Heap<T>(less);
    heap.data = [...items];
    for (let i = (heap.data.length >> 1) - 1; i >= 0; i--) heap.siftDown(i);
    return heap;
  }
}

while (numHeap.size > 0) sortedOut.push(numHeap.pop()!);

type Heap[T any] struct {
	data []T
	less func(a, b T) bool
}

func NewHeap[T any](less func(a, b T) bool) *Heap[T] { return &Heap[T]{less: less} }

func (h *Heap[T]) Len() int { return len(h.data) }
func (h *Heap[T]) Peek() T  { return h.data[0] }

func (h *Heap[T]) Push(item T) {
	h.data = append(h.data, item)
	i := len(h.data) - 1
	for i > 0 {
		parent := (i - 1) / 2
		if !h.less(h.data[i], h.data[parent]) {
			break
		}
		h.data[i], h.data[parent] = h.data[parent], h.data[i]
		i = parent
	}
}

func (h *Heap[T]) Pop() T {
	top := h.data[0]
	last := len(h.data) - 1
	h.data[0] = h.data[last]
	h.data = h.data[:last]
	if len(h.data) > 0 {
		h.siftDown(0)
	}
	return top
}

func (h *Heap[T]) siftDown(i int) {
	n := len(h.data)
	for {
		l, r := 2*i+1, 2*i+2
		best := i
		if l < n && h.less(h.data[l], h.data[best]) {
			best = l
		}
		if r < n && h.less(h.data[r], h.data[best]) {
			best = r
		}
		if best == i {
			return
		}
		h.data[i], h.data[best] = h.data[best], h.data[i]
		i = best
	}
}

// HeapFrom builds a heap in O(n): sift down every parent, from the last one back to the root.
func HeapFrom[T any](items []T, less func(a, b T) bool) *Heap[T] {
	h := &Heap[T]{data: append([]T(nil), items...), less: less}
	for i := len(h.data)/2 - 1; i >= 0; i-- {
		h.siftDown(i)
	}
	return h
}

func exampleHeapSort() {
	h := HeapFrom([]int{5, 1, 4, 2, 9, 3}, func(a, b int) bool { return a < b })
	sorted := []int{}
	for h.Len() > 0 {
		sorted = append(sorted, h.Pop())
	}
	fmt.Println(sorted) // [1 2 3 4 5 9]   (that is heap sort)
}

Go note. The standard library's container/heap works too (file 03 shows the five-method version); a hand-written generic heap is shorter to read in an interview and avoids the any type assertions.

4. How to recognize a heap problem

The "size K" trick: which heap, min or max?

To keep the K largest items, use a min-heap of size K. Its top is the smallest of the K winners, the one that would be knocked out first. A new item beats it only if it is bigger, so compare with the top, and if bigger, replace. (To keep the K smallest, use a max-heap.) Most people get this backwards on the first try.

Problem 1 · Kth Largest Element in an Array (LeetCode 215, Medium; v2 list)

Task. Return the k-th largest value (counting duplicates). [3, 2, 1, 5, 6, 4], k = 2 → 5.

Options (say all three): sort O(n log n); quickselect O(n) average (file 09); min-heap of size k O(n log k), which also works on a stream and uses only O(k) memory.

function findKthLargest(nums: number[], k: number): number {
  const heap = new Heap<number>((a, b) => a < b); // min-heap
  for (const x of nums) {
    heap.push(x);
    if (heap.size > k) heap.pop(); // drop the smallest: it cannot be among the k largest
  }
  return heap.peek()!;
}

console.log(findKthLargest([3, 2, 3, 1, 2, 4, 5, 5, 6], 4)); // 4
console.log(findKthLargest([1], 1)); // 1
func findKthLargest(nums []int, k int) int {
	h := NewHeap(func(a, b int) bool { return a < b }) // min-heap
	for _, x := range nums {
		h.Push(x)
		if h.Len() > k {
			h.Pop() // drop the smallest: it cannot be among the k largest
		}
	}
	return h.Peek()
}

func exampleFindKthLargest() {
	fmt.Println(findKthLargest([]int{3, 2, 1, 5, 6, 4}, 2))             // 5
	fmt.Println(findKthLargest([]int{3, 2, 3, 1, 2, 4, 5, 5, 6}, 4)) // 4
	fmt.Println(findKthLargest([]int{1}, 1))                           // 1
}

Complexity. Time O(n log k), space O(k).

Problem 2 · Top K Frequent Elements (LeetCode 347, Medium; v2 list)

Task. Return the k most frequent values. [1,1,1,2,2,3], k = 2 → [1, 2].

Idea. (1) Count frequencies with a map (file 04). (2) Keep a min-heap of size k ordered by frequency; when it grows past k, pop the least frequent. What remains are the k most frequent.

Faster alternative to mention: bucket sort by frequency. A value can appear at most n times, so make n + 1 buckets (index = frequency), drop values in, and read from the highest bucket down: O(n) total.

function topKFrequent(nums: number[], k: number): number[] {
  const freq = new Map<number, number>();
  for (const x of nums) freq.set(x, (freq.get(x) ?? 0) + 1);
  const heap = new Heap<[number, number]>((a, b) => a[1] < b[1]); // [value, count], least frequent on top
  for (const entry of freq) {
    heap.push(entry);
    if (heap.size > k) heap.pop();
  }
  const result: number[] = [];
  while (heap.size > 0) result.push(heap.pop()![0]);
  return result.reverse(); // most frequent first
}
console.log(topKFrequent([1, 1, 1, 2, 2, 3], 2)); // [ 1, 2 ]
console.log(topKFrequent([1], 1)); // [ 1 ]
console.log(topKFrequent([4, 4, 4, 4, 5, 5, 5, 6, 6, 7], 3)); // [ 4, 5, 6 ]
func topKFrequent(nums []int, k int) []int {
	freq := make(map[int]int)
	for _, x := range nums {
		freq[x]++
	}
	type entry struct{ value, count int }
	h := NewHeap(func(a, b entry) bool { return a.count < b.count }) // least frequent on top
	for value, count := range freq {
		h.Push(entry{value, count})
		if h.Len() > k {
			h.Pop()
		}
	}
	result := make([]int, h.Len())
	for i := len(result) - 1; i >= 0; i-- { // fill from the back: most frequent first
		result[i] = h.Pop().value
	}
	return result
}

func exampleTopKFrequent() {
	fmt.Println(topKFrequent([]int{1, 1, 1, 2, 2, 3}, 2))                // [1 2]
	fmt.Println(topKFrequent([]int{1}, 1))                               // [1]
	fmt.Println(topKFrequent([]int{4, 4, 4, 4, 5, 5, 5, 6, 6, 7}, 3)) // [4 5 6]
}

Complexity. Time O(n log k), space O(n) for the map. (Ties between equal frequencies can be returned in any order; the problem guarantees a unique answer.)

Problem 3 · Merge K Sorted Arrays (like LeetCode 23, Hard; v2 "merge K sorted")

Task. Merge k sorted arrays into one sorted array. [[1,4,5],[1,3,4],[2,6]] → [1,1,2,3,4,4,5,6]. (LeetCode 23 uses linked lists; the algorithm is identical, with node pointers instead of indexes.)

Naive ideas. Concatenate and sort: O(N log N). Merge pairwise: O(N·k).

Heap idea. The overall smallest remaining value must be the front of one of the k arrays. So keep a min-heap of at most k items: the current front of each array. Pop the smallest, add it to the output, and push the next item from the same array.

function mergeKSorted(arrays: number[][]): number[] {
  // each heap item: [value, which array, index inside that array]
  const heap = new Heap<[number, number, number]>((a, b) => a[0] < b[0]);
  arrays.forEach((arr, i) => {
    if (arr.length > 0) heap.push([arr[0], i, 0]); // the front of every array
  });
  const merged: number[] = [];
  while (heap.size > 0) {
    const [value, which, idx] = heap.pop()!;
    merged.push(value);
    if (idx + 1 < arrays[which].length) heap.push([arrays[which][idx + 1], which, idx + 1]);
  }
  return merged;
}
console.log(mergeKSorted([[1, 4, 5], [1, 3, 4], [2, 6]])); // [ 1, 1, 2, 3, 4, 4, 5, 6 ]
console.log(mergeKSorted([])); // []
console.log(mergeKSorted([[], [1]])); // [ 1 ]
func mergeKSorted(arrays [][]int) []int {
	type item struct{ value, which, idx int }
	h := NewHeap(func(a, b item) bool { return a.value < b.value })
	for i, arr := range arrays {
		if len(arr) > 0 {
			h.Push(item{arr[0], i, 0}) // the front of every array
		}
	}
	merged := []int{}
	for h.Len() > 0 {
		cur := h.Pop()
		merged = append(merged, cur.value)
		if cur.idx+1 < len(arrays[cur.which]) {
			h.Push(item{arrays[cur.which][cur.idx+1], cur.which, cur.idx + 1})
		}
	}
	return merged
}

func exampleMergeKSorted() {
	fmt.Println(mergeKSorted([][]int{{1, 4, 5}, {1, 3, 4}, {2, 6}})) // [1 1 2 3 4 4 5 6]
	fmt.Println(mergeKSorted(nil))                                   // []
	fmt.Println(mergeKSorted([][]int{{}, {1}}))                      // [1]
}

Complexity. Time O(N log k) where N is the total number of items; space O(k) for the heap (plus the output).

Problem 4 · Kth Smallest Element in a Sorted Matrix (LeetCode 378, Medium; v2 list)

Task. An n × n matrix has every row and every column sorted ascending. Find the k-th smallest value. [[1,5,9],[10,11,13],[12,13,15]], k = 8 → 13.

Idea. This is "merge n sorted lists" in disguise: each row is a sorted list. Put the first item of each row into a min-heap, then pop k times; after popping (r, c), push its right neighbor (r, c+1). The k-th pop is the answer.

Alternative worth naming: binary search on the value (file 08): for a candidate x, count how many matrix values are ≤ x by walking from a corner in O(n); find the smallest x whose count is ≥ k. That costs O(n log(max − min)) and O(1) memory.

function kthSmallestInMatrix(matrix: number[][], k: number): number {
  const n = matrix.length;
  const heap = new Heap<[number, number, number]>((a, b) => a[0] < b[0]); // [value, row, col]
  for (let r = 0; r < Math.min(n, k); r++) heap.push([matrix[r][0], r, 0]); // first of each row
  let value = -1;
  for (let i = 0; i < k; i++) {
    const [v, r, c] = heap.pop()!;
    value = v;
    if (c + 1 < n) heap.push([matrix[r][c + 1], r, c + 1]); // the next in the same row
  }
  return value;
}
console.log(kthSmallestInMatrix([[1, 5, 9], [10, 11, 13], [12, 13, 15]], 8)); // 13
console.log(kthSmallestInMatrix([[-5]], 1)); // -5
console.log(kthSmallestInMatrix([[1, 2], [1, 3]], 2)); // 1
func kthSmallestInMatrix(matrix [][]int, k int) int {
	n := len(matrix)
	type cell struct{ value, row, col int }
	h := NewHeap(func(a, b cell) bool { return a.value < b.value })
	for r := 0; r < min(n, k); r++ {
		h.Push(cell{matrix[r][0], r, 0}) // first of each row
	}
	value := -1
	for i := 0; i < k; i++ {
		cur := h.Pop()
		value = cur.value
		if cur.col+1 < n {
			h.Push(cell{matrix[cur.row][cur.col+1], cur.row, cur.col + 1}) // the next in the same row
		}
	}
	return value
}

func exampleKthSmallestInMatrix() {
	fmt.Println(kthSmallestInMatrix([][]int{{1, 5, 9}, {10, 11, 13}, {12, 13, 15}}, 8)) // 13
	fmt.Println(kthSmallestInMatrix([][]int{{-5}}, 1))                                  // -5
	fmt.Println(kthSmallestInMatrix([][]int{{1, 2}, {1, 3}}, 2))                        // 1
}

Complexity. Time O(min(n, k) + k log min(n, k)), space O(min(n, k)).

Problem 5 · Meeting Rooms II (LeetCode 253, Medium; v2 "minimum rooms")

Task. Given meeting time intervals [start, end], find the minimum number of rooms so no two overlapping meetings share a room. [[0,30],[5,10],[15,20]] → 2.

Thinking. Process meetings in order of start time. Keep a min-heap of the end times of the meetings currently using a room. For a new meeting starting at s:

  • If the earliest-ending meeting (heap top) has already ended (top ≤ s), its room is free: reuse it (pop that end time).
  • Push the new meeting's end time.
  • The heap's size is the number of rooms in use; the answer is the largest size ever reached.

Answer 2.

Related idea without a heap (file 24): split starts and ends into two sorted lists and sweep, counting +1 at a start and −1 at an end. It is also O(n log n) but only sorts.

function minMeetingRooms(intervals: number[][]): number {
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]); // by start time
  const endTimes = new Heap<number>((a, b) => a < b); // end times of meetings in progress
  let rooms = 0;
  for (const [start, end] of sorted) {
    if (endTimes.size > 0 && endTimes.peek()! <= start) endTimes.pop(); // reuse a freed room
    endTimes.push(end);
    rooms = Math.max(rooms, endTimes.size);
  }
  return rooms;
}
console.log(minMeetingRooms([[0, 30], [5, 10], [15, 20]])); // 2
console.log(minMeetingRooms([[7, 10], [2, 4]])); // 1
console.log(minMeetingRooms([[1, 5], [2, 6], [3, 7]])); // 3
console.log(minMeetingRooms([])); // 0
func minMeetingRooms(intervals [][]int) int {
	sorted := append([][]int(nil), intervals...)
	sort.Slice(sorted, func(i, j int) bool { return sorted[i][0] < sorted[j][0] }) // by start time
	endTimes := NewHeap(func(a, b int) bool { return a < b }) // end times of meetings in progress
	rooms := 0
	for _, m := range sorted {
		start, end := m[0], m[1]
		if endTimes.Len() > 0 && endTimes.Peek() <= start {
			endTimes.Pop() // reuse a freed room
		}
		endTimes.Push(end)
		rooms = max(rooms, endTimes.Len())
	}
	return rooms
}

func exampleMinMeetingRooms() {
	fmt.Println(minMeetingRooms([][]int{{0, 30}, {5, 10}, {15, 20}})) // 2
	fmt.Println(minMeetingRooms([][]int{{7, 10}, {2, 4}}))            // 1
	fmt.Println(minMeetingRooms([][]int{{1, 5}, {2, 6}, {3, 7}}))     // 3
	fmt.Println(minMeetingRooms(nil))                                 // 0
}

Complexity. Time O(n log n), space O(n).

Edge case to say aloud: a meeting ending at 10 and another starting at 10 do not conflict (end ≤ start frees the room). Ask the interviewer.

Problem 6 · Find Median from a Data Stream (LeetCode 295, Hard)

Task. Numbers arrive one at a time. After each, you must be able to report the median fast. addNum(1), addNum(2) → median 1.5; addNum(3) → median 2.

Why it is hard. The median is the middle of the sorted data, and the data keeps changing. A sorted array costs O(n) per insert. We need O(log n) insert and O(1) median.

The big idea: split the data into a lower half and an upper half. The median lives at the boundary between the halves, so we only need quick access to the largest of the lower half and the smallest of the upper half. That is:

  • a max-heap low holding the lower half (its top is the biggest of the small numbers),
  • a min-heap high holding the upper half (its top is the smallest of the big numbers).

Invariants to maintain:

  1. Every number in low is ≤ every number in high.
  2. Sizes: low.size equals high.size, or low has exactly one more.

Then: if sizes are equal, the median is the average of the two tops; otherwise the median is the top of low.

Adding a number (the safe three-step dance):

  1. Push the number into low.
  2. Move low's top into high (this guarantees every low item ≤ every high item).
  3. If high now has more items than low, move high's top back into low (restore the size rule).

class MedianFinder {
  private low = new Heap<number>((a, b) => a > b); // max-heap: the smaller half
  private high = new Heap<number>((a, b) => a < b); // min-heap: the larger half

  addNum(num: number): void {
    this.low.push(num); // 1. into the lower half
    this.high.push(this.low.pop()!); // 2. its biggest goes to the upper half
    if (this.high.size > this.low.size) this.low.push(this.high.pop()!); // 3. keep low >= high in size
  }

  findMedian(): number {
    if (this.low.size > this.high.size) return this.low.peek()!;
    return (this.low.peek()! + this.high.peek()!) / 2;
  }
}

type MedianFinder struct {
	low  *Heap[int] // max-heap: the smaller half
	high *Heap[int] // min-heap: the larger half
}

func NewMedianFinder() *MedianFinder {
	return &MedianFinder{
		low:  NewHeap(func(a, b int) bool { return a > b }),
		high: NewHeap(func(a, b int) bool { return a < b }),
	}
}

func (m *MedianFinder) AddNum(num int) {
	m.low.Push(num)              // 1. into the lower half
	m.high.Push(m.low.Pop())     // 2. its biggest goes to the upper half
	if m.high.Len() > m.low.Len() {
		m.low.Push(m.high.Pop()) // 3. keep low >= high in size
	}
}

func (m *MedianFinder) FindMedian() float64 {
	if m.low.Len() > m.high.Len() {
		return float64(m.low.Peek())
	}
	return float64(m.low.Peek()+m.high.Peek()) / 2
}

func exampleMedianFinder() {
	mf := NewMedianFinder()
	mf.AddNum(1)
	mf.AddNum(2)
	fmt.Println(mf.FindMedian()) // 1.5
	mf.AddNum(3)
	fmt.Println(mf.FindMedian()) // 2
	mf.AddNum(-5)
	fmt.Println(mf.FindMedian()) // 1.5
}

Common mistakes

  • Using the wrong kind of heap for "top K". K largest → min-heap of size K.
  • Forgetting JavaScript has no built-in heap; the default Array.sort is not a priority queue.
  • Sorting after every insert (turns O(n log n) into O(n² log n)).
  • Comparator returns a number in TypeScript but less expects a boolean (copying sort comparators into a heap).
  • In Go, calling the wrong push/pop if you use container/heap (use heap.Push(h, x), not h.Push(x)).
  • Breaking ties wrongly (for example Dijkstra or meeting rooms: ≤ vs < on end/start times).
  • Assuming a heap iterates in sorted order. It does not; only the top is ordered.
  • Counting heapify as O(n log n). It is O(n).

Try it without looking

Try each one on paper or in an editor first. Open the hint only when you are stuck, and the answer only after you have an attempt.

1 · Draw it, then insert 1

Draw [2, 5, 3, 9, 6, 4] as a tree. Is it a valid min-heap? Insert 1 and show the sift-up swaps.

Answer

Index 0 is 2 with children 5 and 3; 5 has children 9 and 6; 3 has child 4. Every parent ≤ its children, so it is a valid min-heap. Insert 1 at index 6 (under 3). 1 < 3: swap, 1 is at index 2. 1 < 2: swap, 1 is the root. Result: [1, 5, 2, 9, 6, 4, 3]. Run the second preset of the push-and-pop animation to watch the two swaps.

2 · K largest, min-heap

Why does "K largest" use a min-heap?

Answer

Keep the k largest seen so far. When a new value arrives, the one to evict is the smallest of those k, so it must be on top: a min-heap. Its top is also the answer (the kth largest). Cost O(n log k) and O(k) memory.

3 · Why heapify is O(n)

Explain O(n) heapify using "half the nodes are leaves".

Answer

Sift-down costs the height below a node, not above it. Half the nodes are leaves (cost 0), a quarter sit one level up (cost ≤ 1), an eighth cost ≤ 2, and so on: n/4·1 + n/8·2 + n/16·3 + … ≤ n. Pushing items one by one would instead pay up to log n for most of them: O(n log n).

4 · Last Stone Weight

Last Stone Weight (LeetCode 1046): which heap, and what do you push back each round?

Answer

A max-heap of the stones. Each round pop the two heaviest, x ≥ y. If x > y, push back x − y; if equal, push nothing. When at most one stone is left, return it (or 0). O(n log n).

5 · K Closest Points

K Closest Points to the Origin (LeetCode 973): what do you store in the heap, and is it a min- or max-heap?

Answer

Store [squaredDistance, point] (no square root needed) in a max-heap of size k. Push each point; when the size passes k, pop the farthest. What remains are the k closest: O(n log k). It is the K-largest pattern turned around: keep the k smallest, so evict the biggest.

6 · Reorganize String and Task Scheduler

Reorganize String (LeetCode 767) and Task Scheduler (LeetCode 621): both use a max-heap by frequency. Describe the greedy rule.

Answer

Both are greedy with a max-heap of counts. Reorganize String: always place the most frequent letter that is not the one you just placed (pop the top two, use one each, push them back with count − 1). If one letter has more than ⌈n/2⌉, it is impossible. Task Scheduler: in each window of n + 1 slots run the most frequent distinct tasks, idle for the rest, then push back the leftovers. Shortcut: the answer is max(tasks, (maxCount − 1)·(n + 1) + numberOfTasksWithMaxCount).
