1. The idea in plain English

A stack is a pile where you can only touch the top:

  • push: put something on top.
  • pop: take the top thing off.
  • peek: look at the top without removing it.

Think of a stack of plates in a cafeteria, or the "undo" history in a text editor: the last thing added is the first thing removed (LIFO: last in, first out).

Both push and pop are O(1) when you use the end of a dynamic array (TypeScript push/pop, Go append and re-slice).

Why stacks solve problems

Whenever you have unfinished business that must be resolved in reverse order of arrival, a stack is the natural tool:

  • A bracket you opened must be the first one you close (innermost first).
  • A function you called must finish before the function that called it (the call stack itself).
  • "Undo" must reverse the latest change first.
  • An item waiting for something better to appear later (the next warmer day) stays on the stack until that thing arrives.

2. How to recognize it

  • Matching or nested pairs: brackets, tags, quotes.
  • "Next greater / smaller element", "how many days until a warmer day", "span", "histogram".
  • Evaluating expressions (postfix, parsing) or decoding nested structures.
  • "Undo" or "go back" operations; backtracking done by hand.
  • Converting a recursive function into a loop.

3. The monotonic stack (the powerful variation)

A monotonic stack keeps its items in sorted order (always decreasing, or always increasing, from bottom to top). Before pushing a new item, you pop every item that would break the order. The pops are where the answers happen.

Everyday picture. A line of people waiting to see over a fence, and you only keep a person in line if nobody taller than them has arrived behind them. When a taller person arrives, everyone shorter in front of them gets "answered": "you found the next taller person: it is this one." Those shorter people leave the line.

Why it is O(n) even with a while inside a for: every item is pushed once and popped at most once, so the total number of pops is at most n (the amortized argument from file 02).

Problem 1 · Valid Parentheses (LeetCode 20, Easy; v2 list)

Task. A string has only ()[]{}. Is every bracket closed by the right kind, in the right order? "()[]{}" → true; "(]" → false; "([)]" → false; "{[]}" → true.

Thinking. An opening bracket means "I owe the world a matching closer". Push it. A closing bracket must match the most recent unpaid opener, which is the stack's top. If the top is not the matching opener (or the stack is empty), the string is invalid. At the end the stack must be empty, otherwise some opener was never closed.

function isValid(s: string): boolean {
  const closerToOpener = new Map<string, string>([
    [")", "("],
    ["]", "["],
    ["}", "{"],
  ]);
  const stack: string[] = [];
  for (const ch of s) {
    const opener = closerToOpener.get(ch);
    if (opener === undefined) stack.push(ch); // it is an opening bracket
    else if (stack.pop() !== opener) return false; // wrong match, or nothing to match (undefined)
  }
  return stack.length === 0; // anything left over was never closed
}

console.log(isValid("(]")); // false
console.log(isValid("([)]")); // false
console.log(isValid("{[]}")); // true
console.log(isValid("(")); // false
console.log(isValid("")); // true
func isValid(s string) bool {
	closerToOpener := map[byte]byte{')': '(', ']': '[', '}': '{'}
	stack := []byte{}
	for i := 0; i < len(s); i++ {
		ch := s[i]
		if opener, isCloser := closerToOpener[ch]; isCloser {
			if len(stack) == 0 || stack[len(stack)-1] != opener {
				return false // nothing to match, or the wrong kind
			}
			stack = stack[:len(stack)-1] // pop
		} else {
			stack = append(stack, ch) // push the opener
		}
	}
	return len(stack) == 0 // anything left over was never closed
}

func exampleIsValid() {
	fmt.Println(isValid("()[]{}")) // true
	fmt.Println(isValid("(]"))     // false
	fmt.Println(isValid("([)]"))   // false
	fmt.Println(isValid("{[]}"))   // true
	fmt.Println(isValid("("))      // false
	fmt.Println(isValid(""))       // true
}

Complexity. Time O(n), space O(n).

Quick rejects. If s.length is odd, it cannot be valid. A related follow-up: Longest Valid Parentheses (LeetCode 32): a stack of indexes.

Problem 2 · Min Stack (LeetCode 155, Medium; v2 list)

Task. Design a stack with push, pop, top, and getMin, all O(1).

The trap. If you keep one variable min, what happens after you pop the minimum? You would have to rescan to find the next-smallest, which is O(n).

Idea. Each stack entry remembers the minimum of everything at or below it. Then getMin is just the top's remembered minimum, and popping automatically restores the earlier minimum.

class MinStack {
  private items: { value: number; min: number }[] = []; // each entry knows the min at or below it

  push(value: number): void {
    const min = this.items.length === 0 ? value : Math.min(value, this.getMin());
    this.items.push({ value, min });
  }
  pop(): void {
    this.items.pop();
  }
  top(): number {
    return this.items[this.items.length - 1].value;
  }
  getMin(): number {
    return this.items[this.items.length - 1].min;
  }
}
const minStack = new MinStack();
minStack.push(2);
minStack.push(5);
minStack.push(1);
console.log(minStack.getMin()); // 1
minStack.pop();
console.log(minStack.top(), minStack.getMin()); // 5 2
type minEntry struct{ value, min int }

type MinStack struct{ items []minEntry }

func (s *MinStack) Push(value int) {
	min := value
	if len(s.items) > 0 && s.items[len(s.items)-1].min < value {
		min = s.items[len(s.items)-1].min
	}
	s.items = append(s.items, minEntry{value, min})
}
func (s *MinStack) Pop()        { s.items = s.items[:len(s.items)-1] }
func (s *MinStack) Top() int    { return s.items[len(s.items)-1].value }
func (s *MinStack) GetMin() int { return s.items[len(s.items)-1].min }

func exampleMinStack() {
	s := &MinStack{}
	s.Push(2)
	s.Push(5)
	s.Push(1)
	fmt.Println(s.GetMin()) // 1
	s.Pop()
	fmt.Println(s.Top(), s.GetMin()) // 5 2
}

Complexity. Every operation O(1); space O(n) (one extra number per item).

Follow-up. "Use O(1) extra space (no second number per entry)?" Store the difference value − min and update the min cleverly; mention it exists, and that the pair approach is easier to get right. "Max stack?" Same idea. "Pop the max (LeetCode 716)?" Harder: needs a heap or a linked list with a sorted structure.

Problem 3 · Evaluate Reverse Polish Notation (LeetCode 150, Medium)

Task. Evaluate an expression in postfix notation, where operators come after their operands. ["2","1","+","3","*"] means (2 + 1) × 3 = 9. Division truncates toward zero.

Thinking. Read left to right. A number: push it. An operator: pop the two most recent numbers (the second popped is the left operand), apply, push the result. At the end, one number remains. Postfix is designed so a stack alone is enough, with no brackets or precedence rules.

Trace. ["4","13","5","/","+"] means 4 + (13 / 5)

tokenactionstack
4push4
13push4 13
5push4 13 5
/pop 5, pop 13 → 13 / 5 = 2 (truncated), push4 2
+pop 2, pop 4 → 4 + 2 = 6, push6

Order trap. For - and /, the first popped value is the right operand. Compute second OP first.

function evalRPN(tokens: string[]): number {
  const stack: number[] = [];
  for (const token of tokens) {
    if (token === "+" || token === "-" || token === "*" || token === "/") {
      const right = stack.pop()!; // the most recent number is the RIGHT operand
      const left = stack.pop()!;
      if (token === "+") stack.push(left + right);
      else if (token === "-") stack.push(left - right);
      else if (token === "*") stack.push(left * right);
      else stack.push(Math.trunc(left / right)); // truncate toward zero
    } else {
      stack.push(Number(token));
    }
  }
  return stack[0];
}
console.log(evalRPN(["2", "1", "+", "3", "*"])); // 9
console.log(evalRPN(["4", "13", "5", "/", "+"])); // 6
console.log(evalRPN(["10", "6", "9", "3", "+", "-11", "*", "/", "*", "17", "+", "5", "+"])); // 22
func evalRPN(tokens []string) int {
	stack := []int{}
	for _, token := range tokens {
		switch token {
		case "+", "-", "*", "/":
			right := stack[len(stack)-1] // the most recent number is the RIGHT operand
			left := stack[len(stack)-2]
			stack = stack[:len(stack)-2]
			switch token {
			case "+":
				stack = append(stack, left+right)
			case "-":
				stack = append(stack, left-right)
			case "*":
				stack = append(stack, left*right)
			default:
				stack = append(stack, left/right) // Go integer division truncates toward zero
			}
		default:
			n, _ := strconv.Atoi(token)
			stack = append(stack, n)
		}
	}
	return stack[0]
}

func exampleEvalRPN() {
	fmt.Println(evalRPN([]string{"2", "1", "+", "3", "*"}))                                                   // 9
	fmt.Println(evalRPN([]string{"4", "13", "5", "/", "+"}))                                                  // 6
	fmt.Println(evalRPN([]string{"10", "6", "9", "3", "+", "-11", "*", "/", "*", "17", "+", "5", "+"})) // 22
}

Complexity. Time O(n), space O(n).

Link. Turning a normal expression like (2+1)*3 into postfix is the shunting-yard algorithm: also a stack (of operators).

Problem 4 · Daily Temperatures (LeetCode 739, Medium; v2 list)

Task. For each day, how many days until a warmer temperature? [73, 74, 75, 71, 69, 72, 76, 73] → [1, 1, 4, 2, 1, 1, 0, 0] (0 if none).

Brute force. For each day, scan forward: O(n²).

Monotonic stack idea. Keep a stack of indexes of days that are still waiting for a warmer day. Their temperatures are non-increasing from bottom to top (if a warmer day came, they would already have been answered). When day i arrives, it is warmer than every waiting day whose temperature is lower: pop them and answer them with i − thatDay. Then push i to wait.

function dailyTemperatures(temps: number[]): number[] {
  const answer = new Array<number>(temps.length).fill(0); // 0 means "no warmer day"
  const waiting: number[] = []; // indexes of days still waiting for a warmer day
  for (let i = 0; i < temps.length; i++) {
    while (waiting.length > 0 && temps[waiting[waiting.length - 1]] < temps[i]) {
      const day = waiting.pop()!;
      answer[day] = i - day; // today is the first warmer day for `day`
    }
    waiting.push(i);
  }
  return answer;
}
console.log(dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73])); // [ 1, 1, 4, 2, 1, 1, 0, 0 ]
console.log(dailyTemperatures([30, 40, 50, 60])); // [ 1, 1, 1, 0 ]
console.log(dailyTemperatures([30, 20, 10])); // [ 0, 0, 0 ]
func dailyTemperatures(temps []int) []int {
	answer := make([]int, len(temps)) // 0 means "no warmer day"
	waiting := []int{}                // indexes of days still waiting for a warmer day
	for i, t := range temps {
		for len(waiting) > 0 && temps[waiting[len(waiting)-1]] < t {
			day := waiting[len(waiting)-1]
			waiting = waiting[:len(waiting)-1]
			answer[day] = i - day // today is the first warmer day for `day`
		}
		waiting = append(waiting, i)
	}
	return answer
}

func exampleDailyTemperatures() {
	fmt.Println(dailyTemperatures([]int{73, 74, 75, 71, 69, 72, 76, 73})) // [1 1 4 2 1 1 0 0]
	fmt.Println(dailyTemperatures([]int{30, 40, 50, 60}))                 // [1 1 1 0]
	fmt.Println(dailyTemperatures([]int{30, 20, 10}))                     // [0 0 0]
}

Complexity. Time O(n) (each index pushed once, popped once), space O(n).

Problem 5 · Decode String, the explicit-stack version (LeetCode 394, Medium; v2 list)

File 10 solved this with recursion. Interviewers often ask for the iterative version to avoid deep call stacks. This is exactly "how a recursion becomes a loop": the recursion's pending work moves onto your stack.

Idea. Keep two things per open bracket: the text built so far and the repeat count that applies to the bracket we are entering.

  • On a digit: build count.
  • On [: push the current text and count onto the stack, then start fresh (text = "", count = 0).
  • On a letter: append to text.
  • On ]: pop the saved text and count; the new text is savedText + text × savedCount.

[push ("a", 2), reset""0("",3) ("a",2)
cappend"c"0("",3) ("a",2)
]pop ("a", 2): "a" + "cc""acc"0("",3)
]pop ("", 3): "" + "accaccacc""accaccacc"0
function decodeStringIterative(s: string): string {
  const stack: { text: string; count: number }[] = [];
  let text = "";
  let count = 0;
  for (const ch of s) {
    if (ch >= "0" && ch <= "9") {
      count = count * 10 + Number(ch);
    } else if (ch === "[") {
      stack.push({ text, count }); // remember what we had before this bracket
      text = "";
      count = 0;
    } else if (ch === "]") {
      const saved = stack.pop()!;
      text = saved.text + text.repeat(saved.count);
    } else {
      text += ch;
    }
  }
  return text;
}
console.log(decodeStringIterative("3[a2[c]]")); // accaccacc
console.log(decodeStringIterative("2[abc]3[cd]ef")); // abcabccdcdcdef
console.log(decodeStringIterative("abc")); // abc
func decodeStringIterative(s string) string {
	type frame struct {
		text  string
		count int
	}
	stack := []frame{}
	text := ""
	count := 0
	for i := 0; i < len(s); i++ {
		ch := s[i]
		switch {
		case ch >= '0' && ch <= '9':
			count = count*10 + int(ch-'0')
		case ch == '[':
			stack = append(stack, frame{text, count}) // remember what we had before this bracket
			text, count = "", 0
		case ch == ']':
			saved := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			text = saved.text + strings.Repeat(text, saved.count)
		default:
			text += string(ch)
		}
	}
	return text
}

func exampleDecodeStringIterative() {
	fmt.Println(decodeStringIterative("3[a2[c]]"))      // accaccacc
	fmt.Println(decodeStringIterative("2[abc]3[cd]ef")) // abcabccdcdcdef
	fmt.Println(decodeStringIterative("abc"))           // abc
}

Complexity. Time O(output length)-ish, space O(nesting depth + text). No call-stack limit.

Problem 6 · Largest Rectangle in Histogram (LeetCode 84, Hard)

Task. A histogram has bars of width 1 and heights h[i]. Find the area of the largest rectangle that fits inside it. [2, 1, 5, 6, 2, 3] → 10 (the bars 5, 6, height 5, width 2).

Brute force. For each pair of bars compute the min height between them: O(n²) or O(n³).

The key reframe. Any rectangle's height is limited by its shortest bar. So ask, for each bar i, treating it as the shortest bar of the rectangle, how far can the rectangle stretch left and right? It stretches until it meets a bar shorter than h[i] on each side:

  • left boundary = the nearest bar to the left that is shorter than h[i],
  • right boundary = the nearest bar to the right that is shorter than h[i].

Area for bar i = h[i] × (right − left − 1), where left and right are the indexes of those shorter bars (use −1 and n if none).

"Nearest smaller on each side" is exactly the monotonic stack problem. Use a stack of indexes with increasing heights. When a bar shorter than the top arrives, the top has just found its right boundary (the new bar), and its left boundary is the item just below it on the stack (which is shorter, by the stack's order). So we can compute the top's rectangle at the moment we pop it.

function largestRectangleArea(heights: number[]): number {
  const stack: number[] = []; // indexes of bars with increasing heights
  let best = 0;
  for (let i = 0; i <= heights.length; i++) {
    const cur = i === heights.length ? 0 : heights[i]; // a final height 0 flushes the stack
    while (stack.length > 0 && heights[stack[stack.length - 1]] >= cur) {
      const height = heights[stack.pop()!];
      const left = stack.length > 0 ? stack[stack.length - 1] : -1; // nearest shorter bar on the left
      best = Math.max(best, height * (i - left - 1)); // i is the nearest shorter on the right
    }
    stack.push(i);
  }
  return best;
}
console.log(largestRectangleArea([2, 1, 5, 6, 2, 3])); // 10
console.log(largestRectangleArea([2, 4])); // 4
console.log(largestRectangleArea([2, 2, 2])); // 6
console.log(largestRectangleArea([])); // 0
func largestRectangleArea(heights []int) int {
	stack := []int{} // indexes of bars with increasing heights
	best := 0
	for i := 0; i <= len(heights); i++ {
		cur := 0 // a final height 0 flushes the stack
		if i < len(heights) {
			cur = heights[i]
		}
		for len(stack) > 0 && heights[stack[len(stack)-1]] >= cur {
			height := heights[stack[len(stack)-1]]
			stack = stack[:len(stack)-1]
			left := -1 // nearest shorter bar on the left
			if len(stack) > 0 {
				left = stack[len(stack)-1]
			}
			best = max(best, height*(i-left-1)) // i is the nearest shorter on the right
		}
		stack = append(stack, i)
	}
	return best
}

func exampleLargestRectangleArea() {
	fmt.Println(largestRectangleArea([]int{2, 1, 5, 6, 2, 3})) // 10
	fmt.Println(largestRectangleArea([]int{2, 4}))              // 4
	fmt.Println(largestRectangleArea([]int{2, 2, 2}))           // 6
	fmt.Println(largestRectangleArea([]int{}))                  // 0
}

Complexity. Time O(n), space O(n).

Why >= and not >: popping on equal heights is fine. The earlier equal bar gets a too-narrow rectangle, but the later equal bar (pushed after) gets the correct, wider one, so the maximum is still found, and duplicates need no special handling.

Related problems: Maximal Rectangle in a binary matrix (LeetCode 85: run this on each row's "histogram of consecutive 1s"), and Trapping Rain Water (LeetCode 42) also has a monotonic-stack solution besides the two-pointer one in file 05: a decreasing stack, where each pop fills a "valley" between the new bar and the bar below it.

Common mistakes

  • Popping from an empty stack (pop() returns undefined in JavaScript; a panic in Go). Check length > 0 first.
  • Storing values instead of indexes in a monotonic stack, then being unable to compute distances.
  • Wrong operand order for - and / in postfix evaluation.
  • Forgetting to check that the stack is empty at the end (Valid Parentheses with leftover openers).
  • Wrong comparison direction (< vs >): write the property of the stack in words before coding ("heights increase from bottom to top").
  • Forgetting the sentinel/flush step (the cur = 0 trick) so the bars left on the stack are never evaluated.
  • Using array.shift() as a "stack pop from the front": that is a queue, and it is O(n) in JavaScript.

1 · Why a stack for brackets

Explain why a stack (not a queue) is right for matching brackets, using the string "([{}])".

Answer

In "([{}])" the { is opened last, so it must be closed first; then [, then (. Closing happens in reverse order of opening: last in, first out. A queue would try to close ( first and fail.

2 · Daily Temperatures on [5, 4, 3, 6]

Run the Daily Temperatures stack on [5, 4, 3, 6] by hand. What is the stack after each step?

Answer

i=0: stack [0]. i=1: 4 < 5, stack [0, 1]. i=2: stack [0, 1, 2]. i=3: 6 pops 2 (answer 1), pops 1 (answer 2), pops 0 (answer 3), then stack [3]. Answer [3, 2, 1, 0]. Try it in Problem 4's animation.

3 · Next Greater Element II (circular)

Next Greater Element II (LeetCode 503, circular array): what small change to the loop do you need?

Answer

Loop i from 0 to 2n − 1 and use nums[i % n]. Only push indexes during the first lap (i < n). The second lap lets items near the end find a greater element at the start.

4 · Remove K Digits

Remove K Digits (LeetCode 402): which stack order (increasing or decreasing) lets you drop the largest leading digits?

Answer

Keep an increasing stack of digits. When a smaller digit arrives and removals remain, pop the bigger digits before it, because a smaller digit earlier always gives a smaller number. Remove any leftover k from the end, and strip leading zeros.

5 · Trapping Rain Water with a stack

Trapping Rain Water with a monotonic stack: when a taller bar arrives and you pop a bar, which three bars define the water pocket?

Answer

Keep a decreasing stack of bar indexes. When a taller bar arrives, pop the bottom bar: the three bars are the popped bar (the floor), the new top of the stack (the left wall) and the current bar (the right wall). Water = (min(left, right) − floor) × (distance between the walls − 1).

Check yourself
