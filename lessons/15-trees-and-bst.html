Trees and binary search trees

Ask each child, then combine.

Book link: Grokking Algorithms, chapter 7 (your first tree, depth-first search, binary trees, Huffman coding). The template

Handle the empty tree; ask the left and right children; combine their answers at the node.

Traversals

Preorder, inorder (sorted for a BST), postorder; level order uses a queue.

What it costs

O(n) time; O(h) stack, where h is the height.

1. The idea in plain English

A tree is a family tree turned upside down: one root at the top, each node has children below it, and nothing ever loops back. The folders on your computer are a tree: a folder contains files (no children: leaves) and other folders (which contain more).

Vocabulary (say these words correctly in interviews)

WordMeaning
RootThe top node (no parent).
LeafA node with no children.
Parent / child / siblingDirect connections; siblings share a parent.
SubtreeA node together with everything below it. A tree is made of smaller trees, and that is why recursion fits.
Depth of a nodeNumber of steps from the root down to it (root = 0).
Height of a treeThe longest root-to-leaf path. Counted in nodes (LeetCode "max depth") or edges; say which.
Binary treeEach node has at most two children: left and right.
Binary search tree (BST)A binary tree where, for every node, all values in its left subtree are smaller and all in its right subtree are larger.
BalancedThe two sides of every node have similar heights, so the tree is short: height about log n (file 16).

The BST rule and why it is useful

Because smaller values live on the left and bigger on the right, searching works like the number-guessing game (file 08): at each node, compare and throw away half of the tree.

  • Search, insert, delete: O(height). That is O(log n) if the tree is balanced, but O(n) if the tree is a chain (for example after inserting already sorted numbers).
  • An inorder walk of a BST visits values in sorted order. This one fact solves many BST problems.

2. Two ways to visit every node

Depth-first (DFS): go deep, then come back

Three orders, named by when you handle the node relative to its children:

OrderVisitTypical use
Preordernode, left, rightcopy a tree; serialize it
Inorderleft, node, rightsorted order in a BST
Postorderleft, right, nodecompute something from the children (heights, sizes, delete a tree)

For this tree: preorder 1 2 4 5 3, inorder 4 2 5 1 3, postorder 4 5 2 3 1.

Breadth-first (BFS): level by level

Visit the root, then all its children, then all the grandchildren. Uses a queue (file 14). Output for the tree above: 1, 2, 3, 4, 5.

DFS vs BFS in one sentence: DFS uses a stack (or the call stack) and goes deep; BFS uses a queue and goes wide. For "something about levels" or "the closest…", pick BFS. For "something about paths or subtrees", pick DFS.

4. How to recognize it

  • The input is a TreeNode (or a nested structure like JSON or a folder tree).
  • Words: "subtree", "ancestor", "path from root to leaf", "level", "depth", "balanced", "BST", "traversal".
  • If it's a BST and the problem says "kth", "range", "sorted", "closest value" → use the BST property (inorder = sorted, or go left/right by comparison).

class TreeNode {
  constructor(
    public val: number,
    public left: TreeNode | null = null,
    public right: TreeNode | null = null,
  ) {}
}

// Build from a level-order array where null means "no node" (LeetCode style).
function buildTree(vals: (number | null)[]): TreeNode | null {
  if (vals.length === 0 || vals[0] === null) return null;
  const root = new TreeNode(vals[0]);
  const queue: TreeNode[] = [root];
  let head = 0, i = 1;
  while (head < queue.length && i < vals.length) {
    const node = queue[head++];
    const l = vals[i++];
    if (l !== null && l !== undefined) {
      node.left = new TreeNode(l);
      queue.push(node.left);
    }
    if (i < vals.length) {
      const r = vals[i++];
      if (r !== null && r !== undefined) {
        node.right = new TreeNode(r);
        queue.push(node.right);
      }
    }
  }
  return root;
}

// Print as a level-order array with nulls (trailing nulls removed).
function toLevelArray(root: TreeNode | null): (number | null)[] {
  const out: (number | null)[] = [];
  const queue: (TreeNode | null)[] = [root];
  let head = 0;
  while (head < queue.length) {
    const node = queue[head++];
    if (node === null) {
      out.push(null);
      continue;
    }
    out.push(node.val);
    queue.push(node.left, node.right);
  }
  while (out.length > 0 && out[out.length - 1] === null) out.pop();
  return out;
}

function findNode(root: TreeNode | null, val: number): TreeNode | null {
  if (root === null || root.val === val) return root;
  return findNode(root.left, val) ?? findNode(root.right, val);
}

console.log(toLevelArray(buildTree([3, 9, 20, null, null, 15, 7]))); // [ 3, 9, 20, null, null, 15, 7 ]
type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}

// NULL marks "no node" in level-order arrays (LeetCode style).
const NULL = math.MinInt

func buildTree(vals []int) *TreeNode {
	if len(vals) == 0 || vals[0] == NULL {
		return nil
	}
	root := &TreeNode{Val: vals[0]}
	queue := []*TreeNode{root}
	head, i := 0, 1
	for head < len(queue) && i < len(vals) {
		node := queue[head]
		head++
		if vals[i] != NULL {
			node.Left = &TreeNode{Val: vals[i]}
			queue = append(queue, node.Left)
		}
		i++
		if i < len(vals) {
			if vals[i] != NULL {
				node.Right = &TreeNode{Val: vals[i]}
				queue = append(queue, node.Right)
			}
			i++
		}
	}
	return root
}

// toLevelArray prints as a level-order slice using "null" text (trailing nulls removed).
func toLevelArray(root *TreeNode) []string {
	out := []string{}
	queue := []*TreeNode{root}
	for head := 0; head < len(queue); head++ {
		node := queue[head]
		if node == nil {
			out = append(out, "null")
			continue
		}
		out = append(out, strconv.Itoa(node.Val))
		queue = append(queue, node.Left, node.Right)
	}
	for len(out) > 0 && out[len(out)-1] == "null" {
		out = out[:len(out)-1]
	}
	return out
}

func findNode(root *TreeNode, val int) *TreeNode {
	if root == nil || root.Val == val {
		return root
	}
	if found := findNode(root.Left, val); found != nil {
		return found
	}
	return findNode(root.Right, val)
}

func exampleTreeSetup() {
	fmt.Println(toLevelArray(buildTree([]int{3, 9, 20, NULL, NULL, 15, 7}))) // [3 9 20 null null 15 7]
}

6. Practice problems (easy → hard)

Problem 1 · Maximum Depth (104) and Invert Binary Tree (226), both Easy; v2 list

These two are the "hello world" of tree recursion. Do them out loud until the template feels natural.

Maximum depth. Contract: maxDepth(node) is the number of nodes on the longest path from node down to a leaf. Base: an empty tree has depth 0. Combine: 1 + max(left depth, right depth).

Invert. Contract: invert(node) returns the mirror image of its subtree. Combine: invert both children, then swap them.

Trace of maxDepth on [3, 9, 20, null, null, 15, 7]

CallLeftRightReturns
maxDepth(9)001
maxDepth(15)001
maxDepth(7)001
maxDepth(20)112
maxDepth(3)1 (from 9)2 (from 20)3
function maxDepth(root: TreeNode | null): number {
  if (root === null) return 0; // base case
  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}

function invertTree(root: TreeNode | null): TreeNode | null {
  if (root === null) return null;
  const left = invertTree(root.left); // ask each child for its inverted subtree
  const right = invertTree(root.right);
  root.left = right; // swap
  root.right = left;
  return root;
}

console.log(maxDepth(null)); // 0
console.log(toLevelArray(invertTree(buildTree([4, 2, 7, 1, 3, 6, 9])))); // [ 4, 7, 2, 9, 6, 3, 1 ]
console.log(toLevelArray(invertTree(buildTree([2, 1, 3])))); // [ 2, 3, 1 ]
func maxDepth(root *TreeNode) int {
	if root == nil {
		return 0 // base case
	}
	return 1 + max(maxDepth(root.Left), maxDepth(root.Right))
}

func invertTree(root *TreeNode) *TreeNode {
	if root == nil {
		return nil
	}
	left := invertTree(root.Left) // ask each child for its inverted subtree
	right := invertTree(root.Right)
	root.Left, root.Right = right, left // swap
	return root
}

func exampleDepthAndInvert() {
	fmt.Println(maxDepth(buildTree([]int{3, 9, 20, NULL, NULL, 15, 7})))                   // 3
	fmt.Println(maxDepth(nil))                                                              // 0
	fmt.Println(toLevelArray(invertTree(buildTree([]int{4, 2, 7, 1, 3, 6, 9}))))           // [4 7 2 9 6 3 1]
	fmt.Println(toLevelArray(invertTree(buildTree([]int{2, 1, 3}))))                        // [2 3 1]
}

Complexity. Time O(n) (each node visited once). Space O(h) for the recursion where h is the tree height: O(log n) if balanced, O(n) for a chain.

Follow-ups. Balanced check (LeetCode 110): return the height, or −1 as a signal for "unbalanced below", to do it in one pass. Diameter (LeetCode 543): at each node, the longest path through it is leftHeight + rightHeight.

Problem 2 · Binary Tree Inorder Traversal (LeetCode 94, Easy; v2 list)

Task. Return the values in inorder (left, node, right). [1, null, 2, 3] → [1, 3, 2].

Recursive version. Three lines, mirroring the definition.

Iterative version (a favorite follow-up). Replace the call stack with your own stack:

  1. Walk as far left as possible, pushing each node on the stack (those are "waiting for their turn").
  2. Pop a node: visit it.
  3. Move to its right child and repeat from step 1.

Trace on 1 → right child 2 → left child 3 ([1, null, 2, 3])

StepcurActionstackoutput
11push 1, go left (null)[1]
2nullpop 1, visit, go right to 2[][1]
32push 2, go left to 3[2]
43push 3, go left (null)[2, 3]
5nullpop 3, visit, go right (null)[2][1, 3]
6nullpop 2, visit, go right (null)[][1, 3, 2]
function inorderRecursive(root: TreeNode | null, out: number[] = []): number[] {
  if (root === null) return out;
  inorderRecursive(root.left, out);
  out.push(root.val); // visit the node between its two subtrees
  inorderRecursive(root.right, out);
  return out;
}

function inorderIterative(root: TreeNode | null): number[] {
  const out: number[] = [];
  const stack: TreeNode[] = [];
  let cur = root;
  while (cur !== null || stack.length > 0) {
    while (cur !== null) {
      stack.push(cur); // keep going left, remembering the way back
      cur = cur.left;
    }
    cur = stack.pop()!; // nothing further left: this is the next smallest
    out.push(cur.val);
    cur = cur.right; // then handle the right subtree
  }
  return out;
}

console.log(inorderIterative(t94)); // [ 1, 3, 2 ]
console.log(inorderIterative(buildTree([2, 1, 3]))); // [ 1, 2, 3 ]
console.log(inorderIterative(null)); // []
func inorderRecursive(root *TreeNode, out *[]int) {
	if root == nil {
		return
	}
	inorderRecursive(root.Left, out)
	*out = append(*out, root.Val) // visit the node between its two subtrees
	inorderRecursive(root.Right, out)
}

func inorderIterative(root *TreeNode) []int {
	out := []int{}
	stack := []*TreeNode{}
	cur := root
	for cur != nil || len(stack) > 0 {
		for cur != nil {
			stack = append(stack, cur) // keep going left, remembering the way back
			cur = cur.Left
		}
		cur = stack[len(stack)-1] // nothing further left: this is the next smallest
		stack = stack[:len(stack)-1]
		out = append(out, cur.Val)
		cur = cur.Right // then handle the right subtree
	}
	return out
}

func exampleInorder() {
	t := buildTree([]int{1, NULL, 2, 3})
	var rec []int
	inorderRecursive(t, &rec)
	fmt.Println(rec)                                         // [1 3 2]
	fmt.Println(inorderIterative(t))                         // [1 3 2]
	fmt.Println(inorderIterative(buildTree([]int{2, 1, 3}))) // [1 2 3]
	fmt.Println(inorderIterative(nil))                       // []
}

Complexity. Time O(n), space O(h).

Preorder and postorder use the same shapes. For preorder, visit before recursing. For postorder, visit after both. Iterative preorder is easiest: push root; pop, visit, push right then left.

Mention (advanced): Morris traversal does inorder in O(1) extra space by temporarily rewiring pointers. Name it, don't memorize it.

Problem 3 · Level Order Traversal (LeetCode 102, Medium; v2 list)

Task. Return the values level by level, as a list of lists. [3, 9, 20, null, null, 15, 7] → [[3], [9, 20], [15, 7]].

Idea (BFS with a queue). Start with the root in the queue. For each level:

  1. Note how many nodes are in the queue right now: size. Those are exactly this level.
  2. Process exactly size nodes: record values and enqueue their children (the next level).
  3. Repeat until the queue is empty.

Capturing size first is the trick that separates one level from the next.

function levelOrder(root: TreeNode | null): number[][] {
  const result: number[][] = [];
  if (root === null) return result;
  let queue: TreeNode[] = [root];
  while (queue.length > 0) {
    const level: number[] = [];
    const next: TreeNode[] = []; // the next level, built while we read this one
    for (const node of queue) {
      level.push(node.val);
      if (node.left) next.push(node.left);
      if (node.right) next.push(node.right);
    }
    result.push(level);
    queue = next;
  }
  return result;
}
console.log(levelOrder(buildTree([3, 9, 20, null, null, 15, 7]))); // [ [ 3 ], [ 9, 20 ], [ 15, 7 ] ]
console.log(levelOrder(buildTree([1]))); // [ [ 1 ] ]
console.log(levelOrder(null)); // []
func levelOrder(root *TreeNode) [][]int {
	result := [][]int{}
	if root == nil {
		return result
	}
	queue := []*TreeNode{root}
	for len(queue) > 0 {
		size := len(queue) // exactly this many nodes are on the current level
		level := make([]int, 0, size)
		for i := 0; i < size; i++ {
			node := queue[0]
			queue = queue[1:]
			level = append(level, node.Val)
			if node.Left != nil {
				queue = append(queue, node.Left)
			}
			if node.Right != nil {
				queue = append(queue, node.Right)
			}
		}
		result = append(result, level)
	}
	return result
}

func exampleLevelOrder() {
	fmt.Println(levelOrder(buildTree([]int{3, 9, 20, NULL, NULL, 15, 7}))) // [[3] [9 20] [15 7]]
	fmt.Println(levelOrder(buildTree([]int{1})))                           // [[1]]
	fmt.Println(levelOrder(nil))                                           // []
}

Complexity. Time O(n), space O(w) where w is the widest level (up to n/2).

Variants (change one line each): Right side view (LeetCode 199): keep the last node of each level. Zigzag level order (LeetCode 103): reverse every other level. Average of levels, largest value in each row.

Problem 4 · Validate BST (LeetCode 98) and Kth Smallest Element in a BST (LeetCode 230), Medium; v2 list #230

Part A: Validate BST.

The common mistake. Checking only left < node < right for each parent and its two children is wrong. Look at this tree:

Each parent-child pair looks fine locally (6 > 5, 3 < 6), but 3 is in the right subtree of 5, so it must be > 5. It isn't, so this is not a BST.

Correct idea. Pass allowed bounds down. Every node must lie strictly between lo and hi. Going left, the current value becomes the new upper bound; going right, it becomes the new lower bound.

function isValidBST(root: TreeNode | null, lo = -Infinity, hi = Infinity): boolean {
  if (root === null) return true; // an empty tree is a valid BST
  if (root.val <= lo || root.val >= hi) return false; // outside the allowed window
  return isValidBST(root.left, lo, root.val) && isValidBST(root.right, root.val, hi);
}
console.log(isValidBST(buildTree([2, 1, 3]))); // true
console.log(isValidBST(buildTree([5, 1, 4, null, null, 3, 6]))); // false
console.log(isValidBST(buildTree([5, 1, 6, null, null, 3, 7]))); // false  (the tree drawn above)
console.log(isValidBST(buildTree([2, 2, 2]))); // false  (duplicates are not allowed here)
func isValidBST(root *TreeNode, lo, hi int) bool {
	if root == nil {
		return true // an empty tree is a valid BST
	}
	if root.Val <= lo || root.Val >= hi {
		return false // outside the allowed window
	}
	return isValidBST(root.Left, lo, root.Val) && isValidBST(root.Right, root.Val, hi)
}

func exampleIsValidBST() {
	check := func(vals []int) bool { return isValidBST(buildTree(vals), math.MinInt, math.MaxInt) }
	fmt.Println(check([]int{2, 1, 3}))                    // true
	fmt.Println(check([]int{5, 1, 4, NULL, NULL, 3, 6})) // false
	fmt.Println(check([]int{5, 1, 6, NULL, NULL, 3, 7})) // false
	fmt.Println(check([]int{2, 2, 2}))                    // false
}

(An alternative: do an inorder walk and verify the values are strictly increasing.)

Part B: Kth Smallest in a BST.

Idea. An inorder walk of a BST yields sorted values, so the k-th smallest is the k-th node visited. Use the iterative inorder from Problem 2 and stop early after k pops. That is O(h + k), not O(n).

Trace. [3, 1, 4, null, 2], k = 1: go left to 1 (push 3, push 1), pop 1 → that is the first visited → answer 1.

function kthSmallest(root: TreeNode | null, k: number): number {
  const stack: TreeNode[] = [];
  let cur = root;
  while (cur !== null || stack.length > 0) {
    while (cur !== null) {
      stack.push(cur);
      cur = cur.left;
    }
    cur = stack.pop()!;
    if (--k === 0) return cur.val; // the k-th node of the inorder walk
    cur = cur.right;
  }
  throw new Error("k is larger than the number of nodes");
}
console.log(kthSmallest(buildTree([3, 1, 4, null, 2]), 1)); // 1
console.log(kthSmallest(buildTree([5, 3, 6, 2, 4, null, null, 1]), 3)); // 3
console.log(kthSmallest(buildTree([5, 3, 6, 2, 4, null, null, 1]), 6)); // 6
func kthSmallest(root *TreeNode, k int) int {
	stack := []*TreeNode{}
	cur := root
	for cur != nil || len(stack) > 0 {
		for cur != nil {
			stack = append(stack, cur)
			cur = cur.Left
		}
		cur = stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		k--
		if k == 0 {
			return cur.Val // the k-th node of the inorder walk
		}
		cur = cur.Right
	}
	panic("k is larger than the number of nodes")
}

func exampleKthSmallest() {
	fmt.Println(kthSmallest(buildTree([]int{3, 1, 4, NULL, 2}), 1))                    // 1
	fmt.Println(kthSmallest(buildTree([]int{5, 3, 6, 2, 4, NULL, NULL, 1}), 3))        // 3
	fmt.Println(kthSmallest(buildTree([]int{5, 3, 6, 2, 4, NULL, NULL, 1}), 6))        // 6
}

Complexity. Time O(h + k), space O(h).

Follow-up (a classic). "The tree is modified often and kthSmallest is called often. How do you speed it up?" Store in each node the size of its left subtree so you can descend: if k ≤ leftSize go left; if k == leftSize + 1 it's this node; else go right with k − leftSize − 1. That gives O(h) per query.

Problem 5 · Lowest Common Ancestor of a Binary Tree (LeetCode 236, Medium; v2 list)

Task. Given two nodes p and q in a binary tree, find their lowest common ancestor: the deepest node that has both as descendants (a node can be its own descendant). In [3,5,1,6,2,0,8,null,null,7,4]: LCA(5, 1) = 3; LCA(5, 4) = 5.

"Ask each child" thinking. Contract: lca(node) returns p if only p is in this subtree, q if only q, the LCA if both are in it (found already deeper), or null if neither.

  • Base: if node is null, or node is p or q, return node (found one target; no need to look deeper, because if the other target is below it then this node is the LCA).
  • Ask the left subtree and the right subtree.
  • If both return something non-null, p is on one side and q on the other → this node is the LCA.
  • If only one side returns something, pass that up (either the target or an already-found LCA).

Trace. tree [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1

CallResult
lca(3)asks left (5) and right (1)
lca(5)5 is p → returns 5 immediately
lca(1)1 is q → returns 1 immediately
back at 3left = 5, right = 1: both non-null → return 3
function lowestCommonAncestor(
  root: TreeNode | null,
  p: TreeNode,
  q: TreeNode,
): TreeNode | null {
  if (root === null || root === p || root === q) return root; // found a target (or ran out)
  const left = lowestCommonAncestor(root.left, p, q);
  const right = lowestCommonAncestor(root.right, p, q);
  if (left !== null && right !== null) return root; // targets are on different sides
  return left ?? right; // otherwise pass up whichever side found something
}
const t236 = buildTree([3, 5, 1, 6, 2, 0, 8, null, null, 7, 4]);
console.log(lowestCommonAncestor(t236, findNode(t236, 5)!, findNode(t236, 1)!)?.val); // 3
console.log(lowestCommonAncestor(t236, findNode(t236, 5)!, findNode(t236, 4)!)?.val); // 5
console.log(lowestCommonAncestor(t236, findNode(t236, 6)!, findNode(t236, 4)!)?.val); // 5
func lowestCommonAncestor(root, p, q *TreeNode) *TreeNode {
	if root == nil || root == p || root == q {
		return root // found a target (or ran out)
	}
	left := lowestCommonAncestor(root.Left, p, q)
	right := lowestCommonAncestor(root.Right, p, q)
	if left != nil && right != nil {
		return root // targets are on different sides
	}
	if left != nil {
		return left // otherwise pass up whichever side found something
	}
	return right
}

func exampleLCA() {
	t := buildTree([]int{3, 5, 1, 6, 2, 0, 8, NULL, NULL, 7, 4})
	fmt.Println(lowestCommonAncestor(t, findNode(t, 5), findNode(t, 1)).Val) // 3
	fmt.Println(lowestCommonAncestor(t, findNode(t, 5), findNode(t, 4)).Val) // 5
	fmt.Println(lowestCommonAncestor(t, findNode(t, 6), findNode(t, 4)).Val) // 5
}

Complexity. Time O(n), space O(h).

BST version (LeetCode 235) is simpler: walk down from the root. If both values are smaller than the node, go left; if both are larger, go right; otherwise the current node is the split point and is the LCA. O(h), no recursion needed.

Problem 6 · Construct Binary Tree from Preorder and Inorder Traversal (LeetCode 105, Medium; v2 list)

Task. Given the preorder and inorder traversals of a tree with distinct values, rebuild the tree. preorder = [3, 9, 20, 15, 7], inorder = [9, 3, 15, 20, 7] → [3, 9, 20, null, null, 15, 7].

What each list tells you.

  • Preorder (node, left, right): the first element is the root of the whole tree.
  • Inorder (left, node, right): the root sits between the left and right subtrees. Everything left of the root in inorder belongs to the left subtree; everything right of it belongs to the right subtree.

So: take the root from preorder, find it in inorder, and its position tells you the size of the left subtree. Recurse on the two halves.

Speed-up. Searching the root's position in the inorder array each time costs O(n), making the whole thing O(n²). Precompute a map from value to inorder index once: now each lookup is O(1).

Pointers instead of slices. Pass index ranges [inLo, inHi] into the inorder array and keep one running pointer preIdx into the preorder array. Because preorder visits the left subtree entirely before the right, building left first then right consumes the preorder list in exactly the right order.

function buildTreeFromPreIn(preorder: number[], inorder: number[]): TreeNode | null {
  const inorderIndex = new Map<number, number>(); // value -> position in inorder
  inorder.forEach((v, i) => inorderIndex.set(v, i));
  let preIdx = 0; // the next root to use, moving left to right through preorder

  function build(inLo: number, inHi: number): TreeNode | null {
    if (inLo > inHi) return null; // empty range: no subtree
    const rootVal = preorder[preIdx++]; // preorder always gives the next root
    const root = new TreeNode(rootVal);
    const mid = inorderIndex.get(rootVal)!;
    root.left = build(inLo, mid - 1); // must come BEFORE the right: preorder order
    root.right = build(mid + 1, inHi);
    return root;
  }
  return build(0, inorder.length - 1);
}

console.log(toLevelArray(buildTreeFromPreIn([-1], [-1]))); // [ -1 ]
console.log(toLevelArray(buildTreeFromPreIn([1, 2, 3], [3, 2, 1]))); // [ 1, 2, null, 3 ]
func buildTreeFromPreIn(preorder, inorder []int) *TreeNode {
	inorderIndex := make(map[int]int, len(inorder)) // value -> position in inorder
	for i, v := range inorder {
		inorderIndex[v] = i
	}
	preIdx := 0 // the next root to use, moving left to right through preorder

	var build func(inLo, inHi int) *TreeNode
	build = func(inLo, inHi int) *TreeNode {
		if inLo > inHi {
			return nil // empty range: no subtree
		}
		rootVal := preorder[preIdx] // preorder always gives the next root
		preIdx++
		root := &TreeNode{Val: rootVal}
		mid := inorderIndex[rootVal]
		root.Left = build(inLo, mid-1) // must come BEFORE the right: preorder order
		root.Right = build(mid+1, inHi)
		return root
	}
	return build(0, len(inorder)-1)
}

func exampleBuildFromPreIn() {
	fmt.Println(toLevelArray(buildTreeFromPreIn([]int{3, 9, 20, 15, 7}, []int{9, 3, 15, 20, 7}))) // [3 9 20 null null 15 7]
	fmt.Println(toLevelArray(buildTreeFromPreIn([]int{-1}, []int{-1})))                           // [-1]
	fmt.Println(toLevelArray(buildTreeFromPreIn([]int{1, 2, 3}, []int{3, 2, 1})))                 // [1 2 null 3]
}

Complexity. Time O(n), space O(n) (map + recursion).

Why distinct values? With duplicates, "find the root in inorder" is ambiguous. Related: from inorder + postorder (LeetCode 106): the root is the last element of postorder; build the right subtree first. Preorder alone does not determine a general tree, but preorder of a BST does (insert in order).

Problem 7 · Binary Tree Maximum Path Sum (LeetCode 124, Hard)

Task. A path is any sequence of connected nodes (each node used at most once); it does not need to pass through the root. Find the largest sum of a path. Values may be negative. [-10, 9, 20, null, null, 15, 7] → 42 (the path 15 → 20 → 7).

Why it is hard. There are two different quantities, and mixing them is the classic mistake:

  1. What we can return upward: a path that ends at this node and continues up to the parent can use at most one of the two children (a path cannot branch). So the helper returns: node.val + max(0, best left gain, best right gain), using max(0, …) to ignore negative branches.
  2. What we record as a candidate answer: the best path that bends at this node, using both children: node.val + leftGain + rightGain. A "bent" path cannot be extended to the parent, so we only store it in a global best.

function maxPathSum(root: TreeNode | null): number {
  let best = -Infinity; // the best path seen anywhere
  function gain(node: TreeNode | null): number {
    if (node === null) return 0;
    const leftGain = Math.max(0, gain(node.left)); // ignore branches that hurt
    const rightGain = Math.max(0, gain(node.right));
    best = Math.max(best, node.val + leftGain + rightGain); // a path that bends at this node
    return node.val + Math.max(leftGain, rightGain); // a path that continues upward: ONE side only
  }
  gain(root);
  return best;
}

func maxPathSum(root *TreeNode) int {
	best := math.MinInt // the best path seen anywhere
	var gain func(node *TreeNode) int
	gain = func(node *TreeNode) int {
		if node == nil {
			return 0
		}
		leftGain := max(0, gain(node.Left)) // ignore branches that hurt
		rightGain := max(0, gain(node.Right))
		best = max(best, node.Val+leftGain+rightGain) // a path that bends at this node
		return node.Val + max(leftGain, rightGain)    // a path that continues upward: ONE side only
	}
	gain(root)
	return best
}

func exampleMaxPathSum() {
	fmt.Println(maxPathSum(buildTree([]int{1, 2, 3})))                          // 6
	fmt.Println(maxPathSum(buildTree([]int{-10, 9, 20, NULL, NULL, 15, 7})))    // 42
	fmt.Println(maxPathSum(buildTree([]int{-3})))                               // -3
	fmt.Println(maxPathSum(buildTree([]int{2, -1})))                            // 2
}

Complexity. Time O(n), space O(h).

The pattern to remember: return one thing to the parent, record another thing globally. It also solves Diameter of a Binary Tree and Longest Univalue Path.

7. A short story: Huffman coding (from the book)

The book ends the tree chapter with Huffman coding, a way to compress text using a tree.

The idea. Normally every letter takes the same number of bits (8). But in English, e is common and z is rare. If we give common letters short codes and rare letters long codes, the text shrinks.

How the tree helps. Build a binary tree where each leaf is a letter; the code for a letter is the path from the root (0 for left, 1 for right). Common letters sit near the root (short codes). Because letters are only at the leaves, no code is the beginning of another, so a stream of bits decodes without ambiguity.

How it is built. Repeatedly take the two least frequent items and join them under a new parent whose frequency is their sum. "Repeatedly take the two smallest" is exactly a min-heap (file 17), a good follow-up exercise.

Codes: a = 0, b = 10, c = 11.

Common mistakes

  • Missing the base case for null (crashes with a null pointer).
  • Validating a BST by comparing only parent and child; you need bounds passed down.
  • Forgetting that duplicates may or may not be allowed in a BST; ask.
  • Mixing up depth and height, or counting nodes vs. edges.
  • Using recursion on a very deep, chain-shaped tree in JavaScript: stack overflow. Offer the iterative version.
  • In level order, using queue.length inside the loop after you started adding children (capture the size first).
  • In "max path sum", returning both children to the parent (a path cannot fork).
  • Assuming a balanced tree when you quote O(log n); say "O(h), which is O(log n) if balanced".

1 · Four contracts

Write down the contract, base case, and combine step for: count the nodes, sum of all values, is the tree symmetric?, path sum from root to a leaf equals target (LeetCode 112).

Answer
  • Count nodes: count(null) = 0; count(n) = 1 + count(left) + count(right).
  • Sum: sum(null) = 0; sum(n) = n.val + sum(left) + sum(right).
  • Symmetric: mirror(a, b): both null → true; one null → false; else a.val == b.val and mirror(a.left, b.right) and mirror(a.right, b.left). Call mirror(root.left, root.right).
  • Path sum: has(null, t) = false; at a leaf, t == leaf.val; otherwise has(left, t − val) or has(right, t − val).

2 · Why left < node < right is not enough

Explain with a picture why checking left < node < right alone does not validate a BST.

Answer

In [5, 4, 6, null, null, 3, 7] every node is bigger than its left child and smaller than its right child, yet 3 sits in 5's right subtree, where everything must be bigger than 5. Each node needs a window from all its ancestors. Run the third preset of the Validate BST animation.

3 · Pushing into the queue you are reading

In levelOrder, what breaks if you iterate over the queue while pushing into the same array?

Answer

The loop would keep going into the next level's nodes, so levels merge into one list (a for…of over a growing array keeps reading new items). Either build a separate next array, as the TypeScript code does, or record the level size first and read exactly that many, as the Go code does.

4 · Serialize and deserialize

Serialize and deserialize a binary tree (LeetCode 297): which traversal gives you an unambiguous encoding if you also write # for null?

Answer

Preorder with # for null (or level order with nulls). Preorder with null markers is unambiguous: read a value, build the node, then recursively build its left and right subtrees from the following tokens; # ends a branch.

5 · Inserting 1, 2, 3, 4, 5 in order

Insert the numbers 1, 2, 3, 4, 5 in order into an empty BST. What does it look like, and what is the cost of a search? What fixes it? (File 16.)

Answer

Each new value is bigger, so it goes right every time: the tree becomes a chain, height 5. Searching costs O(n) instead of O(log n). Self-balancing trees (AVL, red-black) fix it by rotating after inserts: lesson 16.
