1. The idea in plain English

A linked list is a chain of small boxes called nodes. Each node holds a value and a pointer (an arrow) to the next node. The last node's pointer is null ("nothing comes next"). You hold only the head, the first box. To reach any other box you must follow the arrows.

Why interviewers like them: there is no index to lean on, so every problem becomes a puzzle about moving and rewiring arrows without losing the rest of the chain. If you change an arrow too early, the rest of the list is gone forever.

The golden rule

Before you overwrite node.next, save what it pointed to.

Almost every bug in this topic is a lost reference.

2. How to recognize it

  • The input is described as a "linked list" or shows ListNode.
  • Words like: "in place", "O(1) extra space", "without using extra memory".
  • "Find the middle", "k-th from the end", "detect a loop", "reverse (part of) the list", "merge", "reorder".

3. The five tools to own

Tool 1 · The dummy node

Many operations have an ugly special case when the head changes (you delete the first node, or the new first node is chosen during a merge). A dummy node is a fake node placed before the head. Then every real node, including the head, has a predecessor, and the code has no special case. At the end, return dummy.next.

Tool 2 · Previous / current / next

To reverse arrows you walk with three references: where you came from (prev), where you are (cur), and where you are going (next, saved before rewiring).

Tool 3 · Slow and fast pointers ("tortoise and hare")

Move slow one step and fast two steps per round. When fast reaches the end, slow is at the middle. If there is a cycle, fast laps slow and they must meet.

Tool 4 · Gap pointers

To find the n-th node from the end without knowing the length: send fast n steps ahead, then move both together. When fast falls off the end, slow is exactly n from the end.

Tool 5 · Reverse a segment

Reversal is used inside many harder problems (palindrome list, reorder list, reverse in groups).

4. Setup used by every example below

class ListNode {
  constructor(public val: number, public next: ListNode | null = null) {}
}

function fromArray(values: number[]): ListNode | null {
  const dummy = new ListNode(0);
  let tail = dummy;
  for (const v of values) {
    tail.next = new ListNode(v);
    tail = tail.next;
  }
  return dummy.next;
}

function toArray(head: ListNode | null, limit = 1000): number[] {
  const out: number[] = [];
  for (let n = head; n !== null && out.length < limit; n = n.next) out.push(n.val);
  return out;
}

// Build a list whose tail points back to the node at index `pos` (-1 = no cycle).
function fromArrayWithCycle(values: number[], pos: number): ListNode | null {
  const head = fromArray(values);
  if (pos < 0 || head === null) return head;
  let target: ListNode = head, tail: ListNode = head;
  for (let i = 0; i < pos; i++) target = target.next!;
  while (tail.next !== null) tail = tail.next;
  tail.next = target;
  return head;
}

console.log(toArray(fromArray([1, 2, 3]))); // [ 1, 2, 3 ]
type ListNode struct {
	Val  int
	Next *ListNode
}

func fromSlice(values []int) *ListNode {
	dummy := &ListNode{}
	tail := dummy
	for _, v := range values {
		tail.Next = &ListNode{Val: v}
		tail = tail.Next
	}
	return dummy.Next
}

func toSlice(head *ListNode) []int {
	out := []int{}
	for n := head; n != nil && len(out) < 1000; n = n.Next {
		out = append(out, n.Val)
	}
	return out
}

// Build a list whose tail points back to the node at index pos (-1 = no cycle).
func fromSliceWithCycle(values []int, pos int) *ListNode {
	head := fromSlice(values)
	if pos < 0 || head == nil {
		return head
	}
	target, tail := head, head
	for i := 0; i < pos; i++ {
		target = target.Next
	}
	for tail.Next != nil {
		tail = tail.Next
	}
	tail.Next = target
	return head
}

func exampleListSetup() {
	fmt.Println(toSlice(fromSlice([]int{1, 2, 3}))) // [1 2 3]
}

5. Practice problems (easy → hard)

Problem 1 · Reverse Linked List (LeetCode 206, Easy; v2 list #1)

Task. Reverse a list. 1 → 2 → 3 → null becomes 3 → 2 → 1 → null.

Thinking. Walk down the list, and for each node point its arrow backwards at the node before it. Keep three references. The order of the four lines inside the loop matters:

  1. Save next = cur.next (otherwise we lose the rest).
  2. Flip: cur.next = prev.
  3. Move prev forward: prev = cur.
  4. Move cur forward: cur = next.

Trace. 1 → 2 → 3

Stepprevcurnext (saved)List state after the flip
startnull11 → 2 → 3
1122null ← 1 and 2 → 3
2233null ← 1 ← 2 and 3
33nullnullnull ← 1 ← 2 ← 3
endreturn prev = 3
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let cur = head;
  while (cur !== null) {
    const next = cur.next; // 1. save the rest of the list
    cur.next = prev; // 2. flip the arrow
    prev = cur; // 3. step forward
    cur = next; // 4.
  }
  return prev;
}

// Recursive version: trust that reverseListRec(head.next) returns the reversed rest.
function reverseListRec(head: ListNode | null): ListNode | null {
  if (head === null || head.next === null) return head; // base case: 0 or 1 node
  const newHead = reverseListRec(head.next); // the rest, already reversed
  head.next.next = head; // the node after me must now point back at me
  head.next = null; // and I become the tail
  return newHead;
}

console.log(toArray(reverseList(fromArray([1, 2, 3])))); // [ 3, 2, 1 ]
console.log(toArray(reverseListRec(fromArray([1, 2, 3, 4])))); // [ 4, 3, 2, 1 ]
console.log(toArray(reverseList(null))); // []
console.log(toArray(reverseList(fromArray([7])))); // [ 7 ]
func reverseList(head *ListNode) *ListNode {
	var prev *ListNode
	cur := head
	for cur != nil {
		next := cur.Next // 1. save the rest of the list
		cur.Next = prev  // 2. flip the arrow
		prev = cur       // 3. step forward
		cur = next       // 4.
	}
	return prev
}

// Recursive version: trust that reverseListRec(head.Next) returns the reversed rest.
func reverseListRec(head *ListNode) *ListNode {
	if head == nil || head.Next == nil {
		return head // base case: 0 or 1 node
	}
	newHead := reverseListRec(head.Next) // the rest, already reversed
	head.Next.Next = head                // the node after me must now point back at me
	head.Next = nil                      // and I become the tail
	return newHead
}

func exampleReverseList() {
	fmt.Println(toSlice(reverseList(fromSlice([]int{1, 2, 3}))))       // [3 2 1]
	fmt.Println(toSlice(reverseListRec(fromSlice([]int{1, 2, 3, 4})))) // [4 3 2 1]
	fmt.Println(toSlice(reverseList(nil)))                              // []
	fmt.Println(toSlice(reverseList(fromSlice([]int{7}))))              // [7]
}

Complexity. Iterative: time O(n), space O(1). Recursive: time O(n), space O(n) (call stack).

Follow-up. "Reverse only positions left to right (LeetCode 92)" or "reverse in groups of k (LeetCode 25)": reverse a segment and reconnect its two ends. Use a dummy node and save the node before the segment.

Problem 2 · Merge Two Sorted Lists (LeetCode 21, Easy)

Task. Merge two sorted lists into one sorted list by re-using the nodes. 1→2→4 and 1→3→4 → 1→1→2→3→4→4.

Thinking. Use a dummy node and a tail pointer. Compare the fronts of both lists, attach the smaller one to tail, advance that list. When one list runs out, attach the rest of the other: it is already sorted, so no more comparing.

function mergeTwoLists(a: ListNode | null, b: ListNode | null): ListNode | null {
  const dummy = new ListNode(0);
  let tail = dummy;
  while (a !== null && b !== null) {
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }
  tail.next = a !== null ? a : b; // attach the leftover (already sorted)
  return dummy.next;
}
console.log(toArray(mergeTwoLists(fromArray([1, 2, 4]), fromArray([1, 3, 4])))); // [ 1, 1, 2, 3, 4, 4 ]
console.log(toArray(mergeTwoLists(null, fromArray([0])))); // [ 0 ]
console.log(toArray(mergeTwoLists(null, null))); // []
func mergeTwoLists(a, b *ListNode) *ListNode {
	dummy := &ListNode{}
	tail := dummy
	for a != nil && b != nil {
		if a.Val <= b.Val {
			tail.Next = a
			a = a.Next
		} else {
			tail.Next = b
			b = b.Next
		}
		tail = tail.Next
	}
	if a != nil {
		tail.Next = a // attach the leftover (already sorted)
	} else {
		tail.Next = b
	}
	return dummy.Next
}

func exampleMergeTwoLists() {
	fmt.Println(toSlice(mergeTwoLists(fromSlice([]int{1, 2, 4}), fromSlice([]int{1, 3, 4})))) // [1 1 2 3 4 4]
	fmt.Println(toSlice(mergeTwoLists(nil, fromSlice([]int{0}))))                             // [0]
	fmt.Println(toSlice(mergeTwoLists(nil, nil)))                                             // []
}

Complexity. Time O(a + b), space O(1).

Follow-up. "Merge k sorted lists (LeetCode 23)": repeatedly merging is O(k · N); a min-heap of the k current fronts gives O(N log k) (file 17).

Problem 3 · Linked List Cycle and where it starts (LeetCode 141 and 142, Medium)

Task. (a) Does the list contain a cycle (some next points back to an earlier node)? (b) If so, which node starts the cycle? Use O(1) extra memory.

Easy answer with memory. Store visited nodes in a set; the first repeated node is the cycle start. O(n) time and memory. Say this first, then improve.

The slow/fast answer. slow moves 1 step, fast moves 2 steps. Without a cycle, fast reaches null. With a cycle, both end up circling in it, and fast gains 1 step per round, so it must land exactly on slow (the gap shrinks by 1 each round and cannot jump over 0).

Finding the start (the clever part). After they meet:

  1. Put a pointer at the head and keep one at the meeting point.
  2. Move both one step at a time.
  3. They meet again exactly at the cycle start.

Why this works (proof in plain words).

  • Let a = distance from head to the cycle start, c = the cycle length, and b = how far past the start the meeting point lies.
  • When they meet, slow has walked a + b steps; fast has walked 2(a + b). Fast has done extra laps: the difference a + b must be a whole number of cycle laps, say a + b = k·c.
  • So a = k·c − b: walking a steps from the meeting point lands you exactly at the cycle start (go forward c − b to finish the lap to the start, plus (k − 1) more laps).
  • A pointer starting at the head also takes a steps to get to the start. Same distance, so they arrive together.
function hasCycle(head: ListNode | null): boolean {
  let slow = head, fast = head;
  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}

function detectCycle(head: ListNode | null): ListNode | null {
  let slow = head, fast = head;
  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;
    if (slow === fast) {
      let ptr = head; // restart one pointer at the head
      while (ptr !== slow) {
        ptr = ptr!.next;
        slow = slow!.next;
      }
      return ptr; // both arrive at the cycle start together
    }
  }
  return null;
}

const looped = fromArrayWithCycle([1, 2, 3, 4, 5, 6], 2); // tail points back to the node with value 3
console.log(hasCycle(looped)); // true
console.log(detectCycle(looped)?.val); // 3
console.log(hasCycle(fromArray([1, 2, 3]))); // false
console.log(detectCycle(fromArray([1, 2, 3]))); // null
console.log(detectCycle(fromArrayWithCycle([1], 0))?.val); // 1  (a node pointing at itself)
func hasCycle(head *ListNode) bool {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
		if slow == fast {
			return true
		}
	}
	return false
}

func detectCycle(head *ListNode) *ListNode {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
		if slow == fast {
			ptr := head // restart one pointer at the head
			for ptr != slow {
				ptr = ptr.Next
				slow = slow.Next
			}
			return ptr // both arrive at the cycle start together
		}
	}
	return nil
}

func exampleDetectCycle() {
	looped := fromSliceWithCycle([]int{1, 2, 3, 4, 5, 6}, 2) // tail points back to the node with value 3
	fmt.Println(hasCycle(looped))                              // true
	fmt.Println(detectCycle(looped).Val)                       // 3
	fmt.Println(hasCycle(fromSlice([]int{1, 2, 3})))           // false
	fmt.Println(detectCycle(fromSlice([]int{1, 2, 3})) == nil) // true
	fmt.Println(detectCycle(fromSliceWithCycle([]int{1}, 0)).Val) // 1  (a node pointing at itself)
}

Complexity. Time O(n), space O(1).

Why fast moves two and not three? With step 2 the gap changes by exactly 1 per round, so they can never skip over each other. With step 3 the gap changes by 2, and the pointers could jump past each other inside an odd-length cycle (they'd still meet eventually, but the proof is harder).

Problem 4 · Remove the N-th Node From the End (LeetCode 19, Medium)

Task. Remove the n-th node from the end in one pass. 1→2→3→4→5, n = 2 → 1→2→3→5.

Thinking. We do not know the length, so we cannot count from the front. Use the gap trick: put fast exactly n + 1 nodes ahead of slow (starting from the dummy). Move both until fast falls off the end. Now slow is just before the node to delete, because the gap preserved the distance. Delete with slow.next = slow.next.next.

The dummy node handles removing the head (when n equals the list length).

Trace. 1→2→3→4→5, n = 2 (delete value 4)

Momentslow atfast at
after moving fast 3 steps (n+1)dummy3
together14
together25
together3null (stop)
delete3.next = 3.next.next → skips 4
function removeNthFromEnd(head: ListNode | null, n: number): ListNode | null {
  const dummy = new ListNode(0, head);
  let slow: ListNode = dummy;
  let fast: ListNode | null = dummy;
  for (let i = 0; i <= n; i++) fast = fast!.next; // gap of n + 1 nodes
  while (fast !== null) {
    fast = fast.next;
    slow = slow.next!;
  }
  slow.next = slow.next!.next; // skip the target node
  return dummy.next;
}
console.log(toArray(removeNthFromEnd(fromArray([1, 2, 3, 4, 5]), 2))); // [ 1, 2, 3, 5 ]
console.log(toArray(removeNthFromEnd(fromArray([1]), 1))); // []
console.log(toArray(removeNthFromEnd(fromArray([1, 2]), 2))); // [ 2 ]
func removeNthFromEnd(head *ListNode, n int) *ListNode {
	dummy := &ListNode{Next: head}
	slow, fast := dummy, dummy
	for i := 0; i <= n; i++ {
		fast = fast.Next // gap of n + 1 nodes
	}
	for fast != nil {
		fast = fast.Next
		slow = slow.Next
	}
	slow.Next = slow.Next.Next // skip the target node
	return dummy.Next
}

func exampleRemoveNthFromEnd() {
	fmt.Println(toSlice(removeNthFromEnd(fromSlice([]int{1, 2, 3, 4, 5}), 2))) // [1 2 3 5]
	fmt.Println(toSlice(removeNthFromEnd(fromSlice([]int{1}), 1)))             // []
	fmt.Println(toSlice(removeNthFromEnd(fromSlice([]int{1, 2}), 2)))          // [2]
}

Complexity. Time O(n) (one pass), space O(1).

Problem 5 · Add Two Numbers (LeetCode 2, Medium)

Task. Two non-negative numbers are stored as lists with the digits in reverse order (the head is the ones digit). Add them and return the sum in the same form. 2→4→3 (342) + 5→6→4 (465) = 7→0→8 (807).

Why reverse order is a gift: the ones digit comes first, which is exactly the order you add on paper, with a carry moving to the next digit.

Thinking. Walk both lists together. At each step: sum = a.digit + b.digit + carry. The new digit is sum % 10; the new carry is ⌊sum / 10⌋. Treat a missing node as digit 0. Keep going while either list has nodes or a carry remains, because 99 + 1 = 100 needs a new last digit.

Trace. 9→9 + 1

Stepabcarry insumdigitcarry out
19101001
29011001
3001110

Result 0→0→1 (which is 100) ✔

function addTwoNumbers(a: ListNode | null, b: ListNode | null): ListNode | null {
  const dummy = new ListNode(0);
  let tail = dummy;
  let carry = 0;
  while (a !== null || b !== null || carry > 0) {
    const sum = (a?.val ?? 0) + (b?.val ?? 0) + carry;
    tail.next = new ListNode(sum % 10);
    tail = tail.next;
    carry = Math.floor(sum / 10);
    a = a?.next ?? null;
    b = b?.next ?? null;
  }
  return dummy.next;
}
console.log(toArray(addTwoNumbers(fromArray([2, 4, 3]), fromArray([5, 6, 4])))); // [ 7, 0, 8 ]
console.log(toArray(addTwoNumbers(fromArray([9, 9]), fromArray([1])))); // [ 0, 0, 1 ]
console.log(toArray(addTwoNumbers(fromArray([0]), fromArray([0])))); // [ 0 ]
func addTwoNumbers(a, b *ListNode) *ListNode {
	dummy := &ListNode{}
	tail := dummy
	carry := 0
	for a != nil || b != nil || carry > 0 {
		sum := carry
		if a != nil {
			sum += a.Val
			a = a.Next
		}
		if b != nil {
			sum += b.Val
			b = b.Next
		}
		tail.Next = &ListNode{Val: sum % 10}
		tail = tail.Next
		carry = sum / 10
	}
	return dummy.Next
}

func exampleAddTwoNumbers() {
	fmt.Println(toSlice(addTwoNumbers(fromSlice([]int{2, 4, 3}), fromSlice([]int{5, 6, 4})))) // [7 0 8]
	fmt.Println(toSlice(addTwoNumbers(fromSlice([]int{9, 9}), fromSlice([]int{1}))))          // [0 0 1]
	fmt.Println(toSlice(addTwoNumbers(fromSlice([]int{0}), fromSlice([]int{0}))))             // [0]
}

Complexity. Time O(max(a, b)), space O(max(a, b)) for the new list.

Follow-up. "Digits stored in forward order (LeetCode 445)": reverse both lists first, add, reverse the result; or use two stacks (file 13) without modifying the input.

Problem 6 · Reorder List (LeetCode 143, Medium/Hard)

Task. Reorder L0 → L1 → … → Ln into L0 → Ln → L1 → Ln−1 → L2 → Ln−2 → …, in place. 1→2→3→4→5 → 1→5→2→4→3.

Why it is hard. The target order alternates between the front and the back, and a singly linked list cannot walk backward. The trick is to combine three tools you already know:

Trace on 1→2→3→4→5:

PhaseResult
find middleslow stops at 3; first half 1→2→3, second half 4→5
cut and reverse the second half5→4
interleave first 1→2→3 with 5→41→5→2→4→3
function reorderList(head: ListNode | null): void {
  if (head === null || head.next === null) return;

  // 1. find the middle (slow ends on the last node of the first half)
  let slow: ListNode = head, fast: ListNode | null = head;
  while (fast!.next !== null && fast!.next.next !== null) {
    slow = slow.next!;
    fast = fast!.next.next;
  }

  // 2. cut the list in two and reverse the second half
  let second = reverseList(slow.next);
  slow.next = null;

  // 3. interleave the two halves
  let first: ListNode | null = head;
  while (second !== null) {
    const firstNext: ListNode | null = first!.next;
    const secondNext: ListNode | null = second.next;
    first!.next = second;
    second.next = firstNext;
    first = firstNext;
    second = secondNext;
  }
}

const toReorder = fromArray([1, 2, 3, 4, 5]);
reorderList(toReorder);
console.log(toArray(toReorder)); // [ 1, 5, 2, 4, 3 ]
const toReorder2 = fromArray([1, 2, 3, 4]);
reorderList(toReorder2);
console.log(toArray(toReorder2)); // [ 1, 4, 2, 3 ]
func reorderList(head *ListNode) {
	if head == nil || head.Next == nil {
		return
	}

	// 1. find the middle (slow ends on the last node of the first half)
	slow, fast := head, head
	for fast.Next != nil && fast.Next.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
	}

	// 2. cut the list in two and reverse the second half
	second := reverseList(slow.Next)
	slow.Next = nil

	// 3. interleave the two halves
	first := head
	for second != nil {
		firstNext, secondNext := first.Next, second.Next
		first.Next = second
		second.Next = firstNext
		first, second = firstNext, secondNext
	}
}

func exampleReorderList() {
	a := fromSlice([]int{1, 2, 3, 4, 5})
	reorderList(a)
	fmt.Println(toSlice(a)) // [1 5 2 4 3]
	b := fromSlice([]int{1, 2, 3, 4})
	reorderList(b)
	fmt.Println(toSlice(b)) // [1 4 2 3]
}

Complexity. Time O(n), space O(1).

What to say about the middle. For an even length (1→2→3→4) this version stops slow at node 2, so the first half is 1→2 and the second is 3→4. For odd length the first half gets the extra middle node. Say which one you chose; it keeps the interleave loop correct (the loop runs while the second half has nodes, and the first half is never shorter).

Common mistakes

  • Losing the rest of the list by overwriting next before saving it.
  • No dummy node and then special-casing the head, with off-by-one errors.
  • fast.next.next without checking fast !== null && fast.next !== null (null pointer crash).
  • Forgetting to terminate the list (tail.next = null) after rearranging, which creates an accidental cycle.
  • Returning the wrong head (the original head after reversing it is now the tail).
  • Comparing values instead of node identity when detecting a cycle (duplicate values are common).
  • Modifying while traversing without a saved reference.

Try it without looking

Try each one on paper or in an editor first. Open the hint only when you are stuck, and the answer only after you have an attempt.

1 · Arrows of reverseList

Draw the arrows for each iteration of reverseList on 1→2→3 and say which line breaks if you skip "save next".

Answer

Start: null ← (prev), 1 → 2 → 3. Iteration 1: 1 → null. Iteration 2: 2 → 1. Iteration 3: 3 → 2. Return 3. If you skip "save next", the line cur = next has nothing to move to: after cur.next = prev the rest of the list is unreachable. Step through Problem 1 to watch each arrow flip.

2 · The middle in one pass

Find the middle of a list in one pass. For 1→2→3→4, which node do you return, and how would you change the loop to get the other one?

Answer

Slow moves 1, fast moves 2. With while (fast !== null && fast.next !== null), for 1→2→3→4 slow ends at 3 (the second middle). With while (fast.next !== null && fast.next.next !== null) (as in Reorder List) it ends at 2 (the first middle).

3 · Palindrome Linked List

Palindrome Linked List (LeetCode 234) in O(1) space: which two tools from this file do you combine?

Answer

Slow/fast pointers to find the middle, then reverse the second half, then compare the two halves node by node. Optionally reverse it back to restore the list. O(n) time, O(1) space.

4 · Intersection of Two Linked Lists

Intersection of Two Linked Lists (LeetCode 160): walk two pointers so each switches to the other list's head at the end. Why do they meet at the intersection?

Answer

Pointer A walks list a then list b; pointer B walks list b then list a. Both walk exactly len(a) + len(b) steps before reaching the end, so if the lists share a tail they line up and meet at the first shared node; if not, both reach null at the same time.

5 · Swap Nodes in Pairs

Swap Nodes in Pairs (LeetCode 24): why does a dummy node make this easy?

Answer

The head itself changes (the second node becomes the new head). With a dummy in front, every swap is the same rewiring: prev → second → first → rest, then move prev to first. No special case for the first pair.
