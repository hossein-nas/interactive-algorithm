Hash tables: Map and Set

Remember things so you never search twice.

Book link: Grokking Algorithms, chapter 5 (hash tables: hash functions, use cases, collisions, performance). v2 covered this as "Map and Set: save information for later". Here it gets the full treatment, including how a hash table works inside, since interviewers ask.

Reach for it when

You keep asking "have I seen this?", "how many?", "group by…", or "where is its partner?".

The big trick

Replace an inner search loop with a lookup: O(n²) becomes O(n).

What it costs

O(1) per operation on average, paid for with O(n) memory.

1. The idea in plain English

Imagine a coat check at a theater. You hand over your coat and get ticket #47. Later you show ticket 47 and the attendant walks straight to hook 47. They never look through every coat.

A hash table is that coat check. You give it a key (like a name). It runs the key through a hash function, which turns the key into a number (the hook). It stores your value at that spot. To get it back, it hashes the key again and goes straight there.

That is why lookup, insert, and delete take O(1) on average: one hash, one jump.

The three jobs a hash table does best

  1. Look things up fast. "What is this word's definition?" "What index did I see this number at?"
  2. Detect duplicates. "Have I seen this before?" (a Set).
  3. Count and group. "How many times does each letter appear?" "Which words are anagrams of each other?"

When you hear a problem say "have I seen…", "count the…", "group by…", "find a pair…", or "first non-repeating…", think hash table first.

2. How it works inside (what interviewers may ask)

A good hash function

A good hash function must:

  1. Give the same output for the same input every time (otherwise you could never find your value again).
  2. Spread keys evenly across the slots, so no slot gets crowded.

Collisions: two keys, one slot

What if two different keys hash to the same slot? That is a collision. It is not a bug; it is expected, because there are far more possible keys than slots.

The simplest fix is chaining: each slot holds a small linked list of every key/value that landed there. On lookup, you hash to the slot, then walk that short list comparing keys.

Here "apple" and "avocado" collide in slot 1. Lookups for either key go to slot 1 and walk a list of two.

(The other main fix is open addressing: if the slot is taken, probe the next slot, and the next, until you find a free one. Go's map and many languages use cleverly tuned versions of these ideas. You do not need to implement either in an interview, but you should be able to describe chaining.)

Load factor and resizing

The load factor is items ÷ slots. When the table is too full (commonly around 0.7–0.75), chains get long and lookups slow down. So the table resizes: it allocates a larger array (usually double) and re-inserts every item. That one resize costs O(n), but it happens rarely, so the amortized cost of an insert stays O(1) (see the amortized section in file 02).

Watch a small table work: hash, collide, chain, and resize when the load factor passes 0.75. The code is the hash set from exercise 5.

What can be a key?

  • TypeScript Map: any value, but objects and arrays are compared by identity (the same box in memory), not by contents. [1,2] and [1,2] are different keys. Turn them into strings ("1,2").
  • Go map: any comparable type: numbers, strings, bools, arrays like [26]int, structs of comparable fields. Not slices, maps, or functions.

3. How to recognize a hash-table problem

The most powerful hash-table trick is the "replace the inner loop" idea. If you have a nested loop where the inner loop searches for something, ask "can I look that thing up instead?" That turns O(n²) into O(n), paying with O(n) memory.

4. Reusable templates

Template A · Frequency count

function frequencyOf<T>(items: T[]): Map<T, number> {
  const freq = new Map<T, number>();
  for (const item of items) freq.set(item, (freq.get(item) ?? 0) + 1);
  return freq;
}
console.log(frequencyOf(["a", "b", "a"])); // Map(2) { 'a' => 2, 'b' => 1 }
func frequencyOf[T comparable](items []T) map[T]int {
	freq := make(map[T]int)
	for _, item := range items {
		freq[item]++
	}
	return freq
}

func exampleFrequencyOf() {
	fmt.Println(frequencyOf([]string{"a", "b", "a"})) // map[a:2 b:1]
}

Template B · "Seen before?" with a Set

function hasDuplicate(nums: number[]): boolean {
  const seen = new Set<number>();
  for (const x of nums) {
    if (seen.has(x)) return true;
    seen.add(x);
  }
  return false;
}
console.log(hasDuplicate([1, 2, 3, 1]), hasDuplicate([1, 2, 3])); // true false
func hasDuplicate(nums []int) bool {
	seen := make(map[int]struct{})
	for _, x := range nums {
		if _, ok := seen[x]; ok {
			return true
		}
		seen[x] = struct{}{}
	}
	return false
}

func exampleHasDuplicate() {
	fmt.Println(hasDuplicate([]int{1, 2, 3, 1}), hasDuplicate([]int{1, 2, 3})) // true false
}

5. Practice problems (easy → hard)

Problem 1 · Two Sum (LeetCode 1, Easy)

Task. Given nums and target, return the indexes of the two numbers that add up to target. Exactly one answer exists; you cannot use the same element twice.

Example: nums = [2, 7, 11, 15], target = 9 → [0, 1].

Brute force. Try every pair: O(n²) time, O(1) space.

The key insight. For each number x, the partner you need is target - x. The slow part is searching for that partner. A hash map answers "have I seen this value, and at which index?" in O(1). So walk the array once; before storing x, ask the map whether target - x is already there.

Trace. nums = [2, 7, 11, 15], target = 9

ixneed = 9 − xmap beforeFound?map after
027{}no{2:0}
172{2:0}yes, index 0return [0,1]

Why check before storing? For [3, 3] with target 6: at index 0 the map is empty, so we store 3→0. At index 1 we need 3, find it at index 0, and return [0,1]. If we had stored first, at index 0 we would have found ourselves and wrongly paired an element with itself.

function twoSum(nums: number[], target: number): number[] {
  const indexOf = new Map<number, number>(); // value -> index
  for (let i = 0; i < nums.length; i++) {
    const partner = indexOf.get(target - nums[i]);
    if (partner !== undefined) return [partner, i];
    indexOf.set(nums[i], i);
  }
  return [];
}
console.log(twoSum([2, 7, 11, 15], 9)); // [ 0, 1 ]
console.log(twoSum([3, 3], 6)); // [ 0, 1 ]
console.log(twoSum([1, 2], 7)); // []
func twoSum(nums []int, target int) []int {
	indexOf := make(map[int]int) // value -> index
	for i, x := range nums {
		if j, ok := indexOf[target-x]; ok {
			return []int{j, i}
		}
		indexOf[x] = i
	}
	return []int{}
}

func exampleTwoSum() {
	fmt.Println(twoSum([]int{2, 7, 11, 15}, 9)) // [0 1]
	fmt.Println(twoSum([]int{3, 3}, 6))         // [0 1]
	fmt.Println(twoSum([]int{1, 2}, 7))         // []
}

Complexity. Time O(n): one pass, each map step is O(1) on average. Space O(n): the map can hold every number.

Interviewer follow-ups.

  • "What if the array were sorted and I want O(1) memory?" → two pointers (file 05).
  • "What if there can be many answers?" → collect all pairs; handle duplicate values carefully.
  • "What if the values are huge streams?" → the map needs memory proportional to the stream; consider sorting on disk.

Problem 2 · Valid Anagram (LeetCode 242, Easy)

Task. Return whether t is a rearrangement of the letters of s. Example: "anagram", "nagaram" → true; "rat", "car" → false.

Brute force. Sort both strings and compare: O(n log n). Valid, and a fine first answer.

Better idea. Two words are anagrams exactly when every letter appears the same number of times. Count the letters of s going up; count t going down; if everything ends at zero, they match. For lowercase a–z a 26-slot array is the fastest "map".

Trace. s = "aab", t = "aba"

StepActioncounts (a, b)
start(0, 0)
s[0]='a'+1(1, 0)
s[1]='a'+1(2, 0)
s[2]='b'+1(2, 1)
t[0]='a'−1(1, 1)
t[1]='b'−1(1, 0)
t[2]='a'−1(0, 0)

All zeros → anagram. If any count would go negative while subtracting, t has a letter s does not have enough of, so you can stop and return false early.

function isAnagram(s: string, t: string): boolean {
  if (s.length !== t.length) return false; // different lengths can never match
  const counts = new Map<string, number>(); // Map handles any characters, not only a-z
  for (const ch of s) counts.set(ch, (counts.get(ch) ?? 0) + 1);
  for (const ch of t) {
    const left = counts.get(ch) ?? 0;
    if (left === 0) return false; // t has more of ch than s does
    counts.set(ch, left - 1);
  }
  return true;
}
console.log(isAnagram("anagram", "nagaram")); // true
console.log(isAnagram("rat", "car")); // false
console.log(isAnagram("", "")); // true
func isAnagram(s, t string) bool {
	if len(s) != len(t) {
		return false
	}
	counts := make(map[rune]int) // rune handles any character, not only a-z
	for _, ch := range s {
		counts[ch]++
	}
	for _, ch := range t {
		if counts[ch] == 0 {
			return false
		}
		counts[ch]--
	}
	return true
}

func exampleIsAnagram() {
	fmt.Println(isAnagram("anagram", "nagaram")) // true
	fmt.Println(isAnagram("rat", "car"))         // false
	fmt.Println(isAnagram("", ""))               // true
}

Complexity. Time O(n). Space O(k) where k is the number of distinct characters (at most 26 for lowercase English: effectively O(1)).

Follow-up. "What if the input has Unicode?" The map version already works; a fixed 26-array would not. In Go note that the length check uses bytes, which is still correct for equality of anagrams made of the same characters (same characters → same byte length).

Problem 3 · Group Anagrams (LeetCode 49, Medium)

Task. Group the words that are anagrams of each other. ["eat","tea","tan","ate","nat","bat"] → [["eat","tea","ate"],["tan","nat"],["bat"]] (any order).

Key insight. We need a signature that is identical for all anagrams and different otherwise. Two good signatures:

  1. Sorted letters: "eat", "tea", "ate" all become "aet". Cost per word: O(L log L).
  2. 26 letter counts: "eat" → 1,0,0,0,1,...,1,.... Cost per word: O(L).

Use the signature as the map key; the value is the list of words.

function groupAnagrams(words: string[]): string[][] {
  const groups = new Map<string, string[]>();
  for (const word of words) {
    const key = [...word].sort().join(""); // signature: letters in order
    const bucket = groups.get(key);
    if (bucket) bucket.push(word);
    else groups.set(key, [word]);
  }
  return [...groups.values()];
}
console.log(groupAnagrams(["eat", "tea", "tan", "ate", "nat", "bat"]));
// [ [ 'eat', 'tea', 'ate' ], [ 'tan', 'nat' ], [ 'bat' ] ]
console.log(groupAnagrams([""])); // [ [ '' ] ]
func groupAnagrams(words []string) [][]string {
	groups := make(map[[26]int][]string) // an array of counts is a valid map key
	order := [][26]int{}                 // remember first-seen order so output is stable
	for _, word := range words {
		var key [26]int
		for i := 0; i < len(word); i++ {
			key[word[i]-'a']++
		}
		if _, ok := groups[key]; !ok {
			order = append(order, key)
		}
		groups[key] = append(groups[key], word)
	}
	result := make([][]string, 0, len(groups))
	for _, key := range order {
		result = append(result, groups[key])
	}
	return result
}

func exampleGroupAnagrams() {
	fmt.Println(groupAnagrams([]string{"eat", "tea", "tan", "ate", "nat", "bat"}))
	// [[eat tea ate] [tan nat] [bat]]
	fmt.Println(len(groupAnagrams([]string{""}))) // 1
}

Complexity. With m words of maximum length L: TypeScript (sorted key) O(m · L log L), Go (count key) O(m · L). Space O(m · L) for the keys and groups.

Why a Go map iteration needs order: Go's map iteration order is random, so we keep a slice of keys in first-seen order to make our output predictable and easy to test. In an interview you can usually say "order does not matter", but stable output is easier to check.

Problem 4 · Intersection of Two Arrays (LeetCode 349, Easy)

Task. Return the distinct values that appear in both arrays. [1,2,2,1] and [2,2] → [2].

Brute force. For each item in a, scan b: O(a · b).

Better idea. Put a into a set. Walk b; whenever an item is in the set, add it to the answer and remove it from the set so it is not added twice.

function intersection(a: number[], b: number[]): number[] {
  const pending = new Set(a); // values from a that we have not yet reported
  const result: number[] = [];
  for (const x of b) {
    if (pending.has(x)) {
      result.push(x);
      pending.delete(x); // report each value only once
    }
  }
  return result;
}
console.log(intersection([1, 2, 2, 1], [2, 2])); // [ 2 ]
console.log(intersection([4, 9, 5], [9, 4, 9, 8, 4])); // [ 9, 4 ]
func intersection(a, b []int) []int {
	pending := make(map[int]struct{}, len(a))
	for _, x := range a {
		pending[x] = struct{}{}
	}
	result := []int{}
	for _, x := range b {
		if _, ok := pending[x]; ok {
			result = append(result, x)
			delete(pending, x) // report each value only once
		}
	}
	return result
}

func exampleIntersection() {
	fmt.Println(intersection([]int{1, 2, 2, 1}, []int{2, 2}))       // [2]
	fmt.Println(intersection([]int{4, 9, 5}, []int{9, 4, 9, 8, 4})) // [9 4]
}

Complexity. Time O(a + b), space O(a).

Follow-up (very common). "What if both arrays are already sorted?" Use two pointers: no extra memory (file 05). "What if a is tiny and b is huge?" Put the small one in the set and stream the big one. "What if you must keep duplicates (LeetCode 350)?" Use a count map and decrement it on each match.

Problem 5 · Longest Consecutive Sequence (LeetCode 128, Medium)

Task. Given an unsorted array, return the length of the longest run of consecutive integers (like 100, 101, 102), in O(n) time. [100, 4, 200, 1, 3, 2] → 4 (the run 1,2,3,4).

Brute force. Sort and scan: O(n log n). The problem demands O(n), so sorting is not allowed.

The key insight, step by step.

  1. Put every number in a set so "is x+1 present?" is instant.
  2. For each number, we could count how far the run goes upward. But if we did that from every number, a long run like 1,2,3,…,n would be counted over and over: O(n²).
  3. Only start counting from the beginning of a run. A number is a run's start if x - 1 is not in the set. Skip all others.
  4. From each start, walk upward while x + 1 exists.

Each number is visited at most twice overall (once as a candidate, at most once inside one run), so the total is O(n), even though there is a while inside a for.

Trace. [100, 4, 200, 1, 3, 2], set {100, 4, 200, 1, 3, 2}

function longestConsecutive(nums: number[]): number {
  const all = new Set(nums); // also removes duplicates
  let best = 0;
  for (const x of all) {
    if (all.has(x - 1)) continue; // not the start of a run
    let cur = x;
    while (all.has(cur + 1)) cur++;
    best = Math.max(best, cur - x + 1);
  }
  return best;
}
console.log(longestConsecutive([100, 4, 200, 1, 3, 2])); // 4
console.log(longestConsecutive([0, 3, 7, 2, 5, 8, 4, 6, 0, 1])); // 9
console.log(longestConsecutive([])); // 0
func longestConsecutive(nums []int) int {
	all := make(map[int]struct{}, len(nums))
	for _, x := range nums {
		all[x] = struct{}{}
	}
	best := 0
	for x := range all {
		if _, ok := all[x-1]; ok {
			continue // not the start of a run
		}
		cur := x
		for {
			if _, ok := all[cur+1]; !ok {
				break
			}
			cur++
		}
		best = max(best, cur-x+1)
	}
	return best
}

func exampleLongestConsecutive() {
	fmt.Println(longestConsecutive([]int{100, 4, 200, 1, 3, 2}))            // 4
	fmt.Println(longestConsecutive([]int{0, 3, 7, 2, 5, 8, 4, 6, 0, 1})) // 9
	fmt.Println(longestConsecutive(nil))                                    // 0
}

Complexity. Time O(n) average. Space O(n).

Why interviewers love this one. It tests whether you can explain why a nested loop is still linear. The magic sentence: "I only start counting from numbers with no left neighbor, so each number is walked at most once."

Problem 6 · LRU Cache (LeetCode 146, Medium)

Task. Design a cache with fixed capacity. get(key) returns the value (or -1); put(key, value) stores it. When full, evict the least recently used key. Both operations must be O(1).

Why a hash map alone is not enough. A map finds a key instantly but cannot tell you which key is the oldest. A list alone is not enough either, because finding a key inside it takes O(n).

Combine them. This is a classic combination from the book's ideas: a hash table for instant lookup, and a doubly linked list for instant reordering.

  • On get: find the node via the map, move it to the front (most recent), return its value.
  • On put: if the key exists, update and move to front. If new, add at the front; if over capacity, remove the node at the back and delete its key from the map.

TypeScript shortcut. A JavaScript Map remembers insertion order. So "move to front" is just delete the key, then set it again (it goes to the end of the order). The first key in the map is then the least recently used.

Go. There is no ordered map, so we use container/list (a doubly linked list) plus a map[int]*list.Element.

class LRUCache {
  private store = new Map<number, number>(); // insertion order = recency order
  constructor(private capacity: number) {}

  get(key: number): number {
    const value = this.store.get(key);
    if (value === undefined) return -1;
    this.store.delete(key); // refresh: remove then re-insert at the end
    this.store.set(key, value);
    return value;
  }

  put(key: number, value: number): void {
    if (this.store.has(key)) this.store.delete(key);
    this.store.set(key, value);
    if (this.store.size > this.capacity) {
      const oldest = this.store.keys().next().value as number; // first key = least recent
      this.store.delete(oldest);
    }
  }
}

type lruEntry struct{ key, value int }

type LRUCache struct {
	capacity int
	order    *list.List            // front = most recent, back = least recent
	nodes    map[int]*list.Element // key -> its node in the list
}

func NewLRUCache(capacity int) *LRUCache {
	return &LRUCache{capacity: capacity, order: list.New(), nodes: make(map[int]*list.Element)}
}

func (c *LRUCache) Get(key int) int {
	node, ok := c.nodes[key]
	if !ok {
		return -1
	}
	c.order.MoveToFront(node)
	return node.Value.(*lruEntry).value
}

func (c *LRUCache) Put(key, value int) {
	if node, ok := c.nodes[key]; ok {
		node.Value.(*lruEntry).value = value
		c.order.MoveToFront(node)
		return
	}
	c.nodes[key] = c.order.PushFront(&lruEntry{key, value})
	if c.order.Len() > c.capacity {
		oldest := c.order.Back()
		c.order.Remove(oldest)
		delete(c.nodes, oldest.Value.(*lruEntry).key)
	}
}

func exampleLRUCache() {
	cache := NewLRUCache(2)
	cache.Put(1, 1)
	cache.Put(2, 2)
	fmt.Println(cache.Get(1)) // 1
	cache.Put(3, 3)           // evicts key 2
	fmt.Println(cache.Get(2)) // -1
	cache.Put(4, 4)           // evicts key 1
	fmt.Println(cache.Get(1), cache.Get(3), cache.Get(4)) // -1 3 4
}

Follow-ups. "Make it thread-safe" → a mutex around every operation. "LFU instead of LRU" → count frequencies, which needs a second structure. "Add expiry times" → store a timestamp and discard lazily on get.

Common mistakes

  • Checking truthiness instead of presence. In TypeScript if (map.get(k)) fails when the stored value is 0. In Go use the v, ok form when zero is a valid value.
  • Storing before checking in pair problems (pairing an item with itself).
  • Using an object or array as a TypeScript Map key and expecting content-based equality.
  • Relying on Go's map iteration order. It is intentionally random.
  • Mutating a collection while iterating over it.
  • Forgetting about duplicates when converting an array to a set (it removes them, which may change counts).
  • Assuming O(1) is a guarantee. It is an average.

2 · First non-repeating character

Solve "first non-repeating character in a string" with a frequency map in two passes. Why does it need two passes?

Hint

A character's count is only known after you have seen the whole string.

Answer

Pass 1 counts every character. Pass 2 walks the string again in order and returns the first index whose count is 1. It needs two passes because when you first meet a character you cannot know whether it appears again later. O(n) time, O(k) space.

function firstUniqueChar(s: string): number {
  const counts = new Map<string, number>();
  for (const ch of s) counts.set(ch, (counts.get(ch) ?? 0) + 1); // pass 1: count everything
  for (let i = 0; i < s.length; i++) {
    if (counts.get(s[i]) === 1) return i; // pass 2: the first character seen once
  }
  return -1;
}
console.log(firstUniqueChar("leetcode")); // 0
console.log(firstUniqueChar("loveleetcode")); // 2
console.log(firstUniqueChar("aabb")); // -1
func firstUniqueChar(s string) int {
	counts := make(map[byte]int)
	for i := 0; i < len(s); i++ {
		counts[s[i]]++ // pass 1: count everything
	}
	for i := 0; i < len(s); i++ {
		if counts[s[i]] == 1 {
			return i // pass 2: the first character seen once
		}
	}
	return -1
}

func exampleFirstUniqueChar() {
	fmt.Println(firstUniqueChar("leetcode"))     // 0
	fmt.Println(firstUniqueChar("loveleetcode")) // 2
	fmt.Println(firstUniqueChar("aabb"))         // -1
}

3 · Isomorphic strings

Given s and t, decide whether they are isomorphic (a one-to-one character mapping exists). Which two maps do you need, and why?

Hint

Try "badc" and "baba" with only one map. What goes wrong?

Answer

You need two maps: s → t makes sure each character of s always maps to the same character of t, and t → s makes sure no two characters of s map to the same character of t. With only the first map, "badc" and "baba" would pass, because b → b and d → b both look fine on their own.

function isIsomorphic(s: string, t: string): boolean {
  if (s.length !== t.length) return false;
  const sToT = new Map<string, string>(); // each s-char maps to one t-char
  const tToS = new Map<string, string>(); // and no two s-chars share a t-char
  for (let i = 0; i < s.length; i++) {
    const a = s[i], b = t[i];
    if (sToT.has(a) && sToT.get(a) !== b) return false;
    if (tToS.has(b) && tToS.get(b) !== a) return false;
    sToT.set(a, b);
    tToS.set(b, a);
  }
  return true;
}

console.log(isIsomorphic("foo", "bar")); // false

func isIsomorphic(s, t string) bool {
	if len(s) != len(t) {
		return false
	}
	sToT := make(map[byte]byte) // each s-char maps to one t-char
	tToS := make(map[byte]byte) // and no two s-chars share a t-char
	for i := 0; i < len(s); i++ {
		a, b := s[i], t[i]
		if v, ok := sToT[a]; ok && v != b {
			return false
		}
		if v, ok := tToS[b]; ok && v != a {
			return false
		}
		sToT[a] = b
		tToS[b] = a
	}
	return true
}

	fmt.Println(isIsomorphic("foo", "bar"))   // false
	fmt.Println(isIsomorphic("badc", "baba")) // false
}

4 · Why start only at run beginnings

Why does Longest Consecutive Sequence only start counting at numbers whose left neighbor is missing?

Answer

If you counted upward from every number, a run of length n would be walked from each of its numbers: n + (n−1) + … + 1, which is O(n²). Starting only where x − 1 is missing walks each run exactly once, from its first number, so every number is visited at most twice in total: O(n). 5 · A HashSet with chaining

Design a HashSet class with add, remove, contains using only an array of arrays (chaining). What do you do on resize?

Hint

Store an array of buckets; the slot is key mod the number of buckets. What should happen when there are many more keys than buckets?

Answer

Keep an array of buckets, each a small list. add hashes the key to a slot and appends it if it is not already in that chain; contains searches one chain; remove deletes from one chain. On resize, when count / buckets passes about 0.75, allocate twice as many buckets and re-insert every key, because a key's slot depends on the number of buckets. The resize is O(n) but rare, so operations stay amortized O(1). The hash-table animation in section 2 runs this exact code.

class MyHashSet {
  private buckets: number[][] = Array.from({ length: 4 }, () => []);
  private count = 0;

  private slot(key: number): number {
    const n = this.buckets.length;
    return ((key % n) + n) % n; // positive modulo, so negative keys work too
  }

  add(key: number): void {
    if (this.contains(key)) return;
    this.buckets[this.slot(key)].push(key);
    this.count++;
    if (this.count / this.buckets.length > 0.75) this.resize(); // keep chains short
  }

  remove(key: number): void {
    const chain = this.buckets[this.slot(key)];
    const i = chain.indexOf(key);
    if (i >= 0) {
      chain.splice(i, 1);
      this.count--;
    }
  }

  contains(key: number): boolean {
    return this.buckets[this.slot(key)].includes(key);
  }

  private resize(): void {
    const old = this.buckets;
    this.buckets = Array.from({ length: old.length * 2 }, () => []);
    for (const chain of old) for (const key of chain) this.buckets[this.slot(key)].push(key); // re-insert everything
  }
}

type MyHashSet struct {
	buckets [][]int
	count   int
}

func NewMyHashSet() *MyHashSet {
	return &MyHashSet{buckets: make([][]int, 4)}
}

func (h *MyHashSet) slot(key int) int {
	n := len(h.buckets)
	return ((key % n) + n) % n // positive modulo, so negative keys work too
}

func (h *MyHashSet) Add(key int) {
	if h.Contains(key) {
		return
	}
	s := h.slot(key)
	h.buckets[s] = append(h.buckets[s], key)
	h.count++
	if float64(h.count)/float64(len(h.buckets)) > 0.75 {
		h.resize() // keep chains short
	}
}

func (h *MyHashSet) Remove(key int) {
	s := h.slot(key)
	chain := h.buckets[s]
	for i, k := range chain {
		if k == key {
			h.buckets[s] = append(chain[:i], chain[i+1:]...)
			h.count--
			return
		}
	}
}

func (h *MyHashSet) Contains(key int) bool {
	for _, k := range h.buckets[h.slot(key)] {
		if k == key {
			return true
		}
	}
	return false
}

func (h *MyHashSet) resize() {
	old := h.buckets
	h.buckets = make([][]int, len(old)*2)
	for _, chain := range old {
		for _, key := range chain {
			s := h.slot(key) // re-insert everything
			h.buckets[s] = append(h.buckets[s], key)
		}
	}
}

	hs := NewMyHashSet()
	for _, k := range []int{1, 5, 9, 2, 6} {
		hs.Add(k)
	}
	fmt.Println(hs.Contains(9), hs.Contains(3)) // true false
	hs.Remove(9)
	fmt.Println(hs.Contains(9)) // false
}
