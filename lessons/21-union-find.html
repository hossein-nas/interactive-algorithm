Union-find

Every group has a leader; merging is just pointing one leader at another.

Book link: Grokking Algorithms does not cover this structure, but it solves the same family of questions as chapter 6's connected-friends graph search ("who is connected to whom?") with a much faster tool when the graph grows over time. It is the engine behind Kruskal's minimum spanning tree (the book's appendix on NP-hard problems and chapter 9 mention related graph ideas). This file is new compared with v2.

Reach for it when

Groups that only ever merge: connectivity as edges arrive, cycles in undirected graphs, Kruskal.

How it works

parent[] forms a forest; a tree's root is the group's leader. find climbs to it; union hangs one root under another.

What it costs

With union by size and path compression, nearly O(1) per operation.

1. The idea in plain English

Imagine a party where people keep discovering that they know each other. After "Ann knows Bob" and "Bob knows Cara", Ann, Bob, and Cara form one friend group. Your job is to answer, quickly, at any moment:

  • Are Ann and Dan in the same group?
  • How many separate groups are there?

You could run BFS every time (file 19), but that costs O(V + E) per question. Union-find (also called disjoint set union, DSU) answers each question in almost constant time, even while groups merge.

It supports two operations:

OperationMeaning
find(x)Which group is x in? (Returns a representative, the "leader" of the group.)
union(a, b)Merge the group of a and the group of b.

Two items are in the same group exactly when find(a) == find(b).

2. How it works inside

Each item points to a parent; the leader points to itself

Store one array parent. At the start, everyone is their own leader: parent[i] = i. A group is a little tree whose root is the leader.

  • find(x): follow parent pointers up until you reach an item that is its own parent: that is the leader.
  • union(a, b): find both leaders; if they differ, make one leader point to the other.

The problem: trees can become tall chains

If you always attach in the same direction, union(1,2), union(2,3), union(3,4)… can build a chain 1 → 2 → 3 → … and find becomes O(n). Two small, famous fixes make it nearly constant:

Path compression picture: find(5) walks 5 → 4 → 3 → 1. Afterwards 5, 4, and 3 all point directly at 1.

Cost with both fixes: each operation takes O(α(n)) amortized, where α is the inverse Ackermann function, which is at most 4 for any n you could ever store in the universe. In an interview say "effectively constant" (and "O(α(n)), the inverse Ackermann" if you want to impress).

The standard implementation

class UnionFind {
  private parent: number[];
  private size: number[]; // size[root] = number of items in that group
  count: number; // the number of separate groups

  constructor(n: number) {
    this.parent = Array.from({ length: n }, (_, i) => i); // everyone is their own leader
    this.size = new Array<number>(n).fill(1);
    this.count = n;
  }

  find(x: number): number {
    while (this.parent[x] !== x) {
      this.parent[x] = this.parent[this.parent[x]]; // path halving: skip one level as we climb
      x = this.parent[x];
    }
    return x;
  }

  // Returns true if a merge happened, false if they were already together.
  union(a: number, b: number): boolean {
    let rootA = this.find(a), rootB = this.find(b);
    if (rootA === rootB) return false; // already in the same group
    if (this.size[rootA] < this.size[rootB]) [rootA, rootB] = [rootB, rootA]; // A is the bigger tree
    this.parent[rootB] = rootA; // hang the smaller tree under the bigger
    this.size[rootA] += this.size[rootB];
    this.count--;
    return true;
  }

  connected(a: number, b: number): boolean {
    return this.find(a) === this.find(b);
  }
}

type UnionFind struct {
	parent []int
	size   []int // size[root] = number of items in that group
	Count  int   // the number of separate groups
}

func NewUnionFind(n int) *UnionFind {
	uf := &UnionFind{parent: make([]int, n), size: make([]int, n), Count: n}
	for i := range uf.parent {
		uf.parent[i] = i // everyone is their own leader
		uf.size[i] = 1
	}
	return uf
}

func (u *UnionFind) Find(x int) int {
	for u.parent[x] != x {
		u.parent[x] = u.parent[u.parent[x]] // path halving: skip one level as we climb
		x = u.parent[x]
	}
	return x
}

// Union returns true if a merge happened, false if they were already together.
func (u *UnionFind) Union(a, b int) bool {
	rootA, rootB := u.Find(a), u.Find(b)
	if rootA == rootB {
		return false // already in the same group
	}
	if u.size[rootA] < u.size[rootB] {
		rootA, rootB = rootB, rootA // A is the bigger tree
	}
	u.parent[rootB] = rootA // hang the smaller tree under the bigger
	u.size[rootA] += u.size[rootB]
	u.Count--
	return true
}

func (u *UnionFind) Connected(a, b int) bool { return u.Find(a) == u.Find(b) }

func exampleUnionFind() {
	uf := NewUnionFind(6)
	uf.Union(0, 1)
	uf.Union(1, 2)
	uf.Union(3, 4)
	fmt.Println(uf.Connected(0, 2), uf.Connected(0, 3)) // true false
	fmt.Println(uf.Count)                                // 3   groups: {0,1,2}, {3,4}, {5}
	fmt.Println(uf.Union(0, 2))                          // false  (already together)
}

Path halving vs. full compression. Full compression (recursive: parent[x] = find(parent[x])) makes every node on the path point at the root. Path halving (the code above) is iterative and has the same speed. Use it to avoid deep recursion.

What is "the leader"? Only the root of each tree. Its identity can change after a union, so never store a leader; always call find.

3. When to use union-find (vs. BFS/DFS)

SituationBest tool
Graph is fixed; answer a single connectivity questionBFS/DFS: simple
Edges arrive over time; keep asking "are these connected?" or "how many groups?"Union-find
"Does adding this edge create a cycle?" in an undirected graphUnion-find: if find(a) == find(b) the edge closes a cycle
Kruskal's minimum spanning tree (sort edges, add if they join different groups)Union-find
Group items that are "equivalent" under a rule (accounts with a shared email)Union-find
Directed graph cycle / orderingtopological sort (file 20), not union-find
Shortest pathsBFS or Dijkstra

Union-find cannot split groups (no "delete an edge"). If edges are removed, run it backwards in time (add them instead) or use another structure.

Problem 1 · Number of Connected Components (LeetCode 323, Medium)

Task. n nodes labeled 0..n−1 and a list of undirected edges. Return the number of connected components. n = 5, edges [[0,1],[1,2],[3,4]] → 2.

Idea. Start with n groups (everyone alone). For each edge, union the endpoints; every successful merge reduces the group count by one. The final count is the answer. (BFS/DFS also works: this is the "new search per unvisited node" count.)

function countComponents(n: number, edges: number[][]): number {
  const uf = new UnionFind(n);
  for (const [a, b] of edges) uf.union(a, b);
  return uf.count;
}
console.log(countComponents(5, [[0, 1], [1, 2], [3, 4]])); // 2
console.log(countComponents(5, [[0, 1], [1, 2], [2, 3], [3, 4]])); // 1
console.log(countComponents(3, [])); // 3
func countComponents(n int, edges [][]int) int {
	uf := NewUnionFind(n)
	for _, e := range edges {
		uf.Union(e[0], e[1])
	}
	return uf.Count
}

func exampleCountComponents() {
	fmt.Println(countComponents(5, [][]int{{0, 1}, {1, 2}, {3, 4}}))         // 2
	fmt.Println(countComponents(5, [][]int{{0, 1}, {1, 2}, {2, 3}, {3, 4}})) // 1
	fmt.Println(countComponents(3, nil))                                     // 3
}

Complexity. Time O((V + E) · α(V)), space O(V).

Problem 2 · Redundant Connection (LeetCode 684, Medium)

Task. A tree with n nodes (labeled 1..n) had one extra edge added, creating exactly one cycle. Given the edge list, return the edge that can be removed to make it a tree again; if several work, return the one that appears last in the input. [[1,2],[1,3],[2,3]] → [2,3].

Idea. Add the edges one by one. An edge (a, b) is redundant exactly when a and b are already connected: the new edge would close a cycle. The first edge for which union returns false is the one that closes the cycle (and it is the last in input order among the cycle's edges).

1–2differentmerge
1–3differentmerge

function findRedundantConnection(edges: number[][]): number[] {
  const uf = new UnionFind(edges.length + 1); // nodes are 1..n and a tree plus one edge has n edges
  for (const [a, b] of edges) {
    if (!uf.union(a, b)) return [a, b]; // already connected: this edge closes a cycle
  }
  return [];
}
console.log(findRedundantConnection([[1, 2], [1, 3], [2, 3]])); // [ 2, 3 ]
console.log(findRedundantConnection([[1, 2], [2, 3], [3, 4], [1, 4], [1, 5]])); // [ 1, 4 ]
func findRedundantConnection(edges [][]int) []int {
	uf := NewUnionFind(len(edges) + 1) // nodes are 1..n and a tree plus one edge has n edges
	for _, e := range edges {
		if !uf.Union(e[0], e[1]) {
			return e // already connected: this edge closes a cycle
		}
	}
	return nil
}

func exampleFindRedundantConnection() {
	fmt.Println(findRedundantConnection([][]int{{1, 2}, {1, 3}, {2, 3}}))                   // [2 3]
	fmt.Println(findRedundantConnection([][]int{{1, 2}, {2, 3}, {3, 4}, {1, 4}, {1, 5}})) // [1 4]
}

Complexity. Time O(n · α(n)), space O(n).

Problem 3 · Graph Valid Tree (LeetCode 261, Medium)

Task. n nodes and a list of undirected edges. Is the graph a valid tree (connected, no cycles)? n = 5, [[0,1],[0,2],[0,3],[1,4]] → true; [[0,1],[1,2],[2,3],[1,3],[1,4]] → false.

Idea. A tree on n nodes has exactly n − 1 edges, is connected, and has no cycle. Any two of these imply the third. So:

  1. If edges.length != n − 1, answer false immediately.
  2. Union every edge. If any union finds the endpoints already connected, there is a cycle → false.
  3. With n − 1 edges and no cycles, the graph is automatically connected → true.
function validTree(n: number, edges: number[][]): boolean {
  if (edges.length !== n - 1) return false; // a tree has exactly n - 1 edges
  const uf = new UnionFind(n);
  for (const [a, b] of edges) {
    if (!uf.union(a, b)) return false; // a cycle
  }
  return true; // n - 1 edges and no cycle: it must be connected
}
console.log(validTree(5, [[0, 1], [0, 2], [0, 3], [1, 4]])); // true
console.log(validTree(5, [[0, 1], [1, 2], [2, 3], [1, 3], [1, 4]])); // false
console.log(validTree(4, [[0, 1], [2, 3], [2, 3]])); // false   (a duplicate edge makes a cycle)
console.log(validTree(1, [])); // true
func validTree(n int, edges [][]int) bool {
	if len(edges) != n-1 {
		return false // a tree has exactly n - 1 edges
	}
	uf := NewUnionFind(n)
	for _, e := range edges {
		if !uf.Union(e[0], e[1]) {
			return false // a cycle
		}
	}
	return true // n - 1 edges and no cycle: it must be connected
}

func exampleValidTree() {
	fmt.Println(validTree(5, [][]int{{0, 1}, {0, 2}, {0, 3}, {1, 4}}))         // true
	fmt.Println(validTree(5, [][]int{{0, 1}, {1, 2}, {2, 3}, {1, 3}, {1, 4}})) // false
	fmt.Println(validTree(4, [][]int{{0, 1}, {2, 3}, {2, 3}}))                 // false
	fmt.Println(validTree(1, nil))                                             // true
}

Complexity. Time O(n · α(n)), space O(n).

Problem 4 · Accounts Merge (LeetCode 721, Medium)

Task. Each account is [name, email1, email2, …]. Two accounts belong to the same person if they share any email (names alone are not enough: two different people can share a name). Merge the accounts of the same person; return each as [name, sorted emails…].

Idea. Treat emails as the items. All emails in one account belong together, so union the first email with each of the other emails of that account. After processing every account, the emails fall into groups: each group is one person. Remember each email's name, then collect groups by their leader.

Steps.

  1. Give each distinct email an integer id (map: email → id) and remember emailToName.
  2. For each account: union(id(first email), id(other email)).
  3. Group all emails by find(id).
  4. For each group: sort its emails, prepend the name.
function accountsMerge(accounts: string[][]): string[][] {
  const emailId = new Map<string, number>();
  const emailName = new Map<string, string>();
  for (const [name, ...emails] of accounts) {
    for (const email of emails) {
      if (!emailId.has(email)) emailId.set(email, emailId.size);
      emailName.set(email, name);
    }
  }
  const uf = new UnionFind(emailId.size);
  for (const [, first, ...rest] of accounts) {
    for (const email of rest) uf.union(emailId.get(first)!, emailId.get(email)!); // same account = same person
  }
  const groups = new Map<number, string[]>(); // leader id -> emails
  for (const [email, id] of emailId) {
    const leader = uf.find(id);
    if (!groups.has(leader)) groups.set(leader, []);
    groups.get(leader)!.push(email);
  }
  const merged = [...groups.values()].map((emails) => {
    emails.sort();
    return [emailName.get(emails[0])!, ...emails];
  });
  return merged.sort((a, b) => a[1].localeCompare(b[1])); // stable output order for display
}

  ["Mary", "mary@mail.com"],
  ["John", "johnnybravo@mail.com"],
]));

func accountsMerge(accounts [][]string) [][]string {
	emailID := make(map[string]int)
	emailName := make(map[string]string)
	for _, account := range accounts {
		for _, email := range account[1:] {
			if _, ok := emailID[email]; !ok {
				emailID[email] = len(emailID)
			}
			emailName[email] = account[0]
		}
	}
	uf := NewUnionFind(len(emailID))
	for _, account := range accounts {
		for _, email := range account[2:] {
			uf.Union(emailID[account[1]], emailID[email]) // same account = same person
		}
	}
	groups := make(map[int][]string) // leader id -> emails
	for email, id := range emailID {
		leader := uf.Find(id)
		groups[leader] = append(groups[leader], email)
	}
	merged := make([][]string, 0, len(groups))
	for _, emails := range groups {
		sort.Strings(emails)
		merged = append(merged, append([]string{emailName[emails[0]]}, emails...))
	}
	sort.Slice(merged, func(i, j int) bool { return merged[i][1] < merged[j][1] }) // stable output order for display
	return merged
}

func exampleAccountsMerge() {
	result := accountsMerge([][]string{
		{"John", "johnsmith@mail.com", "john_newyork@mail.com"},
		{"John", "johnsmith@mail.com", "john00@mail.com"},
		{"Mary", "mary@mail.com"},
		{"John", "johnnybravo@mail.com"},
	})
	for _, account := range result {
		fmt.Println(account)
	}
	// [John john00@mail.com john_newyork@mail.com johnsmith@mail.com]
	// [John johnnybravo@mail.com]
	// [Mary mary@mail.com]
}

Complexity. With E total emails: time O(E · α(E) + E log E) (the sorting dominates), space O(E).

Why union-find over DFS here? DFS needs you to build a graph (an email adjacency list) first. Union-find merges directly while reading the input, with no graph building.

Problem 5 · Number of Islands II (LeetCode 305, Hard)

Task. A m × n grid starts as all water. A list of positions turns water into land one at a time. After each addition, return the number of islands. m = 3, n = 3, positions [[0,0],[0,1],[1,2],[2,1]] → [1, 1, 2, 3].

Why union-find, not BFS. After each addition, re-running Number of Islands (file 19) costs O(m·n), so O(k · m · n) total: too slow. Union-find handles dynamic growth: each new land cell either creates a new island (+1) or merges with neighboring land (−1 per successful merge).

Idea.

  1. Flatten (r, c) to a single id: r * n + c.
  2. Keep a land array. When a cell is added:
    • If it is already land, the count is unchanged (a repeated position).
    • Otherwise count++ (a new island).
    • For each of its four neighbors that is land, union; every union that actually merges two different groups does count--.
  3. Record count after each addition.

Trace. 3×3 grid; positions (0,0), (0,1), (1,2), (2,1)

AddNew island?Mergescount
(0,0)+1none1
(0,1)+1joins (0,0): −11
(1,2)+1no land neighbors2
(2,1)+1no land neighbors (its neighbors (1,1), (2,0), (2,2) are water)3
function numIslands2(m: number, n: number, positions: number[][]): number[] {
  const uf = new UnionFind(m * n);
  const land = new Array<boolean>(m * n).fill(false);
  let islands = 0;
  const answer: number[] = [];
  const dirs = [[1, 0], [-1, 0], [0, 1], [0, -1]];
  for (const [r, c] of positions) {
    const id = r * n + c;
    if (!land[id]) {
      land[id] = true;
      islands++; // assume a new island...
      for (const [dr, dc] of dirs) {
        const nr = r + dr, nc = c + dc;
        if (nr < 0 || nr >= m || nc < 0 || nc >= n || !land[nr * n + nc]) continue;
        if (uf.union(id, nr * n + nc)) islands--; // ...each real merge removes one island
      }
    }
    answer.push(islands);
  }
  return answer;
}

console.log(numIslands2(3, 3, [[0, 0], [0, 1], [1, 2], [1, 2]])); // [ 1, 1, 2, 2 ]  (the repeat is ignored)
console.log(numIslands2(1, 1, [[0, 0]])); // [ 1 ]
console.log(numIslands2(3, 3, [[0, 0], [1, 1], [0, 1]])); // [ 1, 2, 1 ]  (the third cell bridges the two)
func numIslands2(m, n int, positions [][]int) []int {
	uf := NewUnionFind(m * n)
	land := make([]bool, m*n)
	islands := 0
	answer := make([]int, 0, len(positions))
	dirs := [][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}
	for _, p := range positions {
		r, c := p[0], p[1]
		id := r*n + c
		if !land[id] {
			land[id] = true
			islands++ // assume a new island...
			for _, d := range dirs {
				nr, nc := r+d[0], c+d[1]
				if nr < 0 || nr >= m || nc < 0 || nc >= n || !land[nr*n+nc] {
					continue
				}
				if uf.Union(id, nr*n+nc) {
					islands-- // ...each real merge removes one island
				}
			}
		}
		answer = append(answer, islands)
	}
	return answer
}

func exampleNumIslands2() {
	fmt.Println(numIslands2(3, 3, [][]int{{0, 0}, {0, 1}, {1, 2}, {2, 1}})) // [1 1 2 3]
	fmt.Println(numIslands2(3, 3, [][]int{{0, 0}, {0, 1}, {1, 2}, {1, 2}})) // [1 1 2 2]
	fmt.Println(numIslands2(1, 1, [][]int{{0, 0}}))                         // [1]
	fmt.Println(numIslands2(3, 3, [][]int{{0, 0}, {1, 1}, {0, 1}}))         // [1 2 1]
}

Complexity. Time O(k · α(m·n)) for k positions (plus O(m·n) to initialize), space O(m·n).

Common mistakes

  • Not initializing parent[i] = i.
  • Comparing parent[a] and parent[b] instead of find(a) and find(b) (parents are not leaders).
  • Storing a leader and reusing it after unions (it can change).
  • Forgetting to decrement count only on a successful merge.
  • Mixing 0-based and 1-based nodes (Redundant Connection uses 1..n; allocate n + 1).
  • No size/rank and no path compression (degenerates to O(n) per find).
  • Using union-find for directed cycle detection (it only understands undirected connectivity).
  • Trying to "un-union": it is not supported.

Try it without looking

Try each one on paper or in an editor first. Open the hint only when you are stuck, and the answer only after you have an attempt.

1 · Write it from memory

From memory: write find with path halving, then union by size. Say what each of the three lines in find's loop does.

Answer

The loop in find runs while parent[x] !== x (x is not a leader yet). Line one, parent[x] = parent[parent[x]], points x at its grandparent: path halving, so later finds are shorter. Line two, x = parent[x], climbs. After the loop, return x, the leader. union finds both leaders, returns false if they are equal, hangs the smaller tree's leader under the bigger one, adds the sizes and decrements count.

2 · Four unions

Run union(1,2), union(3,4), union(2,4), union(1,3) on a fresh structure and report count and each return value.

Answer

union(1,2) → true; union(3,4) → true; union(2,4) → true (it joins {1,2} and {3,4}); union(1,3) → false, they are already together. Three successful merges, so count = n − 3: with n = 5 (items 0..4) that is 2 groups, {0} and {1,2,3,4}. The third preset of the first animation runs exactly this.

3 · Number of Provinces

Number of Provinces (LeetCode 547): the input is an adjacency matrix. Which loop bounds do you need so you union each pair only once?

Answer

The matrix is symmetric and its diagonal is all 1s, so union only the upper triangle: for i in 0..n-1, for j in i+1..n-1, if isConnected[i][j] == 1: union(i, j). The answer is count. (BFS or DFS from each unvisited city also works.)

4 · Equality equations

Satisfiability of Equality Equations (LeetCode 990): process all == first, then check each !=. Why in that order?

Answer

The == equations build the groups; a != can only be checked once every group is complete. If you checked a != b first, a later a == c and c == b could still put a and b together. So: union every ==, then for each != return false if find(a) === find(b).

5 · Kruskal

Kruskal's algorithm for the minimum spanning tree: sort edges by weight, add an edge only if it joins two different groups. Which operation tells you that?

Answer

union's return value (or comparing find(a) and find(b)). Sort edges by weight; for each, if union(a, b) returns true, the edge joins two different trees, so add it to the spanning tree; if false, it would close a cycle, so skip it. Stop after V − 1 edges. Cost O(E log E), from the sort.
