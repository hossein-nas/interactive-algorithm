Sliding window

Keep a useful stretch of neighbors, and slide it forward.

Book link: this pattern is not a chapter in Grokking Algorithms. It is the natural partner of two pointers: it also scans an array once, but the stretch between the two pointers carries meaning. This file replaces v2 file 02.

Reach for it when

A contiguous subarray or substring, with longest, shortest, at most k, or every window of size k.

The template

Grow right; while the rule breaks, shrink left; then record.

What it costs

O(n): each item enters once and leaves once, even with the inner while.

1. The idea in plain English

A window is a stretch of neighboring items: positions left to right, inclusive. "Sliding" means you move the window along the array one step at a time, instead of rebuilding it from scratch each time.

An everyday comparison. You are on a train looking out a window. The scenery slides past: new things appear at the front edge, old things leave at the back edge. You do not re-look at everything each moment; you only notice what entered and what left.

That is the entire trick. When the window moves one step, you update your answer using only the one item that entered and the one item that left, which costs O(1), instead of recomputing the whole window, which costs O(window size).

2. How to recognize it

Think "sliding window" when the problem asks about a contiguous part of an array or string (a subarray or substring, never a subsequence) and says something like:

  • "longest substring such that…" or "shortest subarray with…"
  • "at most k distinct / at most k zeros / sum at least S"
  • "every subarray of size k"
  • "without repeating characters", "containing all characters of…"

The big warning: a variable window needs a rule whose truth moves in one direction as you grow or shrink.

  • "Sum ≥ target, with only positive numbers": growing the window can only increase the sum, shrinking can only decrease it. ✔ Window works.
  • "Sum ≥ target, with negative numbers allowed": growing might decrease the sum; the rule is no longer one-directional. ✘ Window breaks. Use prefix sums + a map (file 07) instead.

3. The template for a variable window

Say it in words: "Expand right one step at a time. While the window breaks the rule, shrink left. Then record the answer."

The inner while does not make the algorithm quadratic: left only moves forward and never exceeds right, so over the whole run left moves at most n times in total. Time is O(n) (amortized, see file 02).

Two ways to record the answer

  • Longest window → record after the while loop (the window is valid then).
  • Shortest window → record inside the while loop (as long as the window is still valid while you shrink it).

Step through both skeletons. In the variable version, the decision map below the stage shows the template's loop.

// Fixed window of size k: best sum.
function bestSumOfSizeK(nums: number[], k: number): number {
  if (k > nums.length) return NaN;
  let windowSum = 0;
  for (let i = 0; i < k; i++) windowSum += nums[i]; // build the first window
  let best = windowSum;
  for (let right = k; right < nums.length; right++) {
    windowSum += nums[right] - nums[right - k]; // one enters, one leaves
    best = Math.max(best, windowSum);
  }
  return best;
}

// Variable window skeleton: longest stretch with at most `limit` zeros.
function longestWithAtMostZeros(bits: number[], limit: number): number {
  let left = 0, zeros = 0, best = 0;
  for (let right = 0; right < bits.length; right++) {
    if (bits[right] === 0) zeros++; // add the right item
    while (zeros > limit) { // the rule is broken: shrink
      if (bits[left] === 0) zeros--;
      left++;
    }
    best = Math.max(best, right - left + 1); // record after the window is valid
  }
  return best;
}

console.log(bestSumOfSizeK([2, 1, 5, 1, 3, 2], 3)); // 9
console.log(longestWithAtMostZeros([1, 0, 1, 1, 0, 1], 1)); // 4
// Fixed window of size k: best sum.
func bestSumOfSizeK(nums []int, k int) int {
	windowSum := 0
	for i := 0; i < k; i++ {
		windowSum += nums[i] // build the first window
	}
	best := windowSum
	for right := k; right < len(nums); right++ {
		windowSum += nums[right] - nums[right-k] // one enters, one leaves
		best = max(best, windowSum)
	}
	return best
}

// Variable window skeleton: longest stretch with at most `limit` zeros.

	for right := 0; right < len(bits); right++ {

			zeros++ // add the right item
		}

			if bits[left] == 0 {
				zeros--
			}
			left++
		}
		best = max(best, right-left+1) // record after the window is valid
	}
	return best
}

}

4. Practice problems (easy → hard)

Problem 1 · Maximum Sum Subarray of Size K (fixed window; like LeetCode 643)

Task. Find the largest sum of any k consecutive numbers. [2, 1, 5, 1, 3, 2], k = 3 → 9 (the window 5, 1, 3).

Brute force. For each start, add k numbers: O(n · k).

Window idea. Once you have the sum of window [0..2], the sum of [1..3] is the old sum, plus the new item, minus the item that left.

[1, 5, 1]8 + 1 − 27

The code is bestSumOfSizeK in the skeleton section above. Complexity: O(n) time, O(1) space. (For average, divide by k.)

Edge cases: k larger than the array (decide what to return: ask the interviewer), k = 1, negative numbers (fine for a fixed window, since the size doesn't change).

Problem 2 · Longest Substring Without Repeating Characters (LeetCode 3, Medium)

Task. Return the length of the longest substring in which no character repeats. "abcabcbb" → 3 ("abc"). "bbbbb" → 1. "pwwkew" → 3 ("wke").

Brute force. Check every substring for duplicates: O(n³) naive, O(n²) with a set.

Window idea. The rule is "no repeats inside the window". When the new right character is already inside the window, jump left to just after its previous position. To jump instantly, keep a map lastSeen[char] = index.

One subtle point. The old position of a character might be left of the current window (already removed). So take the max: left = max(left, lastSeen[ch] + 1). Without the max, left could move backward, which is the number one bug here.

Trace. "abba" (the famous tricky one)

rightchlastSeen beforeleft afterwindowbest
0anone0a1
1bnone0ab2
2bb@1 (inside)2b2
3aa@0 (outside: 0 < left 2)stays 2 (not 1!)ba2

At the last step, without max, left would drop to 1 and wrongly give length 3.

function lengthOfLongestSubstring(s: string): number {
  const lastSeen = new Map<string, number>();
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    const prev = lastSeen.get(ch);
    if (prev !== undefined) left = Math.max(left, prev + 1); // never move left backward
    lastSeen.set(ch, right);
    best = Math.max(best, right - left + 1);
  }
  return best;
}

console.log(lengthOfLongestSubstring("bbbbb")); // 1
console.log(lengthOfLongestSubstring("pwwkew")); // 3
console.log(lengthOfLongestSubstring("abba")); // 2
console.log(lengthOfLongestSubstring("")); // 0
func lengthOfLongestSubstring(s string) int {
	lastSeen := make(map[byte]int) // assumes single-byte characters; use runes for Unicode
	left, best := 0, 0
	for right := 0; right < len(s); right++ {
		ch := s[right]
		if prev, ok := lastSeen[ch]; ok {
			left = max(left, prev+1) // never move left backward
		}
		lastSeen[ch] = right
		best = max(best, right-left+1)
	}
	return best
}

func exampleLengthOfLongestSubstring() {
	fmt.Println(lengthOfLongestSubstring("abcabcbb")) // 3
	fmt.Println(lengthOfLongestSubstring("bbbbb"))    // 1
	fmt.Println(lengthOfLongestSubstring("pwwkew"))   // 3
	fmt.Println(lengthOfLongestSubstring("abba"))     // 2
	fmt.Println(lengthOfLongestSubstring(""))         // 0
}

Complexity. Time O(n), space O(k) where k is the alphabet size (at most 128 for ASCII: effectively O(1)).

Follow-up. "Return the substring itself." Save bestLeft whenever you improve best.

Problem 3 · Minimum Size Subarray Sum (LeetCode 209, Medium)

Task. All numbers are positive. Find the shortest contiguous subarray whose sum is at least target. target = 7, [2, 3, 1, 2, 4, 3] → 2 (the subarray [4, 3]). If none exists, return 0.

Brute force. Try every start and end: O(n²).

Window idea. Because all numbers are positive, growing the window only raises the sum and shrinking only lowers it. So: grow right until the sum reaches the target (the rule "sum ≥ target" is now true). Then shrink from the left as long as it stays true, recording the length each time. Since we want the shortest, the record happens inside the while loop.

Trace. target = 7, [2, 3, 1, 2, 4, 3]

rightaddsumleftactionbest

2160below∞

5393≥7: record 3; remove 2 → 7, left=4; record 2; remove 4 → 3, left=52
function minSubArrayLen(target: number, nums: number[]): number {
  let left = 0, sum = 0, best = Infinity;
  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];
    while (sum >= target) {
      best = Math.min(best, right - left + 1); // record inside: we want the shortest
      sum -= nums[left];
      left++;
    }
  }
  return best === Infinity ? 0 : best;
}

console.log(minSubArrayLen(4, [1, 4, 4])); // 1
console.log(minSubArrayLen(11, [1, 1, 1, 1, 1])); // 0
func minSubArrayLen(target int, nums []int) int {
	left, sum, best := 0, 0, math.MaxInt
	for right := 0; right < len(nums); right++ {
		sum += nums[right]
		for sum >= target {
			best = min(best, right-left+1) // record inside: we want the shortest
			sum -= nums[left]
			left++
		}
	}
	if best == math.MaxInt {
		return 0
	}
	return best
}

func exampleMinSubArrayLen() {
	fmt.Println(minSubArrayLen(7, []int{2, 3, 1, 2, 4, 3})) // 2
	fmt.Println(minSubArrayLen(4, []int{1, 4, 4}))          // 1
	fmt.Println(minSubArrayLen(11, []int{1, 1, 1, 1, 1}))   // 0
}

Complexity. Time O(n), space O(1).

The classic follow-up: "What if negative numbers are allowed?" The window logic collapses (shrinking might raise the sum). Use prefix sums with a monotonic deque (file 14) for the shortest-subarray version, or a prefix-sum map for the "sum equals K" version (file 07).

Problem 4 · Longest Substring with At Most K Distinct Characters (LeetCode 340, Medium)

Task. Longest substring containing at most k different characters. "eceba", k = 2 → 3 ("ece").

Window idea. State: a count map of each character inside the window. The window is valid when the map has at most k keys. When it exceeds k, remove characters from the left, deleting a key when its count reaches zero (otherwise the map size lies).

Trace. "eceba", k = 2

rightaddcountsdistinctleft afterwindowbest
0ee:110e1
1ce:1, c:120ec2
2ee:2, c:120ece3
3be:2, c:1, b:13 → too manyremove e (e:1), remove c (c:0, delete) → left=2eb3
4ae:1, b:1, a:13 → too manyremove e (e:0, delete) → left=3ba3
function lengthOfLongestSubstringKDistinct(s: string, k: number): number {
  if (k === 0) return 0;
  const counts = new Map<string, number>();
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    counts.set(s[right], (counts.get(s[right]) ?? 0) + 1);
    while (counts.size > k) {
      const out = s[left];
      const c = counts.get(out)! - 1;
      if (c === 0) counts.delete(out); // delete at zero so counts.size stays truthful
      else counts.set(out, c);
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}
console.log(lengthOfLongestSubstringKDistinct("eceba", 2)); // 3
console.log(lengthOfLongestSubstringKDistinct("aa", 1)); // 2
console.log(lengthOfLongestSubstringKDistinct("abc", 0)); // 0
func lengthOfLongestSubstringKDistinct(s string, k int) int {
	if k == 0 {
		return 0
	}
	counts := make(map[byte]int)
	left, best := 0, 0
	for right := 0; right < len(s); right++ {
		counts[s[right]]++
		for len(counts) > k {
			out := s[left]
			counts[out]--
			if counts[out] == 0 {
				delete(counts, out) // delete at zero so len(counts) stays truthful
			}
			left++
		}
		best = max(best, right-left+1)
	}
	return best
}

func exampleKDistinct() {
	fmt.Println(lengthOfLongestSubstringKDistinct("eceba", 2)) // 3
	fmt.Println(lengthOfLongestSubstringKDistinct("aa", 1))    // 2
	fmt.Println(lengthOfLongestSubstringKDistinct("abc", 0))   // 0
}

Complexity. Time O(n), space O(k).

Problem 5 · Longest Repeating Character Replacement (LeetCode 424, Medium)

Task. You may change at most k characters of an uppercase string to any letter. What is the longest run of one repeated letter you can make? "AABABBA", k = 1 → 4.

Key reasoning (this is the hard part). For a window, the cheapest way to make all letters equal is to keep the most frequent letter and replace all the others. The number of replacements needed is

windowLength − (count of the most frequent letter in the window).

The window is valid when that number is ≤ k.

A neat trick explained. Keeping the exact current max count after shrinking is awkward (we would need to scan 26 counts). Instead keep maxCount as "the largest count we have ever seen in any window". It never needs to go down. Why is that safe? We only care about finding a longer window than the best so far. A longer window can only appear if some letter's count exceeds the old max, so an out-of-date (too high) maxCount can never cause a wrong larger answer: when the window is invalid with a stale maxCount, we just shift the window along without growing. This is subtle; explain it slowly in an interview, or use the safe option: recompute the max over 26 counts each time (O(26 n), which is still O(n)).

function characterReplacement(s: string, k: number): number {
  const counts = new Array<number>(26).fill(0);
  let left = 0, maxCount = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    const idx = s.charCodeAt(right) - 65; // 'A' = 65
    counts[idx]++;
    maxCount = Math.max(maxCount, counts[idx]); // largest count ever seen in a window
    // Replacements needed = window length - count of the most common letter.
    while (right - left + 1 - maxCount > k) {
      counts[s.charCodeAt(left) - 65]--;
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}
console.log(characterReplacement("AABABBA", 1)); // 4
console.log(characterReplacement("ABAB", 2)); // 4
console.log(characterReplacement("A", 0)); // 1
func characterReplacement(s string, k int) int {
	var counts [26]int
	left, maxCount, best := 0, 0, 0
	for right := 0; right < len(s); right++ {
		counts[s[right]-'A']++
		maxCount = max(maxCount, counts[s[right]-'A']) // largest count ever seen in a window
		// Replacements needed = window length - count of the most common letter.
		for right-left+1-maxCount > k {
			counts[s[left]-'A']--
			left++
		}
		best = max(best, right-left+1)
	}
	return best
}

func exampleCharacterReplacement() {
	fmt.Println(characterReplacement("AABABBA", 1)) // 4
	fmt.Println(characterReplacement("ABAB", 2))    // 4
	fmt.Println(characterReplacement("A", 0))       // 1
}

Complexity. Time O(n), space O(1) (26 counters).

Problem 6 · Minimum Window Substring (LeetCode 76, Hard)

Task. Given strings s and t, find the shortest substring of s that contains every character of t, including duplicates. s = "ADOBECODEBANC", t = "ABC" → "BANC". If none exists, return "".

Why it is hard. Two things have to be tracked at once: which letters are needed and how many of each. A clean way to avoid re-checking all counts every step is a single number: missing = how many required letters are still absent from the window.

Setup.

  • need[c] = how many copies of c the target t requires.
  • missing starts as t.length (total letters still needed).
  • When the window gains a character c: if need[c] > 0 before we use it up, then it fills a real gap: missing--. Then decrement need[c] (it can go negative, which means "we have a surplus of c").
  • The window is valid when missing == 0.

The loop (it is the shortest-window template).

When removing s[left]: we put its copy back with need[c]++. If need[c] becomes positive, we have just lost a required letter (it was not surplus), so missing++ and the window becomes invalid; the while loop ends.

function minWindow(s: string, t: string): string {
  if (t.length === 0 || t.length > s.length) return "";
  const need = new Map<string, number>();
  for (const ch of t) need.set(ch, (need.get(ch) ?? 0) + 1);
  let missing = t.length; // how many required characters are still absent
  let left = 0, bestStart = 0, bestLen = Infinity;
  for (let right = 0; right < s.length; right++) {
    const add = s[right];
    if (need.has(add)) {
      if (need.get(add)! > 0) missing--; // this copy fills a real gap
      need.set(add, need.get(add)! - 1); // may go negative: a surplus
    }
    while (missing === 0) { // valid window: try to shrink it
      if (right - left + 1 < bestLen) {
        bestLen = right - left + 1;
        bestStart = left;
      }
      const out = s[left];
      if (need.has(out)) {
        need.set(out, need.get(out)! + 1);
        if (need.get(out)! > 0) missing++; // we just lost a required character
      }
      left++;
    }
  }
  return bestLen === Infinity ? "" : s.slice(bestStart, bestStart + bestLen);
}

console.log(minWindow("a", "a")); // a
console.log(minWindow("a", "aa")); // (empty string)
console.log(minWindow("aab", "aab")); // aab
func minWindow(s, t string) string {
	if len(t) == 0 || len(t) > len(s) {
		return ""
	}
	var need [128]int // ASCII; use a map for Unicode
	for i := 0; i < len(t); i++ {
		need[t[i]]++
	}
	missing := len(t) // how many required characters are still absent
	left, bestStart, bestLen := 0, 0, math.MaxInt
	for right := 0; right < len(s); right++ {
		if need[s[right]] > 0 {
			missing-- // this copy fills a real gap
		}
		need[s[right]]-- // may go negative: a surplus (also fine for letters not in t)
		for missing == 0 { // valid window: try to shrink it
			if right-left+1 < bestLen {
				bestLen = right - left + 1
				bestStart = left
			}
			need[s[left]]++
			if need[s[left]] > 0 {
				missing++ // we just lost a required character
			}
			left++
		}
	}
	if bestLen == math.MaxInt {
		return ""
	}
	return s[bestStart : bestStart+bestLen]
}

func exampleMinWindow() {
	fmt.Println(minWindow("ADOBECODEBANC", "ABC")) // BANC
	fmt.Println(minWindow("a", "a"))               // a
	fmt.Printf("%q\n", minWindow("a", "aa"))       // ""
	fmt.Println(minWindow("aab", "aab"))           // aab
}

A detail worth saying aloud (Go version). Letters not in t start with need = 0, and the line need[s[right]]-- makes them negative. When they leave, need++ returns them to 0, which is not > 0, so missing is not wrongly incremented. This lets one array handle both required and irrelevant letters without an if.

Complexity. Time O(|s| + |t|): each character enters and leaves the window at most once. Space O(alphabet).

Follow-ups. "Permutation in String (LeetCode 567)": fixed window of size |t| with the same counting trick. "Find All Anagrams (LeetCode 438)": same idea, record every start.

Common mistakes

  • Using a window when negatives are allowed and the rule is about sums.
  • Not deleting a map key at zero when the rule is "number of distinct keys".
  • Moving left backward (the abba bug): always use max(left, previous + 1).
  • Recording at the wrong place: longest → after the shrink loop; shortest → inside it.
  • Off-by-one in length: the window [left, right] inclusive has length right − left + 1.
  • Treating a subsequence like a substring. A window only handles contiguous parts.
  • Writing if instead of while for the shrink step (you may need to remove several items).

1 · The rule, and where to record

For each of the six problems, say in one sentence what the rule is and whether you record inside or after the shrink loop.

Answer
  1. Max sum of size k: fixed size k; record after each slide.
  2. No repeating characters: no character twice in the window; longest, so record after adjusting left.
  3. Minimum size subarray sum: sum ≥ target; shortest, so record inside the shrink loop.
  4. At most k distinct: the count map has at most k keys; longest, record after the loop.
  5. Character replacement: length − maxCount ≤ k; longest, record after the loop.
  6. Minimum window substring: missing = 0; shortest, record inside the loop.

2 · Why positives only

Why is Minimum Size Subarray Sum correct only for positive numbers? Give a tiny counter-example with a negative number.

Hint

Find an input where shrinking the window makes the sum bigger.

Answer

The algorithm assumes that removing an item from the left can only lower the sum, so once the sum drops below the target it stops shrinking. A negative number breaks that. Counter-example: [1, -1, 3], target 3. The window reaches sum 3 at [1, -1, 3] (length 3), removes 1 (sum 2), and stops. But [3] alone has length 1. Removing the −1 would have raised the sum. The bug replay in Problem 3 shows another case.

3 · Permutation in String

Permutation in String: write the fixed-window version using a 26-slot array in both languages.

Hint

Keep a window exactly as long as t, and the same missing-count trick as Minimum Window Substring.

Answer

A fixed window of size |t| slides over s. need[c] starts as the letter counts of t; missing starts at |t|. When a letter enters and need[c] was positive, missing--; when a letter leaves and need[c] becomes positive again, missing++. If missing hits 0, the window is a permutation. O(|s|) time, 26 counters.

function checkInclusion(t: string, s: string): boolean {
  if (t.length > s.length) return false;
  const need = new Array<number>(26).fill(0); // letters t still needs inside the window
  for (let i = 0; i < t.length; i++) need[t.charCodeAt(i) - 97]++;
  let missing = t.length;
  for (let right = 0; right < s.length; right++) {
    if (need[s.charCodeAt(right) - 97]-- > 0) missing--; // a needed letter entered
    const left = right - t.length; // the letter that just left the fixed window
    if (left >= 0 && ++need[s.charCodeAt(left) - 97] > 0) missing++; // a needed letter left
    if (missing === 0) return true;
  }
  return false;
}

func checkInclusion(t, s string) bool {
	if len(t) > len(s) {
		return false
	}
	var need [26]int // letters t still needs inside the window
	for i := 0; i < len(t); i++ {
		need[t[i]-'a']++
	}
	missing := len(t)
	for right := 0; right < len(s); right++ {
		if need[s[right]-'a'] > 0 {
			missing-- // a needed letter entered
		}
		need[s[right]-'a']--
		left := right - len(t) // the letter that just left the fixed window
		if left >= 0 {
			need[s[left]-'a']++
			if need[s[left]-'a'] > 0 {
				missing++ // a needed letter left
			}
		}
		if missing == 0 {
			return true
		}
	}
	return false
}

func exampleCheckInclusion() {
	fmt.Println(checkInclusion("ab", "eidbaooo"))  // true
	fmt.Println(checkInclusion("ab", "eidboaoo"))  // false
	fmt.Println(checkInclusion("adc", "dcda"))     // true
}

5 · Count subarrays with sum below k

Count the subarrays with sum less than k (all positive numbers). Hint: when the window [left, right] is valid, there are right − left + 1 valid subarrays ending at right.

Hint

When the window [left, right] is valid, how many valid subarrays end exactly at right?

Answer

Grow right; while the sum is at least k, shrink from the left. Now every subarray that ends at right and starts anywhere from left to right has a smaller sum (all numbers are positive), so add right − left + 1 to the count. O(n) time.

function countSubarraysBelow(nums: number[], k: number): number {
  let left = 0, sum = 0, count = 0;
  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];
    while (sum >= k && left <= right) { // shrink until the window is valid again
      sum -= nums[left];
      left++;
    }
    count += right - left + 1; // every valid subarray that ends at right
  }
  return count;
}

console.log(countSubarraysBelow([1, 1, 1], 3)); // 5
console.log(countSubarraysBelow([10, 20], 5)); // 0
func countSubarraysBelow(nums []int, k int) int {
	left, sum, count := 0, 0, 0
	for right := 0; right < len(nums); right++ {
		sum += nums[right]
		for sum >= k && left <= right { // shrink until the window is valid again
			sum -= nums[left]
			left++
		}
		count += right - left + 1 // every valid subarray that ends at right
	}
	return count
}
