Prefix sums

Answer any range by subtracting two running totals.

Book link: not a chapter in Grokking Algorithms, but it is the same spirit as chapter 5 (hash tables): spend a little memory up front to avoid repeating work later. It also leads straight into dynamic programming (chapter 11): a prefix-sum table is the simplest DP table. This file replaces the prefix-sum part of v2 file 09.

The formula

prefix[0] = 0; sum of nums[l..r] = prefix[r+1] − prefix[l].

With a map

Count subarrays with sum k by looking up prefix − k. Works with negatives.

What it costs

O(n) to build once, then O(1) per range query.

1. The idea in plain English

You walk along a road and write down your odometer reading at every mile marker. Later someone asks: "How far is it from marker 3 to marker 7?" You do not re-drive the road. You just subtract: reading at 7 − reading at 3.

A prefix sum array is that odometer. prefix[i] = the total of the first i numbers. To get the sum of any stretch, you subtract two odometer readings.

The one formula to memorize

prefix[0] = 0, and prefix[i + 1] = prefix[i] + nums[i]. Sum of nums[l..r] (both inclusive) = prefix[r + 1] − prefix[l].

Why start with a leading 0? It makes the formula work even when l = 0 (the range starts at the very beginning) with no special case. Without that extra zero you need an if and it is a classic off-by-one source.

Cost

StepTimeSpace
Build the prefix arrayO(n) onceO(n)

If you will answer many range queries, build the prefix array once. If you only answer one, a plain loop is just as good.

2. How to recognize it

  • "Sum of elements between index i and j" asked many times.
  • "Number of subarrays whose sum equals k" (also with negative numbers!).
  • "Largest/shortest subarray with equal 0s and 1s", or "sum divisible by k".
  • "Apply many range updates, then read the final array" → the difference array (a cousin).
  • "Product of everything except the current item" → prefix and suffix products.
  • Grid version: "sum of a rectangle" → 2D prefix sums.

The key trick for "subarray sum equals K"

A subarray from l to r has sum k exactly when prefix[r+1] − prefix[l] = k, which means

prefix[l] = prefix[r+1] − k.

So as you walk right, ask: "how many earlier prefix values equal current prefix − k?" A hash map of prefix value → how many times seen answers that in O(1). This works with negative numbers, where sliding windows fail.

function buildPrefix(nums: number[]): number[] {
  const prefix = new Array<number>(nums.length + 1).fill(0);
  for (let i = 0; i < nums.length; i++) prefix[i + 1] = prefix[i] + nums[i];
  return prefix;
}
function rangeSum(prefix: number[], l: number, r: number): number {
  return prefix[r + 1] - prefix[l]; // inclusive on both ends
}

Problem 1 · Range Sum Query, Immutable (LeetCode 303, Easy)

Task. Build a class that gets an array once, then answers many sumRange(left, right) calls quickly.

Brute force. Each query loops from left to right: O(n) per query. With a million queries on a million items, that is a trillion steps.

Idea. Build the prefix array in the constructor; each query is one subtraction.

class NumArray {
  private prefix: number[];
  constructor(nums: number[]) {
    this.prefix = new Array<number>(nums.length + 1).fill(0);
    for (let i = 0; i < nums.length; i++) this.prefix[i + 1] = this.prefix[i] + nums[i];
  }
  sumRange(left: number, right: number): number {
    return this.prefix[right + 1] - this.prefix[left];
  }
}
const numArray = new NumArray([-2, 0, 3, -5, 2, -1]);
console.log(numArray.sumRange(0, 2)); // 1
console.log(numArray.sumRange(2, 5)); // -1
console.log(numArray.sumRange(0, 5)); // -3
type NumArray struct{ prefix []int }

func NewNumArray(nums []int) *NumArray {
	prefix := make([]int, len(nums)+1)
	for i, x := range nums {
		prefix[i+1] = prefix[i] + x
	}
	return &NumArray{prefix: prefix}
}

func (a *NumArray) SumRange(left, right int) int {
	return a.prefix[right+1] - a.prefix[left]
}

func exampleNumArray() {
	na := NewNumArray([]int{-2, 0, 3, -5, 2, -1})
	fmt.Println(na.SumRange(0, 2)) // 1
	fmt.Println(na.SumRange(2, 5)) // -1
	fmt.Println(na.SumRange(0, 5)) // -3
}

Complexity. Constructor O(n), each query O(1), space O(n).

Follow-up. "What if values can change (Range Sum Query – Mutable, LeetCode 307)?" A prefix array would need O(n) to rebuild after every update. Use a Fenwick tree or segment tree (O(log n) for both) — a good thing to name.

Problem 2 · Product of Array Except Self (LeetCode 238, Medium)

Task. For each position, return the product of all other numbers. No division allowed; O(n) time. [1, 2, 3, 4] → [24, 12, 8, 6].

Why not divide? There might be zeros (division by zero) and the problem forbids it.

Idea: prefix products and suffix products. The product of everything except i is

(product of everything to the left of i) × (product of everything to the right of i).

Space trick. Fill the answer array with the left products first. Then sweep from the right with one running variable suffix and multiply it in. No second array.

Trace. [1, 2, 3, 4]

Stepanswer array
after left pass (each = product of items to the left)[1, 1, 2, 6]
i=3: multiply by suffix 1, then suffix = 4[1, 1, 2, 6]
i=2: multiply by suffix 4 → 8, then suffix = 12[1, 1, 8, 6]
i=1: multiply by suffix 12 → 12, then suffix = 24[1, 12, 8, 6]
i=0: multiply by suffix 24 → 24[24, 12, 8, 6]
function productExceptSelf(nums: number[]): number[] {
  const n = nums.length;
  const answer = new Array<number>(n).fill(1);
  let left = 1;
  for (let i = 0; i < n; i++) {
    answer[i] = left; // product of everything left of i
    left *= nums[i];
  }
  let right = 1;
  for (let i = n - 1; i >= 0; i--) {
    answer[i] *= right; // multiply in the product of everything right of i
    right *= nums[i];
  }
  return answer;
}
console.log(productExceptSelf([1, 2, 3, 4])); // [ 24, 12, 8, 6 ]
console.log(productExceptSelf([-1, 1, 0, -3, 3])); // [ -0, 0, 9, -0, 0 ]

func productExceptSelf(nums []int) []int {
	n := len(nums)
	answer := make([]int, n)
	left := 1
	for i := 0; i < n; i++ {
		answer[i] = left // product of everything left of i
		left *= nums[i]
	}
	right := 1
	for i := n - 1; i >= 0; i-- {
		answer[i] *= right // multiply in the product of everything right of i
		right *= nums[i]
	}
	return answer
}

func exampleProductExceptSelf() {
	fmt.Println(productExceptSelf([]int{1, 2, 3, 4}))      // [24 12 8 6]
	fmt.Println(productExceptSelf([]int{-1, 1, 0, -3, 3})) // [0 0 9 0 0]
}

Complexity. Time O(n), extra space O(1) (not counting the output).

Interview note. With a zero in the array, only the position holding the zero can be non-zero. The two-pass method handles this automatically; that is a major reason to prefer it over "total product ÷ item".

Problem 3 · Subarray Sum Equals K (LeetCode 560, Medium)

Task. Count the contiguous subarrays whose sum is exactly k. Numbers may be negative or zero. [1, 1, 1], k = 2 → 2. [1, 2, 3], k = 3 → 2 ([1,2] and [3]).

Why a sliding window fails. With negatives, adding an item may lower the sum, so "shrink when too big" is no longer valid.

Idea. Keep a running prefix total. At each position ask: "how many earlier prefix totals equal prefix − k?" Each one marks a start position whose subarray ends here with sum exactly k.

Store count[prefixValue] in a map. Initialize with {0: 1}, meaning the empty prefix before the array begins (so subarrays that start at index 0 are counted).

Order matters: first look up, then store the current prefix. If you stored first, with k = 0 an item would pair with itself.

Trace. [1, 2, 3], k = 3

xprefixlook up prefix − 3foundansmap after
(start)00{0:1}
11−200{0:1, 1:1}
2301 (empty prefix: subarray [1,2])1{0:1, 1:1, 3:1}
3631 (prefix 3: subarray [3])2{0:1,1:1,3:1,6:1}
function subarraySum(nums: number[], k: number): number {
  const seen = new Map<number, number>([[0, 1]]); // the empty prefix has been seen once
  let prefix = 0, count = 0;
  for (const x of nums) {
    prefix += x;
    count += seen.get(prefix - k) ?? 0; // how many starts give a sum of exactly k?
    seen.set(prefix, (seen.get(prefix) ?? 0) + 1);
  }
  return count;
}
console.log(subarraySum([1, 1, 1], 2)); // 2
console.log(subarraySum([1, 2, 3], 3)); // 2
console.log(subarraySum([1, -1, 0], 0)); // 3
func subarraySum(nums []int, k int) int {
	seen := map[int]int{0: 1} // the empty prefix has been seen once
	prefix, count := 0, 0
	for _, x := range nums {
		prefix += x
		count += seen[prefix-k] // how many starts give a sum of exactly k?
		seen[prefix]++
	}
	return count
}

func exampleSubarraySum() {
	fmt.Println(subarraySum([]int{1, 1, 1}, 2))  // 2
	fmt.Println(subarraySum([]int{1, 2, 3}, 3))  // 2
	fmt.Println(subarraySum([]int{1, -1, 0}, 0)) // 3
}

Complexity. Time O(n), space O(n).

Variants worth knowing (same skeleton):

  • Longest subarray with sum k: store the first index of each prefix value instead of a count.
  • Subarray sums divisible by k (LeetCode 974): key the map by prefix mod k (use the positive-modulo form from file 03).

Problem 4 · Contiguous Array (LeetCode 525, Medium)

Task. In a binary array, find the longest subarray with an equal number of 0s and 1s. [0, 1, 0] → 2; [0, 0, 1, 0, 0, 0, 1, 1] → 6.

The clever transformation. Replace every 0 by −1. Now "equal numbers of 0s and 1s" means "the sum is 0", and we want the longest subarray with sum 0. That is the "longest subarray with sum k" variant, with k = 0:

If the running sum at index j equals the running sum at an earlier index i, then everything between i + 1 and j adds to 0.

So store the first index where each running sum appeared, and, on a repeat, measure the distance.

Trace. [0, 1, 0] → treat as −1, +1, −1

indexvaluerunning sumfirst seen atlength candidate
(start)0−1 (before the array)
0−1−10
1+10already at −11 − (−1) = 2
2−1−1already at 02 − 0 = 2
function findMaxLength(nums: number[]): number {
  const firstIndex = new Map<number, number>([[0, -1]]); // running sum 0 "before" index 0
  let sum = 0, best = 0;
  for (let i = 0; i < nums.length; i++) {
    sum += nums[i] === 1 ? 1 : -1; // treat 0 as -1
    const earlier = firstIndex.get(sum);
    if (earlier !== undefined) best = Math.max(best, i - earlier);
    else firstIndex.set(sum, i); // remember only the FIRST time, to keep the longest span
  }
  return best;
}
console.log(findMaxLength([0, 1, 0])); // 2
console.log(findMaxLength([0, 0, 1, 0, 0, 0, 1, 1])); // 6
console.log(findMaxLength([1, 1, 1])); // 0
func findMaxLength(nums []int) int {
	firstIndex := map[int]int{0: -1} // running sum 0 "before" index 0
	sum, best := 0, 0
	for i, x := range nums {
		if x == 1 {
			sum++
		} else {
			sum-- // treat 0 as -1
		}
		if earlier, ok := firstIndex[sum]; ok {
			best = max(best, i-earlier)
		} else {
			firstIndex[sum] = i // remember only the FIRST time, to keep the longest span
		}
	}
	return best
}

func exampleFindMaxLength() {
	fmt.Println(findMaxLength([]int{0, 1, 0}))                   // 2
	fmt.Println(findMaxLength([]int{0, 0, 1, 0, 0, 0, 1, 1})) // 6
	fmt.Println(findMaxLength([]int{1, 1, 1}))                   // 0
}

Complexity. Time O(n), space O(n).

Problem 5 · Range Sum Query 2D, Immutable (LeetCode 304, Medium)

Task. For a matrix, answer many "sum of the rectangle from (r1, c1) to (r2, c2)" queries in O(1) each.

Idea. Let P[r][c] = the sum of the rectangle from the top-left corner (0,0) to (r−1, c−1). Build with inclusion–exclusion: add the block above, add the block to the left, subtract the overlap that got counted twice, add the new cell.

For a query, the target rectangle = big block − block above − block left + overlap added back:

sum = P[r2+1][c2+1] − P[r1][c2+1] − P[r2+1][c1] + P[r1][c1]

class NumMatrix {
  private P: number[][];
  constructor(matrix: number[][]) {
    const rows = matrix.length, cols = rows ? matrix[0].length : 0;
    this.P = Array.from({ length: rows + 1 }, () => new Array<number>(cols + 1).fill(0));
    for (let r = 0; r < rows; r++) {
      for (let c = 0; c < cols; c++) {
        this.P[r + 1][c + 1] = this.P[r][c + 1] + this.P[r + 1][c] - this.P[r][c] + matrix[r][c];
      }
    }
  }
  sumRegion(r1: number, c1: number, r2: number, c2: number): number {
    const P = this.P;
    return P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1];
  }
}
const nm = new NumMatrix([
  [3, 0, 1, 4, 2],
  [5, 6, 3, 2, 1],
  [1, 2, 0, 1, 5],
  [4, 1, 0, 1, 7],
  [1, 0, 3, 0, 5],
]);
console.log(nm.sumRegion(2, 1, 4, 3)); // 8
console.log(nm.sumRegion(1, 1, 2, 2)); // 11
console.log(nm.sumRegion(1, 2, 2, 4)); // 12
type NumMatrix struct{ P [][]int }

func NewNumMatrix(matrix [][]int) *NumMatrix {
	rows := len(matrix)
	cols := 0
	if rows > 0 {
		cols = len(matrix[0])
	}
	P := make([][]int, rows+1)
	for r := range P {
		P[r] = make([]int, cols+1)
	}
	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			P[r+1][c+1] = P[r][c+1] + P[r+1][c] - P[r][c] + matrix[r][c]
		}
	}
	return &NumMatrix{P: P}
}

func (m *NumMatrix) SumRegion(r1, c1, r2, c2 int) int {
	P := m.P
	return P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
}

func exampleNumMatrix() {
	nm := NewNumMatrix([][]int{
		{3, 0, 1, 4, 2},
		{5, 6, 3, 2, 1},
		{1, 2, 0, 1, 5},
		{4, 1, 0, 1, 7},
		{1, 0, 3, 0, 5},
	})
	fmt.Println(nm.SumRegion(2, 1, 4, 3)) // 8
	fmt.Println(nm.SumRegion(1, 1, 2, 2)) // 11
	fmt.Println(nm.SumRegion(1, 2, 2, 4)) // 12
}

Complexity. Build O(rows × cols), query O(1), space O(rows × cols).

Problem 6 · Corporate Flight Bookings / Range Updates with a Difference Array (LeetCode 1109, Medium)

Task. There are n flights. Each booking [first, last, seats] adds seats seats to every flight from first to last (1-based). Return the final seat count for each flight. n = 5, bookings [[1,2,10],[2,3,20],[2,5,25]] → [10, 55, 45, 25, 25].

Brute force. For each booking, loop over its range: O(bookings × n).

The difference array: the reverse of a prefix sum. Instead of touching every flight in [first, last], mark only the two edges:

  • At first, "the amount goes up by seats from here on": diff[first] += seats.
  • Right after last, "it goes back down": diff[last + 1] -= seats.

At the end, a single prefix-sum pass over diff turns the edge marks into the real values.

Trace. Using 1-based flights; diff has size n + 2 so last + 1 is always valid.

Bookingdiff after (index 1..5)
start[0, 0, 0, 0, 0]
[1,2,10]diff[1] += 10, diff[3] -= 10 → [10, 0, -10, 0, 0]
[2,3,20]diff[2] += 20, diff[4] -= 20 → [10, 20, -10, -20, 0]
[2,5,25]diff[2] += 25 (and diff[6] −= 25, ignored) → [10, 45, -10, -20, 0]
prefix sum10, 55, 45, 25, 25 ✔
function corpFlightBookings(bookings: number[][], n: number): number[] {
  const diff = new Array<number>(n + 2).fill(0); // 1-based, plus one spare slot
  for (const [first, last, seats] of bookings) {
    diff[first] += seats; // the amount rises here
    diff[last + 1] -= seats; // and falls just after the range
  }
  const result: number[] = [];
  let running = 0;
  for (let flight = 1; flight <= n; flight++) {
    running += diff[flight]; // prefix sum turns edges into values
    result.push(running);
  }
  return result;
}
console.log(corpFlightBookings([[1, 2, 10], [2, 3, 20], [2, 5, 25]], 5)); // [ 10, 55, 45, 25, 25 ]
console.log(corpFlightBookings([[1, 2, 10], [2, 2, 15]], 2)); // [ 10, 25 ]
func corpFlightBookings(bookings [][]int, n int) []int {
	diff := make([]int, n+2) // 1-based, plus one spare slot
	for _, b := range bookings {
		first, last, seats := b[0], b[1], b[2]
		diff[first] += seats  // the amount rises here
		diff[last+1] -= seats // and falls just after the range
	}
	result := make([]int, 0, n)
	running := 0
	for flight := 1; flight <= n; flight++ {
		running += diff[flight] // prefix sum turns edges into values
		result = append(result, running)
	}
	return result
}

func exampleCorpFlightBookings() {
	fmt.Println(corpFlightBookings([][]int{{1, 2, 10}, {2, 3, 20}, {2, 5, 25}}, 5)) // [10 55 45 25 25]
	fmt.Println(corpFlightBookings([][]int{{1, 2, 10}, {2, 2, 15}}, 2))              // [10 25]
}

Complexity. Time O(bookings + n), space O(n).

Same trick, other disguises: Meeting rooms (count overlapping meetings: +1 at start, −1 at end; file 24), Car Pooling (LeetCode 1094), Range Addition (LeetCode 370).

Common mistakes

  • Forgetting the leading zero in prefix (off-by-one on ranges that start at index 0).
  • Mixing inclusive and exclusive ends. Decide once and write it in a comment: sum(l..r) = prefix[r+1] − prefix[l].
  • Not seeding the map with {0: 1} (misses subarrays that start at the very beginning).
  • Storing before looking up in the count-subarrays loop.
  • For "longest", overwriting the first index of a prefix value. Only record the first time.
  • Integer overflow in totals of many large numbers (JavaScript loses exactness above 2⁵³).
  • Using prefix sums when the array changes between queries. It needs a Fenwick tree for that.

1 · Why both ends are included

Explain why prefix[r + 1] − prefix[l] includes both l and r.

Answer

prefix[r + 1] is the total of nums[0..r], which includes r. prefix[l] is the total of nums[0..l−1], which stops just before l. Subtracting removes exactly the items before l, so what remains is nums[l..r] with both ends.

2 · Why the map starts as {0: 1}

Why does "Subarray Sum Equals K" need the map to start as {0: 1}? Show a one-element example.

Answer

The seed stands for the empty prefix before the array. Without it, a subarray that starts at index 0 has nothing to match. Example: [5], k = 5. At index 0, prefix = 5 and we look up 5 − 5 = 0. With the seed we find it once and count the subarray [5]; without it the answer is 0, which is wrong. Use the "No {0: 1} seed" replay in Problem 3 to watch it fail.

3 · Find Pivot Index

Solve Find Pivot Index (LeetCode 724): the position where the sum to the left equals the sum to the right.

Hint

If you know the total and the sum to the left of i, what is the sum to the right?

Answer

Compute the total once. Walk left to right keeping leftSum; the right side is total − leftSum − nums[i]. Return the first i where they are equal. O(n) time, O(1) space.

function pivotIndex(nums: number[]): number {
  const total = nums.reduce((a, b) => a + b, 0);
  let leftSum = 0; // sum of everything before i
  for (let i = 0; i < nums.length; i++) {
    if (leftSum === total - leftSum - nums[i]) return i; // left side equals right side
    leftSum += nums[i];
  }
  return -1;
}
console.log(pivotIndex([1, 7, 3, 6, 5, 6])); // 3
console.log(pivotIndex([1, 2, 3])); // -1
console.log(pivotIndex([2, 1, -1])); // 0
func pivotIndex(nums []int) int {
	total := 0
	for _, x := range nums {
		total += x
	}
	leftSum := 0 // sum of everything before i
	for i, x := range nums {
		if leftSum == total-leftSum-x {
			return i // left side equals right side
		}
		leftSum += x
	}
	return -1
}

func examplePivotIndex() {
	fmt.Println(pivotIndex([]int{1, 7, 3, 6, 5, 6})) // 3
	fmt.Println(pivotIndex([]int{1, 2, 3}))          // -1
	fmt.Println(pivotIndex([]int{2, 1, -1}))         // 0
}

4 · Subarray Sums Divisible by K

Solve Subarray Sums Divisible by K (LeetCode 974). Which two details from this file do you need?

Hint

Two subarray boundaries give a sum divisible by k exactly when their prefixes have the same remainder.

Answer

Two details from this lesson: the map seeded with remainder 0 seen once (the empty prefix), and the positive modulo ((prefix % k) + k) % k from lesson 03, because a negative prefix would otherwise give a negative remainder that never matches. Count how many earlier prefixes have the same remainder.

function subarraysDivByK(nums: number[], k: number): number {
  const seen = new Map<number, number>([[0, 1]]); // the empty prefix, remainder 0
  let prefix = 0, count = 0;
  for (const x of nums) {
    prefix += x;
    const r = ((prefix % k) + k) % k; // positive remainder, even for negative sums
    count += seen.get(r) ?? 0; // same remainder earlier: the subarray between is divisible by k
    seen.set(r, (seen.get(r) ?? 0) + 1);
  }
  return count;
}
console.log(subarraysDivByK([4, 5, 0, -2, -3, 1], 5)); // 7
console.log(subarraysDivByK([5], 9)); // 0
func subarraysDivByK(nums []int, k int) int {
	seen := map[int]int{0: 1} // the empty prefix, remainder 0
	prefix, count := 0, 0
	for _, x := range nums {
		prefix += x
		r := ((prefix % k) + k) % k // positive remainder, even for negative sums
		count += seen[r]            // same remainder earlier: the subarray between is divisible by k
		seen[r]++
	}
	return count
}

func exampleSubarraysDivByK() {
	fmt.Println(subarraysDivByK([]int{4, 5, 0, -2, -3, 1}, 5)) // 7
	fmt.Println(subarraysDivByK([]int{5}, 9))                  // 0
}

5 · Why the difference array is fast

Why can the difference array turn a thousand range updates into thousand O(1) steps plus one sweep?

Answer

Each update touches only its two edges, diff[first] += v and diff[last + 1] −= v, no matter how long the range is: O(1) per update. One prefix-sum pass at the end (O(n)) turns the edges into actual values. A thousand updates cost a thousand constant steps plus one sweep, instead of up to a thousand times n.
