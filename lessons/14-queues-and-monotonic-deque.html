1. The idea in plain English

A queue is a line at a ticket counter. People join at the back and are served from the front: first in, first out (FIFO).

Compare with a stack (file 13):

StackQueue
Rulelast in, first outfirst in, first out

Used fornesting, backtracking, DFSfairness, level by level, BFS

Deque: a line you can join and leave at both ends

A deque ("deck", double-ended queue) allows push and pop at the front and back. It can act as a stack, a queue, or something in between. Its special power is the monotonic deque, a sliding-window version of the monotonic stack from file 13.

2. How to recognize it

  • "Process in the order received", "recent requests", "time window of the last N events".
  • BFS (shortest path in an unweighted graph, level-order traversal): file 19.
  • "Maximum / minimum of every window of size k" → monotonic deque.
  • "Shortest subarray with sum at least K" with negatives → prefix sums + monotonic deque.
  • Simulating round-robin or turn-taking.

3. The monotonic deque, in plain English

In the sliding window maximum problem we need the maximum of the current window as it moves right. Observe:

If a newer number is bigger than an older number, the older number can never be the maximum again: it leaves the window earlier and is smaller than the newcomer.

So we keep a deque of indexes whose values are decreasing from front to back:

  • front = the index of the current maximum.
  • Before adding a new index at the back, pop from the back every index with a smaller or equal value (they are dead).
  • Pop from the front the index that has just slid out of the window.

Same amortized argument as the monotonic stack: each index enters once and leaves once, so the total is O(n).

Problem 1 · Number of Recent Calls (LeetCode 933, Easy)

Task. Count calls in the last 3000 milliseconds. ping(t) is called with strictly increasing times t and returns how many pings happened in [t − 3000, t].

Thinking. Times arrive in order, so the oldest are at the front. Store each ping time in a queue; on each new ping, drop from the front every time older than t − 3000. The queue length is the answer.

Trace. pings at 1, 100, 3001, 3002

1[1]1
100[1, 100]2
3001drop nothing (1 ≥ 1): [1, 100, 3001]3
3002drop 1 (1 < 2): [100, 3001, 3002]3
class RecentCounter {
  private times: number[] = [];
  private head = 0; // index of the front of the queue; avoids O(n) shift()
  ping(t: number): number {
    this.times.push(t);
    while (this.times[this.head] < t - 3000) this.head++; // drop expired requests
    return this.times.length - this.head;
  }
}
const counter = new RecentCounter();
console.log(counter.ping(1)); // 1
console.log(counter.ping(100)); // 2
console.log(counter.ping(3001)); // 3
console.log(counter.ping(3002)); // 3
type RecentCounter struct{ times []int }

func (c *RecentCounter) Ping(t int) int {
	c.times = append(c.times, t)
	for c.times[0] < t-3000 {
		c.times = c.times[1:] // dequeue from the front: O(1) in Go
	}
	return len(c.times)
}

func exampleRecentCounter() {
	c := &RecentCounter{}
	fmt.Println(c.Ping(1))    // 1
	fmt.Println(c.Ping(100))  // 2
	fmt.Println(c.Ping(3001)) // 3
	fmt.Println(c.Ping(3002)) // 3
}

Complexity. Each ping is O(1) amortized (every time is added once and dropped at most once). Space O(window size) in Go; the TypeScript version keeps old entries, so for a long-running service trim the array occasionally.

Problem 2 · Implement Queue using Stacks (LeetCode 232, Easy)

Task. Build a FIFO queue using only stack operations (push, pop, peek on a stack).

Thinking. One stack reverses order. Two reversals restore it. Use an inbox stack for new items and an outbox stack for items ready to leave:

  • push(x): push onto inbox.
  • pop()/peek(): if outbox is empty, move everything from inbox to outbox (this reverses it, so the oldest ends up on top); then take from outbox.

Why it is O(1) amortized. An item moves from inbox to outbox at most once. So across n operations, the moving costs at most n in total.

class QueueViaStacks {
  private inbox: number[] = [];
  private outbox: number[] = [];
  push(x: number): void {
    this.inbox.push(x);
  }
  private shiftIfNeeded(): void {
    if (this.outbox.length === 0) {
      while (this.inbox.length > 0) this.outbox.push(this.inbox.pop()!); // reverses the order
    }
  }
  pop(): number {
    this.shiftIfNeeded();
    return this.outbox.pop()!;
  }
  peek(): number {
    this.shiftIfNeeded();
    return this.outbox[this.outbox.length - 1];
  }
  empty(): boolean {
    return this.inbox.length === 0 && this.outbox.length === 0;
  }
}
const qs = new QueueViaStacks();
qs.push(1);
qs.push(2);
qs.push(3);
console.log(qs.pop(), qs.peek()); // 1 2
qs.push(4);
console.log(qs.pop(), qs.pop(), qs.pop(), qs.empty()); // 2 3 4 true
type QueueViaStacks struct{ inbox, outbox []int }

func (q *QueueViaStacks) Push(x int) { q.inbox = append(q.inbox, x) }

func (q *QueueViaStacks) shiftIfNeeded() {
	if len(q.outbox) == 0 {
		for len(q.inbox) > 0 {
			top := q.inbox[len(q.inbox)-1]
			q.inbox = q.inbox[:len(q.inbox)-1]
			q.outbox = append(q.outbox, top) // reverses the order
		}
	}
}

func (q *QueueViaStacks) Pop() int {
	q.shiftIfNeeded()
	top := q.outbox[len(q.outbox)-1]
	q.outbox = q.outbox[:len(q.outbox)-1]
	return top
}

func (q *QueueViaStacks) Peek() int {
	q.shiftIfNeeded()
	return q.outbox[len(q.outbox)-1]
}

func (q *QueueViaStacks) Empty() bool { return len(q.inbox) == 0 && len(q.outbox) == 0 }

func exampleQueueViaStacks() {
	q := &QueueViaStacks{}
	q.Push(1)
	q.Push(2)
	q.Push(3)
	fmt.Println(q.Pop(), q.Peek()) // 1 2
	q.Push(4)
	fmt.Println(q.Pop(), q.Pop(), q.Pop(), q.Empty()) // 2 3 4 true
}

Complexity. push O(1); pop and peek amortized O(1), worst case O(n) for a single call.

Problem 3 · Design Circular Queue (LeetCode 622, Medium)

Task. A fixed-capacity queue that reuses freed space, built on an array. Operations: enQueue, deQueue, Front, Rear, isEmpty, isFull.

Thinking. Imagine the array bent into a ring. Keep head (index of the front), size (count), and compute the back as (head + size − 1) mod capacity. Adding places an item at (head + size) mod capacity. The modulo makes indexes wrap around from the end to the start.

Tracking size (rather than head/tail only) avoids the classic ambiguity "head equals tail means empty or full?".

class CircularQueue {
  private data: number[];
  private head = 0; // index of the front item
  private size = 0;
  constructor(private capacity: number) {
    this.data = new Array<number>(capacity).fill(0);
  }
  enQueue(value: number): boolean {
    if (this.isFull()) return false;
    this.data[(this.head + this.size) % this.capacity] = value; // wrap with modulo
    this.size++;
    return true;
  }
  deQueue(): boolean {
    if (this.isEmpty()) return false;
    this.head = (this.head + 1) % this.capacity;
    this.size--;
    return true;
  }
  front(): number {
    return this.isEmpty() ? -1 : this.data[this.head];
  }
  rear(): number {
    return this.isEmpty() ? -1 : this.data[(this.head + this.size - 1) % this.capacity];
  }
  isEmpty(): boolean {
    return this.size === 0;
  }
  isFull(): boolean {
    return this.size === this.capacity;
  }
}
const cq = new CircularQueue(3);
console.log(cq.enQueue(1), cq.enQueue(2), cq.enQueue(3), cq.enQueue(4)); // true true true false
console.log(cq.rear(), cq.isFull()); // 3 true
console.log(cq.deQueue(), cq.enQueue(4), cq.rear()); // true true 4
console.log(cq.front()); // 2
type CircularQueue struct {
	data     []int
	head     int // index of the front item
	size     int
	capacity int
}

func NewCircularQueue(capacity int) *CircularQueue {
	return &CircularQueue{data: make([]int, capacity), capacity: capacity}
}

func (q *CircularQueue) EnQueue(value int) bool {
	if q.IsFull() {
		return false
	}
	q.data[(q.head+q.size)%q.capacity] = value // wrap with modulo
	q.size++
	return true
}

func (q *CircularQueue) DeQueue() bool {
	if q.IsEmpty() {
		return false
	}
	q.head = (q.head + 1) % q.capacity
	q.size--
	return true
}

func (q *CircularQueue) Front() int {
	if q.IsEmpty() {
		return -1
	}
	return q.data[q.head]
}

func (q *CircularQueue) Rear() int {
	if q.IsEmpty() {
		return -1
	}
	return q.data[(q.head+q.size-1)%q.capacity]
}

func (q *CircularQueue) IsEmpty() bool { return q.size == 0 }
func (q *CircularQueue) IsFull() bool  { return q.size == q.capacity }

func exampleCircularQueue() {
	cq := NewCircularQueue(3)
	fmt.Println(cq.EnQueue(1), cq.EnQueue(2), cq.EnQueue(3), cq.EnQueue(4)) // true true true false
	fmt.Println(cq.Rear(), cq.IsFull())                                      // 3 true
	fmt.Println(cq.DeQueue(), cq.EnQueue(4), cq.Rear())                     // true true 4
	fmt.Println(cq.Front())                                                  // 2
}

Complexity. Every operation O(1), space O(capacity).

Problem 4 · Sliding Window Maximum (LeetCode 239, Hard)

Task. For every window of size k, return its maximum. [1, 3, -1, -3, 5, 3, 6, 7], k = 3 → [3, 3, 5, 5, 6, 7].

Brute force. Scan each window: O(n·k). A heap with lazy deletion gives O(n log n). The monotonic deque gives O(n).

Walk through the idea with the invariant "the deque holds indexes with strictly decreasing values; the front is the maximum":

function maxSlidingWindow(nums: number[], k: number): number[] {
  const result: number[] = [];
  const deque: number[] = []; // indexes; values decreasing from front to back
  let head = 0; // front of the deque (avoids O(n) shift)
  for (let i = 0; i < nums.length; i++) {
    while (deque.length > head && nums[deque[deque.length - 1]] <= nums[i]) deque.pop(); // dead items
    deque.push(i);
    if (deque[head] <= i - k) head++; // the front slid out of the window
    if (i >= k - 1) result.push(nums[deque[head]]); // the front is the window's max
  }
  return result;
}
console.log(maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3)); // [ 3, 3, 5, 5, 6, 7 ]
console.log(maxSlidingWindow([1], 1)); // [ 1 ]
console.log(maxSlidingWindow([9, 8, 7], 2)); // [ 9, 8 ]
console.log(maxSlidingWindow([1, 2, 3], 3)); // [ 3 ]
func maxSlidingWindow(nums []int, k int) []int {
	result := []int{}
	deque := []int{} // indexes; values decreasing from front to back
	head := 0        // front of the deque
	for i, x := range nums {
		for len(deque) > head && nums[deque[len(deque)-1]] <= x {
			deque = deque[:len(deque)-1] // dead items
		}
		deque = append(deque, i)
		if deque[head] <= i-k {
			head++ // the front slid out of the window
		}
		if i >= k-1 {
			result = append(result, nums[deque[head]]) // the front is the window's max
		}
	}
	return result
}

func exampleMaxSlidingWindow() {
	fmt.Println(maxSlidingWindow([]int{1, 3, -1, -3, 5, 3, 6, 7}, 3)) // [3 3 5 5 6 7]
	fmt.Println(maxSlidingWindow([]int{1}, 1))                       // [1]
	fmt.Println(maxSlidingWindow([]int{9, 8, 7}, 2))                 // [9 8]
	fmt.Println(maxSlidingWindow([]int{1, 2, 3}, 3))                 // [3]
}

Complexity. Time O(n), space O(k).

Why we pop on <= (not <). Among equal values the newer one outlives the older one, so the older is useless. Either choice gives correct answers; <= keeps the deque smaller.

Follow-ups. Sliding window minimum: flip the comparison. Max of all windows with an unknown size that changes: a segment tree or sparse table. "Why not a heap?" A heap needs lazy deletion of items that left the window, giving O(n log n).

Problem 5 · Shortest Subarray with Sum at Least K (LeetCode 862, Hard)

Task. nums may contain negative numbers. Return the length of the shortest non-empty subarray with sum ≥ K, or −1. [2, −1, 2], K = 3 → 3.

Why earlier tools fail. A sliding window (file 06) breaks with negatives: adding a negative number lowers the sum, so "shrink when valid" is not safe. So use prefix sums (file 07): P[0] = 0, P[j+1] = P[j] + nums[j]. A subarray i..j−1 has sum P[j] − P[i]. We need, for each j, the largest i < j with P[i] ≤ P[j] − K (largest i = shortest subarray).

Deque rules (the deque stores indexes into P, with P values increasing from front to back):

  1. Answer from the front. While P[j] − P[front] ≥ K: record j − front and pop the front. Why is popping safe? Any later j' would give a longer subarray for the same front, so this front is never useful again.
  2. Keep it increasing. Before pushing j, pop the back while P[back] ≥ P[j]. Why? A later j' prefers a smaller P[i] (bigger difference) and a later i (shorter length). The new j is both later and has a smaller-or-equal P, so the old back is never better.
  3. Push j.

Trace. nums = [2, −1, 2], K = 3, so P = [0, 2, 1, 3]

function shortestSubarray(nums: number[], K: number): number {
  const n = nums.length;
  const P = new Array<number>(n + 1).fill(0); // prefix sums
  for (let i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
  const deque: number[] = []; // indexes into P; P values increasing front to back
  let head = 0;
  let best = Infinity;
  for (let j = 0; j <= n; j++) {
    while (deque.length > head && P[j] - P[deque[head]] >= K) {
      best = Math.min(best, j - deque[head]);
      head++; // this front can never give a shorter answer later
    }
    while (deque.length > head && P[deque[deque.length - 1]] >= P[j]) deque.pop(); // worse than j
    deque.push(j);
  }
  return best === Infinity ? -1 : best;
}
console.log(shortestSubarray([1], 1)); // 1
console.log(shortestSubarray([1, 2], 4)); // -1
console.log(shortestSubarray([2, -1, 2], 3)); // 3
console.log(shortestSubarray([84, -37, 32, 40, 95], 167)); // 3
func shortestSubarray(nums []int, K int) int {
	n := len(nums)
	P := make([]int, n+1) // prefix sums
	for i, x := range nums {
		P[i+1] = P[i] + x
	}
	deque := []int{} // indexes into P; P values increasing front to back
	head := 0
	best := math.MaxInt
	for j := 0; j <= n; j++ {
		for len(deque) > head && P[j]-P[deque[head]] >= K {
			best = min(best, j-deque[head])
			head++ // this front can never give a shorter answer later
		}
		for len(deque) > head && P[deque[len(deque)-1]] >= P[j] {
			deque = deque[:len(deque)-1] // worse than j
		}
		deque = append(deque, j)
	}
	if best == math.MaxInt {
		return -1
	}
	return best
}

func exampleShortestSubarray() {
	fmt.Println(shortestSubarray([]int{1}, 1))                      // 1
	fmt.Println(shortestSubarray([]int{1, 2}, 4))                   // -1
	fmt.Println(shortestSubarray([]int{2, -1, 2}, 3))               // 3
	fmt.Println(shortestSubarray([]int{84, -37, 32, 40, 95}, 167)) // 3
}

Complexity. Time O(n) (each index enters and leaves the deque once), space O(n).

Why this is the "senior" problem: it combines three ideas (prefix sums, why windows fail with negatives, monotonic deque) and each pop needs a one-sentence justification. Practice saying those justifications aloud.

Common mistakes

  • Using shift() for the queue front in JavaScript on large inputs (O(n²) total).
  • Storing values instead of indexes in the monotonic deque, then being unable to tell whether the front left the window.
  • Wrong order of operations in sliding-window max: pop dead items, push, then expire the front, then read the answer.
  • Reading the answer before the first full window (i < k − 1).
  • Circular queue: ambiguity between full and empty if you only track head and tail. Track size.
  • Using a sliding window (file 06) for sums with negatives.
  • Forgetting that Go's q = q[1:] keeps the whole backing array alive (a slow memory leak for very long runs).

1 · Amortized pop with two stacks

Explain why the amortized cost of pop in "queue using two stacks" is O(1), using the words "each item moves at most once".

Answer

Each item is pushed onto the inbox once, moved to the outbox at most once, and popped from the outbox once: at most three constant-time steps per item over its whole life. A single pop can be O(n) when it pours the inbox, but across n operations the total is O(n), so each is amortized O(1).

2 · maxSlidingWindow([4, 2, 12, 11, −5], 2)

Run maxSlidingWindow([4, 2, 12, 11, −5], 2) by hand, listing the deque after each step.

Answer

i=0: deque [0]. i=1: [0, 1] → max 4. i=2: 12 pops 1 and 0 → [2] → max 12. i=3: [2, 3] → max 12. i=4: [2, 3, 4], index 2 expires → [3, 4] → max 11. Answer [4, 12, 12, 11]. Check it with Problem 4's second preset.

3 · Indexes, not values

Why must the monotonic deque hold indexes and not values?

Answer

The front must be dropped when it slides out of the window, and only its index tells you that (index ≤ i − k). Values also repeat, so a value cannot tell two positions apart.

4 · Sliding Window Median

Sliding Window Median (LeetCode 480) is harder: which data structure replaces the deque, and why?

Answer

A median needs the middle of the window, not just its extreme, so a deque is not enough. Use two heaps (a max-heap for the lower half and a min-heap for the upper half) with lazy deletion, or a balanced ordered structure, for O(n log k).

5 · Jump Game VI

Jump Game VI (LeetCode 1696): dp[i] = nums[i] + max(dp[i−k..i−1]). Which tool from this file gives O(n)?

Answer

A monotonic deque over dp values: it holds the indexes of the last k dp values in decreasing order, so max(dp[i−k..i−1]) is always at the front. That gives O(n) instead of O(n·k).
