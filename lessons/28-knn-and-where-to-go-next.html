The idea

To classify or predict for a new point, find the k most similar known points and let them vote (or average).

The decisions

Which features, how to measure distance, which k. Normalize features so one big scale does not dominate.

Beyond

Bloom filters answer "seen it?" in tiny memory; inverted indexes power search; LSH finds near neighbors fast.

1. The idea of k-nearest neighbors (k-NN), in plain English

"Tell me who your neighbors are, and I will tell you who you are."

Suppose you must decide whether a mystery fruit is an orange or a grapefruit. You know two facts about each fruit: its size and its color. Plot every fruit you already know as a dot on a graph (size on one axis, redness on the other). Oranges cluster in one area, grapefruits in another. To classify a new fruit, put its dot on the graph and look at the k nearest dots (its neighbors). If most of them are grapefruits, call it a grapefruit.

That is the whole algorithm. There is no training step: the "model" is just the stored data.

The three decisions that matter

DecisionWhat it meansTypical choice
FeaturesWhat numbers describe each item? Choosing good features is most of the work.size, color, price, rating, age…
DistanceHow do we measure "close"?Euclidean (the straight-line distance from the Pythagorean theorem), or cosine similarity for "direction"
kHow many neighbors vote?small odd numbers (3, 5, 7); too small is noisy, too large blurs boundaries

Distance formulas (the book's version)

For two items with feature lists (a₁, a₂, …) and (b₁, b₂, …):

Euclidean distance = √( (a₁−b₁)² + (a₂−b₂)² + … )

Cosine similarity compares the angle between the two feature vectors rather than their length, and is common for ratings and text: cos = (a·b) / (|a| |b|), where 1 means "pointing the same way" and 0 means "unrelated". It is better than Euclidean distance when one user rates everything high and another rates everything low but they agree on the relative order.

The classic pitfall: normalize your features

If one feature is measured in hundreds (price) and another in 0 to 1 (a score), the big numbers swamp the distance and the small feature is ignored. Rescale each feature to a common range, for example min-max scaling: (x − min) / (max − min), giving values between 0 and 1.

2. Three uses of k-NN (from the book)

  1. Classification: put the item in a category by voting: orange vs. grapefruit, spam vs. not spam, which digit is this image.
  2. Regression: predict a number by averaging the neighbors' numbers: how many loaves of bread to bake today, based on the weather, the day of the week, and whether there is a game, using the five most similar past days.
  3. Recommendations: to suggest movies to you, find the users most similar to you (by their ratings) and recommend what they loved that you have not seen. (This is what the book's Netflix example does.)

Cost

For n stored items with d features:

  • Query time: O(n · d) for the plain version (measure the distance to everyone), plus picking the k smallest (O(n log k) with a heap, or O(n) with quickselect: see files 17 and 09).
  • Memory: O(n · d): it stores everything.
  • Speed-ups: space-partitioning trees (k-d trees, ball trees) work well for few features; for many features use approximate nearest-neighbor search (locality-sensitive hashing, HNSW graphs).

Machine learning in one paragraph (from the book)

Training a model means feeding it examples so it can find patterns. k-NN is the simplest model because "training" is just storing the data. Other models (linear regression, decision trees, neural networks) learn parameters from the data and then throw the data away. The recurring steps: pick features, collect data, split it into training and test sets, measure how often the model is right on the test set (so you do not fool yourself).

3. Practice problems

Problem 1 · K Closest Points to Origin (LeetCode 973, Medium): "k nearest" as an interview question

Task. Given points on a plane and k, return the k points closest to the origin (0, 0) (Euclidean distance). [[1,3],[-2,2]], k = 1 → [[-2,2]]. [[3,3],[5,-1],[-2,4]], k = 2 → [[3,3],[-2,4]].

Two insights.

  1. Skip the square root. Comparing x² + y² orders points exactly like the true distance does (the square root never changes the order), and avoids floating-point error.
  2. You only need the k smallest, not a full sort. Use a max-heap of size k (file 17): keep the k best so far; the top of the heap is the worst of them, which gets replaced when a closer point arrives. O(n log k). (Or quickselect for O(n) average.)
const squaredDistance = (p: number[]): number => p[0] * p[0] + p[1] * p[1]; // no square root needed

// Simple: sort everything. O(n log n).
function kClosestSorted(points: number[][], k: number): number[][] {
  return [...points].sort((a, b) => squaredDistance(a) - squaredDistance(b)).slice(0, k);
}

// Better when k is small: keep a max-heap of the k best (array-based, written out).
function kClosest(points: number[][], k: number): number[][] {
  const heap: number[][] = []; // max-heap by squared distance: the WORST of the k best is on top
  const worse = (i: number, j: number): boolean => squaredDistance(heap[i]) > squaredDistance(heap[j]);
  const swap = (i: number, j: number): void => {
    [heap[i], heap[j]] = [heap[j], heap[i]];
  };
  const siftUp = (i: number): void => {
    while (i > 0 && worse(i, (i - 1) >> 1)) {
      swap(i, (i - 1) >> 1);
      i = (i - 1) >> 1;
    }
  };
  const siftDown = (i: number): void => {
    for (;;) {
      const l = 2 * i + 1, r = 2 * i + 2;
      let big = i;
      if (l < heap.length && worse(l, big)) big = l;
      if (r < heap.length && worse(r, big)) big = r;
      if (big === i) return;
      swap(i, big);
      i = big;
    }
  };
  for (const p of points) {
    if (heap.length < k) {
      heap.push(p);
      siftUp(heap.length - 1);
    } else if (squaredDistance(p) < squaredDistance(heap[0])) {
      heap[0] = p; // the new point beats the current worst
      siftDown(0);
    }
  }
  return heap;
}

console.log(kClosest([[3, 3], [5, -1], [-2, 4]], 2).sort((a, b) => a[0] - b[0])); // [ [ -2, 4 ], [ 3, 3 ] ]
console.log(kClosest([[1, 1], [2, 2], [3, 3]], 3).length); // 3
func squaredDistance(p []int) int { return p[0]*p[0] + p[1]*p[1] } // no square root needed

// Simple: sort everything. O(n log n).
func kClosestSorted(points [][]int, k int) [][]int {
	sorted := append([][]int(nil), points...)
	sort.Slice(sorted, func(i, j int) bool { return squaredDistance(sorted[i]) < squaredDistance(sorted[j]) })
	return sorted[:k]
}

// Better when k is small: keep a max-heap of the k best (written out by hand).
func kClosest(points [][]int, k int) [][]int {
	heap := make([][]int, 0, k) // max-heap by squared distance: the WORST of the k best is on top
	worse := func(i, j int) bool { return squaredDistance(heap[i]) > squaredDistance(heap[j]) }
	siftUp := func(i int) {
		for i > 0 && worse(i, (i-1)/2) {
			heap[i], heap[(i-1)/2] = heap[(i-1)/2], heap[i]
			i = (i - 1) / 2
		}
	}
	siftDown := func(i int) {
		for {
			l, r := 2*i+1, 2*i+2
			big := i
			if l < len(heap) && worse(l, big) {
				big = l
			}
			if r < len(heap) && worse(r, big) {
				big = r
			}
			if big == i {
				return
			}
			heap[i], heap[big] = heap[big], heap[i]
			i = big
		}
	}
	for _, p := range points {
		if len(heap) < k {
			heap = append(heap, p)
			siftUp(len(heap) - 1)
		} else if squaredDistance(p) < squaredDistance(heap[0]) {
			heap[0] = p // the new point beats the current worst
			siftDown(0)
		}
	}
	return heap
}

func exampleKClosest() {
	fmt.Println(kClosestSorted([][]int{{1, 3}, {-2, 2}}, 1)) // [[-2 2]]
	result := kClosest([][]int{{3, 3}, {5, -1}, {-2, 4}}, 2)
	sort.Slice(result, func(i, j int) bool { return result[i][0] < result[j][0] })
	fmt.Println(result)                                               // [[-2 4] [3 3]]
	fmt.Println(len(kClosest([][]int{{1, 1}, {2, 2}, {3, 3}}, 3))) // 3
}

Complexity. Sorting: O(n log n). Heap: O(n log k), space O(k).

Problem 2 · A k-NN classifier from scratch (the book's orange vs. grapefruit)

Task. Build classify(query, k): given labeled fruits (diameter in cm, redness from 0 to 1), label a new fruit.

orange:     (7.0, 0.30)  (7.5, 0.35)  (8.0, 0.32)  (7.2, 0.28)
grapefruit: (11.0, 0.60) (12.0, 0.65) (10.5, 0.70) (11.5, 0.62)

Steps. (1) Min-max normalize each feature using the min and max in the training data. (2) For the query, compute the distance to every stored fruit. (3) Take the k closest. (4) Return the most common label.

Why normalization matters here: diameters range over 5 cm (7 to 12) while redness ranges over 0.42. In raw units the diameter drowns the color. Take a fruit that is 9 cm and very red (0.69):

  • Without normalization the closest fruits by raw distance are an 8 cm orange, a 10.5 cm grapefruit, and a 7.5 cm orange. They vote orange: the redness barely counted.
  • With normalization color counts as much as size. The very red query sits close to the red grapefruits, and the vote is grapefruit.
type Labeled = { features: number[]; label: string };

const fruits: Labeled[] = [
  { features: [7.0, 0.3], label: "orange" },
  { features: [7.5, 0.35], label: "orange" },
  { features: [8.0, 0.32], label: "orange" },
  { features: [7.2, 0.28], label: "orange" },
  { features: [11.0, 0.6], label: "grapefruit" },
  { features: [12.0, 0.65], label: "grapefruit" },
  { features: [10.5, 0.7], label: "grapefruit" },
  { features: [11.5, 0.62], label: "grapefruit" },
];

function euclidean(a: number[], b: number[]): number {
  let sum = 0;
  for (let i = 0; i < a.length; i++) sum += (a[i] - b[i]) ** 2;
  return Math.sqrt(sum);
}

// Learn the min and max of every feature from the training data.
function featureRanges(data: Labeled[]): { min: number[]; max: number[] } {
  const d = data[0].features.length;
  const min = new Array<number>(d).fill(Infinity);
  const max = new Array<number>(d).fill(-Infinity);
  for (const { features } of data) {
    features.forEach((v, i) => {
      min[i] = Math.min(min[i], v);
      max[i] = Math.max(max[i], v);
    });
  }
  return { min, max };
}

function scale(v: number[], min: number[], max: number[]): number[] {
  return v.map((x, i) => (max[i] === min[i] ? 0 : (x - min[i]) / (max[i] - min[i])));
}

function classify(data: Labeled[], query: number[], k: number, normalize = true): string {
  const { min, max } = featureRanges(data);
  const prep = (v: number[]): number[] => (normalize ? scale(v, min, max) : v);
  const q = prep(query);
  const nearest = data
    .map((item) => ({ label: item.label, dist: euclidean(prep(item.features), q) }))
    .sort((a, b) => a.dist - b.dist)
    .slice(0, k); // the k closest neighbors
  const votes = new Map<string, number>();
  for (const n of nearest) votes.set(n.label, (votes.get(n.label) ?? 0) + 1);
  return [...votes.entries()].sort((a, b) => b[1] - a[1])[0][0]; // the majority label
}

console.log(classify(fruits, [11.2, 0.64], 3)); // grapefruit
console.log(classify(fruits, [9.0, 0.69], 3, false)); // orange      (raw units: size dominates)
console.log(classify(fruits, [9.0, 0.69], 3, true)); // grapefruit  (normalized: color counts)
type Labeled struct {
	features []float64
	label    string
}

func euclidean(a, b []float64) float64 {
	sum := 0.0
	for i := range a {
		d := a[i] - b[i]
		sum += d * d
	}
	return math.Sqrt(sum)
}

// Learn the min and max of every feature from the training data.
func featureRanges(data []Labeled) (min, max []float64) {
	d := len(data[0].features)
	min = make([]float64, d)
	max = make([]float64, d)
	for i := 0; i < d; i++ {
		min[i], max[i] = math.Inf(1), math.Inf(-1)
	}
	for _, item := range data {
		for i, v := range item.features {
			min[i] = math.Min(min[i], v)
			max[i] = math.Max(max[i], v)
		}
	}
	return min, max
}

func scale(v, min, max []float64) []float64 {
	out := make([]float64, len(v))
	for i, x := range v {
		if max[i] != min[i] {
			out[i] = (x - min[i]) / (max[i] - min[i])
		}
	}
	return out
}

func classify(data []Labeled, query []float64, k int, normalize bool) string {
	minV, maxV := featureRanges(data)
	prep := func(v []float64) []float64 {
		if normalize {
			return scale(v, minV, maxV)
		}
		return v
	}
	q := prep(query)
	type neighbor struct {
		label string
		dist  float64
	}
	all := make([]neighbor, len(data))
	for i, item := range data {
		all[i] = neighbor{item.label, euclidean(prep(item.features), q)}
	}
	sort.Slice(all, func(i, j int) bool { return all[i].dist < all[j].dist })
	votes := make(map[string]int)
	for _, n := range all[:k] { // the k closest neighbors
		votes[n.label]++
	}
	bestLabel, bestVotes := "", -1
	for label, v := range votes {
		if v > bestVotes || (v == bestVotes && label < bestLabel) { // deterministic tie-break
			bestLabel, bestVotes = label, v
		}
	}
	return bestLabel // the majority label
}

func exampleClassify() {
	fruits := []Labeled{
		{[]float64{7.0, 0.3}, "orange"},
		{[]float64{7.5, 0.35}, "orange"},
		{[]float64{8.0, 0.32}, "orange"},
		{[]float64{7.2, 0.28}, "orange"},
		{[]float64{11.0, 0.6}, "grapefruit"},
		{[]float64{12.0, 0.65}, "grapefruit"},
		{[]float64{10.5, 0.7}, "grapefruit"},
		{[]float64{11.5, 0.62}, "grapefruit"},
	}
	fmt.Println(classify(fruits, []float64{7.8, 0.33}, 3, true))  // orange
	fmt.Println(classify(fruits, []float64{11.2, 0.64}, 3, true)) // grapefruit
	fmt.Println(classify(fruits, []float64{9.0, 0.69}, 3, false)) // orange      (raw units: size dominates)
	fmt.Println(classify(fruits, []float64{9.0, 0.69}, 3, true))  // grapefruit  (normalized: color counts)
}

Complexity. Per query: O(n · d + n log n) as written (sort); O(n · d + n log k) with a heap.

Regression (the bakery). A bakery wants to know how many loaves to bake today. For each past day it recorded three features and the loaves sold:

weather (1 bad to 5 great)weekend (0/1)big game (0/1)loaves sold

To predict today, find the k past days most similar to today and average their loaves. (For k = 3 and today = (4, 1, 0) the three nearest past days are (4,1,0), (3,1,1), and (4,0,1); see the note below the code for the arithmetic.)

Recommendations (the movies). Each user rates five genres from 1 to 5: comedy, action, drama, horror, romance.

Priyanka: 3 4 4 1 4
Justin:   4 3 5 1 5
Morpheus: 2 5 1 3 1

Euclidean distance from Priyanka to Justin is √(1+1+1+0+1) = 2; to Morpheus it is √(1+1+9+4+9) = √24 ≈ 4.9. So Justin is her nearest neighbor: recommend what Justin loved. (The book also notes a quirk: some users rate everything high. Cosine similarity or normalizing each user's average fixes that.)

function knnRegress(history: { features: number[]; value: number }[], query: number[], k: number): number {
  const nearest = history
    .map((h) => ({ value: h.value, dist: euclidean(h.features, query) })) // euclidean() from Problem 2
    .sort((a, b) => a.dist - b.dist)
    .slice(0, k);
  return nearest.reduce((sum, n) => sum + n.value, 0) / nearest.length; // average of the neighbors
}

function cosineSimilarity(a: number[], b: number[]): number {
  let dot = 0, na = 0, nb = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    na += a[i] * a[i];
    nb += b[i] * b[i];
  }
  return dot / (Math.sqrt(na) * Math.sqrt(nb));
}

function mostSimilarUser(target: number[], others: Map<string, number[]>): string {
  let bestName = "", bestDist = Infinity;
  for (const [name, ratings] of others) {
    const d = euclidean(target, ratings);
    if (d < bestDist) {
      bestDist = d;
      bestName = name;
    }
  }
  return bestName;
}

type Past struct {
	features []float64
	value    float64
}

func knnRegress(history []Past, query []float64, k int) float64 {
	type neighbor struct{ value, dist float64 }
	all := make([]neighbor, len(history))
	for i, h := range history {
		all[i] = neighbor{h.value, euclidean(h.features, query)} // euclidean() from Problem 2
	}
	sort.Slice(all, func(i, j int) bool { return all[i].dist < all[j].dist })
	sum := 0.0
	for _, n := range all[:k] {
		sum += n.value
	}
	return sum / float64(k) // average of the neighbors
}

func cosineSimilarity(a, b []float64) float64 {
	dot, na, nb := 0.0, 0.0, 0.0
	for i := range a {
		dot += a[i] * b[i]
		na += a[i] * a[i]
		nb += b[i] * b[i]
	}
	return dot / (math.Sqrt(na) * math.Sqrt(nb))
}

func mostSimilarUser(target []float64, names []string, others [][]float64) string {
	bestName, bestDist := "", math.Inf(1)
	for i, ratings := range others {
		if d := euclidean(target, ratings); d < bestDist {
			bestDist, bestName = d, names[i]
		}
	}
	return bestName
}

		{[]float64{4, 0, 1}, 200},
		{[]float64{4, 1, 0}, 150},

4. Where to go next: a short tour of the book's final chapter

Each of these is one idea you can explain in 30 seconds. They are the bridge between "algorithm interviews" and "system design interviews".

4.1 Inverted indexes: how search engines find pages

A forward index maps document → words. A search engine needs the reverse: word → the documents that contain it. That map is an inverted index. To answer a query with several words, look up each word's list of document ids and intersect the lists (the same two-pointer idea as file 24).

4.2 Bloom filters and HyperLogLog: answering "have I seen this?" with tiny memory

  • A Bloom filter is a bit array plus a few hash functions. To add an item, set the bits that its hashes point at. To check an item, look at those same bits. If any is 0, the item is definitely not present. If all are 1, it is probably present (other items may have set the same bits by chance: a false positive). It never gives a false negative, cannot delete items, and uses a small, fixed amount of memory regardless of the item size. Uses: "is this URL on the malware list?", "does this username exist?" before an expensive lookup, databases skipping disk reads.
  • HyperLogLog estimates how many distinct items a huge stream contains, using a few kilobytes, with an error of about 1 to 2 percent. Uses: unique visitors per day.

4.3 The Fourier transform

It breaks a signal (a sound, an image row) into the sine waves that add up to it: like unmixing a smoothie into its fruits. Uses: audio compression (MP3), JPEG, noise removal, Shazam-style recognition. The Fast Fourier Transform computes it in O(n log n) and also multiplies huge polynomials/numbers quickly.

4.4 Parallel algorithms and MapReduce

When one computer is too slow, split the work across many (cores or machines).

  • Parallel algorithms must divide the problem so pieces do not depend on each other (parallel merge sort splits the array, sorts halves at the same time, then merges).
  • MapReduce is a pattern: the map step runs the same function on many pieces of data in parallel and emits key/value pairs; the reduce step combines all values for each key. Example: count words in a billion pages: map each page to (word, 1) pairs, reduce by summing per word. Frameworks: Hadoop, Spark.

4.5 HTTPS and the Diffie–Hellman key exchange

Two strangers must agree on a secret key over a channel that an eavesdropper is listening to. Diffie–Hellman does it with math that is easy in one direction and very hard to reverse (modular exponentiation vs. the discrete logarithm). The famous paint analogy: each person mixes a secret color with a shared public color, they swap the mixtures, and each adds their own secret color again, so both end with the same final color, which the eavesdropper (who only saw mixtures) cannot reproduce. This is how a browser and a server agree on the key that encrypts an HTTPS session.

4.6 Locality-sensitive hashing (LSH)

Normal hashes scatter similar inputs apart. An LSH does the opposite: similar items land in the same bucket with high probability. So to find the neighbors of an item, hash it and look only inside its bucket instead of comparing against everything. Uses: near-duplicate detection, "similar images", approximate nearest-neighbor search at huge scale (the practical partner of k-NN).

4.7 Linear programming and linear regression

  • Linear regression fits a line through data to predict a number (the cousin of k-NN regression, but it learns two parameters and discards the data). Uses: trend forecasting.
  • Linear programming maximizes or minimizes a linear goal under linear constraints (like "maximize profit given limited hours and materials"). The simplex method solves it. Many graph problems, such as max flow and shortest paths, can be phrased this way.

Problem 4 · A Bloom filter you can run

Task. Implement add(item) and mightContain(item); show that there are no false negatives and measure the false-positive rate.

Design.

  • m bits and k hash functions. A good starting point for n items and a target error rate p: m = −n · ln(p) / (ln 2)² and k = (m / n) · ln 2. For n = 1000, p = 1%: m ≈ 9586 bits, k ≈ 7.
  • Instead of k independent hash functions, use double hashing: compute two hashes h1 and h2 and let the i-th index be (h1 + i · h2) mod m.
  • Our hash is FNV-1a (a tiny, well-known string hash), so the TypeScript and Go versions produce the same bit patterns and the same counts.
function fnv1a(text: string, seed = 2166136261): number {
  let h = seed >>> 0;
  for (let i = 0; i < text.length; i++) {
    h ^= text.charCodeAt(i);
    h = Math.imul(h, 16777619) >>> 0; // 32-bit multiply, kept unsigned
  }
  return h;
}

class BloomFilter {
  private bits: Uint8Array; // one byte per bit, for clarity (a real one packs 8 bits per byte)
  constructor(private m: number, private k: number) {
    this.bits = new Uint8Array(m);
  }
  private positions(item: string): number[] {
    const h1 = fnv1a(item);
    const h2 = (fnv1a(item, 0x9747b28c) | 1) >>> 0; // odd; >>> 0 makes it unsigned (| 1 alone gives a SIGNED 32-bit result in JavaScript)
    const out: number[] = [];
    for (let i = 0; i < this.k; i++) out.push((h1 + i * h2) % this.m); // double hashing
    return out;
  }
  add(item: string): void {
    for (const p of this.positions(item)) this.bits[p] = 1;
  }
  mightContain(item: string): boolean {
    return this.positions(item).every((p) => this.bits[p] === 1); // any 0 means "definitely not"
  }
}

func fnv1a(text string, seed uint32) uint32 {
	h := seed
	for i := 0; i < len(text); i++ {
		h ^= uint32(text[i])
		h *= 16777619 // 32-bit multiply wraps around automatically
	}
	return h
}

type BloomFilter struct {
	bits []bool // one entry per bit, for clarity (a real one packs 8 bits per byte)
	m, k uint64
}

func NewBloomFilter(m, k int) *BloomFilter {
	return &BloomFilter{bits: make([]bool, m), m: uint64(m), k: uint64(k)}
}

func (b *BloomFilter) positions(item string) []uint64 {
	h1 := uint64(fnv1a(item, 2166136261))
	h2 := uint64(fnv1a(item, 0x9747b28c)) | 1 // odd, so the steps spread over all positions
	out := make([]uint64, b.k)
	for i := uint64(0); i < b.k; i++ {
		out[i] = (h1 + i*h2) % b.m // double hashing
	}
	return out
}

func (b *BloomFilter) Add(item string) {
	for _, p := range b.positions(item) {
		b.bits[p] = true
	}
}

func (b *BloomFilter) MightContain(item string) bool {
	for _, p := range b.positions(item) {
		if !b.bits[p] {
			return false // any 0 means "definitely not"
		}
	}
	return true
}

func exampleBloomFilter() {
	bloom := NewBloomFilter(9586, 7) // sized for 1000 items at about a 1% false-positive rate
	for i := 0; i < 1000; i++ {
		bloom.Add("user" + strconv.Itoa(i))
	}
	missed := 0 // false negatives: must be zero
	for i := 0; i < 1000; i++ {
		if !bloom.MightContain("user" + strconv.Itoa(i)) {
			missed++
		}
	}
	falsePositives := 0
	for i := 0; i < 10000; i++ {
		if bloom.MightContain("other" + strconv.Itoa(i)) {
			falsePositives++
		}
	}
	fmt.Println("false negatives:", missed)                      // false negatives: 0
	fmt.Println("false positives out of 10000:", falsePositives) // 76  (0.76%, under the 1% target; TypeScript prints the same)
}

Complexity. add and mightContain take O(k) time; memory is m bits, independent of how long each item is.

A real bug worth remembering (found while testing this very guide). The first TypeScript version wrote fnv1a(item, seed) | 1 for the second hash. In JavaScript, any bitwise operator returns a signed 32-bit integer, so values at or above 2³¹ turn negative. The computed index (h1 + i * h2) % m then became negative, the bit was written to a place that does not exist, and the filter reported 346 false negatives, which a Bloom filter must never do. Adding >>> 0 (convert back to unsigned) fixed it, after which TypeScript and Go gave identical results. The lesson: when you mix hashing with bit operators in JavaScript, force the result unsigned with >>> 0, and always test the "no false negatives" property.

What to say in an interview. "A Bloom filter trades exactness for memory. It is perfect in front of an expensive lookup: a no answer is final and saves the lookup; a yes answer is checked against the real store." Mention that it cannot delete (a counting Bloom filter can) and that the false-positive rate rises as it fills up.

Problem 5 · An inverted index with an AND query

Task. Build an inverted index over small documents and answer a query of several words with all words present (an AND search). Documents:

1: "the quick brown fox"
2: "the lazy dog"
3: "quick brown dogs and the fox"

search("quick fox") → [1, 3]. search("the") → [1, 2, 3]. search("cat") → [].

Plan.

  1. Index: for each document (in id order) split into words, lowercase, and append the doc id to each distinct word's list. Ids are added in increasing order, so every list is already sorted.
  2. Query: look up each word's list, then intersect them with the two-pointer merge (file 24). Start with the shortest list to do less work.
class InvertedIndex {
  private index = new Map<string, number[]>(); // word -> sorted list of document ids
  addDocument(id: number, text: string): void {
    for (const word of new Set(text.toLowerCase().split(/\s+/))) { // Set: count each word once per doc
      const list = this.index.get(word);
      if (list) list.push(id); // ids arrive in increasing order, so the list stays sorted
      else this.index.set(word, [id]);
    }
  }
  search(query: string): number[] {
    const lists = query.toLowerCase().split(/\s+/).map((w) => this.index.get(w) ?? []);
    if (lists.some((l) => l.length === 0)) return []; // a word nobody has: no result
    lists.sort((a, b) => a.length - b.length); // start with the shortest list
    return lists.reduce((acc, list) => intersectSorted(acc, list));
  }
}

function intersectSorted(a: number[], b: number[]): number[] {
  const out: number[] = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] === b[j]) {
      out.push(a[i]);
      i++;
      j++;
    } else if (a[i] < b[j]) i++;
    else j++;
  }
  return out;
}

search.addDocument(2, "the lazy dog");
search.addDocument(3, "quick brown dogs and the fox");

console.log(search.search("the")); // [ 1, 2, 3 ]
console.log(search.search("cat")); // []
console.log(search.search("quick dog")); // []   ("dogs" in doc 3 is a different word from "dog")
type InvertedIndex struct{ index map[string][]int } // word -> sorted list of document ids

func NewInvertedIndex() *InvertedIndex { return &InvertedIndex{index: make(map[string][]int)} }

func (ix *InvertedIndex) AddDocument(id int, text string) {
	seen := make(map[string]bool) // count each word once per document
	for _, word := range strings.Fields(strings.ToLower(text)) {
		if !seen[word] {
			seen[word] = true
			ix.index[word] = append(ix.index[word], id) // ids arrive in increasing order, so lists stay sorted
		}
	}
}

func intersectSorted(a, b []int) []int {
	out := []int{}
	i, j := 0, 0
	for i < len(a) && j < len(b) {
		switch {
		case a[i] == b[j]:
			out = append(out, a[i])
			i++
			j++
		case a[i] < b[j]:
			i++
		default:
			j++
		}
	}
	return out
}

func (ix *InvertedIndex) Search(query string) []int {
	words := strings.Fields(strings.ToLower(query))
	lists := make([][]int, 0, len(words))
	for _, w := range words {
		list := ix.index[w]
		if len(list) == 0 {
			return []int{} // a word nobody has: no result
		}
		lists = append(lists, list)
	}
	sort.Slice(lists, func(i, j int) bool { return len(lists[i]) < len(lists[j]) }) // start with the shortest list
	result := lists[0]
	for _, list := range lists[1:] {
		result = intersectSorted(result, list)
	}
	return result
}

func exampleInvertedIndex() {
	ix := NewInvertedIndex()
	ix.AddDocument(1, "the quick brown fox")
	ix.AddDocument(2, "the lazy dog")
	ix.AddDocument(3, "quick brown dogs and the fox")
	fmt.Println(ix.Search("quick fox"))  // [1 3]
	fmt.Println(ix.Search("the"))        // [1 2 3]
	fmt.Println(ix.Search("cat"))        // []
	fmt.Println(ix.Search("quick dog"))  // []
}

Complexity. Index: time O(total words). Query: O(sum of the list lengths) (the two-pointer merges), and starting with the rarest word keeps intermediate results small.

What real search engines add: ranking (TF-IDF, BM25), phrase queries (store word positions), stemming ("dogs" → "dog"), compression of the id lists, and sharding across machines.

A learning path after this guide

Common mistakes (k-NN)

  • Not normalizing features (the big-scale feature silently dominates).
  • Using k = 1 (very noisy) or a k equal to the dataset size (always votes for the majority class).
  • Using an even k with two classes (ties). Prefer odd k, or a deterministic tie-break.
  • Computing the square root needlessly when only the order of distances matters.
  • Testing on the training data (it will look perfect). Hold out test data.
  • Using k-NN on huge, high-dimensional data without approximate methods: distances become meaningless ("the curse of dimensionality") and queries become too slow.

1 · k-NN in three sentences

Explain k-NN to a friend with the orange/grapefruit story in three sentences.

Answer

To decide whether a new fruit is an orange or a grapefruit, look at the fruits you already know that are most like it in size and color. Take the k closest, say 3. Whatever most of them are, call the new fruit that.

2 · Squared distances

Why do we compare squared distances in K Closest Points? When would you need the true distance?

Answer

The square root is increasing, so it never changes which point is closer: comparing x² + y² gives the same order, with no slow square root and no floating-point rounding. You need the true distance when the number itself matters: reporting it, comparing it with a radius given in real units, or adding distances together.

3 · Can a Bloom filter be wrong?

A Bloom filter says "not present" for an item. Can it be wrong? A "present"? Explain both.

Answer

"Not present" is always right: adding an item sets all its bits, and bits are never cleared, so a 0 at any of its positions proves it was never added. "Present" can be wrong: other items may have set all of its bits by chance (a false positive). The second preset of the Bloom animation crowds a small filter to show this.

4 · Sorted posting lists

Why is each inverted-index list stored sorted, and what does that buy the AND query?

Answer

Two sorted lists intersect with two pointers in O(a + b), like the merge step of merge sort: advance whichever pointer has the smaller id. Starting from the shortest list keeps the intermediate results small, and sorted lists also allow skip pointers or galloping to jump ahead. Without sorting you would need a hash set per query.

5 · MapReduce word count

In MapReduce word count, what are the keys and values emitted by map, and what does reduce receive?

Answer

Map reads a chunk of text and emits (word, 1) for every word. The framework groups by key, so reduce receives (word, [1, 1, …]) and emits (word, sum). Each machine maps its own chunk; each reducer handles its own share of the words.

6 · Exact k-NN or LSH

Which would you pick to find near-duplicate documents among a billion: exact k-NN or LSH, and why?

Answer

LSH. Exact k-NN compares every document with every other: about 10¹⁸ comparisons for a billion. Locality-sensitive hashing hashes similar documents into the same buckets with high probability, so you compare only within buckets. You accept a small chance of missing a pair in return for a huge speed-up.
